```text
   Mermaid 类：provider.chat 出源码 → validate_mermaid
               失败 → MERMAID_REPAIR_PROMPT 修复 1 次 → 再校验
   JSON 类：provider.chat 出结构化数据
        ↓ 结果落库 sections.{type}_json
⑤ 前端预览 (DiagramPreview.tsx)
   mermaid.render → innerHTML；失败 → 原生 SVG 降级
        ↓
⑥ 导出 Word (export.py:1481 _add_inline_chart → 1530 _render_commercial)
   ⚠️ 导出时重新渲染，不复用前端 SVG
   L1 内存缓存 → L2 磁盘 ChartCache → L1.5 HTTP → L2 PIL 自绘
   全失败 → 插入灰色斜体「【图表渲染失败】」文字（V6.1 设计，正确）
```

### 5.2 渲染降级链

```text
┌─────────────────────────────────────────────────────────────┐
│  L1 内存缓存（进程内，LRU 500MB）                            │
│  ↓ 未命中                                                    │
│  L2 磁盘 ChartCache（MD5 key，7 天清理）                     │
│  ↓ 未命中                                                    │
│  L1.5 HTTP 渲染（Docker → Railway → mmdc CLI）               │
│  ├─ 仅接受合法 Mermaid 语法（{ 开头跳过）                     │
│  ├─ HTTP 总预算 20s，最多重试 2 次                            │
│  └─ 默认地址 localhost:8080/render                            │
│  ↓ 未命中                                                    │
│  L2 PIL 自绘（7 个 v2 渲染器，300 DPI + 2.5x 超采样）         │
│  ↓ 全部失败                                                  │
│  插入灰色斜体「【图表渲染失败】」文字，不伪造数据（V6.1 设计）  │
└─────────────────────────────────────────────────────────────┘
```

### 5.3 关于 `mermaid_layout.py` 的澄清

**它不是通用布局算法**，而是「施工现场总平面布置图」专用渲染器：

- 布局为**固定网格法**：`cols=ceil(sqrt(n*1.5))`，`rows=ceil(n/cols)`（`:126`）
- 区域尺寸硬编码：`zone_w=220*scale`
- **防重叠仅靠固定间距、无碰撞检测**
- 连接线取中心点直线，**可能穿越其他区域**

**风险**：复杂总平面图可能出现区域重叠或连线穿越，需人工复核。
