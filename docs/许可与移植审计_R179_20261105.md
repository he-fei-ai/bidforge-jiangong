## 一、许可结论

对方项目 **OpenBidKit（易标）** 的许可证为 **AGPL-3.0-only**（强 copyleft）。
据此确立三条不可动摇的结论：

1. **不得复制、翻译、改写对方代码**，包括"改个变量名/换门语言"的改写；
2. **删除注释里的"移植自/对齐对方"表述，不消除任何许可义务** —— 许可义务附着于
   表达本身，不附着于注释。只改注释、不改实现，等于把风险从"显式声明"变成
   "隐式侵权"，**比不改更糟**；
3. 若本软件对外分发或通过网络向用户提供服务，AGPL 要求提供完整 Corresponding
   Source 并保留许可与版权声明（§13 网络条款同样适用）。

因此本次执行顺序严格为：**逐文件判定 → A 类独立重写 → 重写绿了才动注释**。

## 三、A 类重写记录与等价性证明

等价性证明方式统一为：**先跑该文件既有定向测试建立绿基线 → 重写 → 同一测试集复跑**；
新增行为护栏不放松任何既有断言。重写均"换分解方式 / 换数据结构 / 重排控制流"，
不逐行对照翻译。

### 3.1 `bid_section_detector.py`（整文件重写）

- 16 条硬编码正则改为 **"单位 × 形态"生成器**（`_UNITS × _DEFINITION_FORMS`），
  匹配优先级仍由单位顺序决定；
- 中文数字组合位改为独立解析原语（`_digit_value` / `_ten_with_ones` /
  `_tens_only` / `_tens_and_ones` / `_parse_composite`）；
- 三条证据（显式总数 / 定义式 / 括号编号）改为独立采集，`_summary` 统一出参；
- 删除未使用的 `_chinese_to_digit`。
- 测试：`tests/test_bid_section_detector.py` **39 → 39 passed**（覆盖 1–99 全形态、
  "十X"非法位、合并列举、文号排除、括号父子、空输入）。

### 3.2 `content_shrink.py`（整文件重写）

- 保护区改为通用行块合并器 `_merge_line_blocks`（列表/表格共用一套行块语义）；
- JSON 解析拆为 `_strip_json_fence` / `_load_json_object` / `_coerce_operation`；
- 目标定位拆为 `_unique_span`（逐字唯一）+ `_normalize_for_match` 规范化回退
  （改为"先展开 NFKC 结果，再折叠空白段"，保留原文下标映射）；
- 应用改为 `_apply_edits`（按起点倒序）；
- 主循环由 `for/else` 改为 `while` + 显式收敛判定。
- 测试：`tests/test_content_shrink.py` **19 → 19 passed**，
  `tests/test_content_deep_audit.py` **33 passed**（合计 52）。

### 3.3 `duplicate_detection.py`（整文件重写）

- 三条日期规则合并为单交替（顺序等价，避免二次扫描差异）；
- 骨架规则改为声明式 stages（`_SKELETON_RULES` + `_mask_variable_fields`）；
- 分档改具名常量 `_TIER_LONG` / `_TIER_SHORT`，阈值不变（行为契约）；
- 倒排索引用 `defaultdict`、候选计数用 `Counter`；
- 两级检测拆为 `_collect_exact_groups` / `_collect_near_groups`；
- 标题去重拆 `_unique_title_nodes`。
- 测试：`tests/test_duplicate_detection_20261001.py` **63 → 63 passed**（含阈值边界、
  剪枝无损、高 DF、排除对、预算截断）。
- 锚点迁移：1 条源码顺序护栏原断言"`_SKELETON_RULES` 的位置"，重写后规则移入
  `_mask_variable_fields`。已改为断言 **"NFKC → 字段规则 → 剔除标点" 的顺序**，并
  追加"`_mask_variable_fields` 必须真引用 `_SKELETON_RULES`"，判别力不降。

### 3.4 `legacy_office.py`（转换后端部分重写）

- 后端探测改为"可用性字典 + 顺序表"，探测顺序与返回值完全不变；
- `soffice` 参数与产物选择拆为 `_libreoffice_argv` / `_pick_produced_docx`；
- COM 调用拆为 `_com_convert_argv`；
- PowerShell 脚本重写：函数改名（`Clear-ComObject` / `Invoke-Quietly` /
  `Export-Docx`）、控制流改为 `try/finally`，但"两种保存格式、三项应用设置、
  只读打开、异常清理顺序"逐项保持。COM 的调用序列由 Office API 决定，
  无法也不应差异化。
- 测试：`tests/test_legacy_office.py` + `tests/test_import_parse_contract_r73_20261012.py`
  **58 passed**（该文件的改动前基线未单独采集，属本次流程瑕疵，已在此登记）。

   `0.90/0.82`、`0.95/0.88`、`5000ms`、16 条字段规则等数值与语义。它们属于功能参数，

   本批未做逐段比对（超出 §0.3 范围）。
4. **`legacy_office` 的 COM 调用序列无法进一步差异化**（Office API 决定），只能保证
   脚本结构与命名独立。
5. **"招投标方案平台"来源的许可未确认。** `facts_extractor.py` 中 6 处指向该来源的

6. **前端、脚本、文档未纳入本次判定**；`docs/` 中此前的对照建议文档本身仍保留
