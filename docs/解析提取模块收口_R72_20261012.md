## 2. 现状分析（关键链路与发现）

**上传→解析→入库链**：`upload_outline.py` / `global_facts_docs.py` 接收文件 → `file_parser.py` 按扩展名分派解析 → 解析文本经 `load_parsed_texts` 供下游消费。上游对**超大/多页文档做了截断**（`truncated_out` 采集被截断文档清单）。

**三条 AI 生成链的截断告知口径不一致**（核心问题）：
- **事实提取链** `generate_facts`（sse_handlers:7324 附近）：早已对截断文档发 `warning` 事件 —— **正确基线**。
- **目录生成链** `generate_outline`：装配阶段 `_assemble_context` **早已采集** `_truncated_docs`（用 `truncated_out`），注释也承诺「清单带到事件流」，但装配逻辑重构移入闭包时**丢了 yield 点** —— 清单只落日志、**从不进 SSE**（P1 断链）。
- **正文生成链** `generate_content`：`load_parsed_texts` **根本不传** `truncated_out`，采集都不做（P2 口径不对称）。

**写路径 rowcount 缺口**：`delete_document` / `update_document_category` 只做「游标 None → 503」双层守卫的第一层，**未校验影响行数**；并发删除下 0 行仍回 `ok=True`，与本仓 `_r13_write` / `safe_rowcount` 已确立的「行数不足 → 404」口径不一致（P2 假成功）。

**前端目录库弹窗导入**：`OutlineLibraryEditModal.handleImportOutline` 直接读 `data.outline` 无条件 `setTree` 覆盖 —— **解析空结果会清空用户当前目录树**；且未复用页面已有的 `summarizeUploadOutlineResult` 纯函数，形成第二份判定口径（P2 交互 + 技术债）。

**扩展名集合双份字面量**：`file_parser.py` 对外声明 `SUPPORTED_EXTENSIONS` 与内部分派 `_SUPPORTED_EXTENSIONS` 各写一份相同 14 项集合（P3 技术债，易漂移）。

## 4. 修复项清单（落地位置）

### A · 目录生成链截断告知（`backend/app/routers/sse_handlers.py`）
- `_assembled` 装配产物新增键 `"truncated_docs": list(_truncated_docs)`；
- `event_stream` 解包 `_trunc_docs = _assembled.get("truncated_docs", [])`；
- `connecting` 首个 yield 后，`if _trunc_docs:` → 发 `{'event':'warning', ...}`，文案与事实提取链同口径（「N 份文档解析不完整（内容被截断）…本次目录生成仅基于已解析到的部分…建议拆分文件后重新上传」）。

### B · 正文生成链截断采集与告知（`sse_handlers.py`）
- `generate_content` 中 `load_parsed_texts(...)` 前声明 `_content_trunc_docs: list[str] = []`，传 `truncated_out=_content_trunc_docs`；
- `_build_structured_brief` 后 `if _content_trunc_docs:` → 同构 `warning` 事件（「本次正文生成仅基于已解析到的部分，后段参数可能不可见」）。
- **三链口径就此对齐**。

### C · 目录库弹窗导入（`frontend/src/components/OutlineLibraryEditModal.tsx`）
- 新增 `import { summarizeUploadOutlineResult } from "../pages/SchemeWorkbenchPage"`（页面不 import 弹窗，无循环依赖）；
- `handleImportOutline` 重写：`summary = summarizeUploadOutlineResult(data)`；`!summary.ok` → 逐条 `msg.warning` + 回传 message 并 `return`（**空结果绝不清空当前树**）；`ok` → `importToTree(summary.outline)` + `setTree` + notices/`msg.success`。判定口径单一事实源。

### D · 写路径 rowcount（`backend/app/routers/global_facts_docs.py`）
- `delete_document`：游标 None 判定后补 `if safe_rowcount(del_doc_cur, ...) < 1: logger.warning(...); raise HTTPException(404, ...)`；
- `update_document_category`：同口径补 `safe_rowcount(upd_cur, ...) < 1 → 404`。

### T-A · 扩展名单一事实源（`backend/app/services/file_parser.py`）
- `_SUPPORTED_EXTENSIONS = SUPPORTED_EXTENSIONS`（对象身份同一，消除手抄两份）。

### F · 前端 warning 事件接线（`frontend/src/pages/SchemeWorkbenchPage.tsx`）—— 收口复测时发现并补修
> **这是对 A/B 的实质补全**：A/B 把截断 `warning` 事件从后端发出来了，但前端消费侧未接 → 链路只走通一半（AGENTS.md §5「实现了但链路不生效」同族缺陷，只有端到端/接线护栏能抓）。
- 定位：目录链与正文链共用事件入口 `onSseEvent`（SchemeWorkbenchPage:4908），**旧实现只处理 `error`、无 `warning` 分支**；事实链自带本地 `else if (evt.event === "warning")` pushLog（6288），故仅目录/正文两链漏消费。
- 修复：在 `onSseEvent` 内补一个与 `error` **对称**的 `warning` 分支——`msg.warning(evt.message || "存在需人工核对的提示"); return false;`（不中断流）。单点接线同时覆盖目录链(5131)/正文链(5929)；与事实链既有「日志行 + toast」双通道形态一致，**不产生回归、不制造第二份口径**。
- 护栏：`frontend/src/tests/importParseWarningWiringR72.test.ts` 4 例（前提校验 / warning 分支存在 / 必须 `return false` 不中断 / 反向锚摘除即红）；沿用本仓 `import.meta.glob(?raw)` 源码扫描范式（contentTerminalParity 同族）。**F 组事件对账护栏 23 例同步绿**（新分支在 `onSseEvent` 回调内、不在 content loop slice，两套正文消费实现仍等价）。

## 5. 优化项清单

- **可观测性**：截断从「静默降级、只落日志」升级为「SSE warning 显式告知」，用户能察觉目录/正文可能漏后段。
- **口径统一**：三链（事实/目录/正文）截断告知同一文案模式；写路径 0 行统一回 404 对齐 `_r13_write`；导入判定复用页面纯函数消除双副本。
- **前端交互安全**：空解析结果由「覆盖清空」改为「保持 + 告警」，避免无声内容损坏。
