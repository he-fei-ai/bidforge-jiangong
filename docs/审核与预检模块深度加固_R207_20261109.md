## 八、教训归档

1. **「稳定键」与「实读来源」必须成对核对**：缓存键覆盖正文/事实/审核状态，却漏了聚合实读的六张来源表 —— 任何「新检查跑完但结论没变」的报障先查缓存键是否覆盖写入面；水位签名要比「逐个写点插失效」更抗漏（外部脚本/迁移写入同样可见）。
2. **写点守卫 > 端点守卫**：R168 的漂移守卫按端点接线，`stage→confirm` 修好了、`/apply` 整条链照样绕过；共用 `_persist_fixed` 的两个端点说明「唯一写点」才是正确收口层。
3. **后端回传字段的「下游映射」与「UI 消费」要各配一层护栏**：R198 补了 `section_ids`，却卡在 `export_issues_to_findings` 只认单数；R181 补了 `conflict_restore_results`，却只被「字符串存在」型源码锁命中类型声明。
4. **既有护栏红时先问「锁的是意图还是实现」**：block 降级是产品意图（回退实现形态），重入锁字面量是实现形态（重锚并加强）—— 两者处理方式相反。
5. **Windows 工具链既有坑复现**：PowerShell `>` 落盘为 UTF-16（读摘要需按 BOM 判编码）；`python -c` 打印中文在 GBK 控制台炸 `UnicodeEncodeError`（须 `PYTHONIOENCODING=utf-8`）；vitest 被 IDE watch 误判 10s 超时（改 python subprocess 包装 + 落盘，判定以日志文件 `Test Files` 摘要为准）；本机无 `rg` 命令（用 `search_content` 工具）。
