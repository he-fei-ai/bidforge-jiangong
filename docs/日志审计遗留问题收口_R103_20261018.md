## 二、L1 · 配置卫生可观测（本轮主修复）

### 2.1 问题根因（R102 日志证据）

- `provider_factory` 的 `_is_dead_provider`（样本充足 + 实时成功率 < 20%）在**每次选路**的内存里判定，日志仅输出聚合文案「已剔除实时成功率过低的候选：agnes」（209 条 WARNING）；
- `warmup_reliability_from_db` 启动时恢复统计（冷启动行为已覆盖），但「重启后哪些配置一上来就被剔除」无可观测输出；
- 前端「文本模型配置」页只见「降级链 9→3」，不知该清理谁。生产实证：4 条 nvidia 死配置（HTTP 404 UnsupportedModel）+ volcengine 不支持 coding plan 的模型长期占据候选池。

### 2.2 修法（三层，全部只读/加法式）

**FIX-1 · 单一访问器**（`app/services/ai/provider_factory.py`）
新增 `provider_health_snapshot(provider_name, model, config_id, base_url) -> dict`：`{samples, success_rate, dead, circuit_open, cooldown_remaining_s, quota_cooldown_s}`。判据**全部复用既有实现**（`_is_dead_provider` / `circuit_breaker.allow_request` / `_quota_cooldown_active`），绝不另写阈值——「界面说的」与「选路做的」恒等。fail-soft 永不为空。

**FIX-2 · 启动死配置报告**（`provider_factory.report_dead_configs_at_startup` + `app/main.py` lifespan）
枚举 `ai_config` 全部行逐行走同一访问器（身份键解析与运行时同函数：库里有 config_id ⇒ `cfg:{id}` 键，**不自己拼键**——自己拼必然与运行时错位，R102 探针首版即因此返回空）。死配置逐条 WARNING：「启动检查：1 条 AI 配置近 24h 实时成功率过低，已被自动剔除出降级链（建议到「文本模型配置」清理或禁用）：nvidia/glm-x（12 次样本，成功率 0%）」。**零行为变更**：不剔除、不禁用、不写库；排在 `warmup_reliability_from_db` 之后（统计未恢复时报告恒空）；fail-soft 不阻断启动。

**FIX-3 · 接口接线**（`app/routers/ai_config/connectivity.py`）
`GET /ai/configs/health` 每项新增 `runtime_health`（加法式键）、汇总新增 `runtime_dead`。前端（`pages/AIConfigPage.tsx` + `types/aiConfig.ts`）：体检汇总消息追加「N 条实时成功率过低（已自动剔除，建议清理或禁用）」、汇总标签「成功率过低 N」、表格新增「运行时健康」列（死配置→可行动 tooltip 含样本/成功率/清理建议；熔断中/冷却中→状态 tag；样本不足→「暂无样本」不误报）。

### 2.3 可观测性降噪（同源发现）

`配额冷却中，跳过 X`（422 条）与 `熔断器 OPEN，跳过 X` 由 WARNING 降为 INFO——二者是设计内节流/自愈，非异常；审计行 `circuit_skipped` 不变（数据链完整）。R11 先例同款。

## 三、L5 · 闭环机制工具化

- `backend/artifacts/r102/log_analysis.py`：可复用日志采集工具。**编码自适应**（UTF-8 优先、失败回退 GBK，并如实回传判定——「日志双轨编码」本身是被报告的问题）；请求数以 uvicorn 访问行为准（避免 uvicorn 行 + 中间件行双记录导致的翻倍）；时延取中间件行；trace 覆盖率单列（访问行/中间件行分开口径）。
- `backend/artifacts/r102/baseline_20261001.json`：R102 基线存档（本快照实测复算：backend_out.log 1952 请求 / 错误率 0.92% / 访问行 trace 覆盖 0；backend_err.log 1339 条中间件行全 trace / p50=12ms / p95=546ms / p99=18.7s）。
- 用法：`python backend/artifacts/r102/log_analysis.py [日志路径...]`，输出 JSON 可直接与 baseline 对比 ⇒ 「日志再分析」闭环可执行。
