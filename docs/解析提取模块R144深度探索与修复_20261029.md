### 3.2 关键取证（代码依据）

**F1（P2）** — `global_facts_docs.py` 同名替换路径（`:761-767`）只 `purge_document`，从不调 `_mark_project_facts_stale` / `_invalidate_project_export_caches`；对照 `delete_document:320-322`、`parse_document:1469-1488`（R79 A-4）、`parse_all:1690-1694` 均已调用 —— **替换是第三条改变输入全集的路径，唯独漏掉**。被替换文档内容退出资料全集，但 `is_stale` 保持 0，生成链路继续用基于旧内容的事实。

**F2（P2）** — `_persist_parse_result`（`:1085-1092`）UPDATE 只判 `cur is None`（R13），不校验 `safe_rowcount`。并发 `delete_document` 在「读行」与「写库」之间删掉文档时，UPDATE 命中 0 行仍返回 True → 调用方继续 `_ingest_parsed_doc`（读到空正文、重建已被删的 parsed 层）+ `_save_parse_checkpoint` 为已删文档写检查点，响应回 `ok=True`（幽灵成功）。

**F3（P2，前端）** — `SchemeWorkbenchPage.tsx:10117` 用**裸** `setTimeout(() => handleUploadDocuments(files), 0)`，从不登记 ref、从不清理 → 组件卸载后定时器仍触发真实上传（幽灵上传 + 卸载后 setState）。这正是 `UploadParseTab.tsx:216-219` FIX-7 已修复的同因缺陷，但只修了那一个入口、漏掉本页面这条**平行上传路径**。另：`:10113`/`:10122`/`:10143` disabled 均缺 `!!parsingDocId`（UploadParseTab 有），且 `handleUploadDocuments`（`:7009`）防重入只查 `uploadingFacts`，漏解析并发 —— 单份解析进行中发起同名上传，后端会删除并替换正在解析的文档，四层产物错乱。

**F4（P3）** — `pipeline.py:1169-1173` `purge_document` 的 `delete_sqls` 只含 `doc_chunks / doc_extractions / doc_validation_reports`，漏 `doc_parse_checkpoints`。该表仅 `doc_id` 主键、无 `project_id`，也不在 `_PROJECT_SCOPED_TABLES`（`projects.py:72-78`），故删除/替换/删项目均级联不到，每次删除遗留一行孤儿。

**F5（P3）** — `global_facts_docs.py:665-671` 同名替换的旧档案 DELETE 只判 `del_cur is None`，不校验 `safe_rowcount`（对照 `:306`/`:1859` 的 R72 口径）。连接池每请求独立连接下，两个并发同名上传各自 SELECT 到同一旧行、各自 DELETE（其一影响 0 行不被察觉）、各自 INSERT → 同一 `project+file_name` 出现两行。

**F7（P3）** — `upload_outline.py:276` AI 兜底要求 `len(raw_text) > 50`；`:380-388` 空文本告警仅当 `not raw_text.strip()`。文本 1–49 字且 `simple_parse_outline` 返回 `[]` 时，既不进 AI、也不触发 `empty_text`/`warning`，前端只看到「识别完成：共 0 个章节」，用户无法区分「文件确实没结构」与「识别失败」。

**F8（P3）** — `doc_categories.py:105` `auto_classify_document` 对完整文件名（含扩展名）做匹配，与 docstring「仅按文件名（不含扩展名）」不符。当前扩展名均不含关键词故无实际误分类，但口径漂移是潜在分类错误源（未来新增含关键词的扩展名即误分类）。

**F9（P3，前端）** — `UploadParseTab.tsx:223` `uploadTimerRef.current = window.setTimeout(...)` 直接赋值；宏任务间隙内再次选文件时旧 timer 被覆盖但未 `clearTimeout`，旧 timer 仍触发 → 两批并发上传（`if (uploadingFacts) return` 因闭包值陈旧拦不住）。

**F10（P3，前端）** — `SchemeWorkbenchPage.tsx` 卸载清理只 `uploadAbortRef.current?.abort()`（`:5041`）不置 null；`handleUploadDocuments` 的 finally（`:7096-7101`）`if (uploadAbortRef.current === ac)` 仍成立 → 在已卸载组件上 `setUploadingFacts(false)` / `setUploadedFiles([])`。
