|---|---|---|
| 前端 marked | `print(1)/```js/print(2)` 在块内、`<p>结尾正文。</p>` 保留 | **正确** |
| 导出 `read_fenced_block` | `[("python","closed",1), ("","eof",1)]` | **导出把「结尾正文。」吞进代码块**（与预览反向分叉） |
| `auto_fix`（宽松） | 报 line5 未闭合 → `changed=true`，**在文末追加 ```** | 落库正文被静默改写；追加后第二块 state 由 `eof`→`closed`，**被吞的正文永久困在代码块里**，而严格判据事后报 `[]` → 缺陷固化且自检绿灯 |

### 缺陷归并（三个可修 BUG + 一个可观测性项）

- **BUG-F1**：闭合判据无单一事实源 → 预检假阳性 + 自动修复空转 + 该 finding 永不闭环。
- **BUG-F2**：`read_fenced_block` 允许带信息串的行闭合（`content_blocks.py:1099`
  只判 `pf[0] == open_char`，未判 `pf[2] == ""`）→ 导出吞正文、与前端反向分叉；
  并被 `auto_fix` 的「文末追加」固化为静默缺陷。
- **BUG-F3**：严格（字数/压缩禁区）与宽松（渲染）两套判据同时作用于同一份正文
  → 字数报 0、压缩禁区为空，而导出正常成图成文（三套口径互不相认）。
- **F4（可观测性）**：`auto_fix` 的补齐动作对「块内已混入正文」的语料只把 `eof` 变成
  `closed`，正文不会回来，但日志只记「补齐 N 处」→ 用户与排障者都看不出正文被吞。

## 5. 修复方案（阶段 3 待落地）

**唯一事实源**：新增叶子模块 `backend/app/services/fence_common.py`（仅依赖 `re`，
无循环导入风险 —— `content_utils` 与 `content_blocks` 互不引用，实测 §2 导入表）：

```
FENCE_LINE_RE                       # 现存三处字面量合并至此
parse_fence_line(line) -> (char,len,info) | None
is_fence_open(...)                  # 开围栏行
is_fence_close(line, open_char, open_len, *, tolerant_length=True) -> bool
      # 谓词：同种字符 + 信息串必须为空 + 长度（tolerant=True 时不要求 ≥，False 时要求 ≥）
find_unclosed(content, *, tolerant_length=True) -> list[dict]
normalize_fence_closes(content) -> (text, log)   # 把「容错判为闭合但长度不足」的闭合行补齐到开围栏长度
```

消费点改造（全部改为调用同一谓词）：

| 落点 | 改动 | 行为影响 |
|---|---|---|
| `content_blocks.read_fenced_block`（:1099/:1110-1111/:1115-1116） | 闭合判定加「信息串为空」 | **修 BUG-F2**：带标签行不再当闭合 → 与前端 CommonMark 对齐、正文不被吞 |
| `content_utils._find_unclosed_fences_lenient`（:652） | 委托 `fence_common.find_unclosed(tolerant=True)` | 与渲染侧同源（消除 BUG-F1 的「定位有/修复无」） |
| `content_utils.find_unclosed_fences`（:587） | 委托 `fence_common.find_unclosed(tolerant=False)`，保留严格语义与签名 | 预检 DLV-07 与 `review_autofix._match_fence` 不动签名、改由同源谓词供给 |
| `content_utils.auto_fix_unclosed_fences`（:703） | **两步**：① `normalize_fence_closes` 补齐长度错配 → ② 对真未闭合在文末追加闭合；返回契约 `(str, list[dict])` 不变，log 增 `action` 键（`normalize_close_length` / `append_close`） | **修 BUG-F1/F3**：归一后 strict≡lenient，DLV-07 假阳性消失、`review_autofix` 真能改动正文（复检可闭环）、字数与压缩禁区不再互相矛盾 |
| 三处写路径（`sse_handlers:5453` / `sections:671` / `export:4657` opt-in） | 无需改动（自动获得归一） | 零迁移 |
| `preflight_engine` DLV-07（:956/:992） | 文案拆两种：真未闭合「会吞噬后续正文」/ 长度错配「导出可容错但预览会吞正文，可一键修复」 | 报警准确性；rule_id 不变（不牵动登记表） |
| `_chart_pipeline.py:197 _FENCE_LINE_RE` | 删除悬空副本（全文件零引用，实测） | 零行为 |
| `MarkdownRenderer.tsx:112-128` | 预处理改为**行锚定 + 同种标记回指**（`` {3,}`` / `~{3,}`，闭合行不得带语言标签）；未闭合检测同步 | 前端支持 4 反引号与 `~~~` 图表围栏，预览与导出对齐 |
| F4 | 补齐时若块内含中文句读结尾行，日志/report 明确「正文可能已被吞，请人工核对」 | 只增加可见性 |

**新增配置项**：`content_fence_normalize_close`（env `CONTENT_FENCE_NORMALIZE_CLOSE`，
**默认 True**）。置 `False` 时 `auto_fix_unclosed_fences` 逐字回退当前行为
（只做文末追加），用于线上出问题时一键回到旧口径 —— 与本仓「默认开启 + 单开关可回退」惯例一致。

**向后兼容**：零数据迁移、零 DDL、返回契约加法式（新增 `action` 键、既有键不动）、
`find_unclosed_fences`/`strip_fenced_code_blocks`/`fence_spans` 签名与严格语义不变。

## 6. 刻意不做（列入遗留，防重复排查）

1. `strip_fenced_code_blocks` / `fence_spans` 不改判据（字数口径、压缩禁区）：
   改宽松会让「4 开 + 3 短围栏行（本意是代码内容）+ 4 闭」的合法嵌套被误判为提前闭合，
   影响面是全仓字数基线（大量护栏断言数值）。本轮以「写入即归一」消除分歧源头。
2. 历史存量正文不做自动回填（无法区分人工内容与误吞内容），
   由 DLV-07 + 一键修复路径覆盖。
3. `sections.py` 的 7 处 `invalidate_export_cache` 与生成路径的「不调用」不统一：
   缓存本身内容寻址（`export.py:5110`），统一属**产物回收策略**议题，非正文生成缺陷。
4. 图号虚跳 / 渲染失败占号 / 列表样式拍平 / 配图上限竞态：均有既有收口与护栏

### 8.2 实现期新发现：保护区间还有三份同判据副本（BUG-F5 / F6）

全仓 AST 扫描 `re.compile` 含围栏字面量后实锤——除 §2 表列九处「闭合判定」外，
**计算围栏保护区间**的自写状态机另有三份，且都带 BUG-F2 同族缺陷：

| 副本 | 位置 | 缺陷 | 收敛 |
|---|---|---|---|
| F5-a | `content_rewrite._FENCE_LINE_RE` + `_split_fences` 自写状态机 | 正则与 `fence_common` **逐字相同**但各持一份；不看信息串 → 块内 ```` ```python ```` 被当收尾，**其后正文滑出保护区被 AI 改写** | `_split_fences` 重写为 `iter_all_blocks` 驱动（保 `segs` 逐字往返） |
| F5-b | `content_checkpoint._FENCE_LINE_RE` + `_fence_ranges` | **严格长度**且不判信息串 → 长度错配块的保护提前结束（与渲染侧分叉） | `_fence_ranges` 改为一行委托 `fence_char_ranges` |
| F6 | `content_polish._FENCE_SPLIT_RE`（非贪婪 ```` ```[\s\S]*?``` ````） | 完全不认未闭合围栏 → 未闭合时**后续正文不再受保护**，清洗/AI 润色可直接改写被吞正文；四处调用点各自重算 | 删副本，四处统一 `_fence_ranges` |

### 8.2b 端到端实抓的本轮自引入回归（BUG-F7 · 图表占位段落格式）

`replaceChartFences` 逐段拼接时用了 `parts.join("\n")`（**单个**换行），而 HEAD 旧实现
的替换串自带 `"\n<div…></div>\n"`，与紧随其后的正文之间恰好留着**空行**。
`<div>` 在 CommonMark 里开启一个 HTML block，只有空行才结束它 ⇒ 单换行时
「```mermaid…``` 后紧跟的那行正文」被吸进 HTML block，marked 不再产出 `<p>`
（预览里段落样式与图表插入位置都和旧实现不一样）。

- 抓法：§8.9 端到端脚本（真实落库正文 → esbuild 转译 `fencePreprocess.ts` 真跑 → marked 渲染），
  `D_well_formed` / `E_tilde` 两例实测 `proseInParagraph=false`。纯单元测试当时是绿的
  （旧断言只查 `toContain("后段。")`，源文本本来就带空行，掩盖了差异）——
  ⚠️ **单测语料带空行 = 把被变异的行为等价化了**，与 AGENTS R63 记的同族。
- 修法：段间统一以**空行**相接，并先剥掉每段首尾空行避免叠出 `\n\n\n`（空白 `<p>` 的来源）：
  `parts.map(stripBlankEdges).filter(s => s.length > 0).join("\n\n")`。
- 回归锁：`fencePreprocessR76.test.ts` 新增「图表块紧随正文（源里本来就无空行）→ 段间必须补出空行」
  一例（含相邻两个图表块不得叠出三连续行），前端护栏 13 → **14 例**。
