## 二、深度探查结果（功能清单 / 代码地图 / 依赖 / 风险）

### 2.1 功能清单（目录模块实际具备的能力）

1. AI 生成目录：短方案直出、长方案分步（按章窗口并发 + 批量合并）、自动审核修复、质量自检。
2. 目录树编辑：增 / 删 / 改名 / 拖拽移动 / 同级新增，三级层级约束。
3. 章节编号：统一重排（点分编号）、中文「第 X 章」展示、正文 Markdown 子标题重编号、DB 子章节与正文子标题命名空间隔离。
4. 落库与结构变更：create / update / delete / reorder / save-outline / apply-library / upload-parse，多入口统一编号与正文重规范化。
5. 容错与一致性：编号校验 / 修复 / 回滚快照、连续性检查、生成中互斥守卫、缓存失效、检查点（checkpoint）与断线重连。
6. 目录库：沉淀 / 版本 / 复制 / 从方案生成 / 应用并保存。

### 2.3 依赖与跨模块

- 编号服务被 sections / outline_library / sse_handlers / 正文规范化共同消费，是跨模块契约核心。
- 生成状态经任务注册表与 SSE 终态 payload（outline/review/failed_chapters）传递；前端经轮询与事件双通道消费。
- 正文子标题与 DB 子章节共用「节」实体但编号命名空间隔离（有 DB 子章时正文降级），避免冲突。

### 2.4 风险点（探查确认的高敏区域）

1. AI 畸形输出：节点数组混入非 dict 项（字符串/数字/null），normalize 不删除只跳过——编号占号口径必须在「重排」与「校验」两侧一致。
2. 结构编辑多入口：任一入口漏本地重算都会造成「界面编号错位直到保存才纠正」。
3. 长/短两条生成路径的后处理必须对齐（质量自检、终态字段）。
4. fail-soft 铁律：编号 / 校验异常不得阻断生成或落库。

## 四、修复项清单（根因 → 方案 → 证据）

### F1【前端·编号不同步】新增子章节后编号不刷新

- 位置：[SchemeWorkbenchPage.tsx](file:///j:/编程/专项方案工具箱/frontend/src/pages/SchemeWorkbenchPage.tsx#L6980) `addChildNode`（根追加 L7009、子追加 L7011）。
- 根因：两处 `setTree([...])` 直接放入新节点，未调用 `renumberTreeLocally`，新节点无 `outlineId`、后续兄弟编号不递增，需保存后 `load` 才纠正。
- 方案：两处 `setTree` 均以 `renumberTreeLocally(...)` 包裹，与 moveNode / 拖拽同口径即时重算（只写 outlineId/sort_order，不碰 key）。

### F2【前端·编号错位】在中间位置新增同级章节，其后兄弟编号错位

- 位置：[SchemeWorkbenchPage.tsx](file:///j:/编程/专项方案工具箱/frontend/src/pages/SchemeWorkbenchPage.tsx#L7027) `addSiblingNode`（L7064）。
- 根因：节点插在参照节点之后，其后兄弟相对序号 +1，但旧实现不本地重算，界面短暂呈「第一章 / 新章节(无编号) / 第二章…」。
- 方案：`setTree(renumberTreeLocally(insertAfter(curTree)))`；无 key（根级追加）时复用 `addChildNode()`，行为统一。

### F3【前端·编号未重算 + 前后端短暂不一致】删除章节后编号不重算

- 位置：[SchemeWorkbenchPage.tsx](file:///j:/编程/专项方案工具箱/frontend/src/pages/SchemeWorkbenchPage.tsx#L7102) `deleteNode`（本地重算 L7121 区域）。
- 根因：旧实现先异步 DELETE、成功后 `load`，失败则本地节点已删 / 未删状态混乱；且删除后兄弟编号未即时重算。
- 方案：引入 `persisted` 标记区分本地 `local_` 节点与已落库节点；先 `setTree(renumberTreeLocally(removeNode(...)))` 即时重算，已落库节点 DELETE 成功后再 `load()` 拉权威树；`useCallback` 依赖补 `load`。失败仅提示、不污染本地结构。

### F4【后端·功能缺口】长方案分步生成漏挂「生成后质量自检」

- 位置：[sse_handlers.py](file:///j:/编程/专项方案工具箱/backend/app/routers/sse_handlers.py#L4336)（`generate_outline` 长路径，短路径对照在 ~L3987）。
- 根因：短方案直出在 `_review_and_fix_outline` 后调用 `_attach_quality_report`（连续性 / 名称覆盖 / 冗余 → `review.quality`，前端 `summarizeOutlineQuality` 消费）；长方案分步（word_budget ≥ 50000，章节最多、最易缺章）**漏挂**，前端对长方案永远拿不到质量自检。
- 方案：在长路径审核完成、空树兜底之后、停止判定之前补
  `if full_outline and isinstance(review_obj, dict): _attach_quality_report(full_outline, basis, review_obj)`，与短路径同口径；函数本身全 try/except fail-soft，不影响终态。

### F5【后端·误报】连续性检查把「非 dict 残片」计入编号占号，误报编号错位

- 位置：[outline_quality.py](file:///j:/编程/专项方案工具箱/backend/app/services/outline_quality.py#L182) `check_outline_continuity`（dict_idx L236-241、top_idx L256-260）。
- 根因：位置路径旧实现用 `enumerate` 的原始下标计数，而 `renumber_outline_nodes` 对非 dict 项「跳过且不占号」。normalize（重排不删除残片）后，脏数组 `[dict, "残片", dict]` 中第二个合法节点的真实 id（"2"）与位置路径（"3"）永不相等，被误报 `numbering_mismatch`，把编号正确的目录判为 `ok=False`，生成日志误报「编号错位」。顶层与嵌套层均存在。
- 方案：位置路径改为「仅对 dict 项连续计数」（嵌套 `dict_idx`、顶层 `top_idx`），与重排占号口径对齐；真错位（如 id "5" 位于第 2 位）仍可检出。

### F6【测试·误报修正，非本模块、非本轮引入】静态闭包检查误判推导式 / 形参

- 位置：[test_content_terminal_payload_20261005.py](file:///j:/编程/专项方案工具箱/backend/tests/test_content_terminal_payload_20261005.py#L439)。
- 现象：全量唯一后端失败，扫描 content 模块 `generate_content._persist_section`，报 `d(store@1048 < load@1047)`、修后又报 `content(store@695 < load@688)`。
- 定性（代码证据）：
  - `d` 来自删图日志 `"、".join(label(d) for d in _chart_dropped)`（sse_handlers.py L5484-5486）——生成器表达式在 Py3 有独立作用域，值表达式对 `d` 的引用与 `for d` target 是同作用域合法绑定；
  - `content` 是 `_persist_section(section_id, content, ...)` 的**形参**（L5074），进入函数即绑定，先读后写（规范化后回赋）合法。
  - 两者都不会产生 `UnboundLocalError`。旧测试用 `ast.walk` 不区分析嵌套作用域、也不排除函数参数，属检查逻辑缺陷；生产代码正确。该失败在本轮改动前即存在（与目录模块、与 `generate_outline` 无关，`inspect.getsource(generate_content)` 是独立源切片）。
- 方案：AST 检查改为只统计函数**直接作用域**裸名（跳过嵌套函数 / lambda / 各类推导式），并排除形参名与 global 名；新增合成 AST 防护用例，证明「放过推导式 / 嵌套函数 / 形参，但真实函数级先读后写遮蔽仍被抓到」。

## 八、遗留问题与后续建议

1. 【非本模块·预存】前端 [ReviewWorkflowPanel.test.tsx](file:///j:/编程/专项方案工具箱/frontend/src/tests/ReviewWorkflowPanel.test.tsx) 1 个失败：「approved 不再出现通过/驳回，rejected 只能重提」。属 review 评审工作流，与目录模块零代码关联，基线索引即为失败。建议由 review 模块负责人核对该组件按钮按 `review_status` 的渲染条件。本轮按范围纪律未改。
2. 【环境噪声】后端全量有 6 条 `PytestUnhandledThreadExceptionWarning`（subprocess reader 在 GBK 控制台解码 UTF-8 的 `UnicodeDecodeError`），不影响断言结果。建议在子进程读取处显式指定 `encoding="utf-8", errors="replace"`。
