**A-5 详细落点**（本轮唯一新增生产代码）：

```python
# file_parser.py
def _env_int(name: str, default: int) -> int:
    try:
        v = int(os.environ.get(name, ""))
        return v if v > 0 else default
    except (TypeError, ValueError):
        return default

MAX_ARCHIVE_ENTRIES = _env_int("BIDFORGE_MAX_ARCHIVE_ENTRIES", 2000)
MAX_ARCHIVE_UNCOMPRESSED_BYTES = _env_int("BIDFORGE_MAX_ARCHIVE_UNCOMPRESSED_BYTES", 400 * 1024 * 1024)
MAX_COMPRESSION_RATIO = _env_int("BIDFORGE_MAX_COMPRESSION_RATIO", 200)
MAX_ARCHIVE_ENTRY_BYTES = _env_int("BIDFORGE_MAX_ARCHIVE_ENTRY_BYTES", 64 * 1024 * 1024)
```

- 默认值与原硬编码**逐字相同**（2000 / 400MB / 200 / 64MB），旧行为不变
- 非法环境变量值（非整数 / 零 / 负数）回退默认值（fail-soft，绝不因误配置阻断解析）
- `_read_zip_entry_limited` 的 `limit is None` 运行时解析契约保留（注释承诺，护栏锁定）

## 六、本轮判据教训归档

1. **「确认已落地」必须落在护栏而非文档散文**：B-3（_repair_json）初版护栏锚错函数（锚 `_repair_json` 而非 `_collect_json_str`，统一通道调用点在后者的函数体）→ 假红；修正为「薄壳委托 `_collect_json_str` + 后者调用统一通道」三跳接线后转绿。**接线类护栏必须锁真实调用链，不能锁函数名在场。**
2. **A-5 环境变量化的护栏要同时锁「默认值不变」与「fail-soft」**：默认值变了是行为变更（用户可见），非法值不回退是脆弱性。两条各自可判别，A/B 分别摘除各定向红。
