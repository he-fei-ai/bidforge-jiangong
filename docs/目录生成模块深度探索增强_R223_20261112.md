## 11. 教训归档

1. **「注释承诺 ≠ 代码事实」第 N 次实证（NUM-4）**：R218 C-2 注释明写「空/非法编号回退存储态（fail-safe）」，实现里回退键根本不存在于数据行上——修复类护栏必须断言**行为**而非注释语义。
2. **判据双尺是抢救型缺陷的温床（NUM-1）**：同一脏值在「提取侧」（stored_outline_id 只过点分形态）与「判据侧」（_stored_id_parts fail-closed）结论不同，`or` 回退链会把刚被判非法的值原样送进下游——两把尺子必须收敛为一把（本轮 `normalize_stored_id_text` 单一出口 + 抢救退役）。
3. **「同族第 N 处」是持续发现模式（NUM-3/DAT-6/FE-2）**：R102 G2 收口三处、本轮找到第 4/5 处；R216 D-4 世代守卫只护 restored 分支、outline/facts 链与接管循环各有漏网——**每次收口必须 grep 全族调用点并数出来**（本轮护栏用计数断言把「4 调用点全门控」钉死）。
4. **停止语义要区分「停止前的既成事实」与「停止后的动作」（SSE-2）**：首试已定格的分类是既成事实，停止只能打断**后续**动作，不能改写账目——改写账目让该章从成果与失败清单双消失（R89 S1 契约被静默击穿）。
5. **源码锁注释不得引用被锁字面量（R166/R212 后第三次踩）**：本轮三处护栏/注释先后自咬（`set(parent_of) - _order_ids`、死回退键、`or _sec_stored`）——AST 锁成员（配额关键词表）+ 注释只述语义是两条硬纪律。
6. **is_stopped(未知任务)=True 的语义陷阱**：「任务不存在视为已结束」意味着**任何**依赖 is_stopped 做单测桩的行为测试都必须显式 monkeypatch——否则测的是入口路径，打不到修复分支（本轮 test_stopped_retry_keeps_first_classification 首版即测错路径，护栏假绿被当场抓出重写）。
7. **并行负载硬杀全量 pytest（EXIT=120，R194 教训复现）**：全量回归必须独占——本轮首跑与前端 vitest 并行，进程 6% 处被杀、输出截断；「完成通知」≠「测试通过」，以 summary 行 + PYTEST_EXIT 为准。
8. **前端 ?raw 导入的 suppress 指令按 R213 先例一律裸写**：逐个试 `@ts-expect-error` 会打地鼠（tsc 对部分 ?raw 报 Unused directive）——既有范式直接抄，不重新发明。
