## 四、修复项清单（本轮落地）

### P1 · 修复检测器零分误判【BUG 修复】

**位置**：`services/chart_validators.py:1849-1850`（`detect_chart_with_metadata`）

**缺陷**：`top_score == 0`（无任何关键词/句式命中）时仍返回 `results[0][0]`——按类型名升序排序后恒为 `architecture`。导致「无任何命中」的章节被**系统性误判为架构图**（探针实测：`安全教育培训`/`项目概况与建设目标`/`质量方针与管理目标`/`文明施工管理措施`/`绿色施工与环境保护` 全部误判 architecture，score=0）。

**修复**：`top_score = results[0][1] if results else 0; top_chart = results[0][0] if top_score > 0 else None`——零分→`None`（宁漏报不误报，与 `input_coverage` 同哲学）。接线方只在检测器给出明确正分匹配时才采信。

**验证**：`tests/test_chart_semantic_detector_r228_20261112.py` 19 passed（修复前 8 红全部抓住零分误判场景）。

### P2a · 统一程序侧关键词表与 AI 判定【增强】

**位置**：`services/chart_validators.py` `TRIGGER_KEYWORDS`（:1452-1641）

**缺陷**：程序侧旧库（v3.1，2026-09-14 前的手动编排管线残留）与 AI 提示词触发关键词表（`prompts/content.py:205-213`）**两套脱节**——程序侧缺 `timeline` 类别（AI 有）、缺「方案比选/质量保证体系/安全保证体系/任务分解/智慧工地/检验流程/验收程序/加工制作/临建设施布置/施工平面布置图/总体施工部署/工期控制/流水施工/工序穿插/施工人员动态管理/多方案对比/投入对比」等 AI 触发词。探针实测：检测器对 AI 会正确配图的场景漏判率 42%（12 样本 5 漏判）。

**修复**：补齐全部 AI 触发词 + 新增 `timeline` 类别（7 类与 `PIL_RENDERABLE_CHART_TYPES` 对齐）。纯加法补词，不改判定逻辑。

**效果**：探针判定质量 7/12 → 10/12（+3 场景补回），剩余 2 漏判（「关键施工技术方案」/「材料供应计划」）为「宁漏不误」可接受。

### P2b · 接线生成后语义交叉校验（观测不干预）【增强】

**位置**：`routers/_chart_pipeline.py`（`_chart_semantic_context` + `build_inline_chart_plan`）+ `routers/sse_handlers.py`

**设计**：
1. 新增 `_chart_semantic_context(content, ordinal, max_paras=3)`：提取第 `ordinal` 个图表围栏**之前**的非空正文段（含引导语），`ordinal` 与 `iter_inline_chart_fences` 同计数口径、同一份规范化文本上遍历（`normalize_chart_fence_shapes` 幂等、行数不变 → 锚点不漂移）。
2. `build_inline_chart_plan` 新增 `semantic_notes_out: list | None = None`（缺省 None = 零行为变化，加法式）。对每个通过校验的图表块，检测其附近正文语义：检测器给出**明确正分匹配**且 ≠ AI 选型 → 记观测 `{type, detected, score, context}`。**不删块、不改类型、不改正文**（观测不干预，宁缺毋滥）。
3. `sse_handlers.py` 透传观测进 `section_done` report（`charts_semantic_notes` / `charts_semantic_notes_count`，非空才写，加法式字段）+ 结构化日志。

**价值**：为「AI 选型质量」增加程序侧可观测维度（增强智能编排），发现「工艺章节放甘特图」「进度章节放架构图」等选型不匹配。前端 `normalizeChartYield` 只读已知字段，对新增字段天然兼容（零前端改动）。

**验证**：`test_semantic_crosscheck_mismatch_observes`（进度章节塞 labor 图 → 观测 detected=gantt，rows 不删）/ `test_semantic_crosscheck_match_no_note`（匹配→无观测）/ `test_semantic_crosscheck_default_none_noop`（缺省零行为变化）/ `test_semantic_context_ordinal_aligns`（多块 ordinal 对齐）。

### 本轮零新增配置项

`semantic_notes_out` 是 `build_inline_chart_plan` 的**可选内部参数**（缺省 None = 旧行为逐字等价），非配置项。`charts_semantic_notes` 是 `section_done` report 的**加法式可选字段**（非空才写）。零迁移、零 DDL、零契约破坏。

## 九、教训归档

①**「规则吃 merge 产物」族**：程序侧关键词库（`TRIGGER_KEYWORDS`）与 AI 提示词触发表**两套脱节**是检测器漏判的根源——同一判据（触发词）不得在提示词与程序侧各写一份，补齐时须以 AI 提示词为准（单一事实来源）。
②**测试锁过期要区分「锁实现」与「锁意图」**：`gc_protect={out_path}` 计 2 处是锁实现，意图是「两条路径都 protect」；实现改 `tmp_out_path` 后意图仍满足，锁文本过期但**不得改实现迁就过期锁**（应重锚锁）。
③**观测与干预分离**：语义交叉校验做成「观测不干预」（不删块/不改类型/不改正文），避免检测器误判造成假删图；观测出口复用既有 `charts_dropped` 通道模式（非空才写 report）。
