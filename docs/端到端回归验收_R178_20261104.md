## 8. 补强护栏（R178）

整树转绿后追加的三组断言。目标不是「用例变多」，而是给**退化时静默无感**的位置补护栏。**未改任何产品逻辑**（本批产品代码改动为零）。

### 8.1 SSRF 判定去 DNS 依赖

**原本缺什么**：守卫用例依赖实时 DNS。`api.openai.com` 在 20 分钟内实测解析出过 3 个不同地址（45.114.11.25 / 103.97.176.73 / 75.126.115.192），解析一旦命中内网/投毒地址，用例就以无关的 `ValueError` 随机变红；而 `test_db_lock_closeout_r108` 组为绕开该抖动直接桩死了 `_host_is_forbidden` —— 判定函数整条被摘掉时也不会有任何用例失败。护栏测试的结果取决于外网，等价于没有护栏。

**现在锁住什么**（`backend/tests/test_ssrf_deterministic_r178_20261104.py`，19 条）：

| 断言 | 锁住的退化 |
|---|---|
| 域名解析到 `127.0.0.1` / `169.254.169.254` / `10.0.0.1` → `ValueError` | 私网/回环/云元数据地址必须拒绝（三条各自参数化） |
| 域名解析到公网 → 放行 | 守卫不能把正常 provider 一起拦死 |
| 多条解析记录中只要含禁区一条 → 拒绝 | 多记录 fail-closed（不能取第一条就放行） |
| 字面 IP 与域名两条路径都拒绝 | 两条入口共用同一判定，域名不能绕过字面 IP 检查 |
| 字面 IP 与域名的拒绝消息**逐字相同** | 判定口径分叉会在这里暴露 |
| `ai_allow_private_base_url=true` 时同一私网地址（字面 IP 与域名）均放行 | 例外开关写了不接线（只声明不生效）会被抓 |
| 拒绝文案含「内网/回环/链路本地」与开关名；不含 `sk-r178-SECRET` / `user:` | 原因可读，且错误信息不得泄露密钥/凭据 |
| 桩点只替换 `socket.getaddrinfo`（`test_db_lock_closeout_r108` 的 `_hermetic_dns` 同改） | 只固定网络入口，`_host_is_forbidden`/字面 IP/私有网段判据照常执行 |

### 8.2 图表告警上锁（`chart_ungenerated` / `chart_failed`）

**原本缺什么**：两个字符串在全仓 tests 中只出现在 `test_export_docx_smoke.py:787` 的 docstring 里，没有任何断言。图表未生成或生成失败时，预检照样成功、导出照样成功，只是交付文档少几张图 —— 完全静默。

**现在锁住什么**（`backend/tests/test_chart_alarm_guard_r178_20261104.py`，10 条）：

| 断言 | 锁住的退化 |
|---|---|
| `pending` → `chart_ungenerated`（带 `chart_type`/`status`/可读 `detail`） | 「未生成」告警被删或退化成裸类型 |
| `failed` → `chart_failed`（`status="failed"`，和 pending 不同） | 「生成失败」和「未生成」合并成同一状态 |
| 两态并存时按 `type` 可分、`detail` 不同 | 用户看不出到底缺图还是画坏了 |
| `done` / `generated` 均不告警 | 历史两套完成态写法被误报成缺图 |
| `chart_total == done + pending + 失败条数`（混合三图） | 失败被吞进 done/pending，统计口径失真 |
| `export_check` 成功响应体里能读到两类告警、`read_degraded=False`、`detail` 随响应返回 | 告警只写日志、不落到用户可见的终态字段 |
| 两类告警经 `export_issues_to_findings` 进入 `DLV-04`，聚合 severity 取 medium（不被 low 拉低），`count=2` | 告警进不了就绪度评分（等于不参与放行判定） |
| 单条 `chart_ungenerated` 单独计 low | 严重度映射被拍平 |
| 三图中间一张必然渲染失败（空壳 labor）：`图 1-1`、`图 1-2` 存在、`图 1-3` 不存在、无「渲染失败」红字 | 失败图**占号**导致后续图号虚跳（1-1 后直接 1-3） |
| 同上场景 `X-Chart-Render-Stats.failed>=1`、`backend_ok>=2` | 渲染失败不入统计头（前端拿不到失败信号） |

已知限制（**非缺陷**）：`export_issues_to_findings` 把两类告警聚合成同一条 `DLV-04`，区分只保留在 `issues` 列表与前端标签。用户可见出口成立（`exportResponse.ts` 展示 `X-Chart-Render-Stats` 失败数、预检清单按 type 显示不同中文标签），故未改产品代码。

### 8.3 导出预检 → 前端消费跨端断言

**原本缺什么**：后端算出问题清单、前端是否正确展示，中间没有任何断言。最危险的形态是「预检假通过」：后端 503 没读到数据，前端把空态渲染成「无问题」。前端只锁过「放行/未放行/stale」三条门禁，从未断言预检结果本体的展示。

**现在锁住什么**（`backend/tests/test_export_check_frontend_contract_r178_20261104.py` 10 条 + `frontend/src/tests/schemeWorkbench.test.tsx` 3 条）：

| 断言 | 锁住的退化 |
|---|---|
| 前端 `handleExportCheck` 里每个 `data.<key>` 都在后端成功响应里有同名键 | 单边改字段名 → 界面读到 `undefined` |
| 字段类型：计数为 int、`empty_ratio` 为数值、`issues` 为 list、摘要类为 dict、`read_degraded` 为 bool | 后端把计数改成字符串/把 `issues` 改成 None |
| 无问题空态 `issues == []`（不是缺键）且计数为 0 | 空态与「字段不存在」被混为一谈 |
| 图表告警 issue 必有非空 `type`、`chart_type`；未生成必有 `detail` | `type` 缺失 → 标签回退成 `undefined`；无 detail → 清单只剩类型名 |
| `EXPORT_ISSUE_LABEL` 中 `chart_failed` / `chart_ungenerated` 各有中文标签且**不同** | 两态共用同一标签，用户无法区分 |
| 前端 `ExportStats` 接口字段 ⊆ 后端真实响应键 | 类型定义与响应形状漂移（前端访问不存在的字段） |
| 503 体含 `read_degraded=true` / `error=export_check_read_failed` / `retry_after=5` / `Retry-After` 头 / detail 明说「不代表「无问题」」 | 降级体少字段或语义含糊，前端有借口当通过 |
| 前端 catch 读 `err.response?.data?.read_degraded` 并 `=== true` 接线到 `setExportCheckIncomplete`，UI 有「⚠️ 预检未完成」「不能视为「无问题」」 | 503 被当普通失败或当空态 → **预检假通过** |
| 新预检开始 `setExportCheckIncomplete(false)` | 一次失败后永久显示「未完成」（状态粘滞） |
| 三态页面级：无问题 → 消息中心「预检通过：2 个章节均无异常」+「章节与图表均已就绪」；有问题 → 「发现 1 个问题」+ 标签「图表未生成」+ 具体 detail；降级 → 「预检未完成」，且**不得**出现任何「预检通过 / 已就绪」措辞 | 三态展示互相串味（降级被展示成通过、有问题无清单） |

**产品缺陷**：无。三处均已有用户可见出口（`export_check` 响应体 / `X-Chart-Render-Stats` / 页面「预检未完成」卡片），故本批未改产品代码。
