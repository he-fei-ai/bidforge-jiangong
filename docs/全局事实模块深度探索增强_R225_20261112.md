## 三、修复项清单（含代码依据）

### 3.1 后端 18 项

**FIX-B1（P1）值比较判据误用，一次收口两份**
- `facts_extractor.py` persist_extraction 判据 `normalize_key(prior_value) != normalize_key(new_value)` → `_norm_value(prior_value) != _norm_value(new_value)`（`_norm_value` docstring 即「用于去重/矛盾比较」；刻意不用数字签名——「12.5m vs 12.5cm」签名同值会把单位错误当「再次证明」，安全方向危险）。
- `global_facts.py` `_apply_item_updates` 的 `value_changed` 同判据同步收口（`normalize_key(old_value)` 全族 grep 确认仅此两份）。
- 效果：450→600 天真变化必登记候选+置 stale；GB 记法变体判同值不再假矛盾。方向性不变式：**新判据只会多报冲突（保守），绝不吞新证据**。

**FIX-B2（P1）finalize 改值后重派生四维**
- `facts_enrich.py` `apply_finalize_result` 在 `target.value = new_value` 后调 `force_rederive_fact_dimensions(target)`（惰性导入，与 `facts_patches._rederive_patched_dimensions` 同用 `facts_classification` 单一出口）。

**FIX-B6（P3）_is_protected 兼容 list-of-strings**

## 八、教训归档

1. **「名称空间的函数不得用于比较值」**——normalize_key 的子串最长匹配对含词条的值恒同键，是一切「变化被吞」的根源；判据选择要看函数的**语义空间**（`_norm_value` docstring 即「用于去重/矛盾比较」），不是看它恰好能跑。同族判据必须一次 grep 全族（本次两份：persist + _apply_item_updates）。
2. **「规则吃 merge 产物」的规则要对 conflict_values 补比对分支**——merge_and_deduplicate 先折叠成「1 条+候选」后，所有「组内不同条目」形态的规则恒空转；展开候选时要收窄到**单例组**，否则与「打标时登记候选」（C4）组合放大成重复诊断（首轮 1→4 条当场抓红）。
3. **撤销/清除语义的粒度必须与判据粒度对齐**——「任一候选兼容就撤销整条」配上「逐候选产出 high 记录」必然背离；收窄判据的同时要把**已产出的记录**同步剔除，否则修了行标记、面板照旧骗人。
4. **锁外快照 + 长窗口 = TOCTOU**——AI 生成窗口（120s）内库状态必变，update/delete 有锁内复检而 add 裸奔的「三缺一」就是正文双值的入口；批内互查（planned peers）与库内复检（锁内 SELECT）是两道都要有的闸。
5. **批量替换脚本读文件必须显式 `newline=''`**——`io.open` 默认 universal newlines 读入会把 CRLF 折成 LF，配合 `newline=''` 写回即整文件 LF 化（R191 教训的「读侧」变体）；字节体检必须覆盖每个被脚本写回的文件。
6. **AST 源段锁对「跨行写法」不可靠**——`_norm_value(old_value) != _norm_value(\n new_value\n)` 中 `_norm_value(new_value)` 不构成连续子串；源码锁优先锁**不会跨行的锚**（单侧函数名 + 调用形态），或退回全文级断言。
7. **「验证脚本返回形态」要与被测契约一致**——chat_fn 的契约是返回原始模型文本（collect_json_response_with_chat 内部解析/修复），测试桩返回 (obj, raw) 元组会以 `'tuple' object has no attribute 'strip'` 的方式暴露在失败原因里。
8. **副本门禁口径分裂是复发性家族病**（第 4 处漏改）——FactsAdjustPanel 的 busy 与同 Space 其余按钮、DocumentParseList 权威口径成对锁（源码锁双向断言），新增/改动门禁维度时必须同步全部副本。
