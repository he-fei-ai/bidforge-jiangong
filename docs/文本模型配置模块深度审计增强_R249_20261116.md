## 2. 现状分析（代码依据）

### 2.1 模型管理

- 表结构：`ai_config`（`is_active` / `enabled` / `priority` / `env` / `request_mode` 等），
  CRUD 集中在 `backend/app/routers/ai_config/config.py`：
  - `save_config`（`config.py:111`）、`duplicate_config`（`config.py:214`）、
    `delete_config`（`config.py:291`）、`toggle_config`（`config.py:398`）、
    `set_config_enabled`（`config.py:460`）。
- 服务层写入：`provider_factory.save_ai_config`（`provider_factory.py:936` 前）负责
  唯一主配置、参数钳制、密钥加密、并发重放。
- 厂商预设与自定义厂商：`PROVIDER_PRESETS` + `CUSTOM_PROVIDER_NAME="custom"`。
  `custom` 是有意不在预设中的哨兵（必须自带 Base URL），非缺口。

### 2.2 参数配置

- 数值字段：`max_tokens` / `temperature` / `timeout` / `concurrency`，统一经
  `clamp_config_numbers` 与 `_RANGE` 钳制。
- 请求方式：`request_mode` 经 `normalize_request_mode` 归一，普通/流式二态。
- 超时：本轮修复前运行时来源为硬编码 900（`provider_factory.py` 旧
  `DEFAULT_CONFIG_NUMBERS`），`config.py:341` 的 `ai_request_timeout=900` 零消费。

### 2.3 密钥管理

- 密钥仅存密文列 `api_key_encrypted`，读写经 `encrypt_api_key` / `decrypt_api_key`；
  明文 Key 从不回传。
- `clear_config_key`（`config.py:330`）、`key_rotation`（`key_rotation.py:136`）、
  `rollback_config`（`audit.py:162`）均不把密钥纳入快照/回滚。
- `_primary_api_key` 仅当配置本身是内置 agnes 时回退 `settings.agnes_api_key`，
  避免把 agnes Key 发往错误厂商地址（`provider_factory.py:1496` 附近）。

### 2.4 模型路由

- 场景路由：`ai_scene_routes` 表 + `KNOWN_SCENES` 白名单 + `resolve_scene_config`；
  `scene_routes.py` 提供单条/批量更新，提交后失效缓存。
- 全局降级链：`_fallback_chain()` 读取全部 `enabled=1` 候选，按
  `priority ASC, updated_at DESC`，再按健康度分档、成功率过滤、`ai_fallback_chain_max`
  截断，末尾保留内置 agnes 兜底（`provider_factory.py:1507` 起）。
- 候选编排：`_resolve_chat_config`（显式 `ai_config` > 场景路由 > 全局主配置）+
  `_build_candidates`（主候选 + 降级链 + 按 `config_id` 去重 + `_order_candidates`）。

### 2.5 提示词配置

- 文本模型配置模块本身不管理提示词正文；提示词注册/治理在 `app/services/prompts`、
  `charts.py` 等模块，另有系统级治理开关（`prompt_injection_defense` /
  `prompt_context_budget`）在 `/system/governance`。配置模块通过
  `test_ai_config_prompt_r181_20261106.py` 护栏保证跨模块提示词契约。

### 2.6 配置存储、读取、校验、切换

- 存储：SQLite（`ai_config` / `ai_scene_routes` / `ai_runtime_settings` /
  `ai_config_audit_logs` / 用量日志）。
- 读取：`_load_active_config` / `_fallback_chain` / `load_scene_routes` /
  `resolve_active_env` / `resolve_disabled_providers`，均带 TTL 缓存 + 代际号防 TOCTOU
  （`provider_factory.py:1216` `invalidate_config_cache`、`:988` 代际号）。
- 校验：必填（provider/model）、数值区间、`normalize_env` 字符集、Base URL 解析、
  `normalize_request_mode`、连通性探测端点。
- 切换：`toggle_config` 全局唯一 `is_active=1`，保存/导入/环境切换后重放并发；
  `set_active_env`（`config.py:1276`）切换多环境过滤。

### 2.7 错误处理、工作流程、AI 调用

- 调用链：`chat_with_fallback` → `_resolve_chat_config` → `_build_candidates` →
  `_gate_candidates`（无 Key / 厂商开关 / 配额冷却 / 熔断器）→ `_order_candidates` →
  `_attempt_candidate`（超时/请求方式/流式）。
- 容错：失败后降级候选逐个尝试、全熔断快速失败、`_provider_reliability` 成功率统计、
  确定性死连击清零、`key_broken` 显式归因。
- 错误边界：HTTP 400/404/500 语义明确；fail-soft 不阻断服务；审计与日志不含明文密钥。

### 2.8 数据链、路由与接口

- 数据链：配置写 → 缓存失效 → 候选构建 → 调用 → 成功率/审计/用量更新。
- 接口：`/api/v1/ai/config*`、`/api/v1/ai/scene-routes*`、`/api/v1/ai/runtime*`、
  `/api/v1/ai/audit*`、`/api/v1/ai/connectivity*`、`/api/v1/ai/key-rotation*`。
- 前端：`frontend/src/pages/AIConfigPage.tsx` + `useAiConfigGovernance.ts` +
  `types/aiConfig.ts`，契约护栏在 `frontend/src/tests/aiConfig*.test.*`。

### 2.9 安全、权限、容错、缓存、并发、日志、配置

- 密钥加密、审计脱敏、快照不含密钥、环境标签白名单、Base URL 校验；
- 缓存代际号、降级链 TTL、熔断器、并发控制器、WARNING 级可观测日志；
- 配置项声明在 `config.py`（`ai_request_timeout`、`ai_fallback_chain_max`、

      _RANGE["timeout"][0],

   `git diff --check` 无输出；纯 CRLF 归一被沙箱写权限阻止，登记为环境型限制，

## 9. 新增配置项说明

- `AI_REQUEST_TIMEOUT` / `settings.ai_request_timeout`：既有配置项，本轮起被运行时消费。
  默认 900 秒；有效区间 `[10, 3600]`；`0` 视为未配置并回落 900。
- `AI_DEFAULT_MAX_TOKENS` / `settings.ai_default_max_tokens`：AI 配置 `max_tokens` 新建默认。
  默认 8192；钳制到 `[256, 200000]`；显式设 `0` 回落 8192。
- `AI_DEFAULT_TEMPERATURE` / `settings.ai_default_temperature`：AI 配置 `temperature` 新建默认。
  默认 0.7；钳制到 `[0.0, 2.0]`；**显式设 `0` 是合法值**，不会被回落吞掉。
- `AI_DEFAULT_CONCURRENCY` / `settings.ai_default_concurrency`：AI 配置 `concurrency` 新建默认。
  默认 4；钳制到 `[1, max_concurrency]`。⚠️ 语义区别于既有
  `DEFAULT_CONCURRENCY`（正文/目录链路并发控制器初始档位，默认 3），两者不要混用。
- 无新增数据库列、无迁移、无 DDL、无新增 HTTP 契约；全部为加法式/收窄式修复。
