## 4. 修复项清单（改了什么 / 为什么 / 如何验证 / 测试结果）

### R179-1 PDF 扫描件判定分母（P1）

- **文件**：`backend/app/services/file_parser.py:1245`（`_parse_pdf`）
- **改了什么**：`avg_chars = len(text)/max(n_pages,1)` → 分母改为 `min(n_pages, MAX_PDF_PAGES)`（`counted_pages`）。
- **为什么**：主通道与回退通道都只解析前 `MAX_PDF_PAGES`（配置 `pdf_text_max_pages=500`）页，而 `n_pages` 是文档**总页数**。800 页文档前 500 页每页 40 字时，旧算法 20000/800=25 字/页 < 阈值 30 → 误判为扫描件，触发整册 OCR（`_pdf_ocr_fallback`），OCR 文本还会追加到已有正文后造成重复。修正后 20000/500=40 → 不触发。真扫描件仍由 `text_missing` 分支命中，行为不变。
- **如何验证**：新增 `test_pdf_long_document_not_misjudged_as_scanned`（800 页 / 前 500 页有文字层，断言 OCR 调用 0 次）+ `test_pdf_scanned_document_still_triggers_ocr`（空白页仍触发 OCR 1 次），防止误伤真扫描件。
- **测试结果**：2/2 通过；本域全量 776 passed（零回归）。

### R179-2 CSV 分隔符嗅探（P1）

- **文件**：`backend/app/services/file_parser.py:1444 _sniff_csv_delimiter`；`_parse_csv` 内 `csv.reader(..., delimiter=_csv_delim)`。
- **改了什么**：固定逗号 → `csv.Sniffer(delimiters=",;\t|")` + 「前几行必须切出 >1 列」二次确认；不达标回退逗号。
- **为什么**：分号（欧洲区域设置 / 国产办公软件导出）或制表符分隔 CSV 会被整表解析成单列，下游 `split_into_chunks` 的表格识别、表格完整性保护、机械统计表（machinery_stat）高权重区全部失效。实测复现：`设备名称;规格型号;数量 / 塔吊;QTZ80;2` 旧输出为单列表格。
- **如何验证**：`test_csv_delimiter_sniffing`（分号 / 制表符 / 竖线 / 逗号 四组参数化，断言表头列数=3）+ `test_csv_single_column_keeps_comma_default`（无分隔符纯文本零回归）。
- **测试结果**：5/5 通过；逗号 CSV 既有断言（`test_csv_table_has_alignment_separator`）保持通过。

### R179-3 `.tif` 扩展名支持（P2，前后端同步）

- **文件**：
  - `backend/app/services/file_parser.py:35`（`SUPPORTED_EXTENSIONS`）、`_BINARY_SIGNATURES["tif"]`、`:390` 图片分派、`_parse_image_ocr:1710` 的 TIFF 多帧分支
  - `frontend/src/utils/uploadAccept.ts`（`UPLOAD_FILE_EXTENSIONS`）
  - `frontend/src/tests/uploadAccept.test.ts`（后端镜像清单，跨语言栅栏）
- **改了什么**：白名单、文件头签名、解析分派、前端 accept、前端镜像五处同步补齐 `tif`。
- **为什么**：底层 `_split_tiff_frames` / `_parse_image_ocr` 对 TIFF 已完整支持，仅白名单漏登记 `.tif`，导致扫描仪/相机直出文件被「不支持的文件格式」400 拒绝。
- **如何验证**：`test_tif_extension_supported_and_signed`（白名单 + `II*\x00`/`MM\x00*` 签名通过、非 TIFF 头拒绝）+ `test_tif_routes_to_image_ocr_dispatch`（分派到 `_parse_image_ocr`）+ 既有跨语言契约 `test_upload_format_contract.py`。
- **测试结果**：后端通过；`test_upload_format_contract` 通过（前后端扩展名集合一致）。

### R179-4 xls 数值 / 日期单元格（P2）

- **文件**：`backend/app/services/file_parser.py:1516 _xlrd_cell_text`；`_parse_excel` xls 分支逐单元格取文本。
- **改了什么**：`sheet.row_values(rx)` → `[ _xlrd_cell_text(cell, book.datemode) for cell in sheet.row(rx) ]`：`XL_CELL_DATE` 按 `xlrd.xldate_as_datetime` 还原为 `YYYY-MM-DD`（含时分秒则带时间）；`XL_CELL_NUMBER` 整数值去掉 `.0`；布尔转 TRUE/FALSE；异常单元格回退原值（fail-soft）。
- **为什么**：xlrd 的 `row_values` 把日期返回为 Excel 序列号浮点（如 `45292.0`）、整数返回 `2.0`。机械统计表数量列显示 `2.0`，日期列不可读，下游事实提取（交工日期 / 工期起止 / 检验批日期）拿到的是序列号。
- **如何验证**：`test_xlrd_numeric_cell_drops_trailing_zero`、`test_xlrd_date_cell_not_serial_number`、`test_xlrd_text_cell_passthrough`（xlrd 缺失时 `importorskip`）。
- **测试结果**：3/3 通过；xlsx 分支未改动，`test_excel_table_has_alignment_separator` 保持通过。

### R179-5 超长文件名截断（P2）

- **文件**：`backend/app/routers/global_facts_docs.py:410 _MAX_SAFE_FILENAME_CHARS`、`:413 _safe_filename`
- **改了什么**：`_safe_filename` 在保留名判定之前增加长度上限 120 字符截断，优先保留扩展名（`rpartition(".")`，扩展名 ≤10 字符时保留）。
- **为什么**：Windows 单段路径有长度上限，超长文件名让 `dest.open("wb")` 抛 `OSError`，被上传路由外层泛化成 500「上传保存失败」，用户无法自助。截断只作用于**落盘名**，数据库 `file_name` 仍存完整原名（下载名不受影响）。
- **如何验证**：`test_safe_filename_truncates_and_keeps_extension`（长名 ≤120 且以 `.docx` 结尾）、`test_safe_filename_short_name_unchanged`（短名逐字不变）、`test_safe_filename_still_guards_reserved_names`（`CON.docx` 仍加前缀）。
- **测试结果**：3/3 通过。

### R179-6 落盘 I/O 失败归因（P2）

- **文件**：`backend/app/routers/global_facts_docs.py:593 write_errors`、`:621` 落盘 try/except、`:825` 响应字段
- **改了什么**：`_stream_to_disk` 的 `OSError` 单独捕获 → 清理半成品文件 → 记入 `write_errors` 并 `continue`（单文件失败不中断整批）；响应**加法式**新增 `write_errors` 字段 + `warnings` 文案。
- **为什么**：旧实现中磁盘满 / 路径过长 / 权限不足会让整批上传 500，用户看不到是哪个文件、什么原因。
- **如何验证**：`test_upload_disk_error_reported_not_500`（断言 `write_errors`、`warnings`、`saved_count=0`）+ `test_upload_disk_error_does_not_block_other_files`（第一个失败、第二个成功，`saved_count=1`）。
- **测试结果**：2/2 通过。

## 7. 遗留问题与后续建议

1. **Excel/CSV 行数上限为模块常量**：`MAX_EXCEL_ROWS` / `MAX_CSV_ROWS` 不可按部署配置。建议（下一批）下沉到 `config.py` 并保留现有默认值，`.env.example` 加法式声明，默认行为不变。
2. **批量解析前端超时**：`parseAllDocuments` 600s。多份扫描件（单份 OCR 数分钟）可能超时，后端仍继续执行。建议（下一批）改为异步任务 + 轮询进度，或按文件数动态估算超时；本轮不改，避免引入新状态机。
3. **表格行/表头列数不齐**：`_md_cells` 逐行独立输出，若后续数据行比表头多列，GFM 以分隔行为准，下游 `_split_pipe_row` 可能列错位。建议（下一批）在 `render_table_with_header` / `_extract_pdf_page_tables` 统一 padding/裁切到最大列数，并补变异验证。
4. **加密 PDF**：只能返回明确错误文案，属能力边界，不登记为缺陷。
5. **并发说明**：本轮执行期间外部会话仍在写导出/事实/图表域文件，本报告结论仅基于本域文件与被改动的 3 个源文件；未运行全量回归（由统一收口执行）。
