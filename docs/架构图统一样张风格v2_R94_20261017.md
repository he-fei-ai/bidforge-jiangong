# 架构图统一样张风格 v2 · R94（2026-10-17）

## 背景与诉求

用户提供两张组织架构图样张（项目经理 → 分管负责人 → 部门 三层树，一个琥珀金高亮叶子），
要求「所有的类型架构图按图片中的样式生成和渲染」。

## 取证与根因

对样张原图（2000px）做逐行/列像素扫描取证（`artifacts/r94/probe_style2.py`）：

| 要素 | 样张实测 | 改造前渲染器 | 差异 |
| --- | --- | --- | --- |
| 根节点填充 | `#1E3A5F` | `#1F3864` | 色差 |
| 一级填充 | `#2B579A` | `#2E5FA3` | 色差 |
| 二级填充 | `#4472C4` | `#4472C4` | 一致 |
| highlight 填充 | `#FBBF24`（深藏青粗体字） | `#FFC000` | 色差 |
| 节点描边 | 深色细描边（≈填充×0.6） | 无描边（扁平） | **缺失** |
| 节点投影 | 右下柔和投影 `#D5D9DF` 薄带 | 无阴影（扁平） | **缺失** |
| 连线 | 蓝灰 `#576881~#728196`（取中值 `#64748B`） | 灰 `#8C8C8C` | 色差 |
| 连线子端 | 朝下小三角箭头 | 无箭头 | **缺失** |
| 标题 | 深藏青 `#1E3A5F` 粗体 | 蓝 `#2E5FA3` | 色差 |

「所有类型」判定：architecture 四子类型（organization/wbs/system/infrastructure，
`chart_validators.detect_architecture_subtype`）只影响校验器节点数区间，渲染恒走
`_render_architecture_image_v2` 单一路径；前端预览 chart-json 亦走后端渲染接口出
PNG（`MarkdownRenderer` → `chartsApi.render`），预览与导出天然同源 ⇒ 样式改一处全链生效。

## 改动

1. **`mermaid_architecture.py` 样式常量单一事实源**：新增 `ARCH_DEPTH_COLORS /
   ARCH_HIGHLIGHT_FILL / ARCH_HIGHLIGHT_TEXT / ARCH_TITLE_COLOR / ARCH_EDGE_COLOR /
   ARCH_SHADOW_COLOR / ARCH_NODE_RADIUS / ARCH_STROKE_FACTOR / ARCH_STROKE_WIDTH /
   ARCH_ARROW_W / ARCH_ARROW_H` 与 `_darken()`（描边=填充逐通道×0.6，不逐色手配）。
2. **绘制链**：标题色改样张深藏青；每条父子折线子端补 `draw.polygon` 下箭头；
   节点先按 (4,5) 设计像素偏移铺 `#D5D9DF` 投影，再画圆角矩形（radius=5 设计像素，
   随 scale 放大）带 `outline=_darken(fill)` 描边。布局、字号自适应、竖排叶子、
   拆图守卫、缓存契约全部不动（加法式样式层）。
3. **提示词措辞对齐**（charts.py 生成条目与专项修复规则 8、content.py 格式 B）：
   「橙色/琥珀橙高亮」→「琥珀金高亮」；生成条目由「可为 1 个节点」收紧为「**应**为
   履约核心且仅 1 个节点加 highlight:true」（与样张"每图恰一个琥珀金叶子"一致；
   校验器仍不强制，向后兼容）。
