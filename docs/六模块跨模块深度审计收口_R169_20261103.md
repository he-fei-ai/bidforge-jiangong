## 四、修复项清单（14 项，全部带护栏）

### FIX-1（P2·提示词）content_plan_user 畸形 JSON 示例
- **根因**：模板用 `.format()` 时代的 `{{...}}` 转义写法，而渲染走 `_registry.render_prompt`（正则单遍替换，不处理 `{{`→`{`）→ 渲染产物含 `{{"writing_focus":...}}`。该模板是 D1 离散编排每章调用一次，弱模型模仿输出畸形 JSON → `extract_json` 提取 `{{...}}` → json.loads 失败 → 每章白烧 1-2 轮修复（38 章 = 最多 76 次无效调用）。既有护栏判据 `assert "{writing_focus" not in out` 因 `{` 与 `writing_focus` 隔引号恒真（判据过弱）。
- **修法**：`app/services/ai/prompts/content.py:423-424` 改单花括号（`{"writing_focus"` 的 `{` 后是引号，不匹配 `[A-Za-z_]` 变量模式，双保险安全）。
- **验证**：护栏 A1（渲染产物 `"{{" not in out` + 新旧判据双验）+ A1b（模板源无 `{{`）+ 只读探针 `doubled: False`。

### FIX-2（P2·提示词）sync-from-code 补审计
- **根因**：`routers/prompts.py` 的 `/admin/prompts/sync-from-code` 对 inserted / force-overwritten 两分支直写 DB，不经 PATCH/reset/rollback 共用的 `_write_with_before`（事务内 CAS + `record_prompt_audit`）→ 审计序列与实际生效历史缺口，force 覆盖的用户编辑不在任何快照、回滚 UI 永远无法恢复。
- **修法**：两分支各接 `record_prompt_audit`（新 action `sync_insert` / `sync_overwrite`，before 取 DB 原行；record_prompt_audit 自身不 commit，与函数末尾统一 commit 同事务原子）。`rollbackable` 判据只看快照形态不看 action，新 action 天然兼容。
- **验证**：护栏 A2（内存库功能实证：inserted 数=审计数 / 幂等不新增 / force 覆盖的快照含被覆盖原文）+ A2b（源码锁双 action 字面量 + record_prompt_audit 调用 ≥3 处）。

### FIX-3（P2·配置）测试连接超时对齐后端最坏探测路径
- **根因**：`connectivity.py` 双探测（流式 120s + 普通 120s）+ DNS/TCP 预检 ≈ 245s，恰为代码自设场景「厂商接受 TCP 但响应极慢」；前端 `api/index.ts` axios 120000ms 先行中止 → 用户只见泛化超时，后端分类的境外延迟建议永远不可达，且前端断开后后端继续空烧。
- **修法**：前端该端点 timeout 120000→260000（后端零改动、探测语义不变；245s < 260s）。
- **验证**：前端锁 test 1（`/ai/config/test` 窗口含 `timeout: 260000` 且无 120000）。

### FIX-4（P2·图表）fix_mermaid JSON 型候选形态闸
- **根因**：修复循环按**候选形态**分流校验（`_validate_inline_chart` 对非 `{` 开头候选回落 Mermaid 校验）→ AI 不遵守「只返回 JSON」把数据型图表改写成 Mermaid 时照样 `validated=True` → 写库 + `_rewrite_code_block`（保留原 ```` ```chart-json ```` 围栏）→ 三侧全部不可见（导出解析 json.loads 失败整块跳过 / labor 渲染器必然 None / 清单 placed 翻 false）。
- **修法**：`charts.py` 新增纯函数 `_json_fix_candidate_rejected(is_json_fix, cand)`，循环内 `best_effort = cand` 之后、形态分流校验之前接线——拒绝该轮候选、`last_error` 反馈「必须返回完整 JSON 数据」进下一轮；3 轮耗尽走既有 best_effort 降级（validated=False，绝不写库）。与提示词选择处 `_looks_mermaid` 纪律对齐。
- **验证**：护栏 B1（纯函数 7 形态）+ B2（AST 锁 fix_mermaid 必须调用闸，防摘线后函数成死码）。

### FIX-5（P2·解析）提取项重试接永久错误闸
- **根因**：`bid_analysis.py` `_do_item` 重试循环对一切异常退避重试（5s/10s/15s），而目录链（AI_RETRY_ON_QUOTA_ERROR）、事实链（R111 P2-7 `is_non_retryable_error`）均已确立「401/402/403/404 重试必败不重试」纪律——本文件 grep 零处接线，为纪律不一致残留面。
- **修法**：except 分支在退避之前 `if is_non_retryable_error(e): break`（与事实链同判据单一出口；429 仍走退避）。
- **验证**：护栏 C2（源码锁：闸在退避 `wait_s` 之前 + 导入在场）。

### FIX-6（P2·解析）markdown 空结果重跑输入预算闸
- **根因**：`_run_single_item` 对「Markdown 项整体空结果」无预算整卷重跑一次——分段项 `tender_text` 可达 `_MAX_DOC_CHARS=400000`，整份塞单条 prompt 必超上下文（白烧超大调用），且失败结果被写成 `error` 而非缺失哨兵 → `missing_required` 误报、任务终态 failed。
- **修法**：新增模块常量 `_MARKDOWN_RERUN_MAX_CHARS = DEFAULT_CHUNK_SIZE * 4`（64000 字 ≈ 3-5 万 token，与分段口径挂钩），超预算保留缺失哨兵 + WARNING 留痕不重跑。
- **验证**：护栏 C1（monkeypatch 功能实证：超预算 1 次调用保哨兵 / 预算内首次+重跑各一次）+ C3（常量与 DEFAULT_CHUNK_SIZE 挂钩）。

### FIX-7（P3·图表）resync 兜底判据 `or` → `is None`
- **根因**：`_chart_pipeline.resync_inline_charts` 尾部 `apply_inline_chart_plan(...) or new_content`——apply 的**合法空串返回**（纯图块章节被限额裁空）被当 None 回退成裁剪前正文 → 图块留在正文、chart_predictions 无行 → 幽灵图（导出照渲、清单查不到、绕过限额），恰是注释反复要杜绝的形态。
- **修法**：`_applied = await apply(...)`；`if _applied is None: _applied = new_content`（原防御意图=挡 None，语义精确化）。
- **验证**：护栏 B3（monkeypatch apply 返回 "" → 输出 ""；返回 None → 回退原正文）。

### FIX-8（P3·图表）_rewrite_code_block eof 残片与 truncated 同口径
- **根因**：`read_fenced_block` 返回四态（closed/recovered/eof/truncated），改写原语只保 truncated；eof 残片在 `code == old_code` 命中改写分支时被**补写闭合围栏**（用户删掉闭合围栏的截断残片被洗白成合法图表），与登记侧（eof 不算图）/导出侧（eof 跳过）三侧口径分叉。
- **修法**：`if state in ("truncated", "eof"):` 原样保留（含原围栏行），绝不改写。
- **验证**：护栏 B4（eof 残片逐字节保持 + 闭合块改写行为不变）。既有 `test_chart_fence_eof_parity_20261003.py` 簇 121 例全绿复证。

### FIX-9（P3·正文）_mark_section_failed 接锁重试族
- **根因**：`sse_handlers` 章节失败标记的 `UPDATE sections SET status='failed'` 裸写——WAL 锁竞争窗口抛 locked 直接逃出 gen_one（其 try 只兜 CancelledError）→ 同章双份 section_error + stats/库状态漂移。同文件正文主落库早已接 `retry_db_op`（R108 P0-1），本函数为锁族漏面。
- **修法**：UPDATE+commit 收敛 `_mark_failed_once` 闭包接 `retry_db_op(max_retries=4, base_delay=0.1)`（单语句幂等可重放，与 `_persist_content_once` 同款纪律）。
- **验证**：护栏 D1（AST：嵌套闭包 + retry_db_op 接线在 generate_content→_mark_section_failed 内）。

### FIX-10（P3·事实）persist_extraction 两处 SELECT 判 R13
- **根因**：R166 FIX-3 只接线了 routers 侧 19 位点；服务层 `persist_extraction` 的「作用域事实加载」与「共享保护行回查」两处 SELECT 仍裸 `.fetchall()` → R13 命中即 AttributeError → 整轮 AI 提取成果在落库前崩掉（与 FIX-4 要避免的「提完即 failed」同形，病因换成读游标）且无定位标识。判空降级空集方向危险（DELETE 范围扩成全量未保护行）。
- **修法**：两处 `if cur is None: raise RuntimeError("R13：db.execute 返回 None（persist_extraction …）")`（可定位失败，调用方终态 failed 留痕）。
- **验证**：护栏 D3（函数源内两处 R13 标识 + `if cur is None` ≥2）。

### FIX-11（P3·图表可观测）事实修复后重建配对透传 dropped_out
- **根因**：R92 的 `resync_inline_chart_rows`（签名接受 dropped_out）在 sse_handlers 事实修复重建点未传 → 该出口的 scheme_type_limit/insert_failed 删图只写 backend.log，`report.charts_dropped` 少记（R48「删图必须用户可解释」在此出口不完整）。
- **修法**：调用点补 `dropped_out=_chart_dropped`（与首建同一累加列表；重建操作于裁剪后正文，已删块不会重复出现）。
- **验证**：护栏 D2（resync 调用窗含 dropped_out + 全源计数 ≥2 处透传）。

### FIX-12（P3·配置）duplicate_hint 前端消费
- **根因**：R111 落地的 `save_config` 去重提示后端回传，前端 `AIConfigSaveResponse` 类型缺字段 + `handleSave` 零消费（grep 零命中）→ AGENTS 登记的复算锚「批量同型配置收到 duplicate_hint 提示」在 UI 永远不可达（「服务层就绪、消费端断线」同族缺口的前端版）。
- **修法**：`types/aiConfig.ts` 补 `duplicate_hint?: string`（可缺省向后兼容）；`AIConfigPage.tsx handleSave` 补 `msg.info(data.duplicate_hint)`。
- **验证**：前端锁 test 2/3（源码锁 handleSave 消费 + 契约字段）。

### FIX-13（P3·配置安全）密钥文件排他创建
- **根因**：`crypto._load_or_create_persistent_key` 用 `write_text` 直接落盘——多进程同时首启各写各的互相覆盖，先写进程已加密落库的 API Key 密文对后写进程即 key_broken（界面「密钥失效」、候选静默跳过）。单进程默认部署不受影响，属部署形态风险。
- **修法**：改 `open(_KEY_FILE, "x")` 排他创建（O_EXCL 语义）；`FileExistsError` 方轮询读取胜出方密钥（0.05s × 10 次，`_is_valid_fernet_key` 判完整落盘——半截内容构造 Fernet 必抛），超限交外层既有降级（进程级临时密钥）。零新增配置、单进程行为逐字不变。
- **验证**：护栏 E1/E1b（真实 tmp_path 胜出/已存在两态）+ E1c（内建 open 拦截模拟竞态：失败方必须采用胜出方密钥）+ E1d（判据函数）。

### FIX-14（P3·测试卫生）conftest 接 reset_reliability
- **根因**：R110 为模块级冷却补齐了 autouse 重置，但同族进程级全局 `_provider_reliability`（滑窗成功率，影响降级链过滤）与 `_det_dead_streak`（R108 确定性 404 连击判死）无重置、provider_factory 也无公开清理入口 → 任一用例触发连击后，同进程后续依赖相同身份键（无 config_id 的候选，如内置 agnes）的用例被静默剔除出链（顺序相关偶发红，与 R110 修过的 thinking-dead 污染完全同族）。
- **修法**：`provider_factory` 新增 `reset_reliability()`（清两全局，带锁）；`tests/conftest.py` autouse fixture 接线。
- **验证**：护栏 E2/E2b（填充→清空功能实证 + conftest 源码锁）。
