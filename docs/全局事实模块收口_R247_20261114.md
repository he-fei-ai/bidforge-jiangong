## 二、功能清单与架构现状

### 2.1 模块边界与关键锚点

- **路由层**：`backend/app/routers/global_facts.py`（主体，约 4400 行）+ `global_facts_docs.py`（文档解析侧，re-export 保持 `gf._xxx` 外部调用不破）。写请求统一经 `_facts_write_guard_dependency`（项目级写锁/租约，`adjust` 豁免——R210）与 `_assert_fact_in_scheme_scope`（方案归属校验）两道闸。
- **服务层**：`facts_extractor.py`（抽取，含 `FACT_SCOPE_PREDICATE`）、`facts_classification.py`（分类/阈值单一事实源）、`facts_enrich.py`（送 AI 整理/补充）、`facts_patches.py`（补丁合并）、`facts_write_guard.py`（写守卫）、`facts_normalization.py`（归一）。

### 2.2 数据链与工作流

文档上传/解析 → `facts_extractor` 抽取（`FactItem` 序列）→ `facts_classification` 打标 → 落 `global_facts`（`fact_key` 归一锚点）→ 导出缓存失效（`_invalidate_fact_scope_cache`，统一 `facts_touched=True` 出口）→ AI 整理/补充（`facts_enrich.items_to_prompt_json` 只送 `fact_key`/`name`/`value` 三键）→ 补丁合并（`facts_patches`）。

**终态消费三路矩阵**（R224 F17b 收口）：在线完成 / 断线重挂恢复（`useUnknownTaskRecovery`）/ 刷新页面接管轮询（`SchemeWorkbenchPage`）。三路都需把 `facts_generation` 终态喂给 `consumeFactsTerminal`（恢复 `segment_stats`/`cross_conflicts`）。

### FIX-4 · A9（P2）adjust 跨方案越权面收口

**文件**：`backend/app/routers/global_facts.py:3992-3999`（`adjust_facts`）

旧实现仅传 `project_id`（无 `scheme_id`）时，`_fact_scope_where` 走「仅 pid」分支 = 该项目**全部**事实（含各方案私有行），一次调用即可跨方案读取并改写其它方案私有事实。现缺 `scheme_id` 直接 400：

```python
if not (scheme_id.strip() if isinstance(scheme_id, str) else ""):
    raise HTTPException(400, "AI 调整必须携带 scheme_id（按方案作用域，禁止跨方案批量改写）")
```

**零 UI 影响**：前端 `FactsAdjustPanel` 以 `schemeId` 为 `ready` 前置、`factsApi.n` 始终带 `scheme_id`，仓内全部既有 adjust 测试也均传 `scheme_id`。仅脚本/直连 API 的 project 级批量调整需显式带 `scheme_id`。

### FIX-5 · A6（P3）`_LOCKS` 无界增长收口

**文件**：`backend/app/services/facts_write_guard.py:41-110`（`_LOCKS_MAX`/`_release_lock_ref`/`_evict_idle_locks_locked`）

`_LOCKS` 按 `(id(loop), project_id)` 累积且旧实现永不清理 ⇒ 长期运行后端进程访问过多少项目就沉淀多少 `asyncio.Lock`（弱内存增长）。现取锁引用计数配对：`_lock_for` 计数 +1、`_release_lock_ref` 计数 -1（异常/超时路径也调用）；归零且锁未被持有即从映射驱逐；规模超 `_LOCKS_MAX`(512) 再兜底清理一次。**计数保证「别的协程已从映射拿到 lock 对象、正要 acquire」时绝不驱逐**（不破坏互斥）。

### FIX-6 · A7（P3）cross-conflicts 只读诊断面 404

**文件**：`backend/app/routers/global_facts.py:1674-1683`（`list_cross_conflicts`）

旧实现 `_scheme_project_id` 返回 `None`（方案不存在）时 `or ""` 吞成空 pid ⇒ 返回空列表，调用方无法区分「该方案确实零冲突」与「scheme_id 写错」。现方案不存在 → 404（与 `_assert_fact_in_scheme_scope` 同口径）；方案存在但未绑定项目（`pid=""`）→ 仍返回空列表（作用域退化非错误）。
