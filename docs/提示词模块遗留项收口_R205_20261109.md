## 2. 本轮落地清单（6 项 + 4 例红灯收口）

### 2.1 提示词模块遗留项

| 项 | 级别 | 问题（代码依据） | 处置 |
|---|---|---|---|
| **L-11** | P2 | 无 PII 脱敏：既有 `redact_text` 仅覆盖高置信**凭据**（sk-/gsk_/api_key=…），身份证/手机号/邮箱**原样外发** | 新增 `prompt_pii_redact_enabled`（默认 False）+ `redact_pii()`（身份证 18 位/`1[3-9]\d{9}`/邮箱三正则，整体替换为 `[已脱敏-PII]`），串联进 `redact_outbound_messages`/`redact_only`（在凭据脱敏之后）。默认关闭 ⇒ 逐字节不变 |
| **L-4** | P2 | 修复轮 `invalid_content` 无长度上限：facts 段一份资料数万字原样塞进修复提示词，每轮重发整份坏 JSON，既浪费 token 又撑爆上下文 | 新增 `_clip_invalid()`（截 8000 字，保留尾部错误区 +「中间已省略」），`render` 与兜底回落两处注入均经此裁剪 |
| **L-5** | P2 | `collect_json_response` 无**整体**截止时间（`timeout` 只约束单次调用，多轮修复可无限拉长） | 两入口新增 `total_timeout` 形参，用 `asyncio.wait_for` 包裹整段「首轮+全部修复轮」；`None` ⇒ 逐字节兼容 |
| **L-10** | P2 | 未知 prompt key 静默返回空串（仅 ERROR + 指标），模型收到空 system 提示词 | `get_prompt` 新增 `strict=True` ⇒ 未知 key 抛 `KeyError`，供路由转 404/500；默认 False 维持兼容 |
| **L-13** | P2 | 缓存加载失败即 `_prompt_cache = None` → `get_prompt` 静默回退**出厂默认**（已生效的 DB 定制全丢），且无「本次用默认回退」指标 | 加载失败改为**保留`_last_good_cache`**（不丢已生效定制）；新增 `prompt_cache_degraded` 计数器（原因归类）；`_metrics` 新增对应登记 |
| **L-2（检测侧）** | P1 | 正文因 `finish_reason=length/max_tokens` 被截断时，半截正文被当成功落库（全链路无「被截断」标记） | `chat_with_fallback_meta` 新增 `truncated` 字段：截断且未重试（或重试不可用）/兜底返回 `_best_partial` 时置 `c["_truncated"]=True` 并透传。**落库持久化需 `sections` 表加列（DDL），登记**（见 §3） |
