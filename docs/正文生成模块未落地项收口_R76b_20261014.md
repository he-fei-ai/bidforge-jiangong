## 3. G1 · 投标分析侧围栏状态机副本收敛（BUG-F10）

### 3.1 缺陷本体

`services/bid_analysis_service.py` 自持一套 26 行的围栏扫描状态机
（`opened_at` / `opened_marker` 配对）。它有两个与 `fence_common` 分叉的点：

1. **只判 `pf[0] == open_char`，不判信息串是否为空** —— 与 R76 修掉的
   `content_blocks.read_fenced_block` 是**同一个缺陷的第六处实例**：块内的
   ```` ```json ````（带信息串的行）会被当成闭合行，保护区**提前收尾**。
2. **长度判定用 `len(mk) >= len(opened_marker)`**，而唯一事实源用「长度容错」口径。

后果是**结构性**的，不只是数字对不上：`split_for_analysis` 的分段断点允许落在
保护区**之外**的任何位置，而保护区被判短了 ⇒ **切分点可以合法地落在一个代码块的
中间**，把块切成两半。

### 3.2 探针实证（`artifacts/r76b/_probe_g1_out.txt` → `_probe_g1_after.txt`）

三份语料，逐字对比副本与唯一事实源：

## 4. G2 · 历史存量只读盘点（129 行 / 0 违规 / 零回填）

### 4.1 为什么必须「只读」

R76 修掉的 BUG-F2（`read_fenced_block` 把后续正文吞进代码块）与
`auto_fix_unclosed_fences` 的「文末追加」行为，意味着**历史存量正文里可能存在围栏
长度错配或真未闭合的残留**。回填有两个方向的风险：

- **误伤**：无法从字面区分「AI 当时故意写的短闭合」与「被 R76 之前的判据误伤的正文」；
- **不可逆**：一旦改了 `sections.content`，就动了用户已交付的成稿。

R76 已就此拿到用户确认：**不做回填**。本轮要把「不做回填」变成**可执行且可复核**
的事实，而不是只写在文档里 —— 所以交付两样东西：一份**只读盘点报告** + 一把**锁死
只读形态的护栏**（否则下一轮会话会把盘点脚本「顺手」改成回填工具）。

### 4.2 盘点结果（`artifacts/r76b/inventory_g2.py` → `_g2_inventory_out.txt`）

连接方式：`sqlite3.connect(f"file:{DB.as_posix()}?mode=ro", uri=True)` —— **只读 URI**，
物理上不可能写入。四个口径：

| 口径 | 实测 |
|---|---|
| `sections` 总行数 | **129** |
| 带模拟标记但列被清零 | **0** |
| 闸门不变式违规 | **0** |
| 段落行受影响面 | **0** |

**结论：无真实历史围栏残留需要处置**，「零回填」决策在数据上成立。

### 4.3 只读形态锁（防被改成回填工具）

`tests/test_r76b_followup_guards_20261014.py::TestInventoryG2IsReadOnly` 两例：

1. `test_inventory_script_exists` —— 遗留项必须**可复核**，不能只写在报告里；
2. `test_inventory_opens_db_read_only_and_writes_nothing` —— 七重断言：
   - 唯一的 `connect` 调用必须带 `uri=True`；
   - **必须在连接参数里**出现 `mode=ro`（`ast.get_source_segment` 取连接串判定，
     不全文扫描 —— 脚本 docstring 把 `mode=ro` 逐字引用了一遍，全文扫描对
     「摘掉 URI 参数」这种真实回归形态是抓不住的）；
   - 零 SQL 写语句（`INSERT` / `UPDATE` / `DELETE` / `DROP` / `ALTER` / `TRUNCATE` /
     `REPLACE INTO`）、零 `commit(` / `executemany` / `executescript`；
   - 每一条 `execute()` 的首参必须是 `SELECT` 或 `PRAGMA`；
   - 不 import `app.db`（按 **AST** 判 —— 脚本 docstring 把 `app.db` / `get_conn`
     作为**禁用反例**逐字引用了一遍，文本扫描自咬）；
   - 不使用 `get_conn` 写连接。

⚠️ **两个「全文扫描自咬」实踩**都写进了断言注释，见 §10。

### 5.4 ⚠️ 这组**刻意不加行为锁**，理由是实测结论不是遗漏

`TestParagraphStructureUsesSingleSource` 只有判据锁、没有行为锁。原因写在护栏注释里：

> `artifacts/r76b/_probe_g3_visible_diff.py` 用 7 份语料（含块内带标签行、4 开 3 闭、
> `~~~` 未闭合、表行混排）对「可见行集合」做新旧差分，结果 **ANY_DIFF=False** ——
> 上游 `strip_code_blocks`（保守非贪婪剥离）已先把围栏结构改写掉，**翻转口径与严格

> （AST 判据锁）定向抓住即为成立，**补行为锁只会锁住一个恒等式（伪护栏）**。

这是本轮最重要的一条方法论：**护栏必须能失败**。若两套实现的输出在给定输入空间上恒等，
写行为锁等于写 `assert True` —— 它看起来有覆盖，实际是盲区（AGENTS §4.25.8 A7 曾
抓出过同类「接线护栏选了不依赖被转发参数的规则码」的盲区）。

## 10. 本轮踩坑（可复用）

### 10.1 ⚠️ 全文文本扫描会被「文档里的反例」自咬（两次实踩）

为讲清反例，源码注释里**逐字引用**了被禁形态。全文扫描立刻自咬：

1. **SQL 关键词大小写**：`_inventory_g2.py` 的 docstring 出现 `INSERT` 字样的可能性不存在，
   但 Python 内置 `sys.path.insert` 是小写的 —— 若把全文小写化再扫，
   「把后端根目录塞进 `sys.path`」会被当成写库操作。故 SQL 写语句必须**大小写敏感**匹配。
2. **禁用 import 路径**：盘点脚本的 docstring 把 `app.db` / `get_conn` 作为
   **禁用反例**逐字引用了一遍 —— 文本扫描 `if "app.db" in src` 必然自咬。
   改用 **AST**（`ImportFrom.module` / `Import.alias.name`）判定。
3. **连接参数 vs 全文**：`mode=ro` 在 docstring 里也被逐字引用，
   全文扫描对「摘掉 URI 参数」这种**真实回归形态**抓不住。
   必须用 `ast.get_source_segment` 取**连接串实参**再判。

**判据**：护栏扫「禁止出现的形态」时，先假设源码的注释/docstring 里**一定有**这个形态
（因为讲清反例本来就该写它），然后按「AST 节点」或「特定实参」收敛扫描面。
本仓既有护栏 `test_review_autofix.py` G7 组已为「只扫非注释行」立过同类锁 ——
本轮把这条判据推广到 docstring 与「特定 AST 实参」两个维度。

### 10.2 ⚠️ PowerShell 重定向与 pytest 输出的编码不一致

`Start-Process -RedirectStandardOutput` 写的是**子进程原始字节**（本例 UTF-8），
而 PowerShell `>` 重定向默认写 **UTF-16LE**。混读会整段乱码
（本例读成 `整瑳屳整瑳…` 形式的伪汉字）。

**判据**：读重定向日志前先试 `Encoding UTF8`，乱码则改 `Unicode`；
不要用「能读出字」当判据 —— 两种编码都能「读出字」，只是伪汉字不同。

### 10.3 ⚠️ 护栏判据要与风险同构，否则是伪护栏

`TestParagraphStructureUsesSingleSource` 刻意只有判据锁、没有行为锁 —— 探针实测
7 份语料 `ANY_DIFF=False`。若为「看起来完整」硬补行为锁，等于写 `assert True`。
（AGENTS §5.14 案例 A/B 同族：护栏判据选错锚点比不写护栏更糟 —— 它逼着后人把护栏改松，
护栏就此名存实亡。）
