## 一、开篇结论

1. **最影响使用的 3 个问题**：
   - **编号一致性能力整族界面缺失（D1）**：后端 4 个端点 + 前端 api 封装齐全，注释声称「2026-10-04 接线」，但生产代码**零调用**——用户永远发现不了「落库正文编号与目录漂移」，且注释与事实矛盾（报告虚报接线）。
   - **SSE 断线重挂 10 分钟上限后静默放弃（D9）**：长正文生成（常见 >10 分钟）中途断网/休眠唤醒，前端轮询 200 次后放弃且**无任何提示**，页面静默回到空闲态，后端任务仍在跑、AI 继续计费，用户大概率重新点生成造成并发/重复计费。
   - **方案名可空串落库（D11）**：「从清单选择」路径创建方案时名称非必填，后端也无非空校验，侧栏树出现空白条目。
2. **「能力已实现但界面缺失」共 12 组**（见第三节矩阵，含 4 组整族缺失）。
3. **有无导致用户数据丢失的交互缺陷**：未发现。所有不可逆操作（删方案/删项目/清目录/重置正文/清空事实/删事实组/删文档）均有二次确认且文案明确后果（如 [SchemeWorkbenchPage.tsx:4108-4118](file:///j:/编程/专项方案工具箱/frontend/src/pages/SchemeWorkbenchPage.tsx#L4108-L4118)、[:2971-2983](file:///j:/编程/专项方案工具箱/frontend/src/pages/SchemeWorkbenchPage.tsx#L2971-L2983)）；正文编辑有 localStorage 草稿（[:1220](file:///j:/编程/专项方案工具箱/frontend/src/pages/SchemeWorkbenchPage.tsx#L1220)、[:2104](file:///j:/编程/专项方案工具箱/frontend/src/pages/SchemeWorkbenchPage.tsx#L2104)）；上传识别替换本地树前有显式确认（[:4138-4145](file:///j:/编程/专项方案工具箱/frontend/src/pages/SchemeWorkbenchPage.tsx#L4138-L4145)）。
