## 一、双路径识别与定义
### 1.1 识别方法

按用户指定的 6 类标识在代码中系统搜索：
1. **分支条件**：`if/else`、`while/for` 内的状态机分派
2. **开关配置**：`config.py` 中所有 `bool/int/str` 字段（50+ 项）
3. **路由分支**：FastAPI 路由装饰器与端点内部门禁
4. **服务分支**：`provider_factory`、`repair_agent`、`facts_enrich` 等服务层分派
5. **提示词分支**：`content_runtime`、`outline_quality` 等提示词装配分支
6. **数据模型分支**：`ai_config.request_mode`、`global_facts.value_kind` 等字段值域

搜索模式：
- `(?:_enabled|_fallback|_legacy|_primary|_secondary|_fast|_slow|_mode|_switch|_path)\s*[:=]` —— 100+ 命中
- `getattr(settings, "[\"']` —— 100+ 命中（运行时读取配置开关的统一模式）
- `if not settings.` —— 5 处关键早退分支
- `os.environ.get(` —— 29 处环境变量直读
- `use_stepwise` / `request_mode` / `export_cache_fast_path` / `content_stable_prefix_enabled` 等具名开关 —— 逐项命中

## 三、合并可行性评估
### 3.1 评估维度与判据

本轮对 22 条双路径逐条按 **8 个维度** 评估合并（合并 = 消除两条实现路径、只保留一条）：

| 维度 | 判据 | 合并成立条件 |
|---|---|---|
| ① 语义等价 | 两条路径的目标产物是否同一 | 产物**逐字等价**或一方是另一方的严格超集 |
| ② 能力差异 | 一方是否具备另一方不具备的能力 | 能力差必须可用**参数/开关**在一条路径内表达 |
| ③ 数据契约 | 表结构 / 返回体 / 落库形态是否需要并存 | 需要并存 ⇒ 合并不可能（只能删一侧） |
| ④ 成本差异 | 调用次数 / token / 延迟是否显著不同 | 差异大 ⇒ 合并会让用户被迫接受不必要成本 |
| ⑤ 失败语义 | 失败时的行为（重试 / 回退 / 降级）是否一致 | 失败语义不同 ⇒ 合并会引入耦合 |
| ⑥ 兼容回退 | 是否需保留"关掉新功能回到旧行为"的瞬时回退能力 | 需要 ⇒ 合并会剥夺逃生开关 |
| ⑦ 拆分成本 | 合并的代码改动量与回归面 | 横跨 god-file（8600/6300 行）⇒ 风险高 |
| ⑧ 长期价值 | 合并后是否更利于维护 | 合并若只是"删代码"而非"收敛判据" ⇒ 无长期价值 |

**结论口径**：
- **可合并** = 判据 ①②③ 成立且 ④⑤⑥⑦⑧ 无硬约束 ⇒ 走「配置驱动合并」（单一实现 + 开关选择行为）。
- **不宜合并** = ③ 数据契约并存、或 ② 能力差异无法参数化、或 ⑥ 必须保留逃生开关 ⇒ 走「主辅路径固化」（明确主路径 + 辅路径定位 + 显式登记）。

### 4.2 辅路径处理原则（统一口径）

1. **默认值逐字不变** —— 辅路径的默认值保持现状（多数为 `False`/`""`），任何"把辅路径设为默认"的改动都属行为变更，须单独评审。
2. **关闭即逐字回退** —— 关掉辅路径后，产物必须与引入前**逐字节一致**；由各条对应护栏锁定（如 `test_switch_default_is_on`、`test_prompt_renders_and_block_absent_when_off`）。

4. **组合交互必须实测** —— 与其它开关组合时的行为必须有护栏；本轮已实测并修复 D3×D4 组合缺陷（R74 G3）。
5. **不得回流副本** —— 合并后的单一出口必须由静态护栏锁死，防止后人在别处另写一份判据（AGENTS 最高频反模式：「同一判据两份副本」）。
