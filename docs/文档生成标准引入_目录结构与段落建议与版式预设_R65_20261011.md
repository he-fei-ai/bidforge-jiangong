# 文档生成标准引入 —— 目录结构建议 / 段落结构建议 / 导出版式预设（R65 · 2026-10-11）

> 来源需求：外部文档《文档生成规则分析与软件标准建立》。用户要求「读取并结合本软件的模块与功能进行引入和增强、优化，**不改变本软件为建筑工程专项施工方案编写功能的特性**」。
> 本轮定位：把外部"通用文档生成标准"与本仓既有能力**逐项对账**，只补**真实缺口**，且全部做成**加法式建议 / 可选预设**；不动既有 `ok` 结论、不动默认产物版式。

## 0. 一句话结论

外部文档的四类标准（目录 / 正文 / 图表 / 导出）+ 15 项增强清单里，**12 项本仓早已落地**（且比外部建议更贴合专项施工方案场景）；本轮只补 3 类真缺口，**零新增依赖、零数据迁移、新增配置项 1 个**（`layout_preset`，缺省空 = 逐字节回退）。

## 2. 落地一：目录结构规范"建议"检查（`outline_quality.py`）

- 纯函数 `check_structure_standards(outline) -> dict`（`:432`）
  - 常量：`OUTLINE_CHAPTER_MIN/MAX = 5/10`、`OUTLINE_CHAPTER_RECOMMENDED = 7`、`OUTLINE_SECTION_MIN/MAX = 2/15`、`OUTLINE_MAX_DEPTH = 4`（`:422`）
  - 返回 `{"evaluated","chapters","max_depth","recommended_chapters","warnings":[{kind,count,allowed,message}]}`
  - 三类 `kind`：`chapter_count` / `max_depth` / `section_count`
- 递归深度 `_max_depth(nodes, level=1)`（`:488`）
- 文案出口 `render_structure_notice(report)`（`:500`）：「目录结构规范建议：…」最多 6 条
- **关键约束**：只产 warning 文案，**绝不参与、绝不翻转** `check_outline_continuity` 的 `ok`（后者被 AST 护栏锁定，不得侵入）。空输入 / `None` → `evaluated=False`，不抛。
- **接线**：`sse_handlers._attach_quality_report` 报告新增 `"structure"` 兄弟键，并用 `logger.info("…（仅建议，不阻断）")`（**info 而非 warning**，避免运维把建议误读成阻断项）。

## 3. 落地二：正文段落结构建议（`content_standard.py`）

- 纯函数 `paragraph_structure_report(content) -> dict`（`:707`）
  - 区间常量 `PARA_MIN/MAX/RECOMMENDED_CHARS = 50/500/150`（`:684`）
  - 三类 `severity:"advisory"` 咨询级 warning：
    - `long_paragraph`：段落 > 500 字
    - `date_format`：`2026/1/5`、`2026-1-5` 这类**非 ISO**（`_PS_BAD_DATE_SLASH_RE` `:692` / `_PS_BAD_DATE_HYPHEN_RE` `:693`；ISO `2026-01-05` 不判）
    - `duration_unit`：「120天」疑似该写「日历天」，靠语义词共现 `_PS_DURATION_CTX` 降噪（避免「养护7天」等误报）
  - 跳过表格行 / 代码围栏（`_PS_TABLE_ROW_RE` / `_PS_FENCE_LINE_RE` / `_PS_LIST_HEAD_RE`）
- **接线**：正文生成后自检段 `report["structure"] = _struct_rep` 并重建 `report_json`，同样只 info 不阻断。
- **⚠️ 本轮最大教训（撞名）**：新常量首版取名 `_FENCE_RE` / `_TABLE_ROW_RE`，与模块**既有同名符号**（`_FENCE_RE` 在 `:181`，供 `strip_code_blocks` 使用）**撞名**，被静默覆盖后打挂 3 条既有用例。全部改 `_PS_` 前缀后修复。
  - 判据：**往老模块追加纯函数时，模块级名字空间是共享的，先 `grep` 再取名。**
  - 回归锁：`test_no_duplicate_module_level_names`（范围限本轮真正追加的 3 个文件，避开 `sse_handlers` 里既有的条件式重定义）+ `test_content_standard_fence_regex_single_definition`。

## 4. 落地三：导出版式预设 `layout_preset`（`export.py`，唯一新增配置项）

- `LAYOUT_PRESETS`（`:1796`）：`"engineering"` 档 = 通用 Word「工程公文」——`line_spacing 1.5`、上下 `2.54cm`、左右 `3.18cm`。
- 纯函数 `_resolve_layout_preset(config, base_opts) -> dict`（`:1804`）
  - **返回新 dict**（`base_opts` 不被就地修改）；缺省 / 未知名 → 原样返回（逐字节回退）
  - 预设命中时只覆盖 `line_spacing` 与 `margins`；用户在 `config.margins` 显式给过的键**赢过**预设补缺（不强改细调）；非数值键静默丢弃
- **应用点**：DOCX/PDF **两条链路唯一收敛点** `_build_docx_task`（`:4184`）套用一次即双侧同生效。
- **真实读取**：`_prepare_export` 的 `docx_options` 内 `config.get("layout_preset")`（`:4120`）—— 满足前后端 parity 护栏「白名单键必须被源码消费」。
- **指纹白名单**：`"layout_preset"` 纳入 `_EXPORT_CONFIG_KEYS`（`:4232`），改它即失效导出缓存。
- **既有默认（四边 2.5cm / 行距 1.15）是历轮锁定的字节契约，一字未动** —— 缺省 `""` 时产物与改造前逐字一致。
- **前端**：`SchemeWorkbenchPage.tsx` 导出「正文样式」面板补 `layout_preset` Select（"不启用（保持标准版式）" / "工程公文（上下2.54 / 左右3.18 / 1.5倍）"，`allowClear`），`initialValues.layout_preset=""` —— 满足 `test_backend_whitelist_keys_are_reachable_from_ui`。
