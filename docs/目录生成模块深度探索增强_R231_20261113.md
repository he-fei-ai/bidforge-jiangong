## 四、缺陷定罪清单（主会话亲验，全部附行为实证）

### BUG-A · P2 · 崩溃面：`parse_outline_json` 容器根形态产出 level=0 → 折叠器 IndexError（500）

`omp_task_agent.parse_outline_json` 的 docstring **承诺支持** `{"title","children":[...]}` 形态，实现以 `walk(data, 0, "")` 起步——根标题存在时被 `if title:` 产出为 **level=0** 条目。下游 `omp_outline_bridge.fold_generated_sections_to_tree` 的哨兵是 `(0, root)`，`stack[-1][0] (0) >= s.level (0)` 把哨兵弹空 ⇒ `stack[-1]` **IndexError**：

```
P1 parsed: [(0, '某桥梁专项施工方案目录'), (1, '章1')]   ← 实测探针
P1 fold CRASH: IndexError list index out of range          ← 两种 dict-root 形态均崩
P1b parsed: [(0, '文档标题'), (1, '章1')]（{"sections":[...],"title":"T"} 同崩）
```

触发链：omp 未写 `OUTLINE.md`、写了 `outline.json`（`_read_workspace` 的 .json 回退路径可达）→ `generate_outline_via_omp` 端点 500（异常无 try/except 包装，仅 finally 释放标记）。「注释承诺 ≠ 代码事实」家族第 N 次实证 + 既有测试只覆盖 list-root 形态（`test_parse_outline_json_nested/flat`），dict-root 零覆盖存活。

### BUG-B · P2 · 数据污染：`_read_workspace` 回退循环不排除 NOTES.md → 备忘散文当章节入库

`OUTLINE.md` 缺失时回退「首个 .md/.json」，`sorted()` 下**大写 N 必排在任何小写产物文件之前**——omp 只写了 NOTES.md（未写 OUTLINE.md 的部分失败形态）时，备忘散文被 `parse_outline_markdown` 解析成章节：

```
CASE1 source_file = NOTES.md
sections = [(1, '工作备忘'), (2, '遗留问题')]   ← 实测探针（NOTES.md + outline.json 并存）
```

讽刺的是代码**知道** NOTES.md 是元文件（`notes` 字段单独读回它），却在回退循环漏排除。散文标题非空 ⇒ 穿过 `validate_outline_numbering` 空标题闸门 ⇒ 「工作备忘」「遗留问题」作为章节整表写入 sections。与 R229 F2（omp_provider 缺 import）同为「接缝文件粗放」家族。

### BUG-C · P3 · 前端 D-02 家族：切方案复位块漏 `setGeneratingOmp(false)`

`generatingOmp` 是页面级布尔（R193 D-02 复位块登记的 `generating/genType/taskPaused/taskStopping/activeTaskIdRef` 同族——omp 状态晚于复位块诞生而漏登记）。切方案 A→B 后 A 的 omp 仍在飞 ⇒ B 页 `outlineBusy` 恒真，**全部目录按钮被禁用数分钟**（omp 同步长任务 6 分钟超时窗）。缓解因素（亲验）：`load` 内建 `currentSchemeIdRef` 守卫，omp 完成回调的旧 `load()` 空转，不会把 A 的树灌进 B 页（R223 FE-4 的树灌回面已被防住）；omp 请求不 abort，后端照常完成 A 的整表写入（预期行为）。

### FIX-4 · P3 · omp 门禁缺口：树行内结构操作未接 omp 互斥（超出可行性报告 §11.4 局限 B 自登记范围）

可行性报告 §11.4 局限 B 登记称「前端 outlineBusy 也禁用主链按钮」——亲验 OutlineTab：**7 个头部按钮确实全部 `disabled={outlineBusy}`，但树行内操作不在按钮族**：`OutlineTreeActions`（新增子章节/上移/下移/删除）、Tree `draggable` 拖拽、双击改名（`useOutlineEditTreeRender` 的 `onDoubleClick` 无条件触发）、字数预算面板。omp 整表重建前的这些操作会被静默覆盖；其中**改名**有正文丢失面（改后标题匹配不到旧路径 ⇒ matcher 判 is_new ⇒ 旧章节连正文级联删除）。后端双 409 感知不到 omp 旁路（omp 不注册 task_registry，omp 工作流刻意不碰），前端门禁是唯一防线。

## 九、教训归档

1. **「注释承诺 ≠ 代码事实」再现于新接缝**：`parse_outline_json` docstring 承诺 dict-root 形态，实现产出 level=0 崩溃且既有测试只覆盖 list-root——对 docstring 声称支持的**每一种输入形态**必须行为探针（R223 NUM-4 教训的接缝版）。
2. **元文件排除判据要放在「遍历生产者」侧**：`_read_workspace` 明知 NOTES.md 是元文件（notes 单独读回）却在回退循环漏排除；`sorted()` 大小写序让大写元文件必胜出——「知道某文件是元数据」和「遍历时不把它当数据」是两个必须同时成立的判据。
3. **useCallback 闭包新增引用必须同步 deps**：`ompBusy` 漏登记 = stale closure（omp 结束后门禁不解除）——R224 终态闭包绑定时序家族的前端 useMemo/useCallback 变体；本轮护栏把 deps 数组字面量也锁进源码锚。

6. **并发限额下多路代理同批失败（429 家族，R226 先例复现）**：审计主会话必须自带亲验兜底路径——本轮指标探针 + 定向核查接管了三路代理的职责，审计不因代理停滞而失覆盖。
7. **护栏源码里的检索针必须用转义而非字面量（§十新增）**：`count("�")` 的字面量 U+FFFD 让护栏文件**自带** FFFD——字节体检断言的检索针一律写 `"\ufffd"` 转义（R212 教训③现场复现）。
8. **mock 签名加形参前先 grep 测试桩（§十新增）**：给 `_save_outline_checkpoint` 加 `skip_terminal` 形参撞红 4 条既有护栏（r188/r213 的 2 参 fake）——**给被 monkeypatch 的函数加形参 = 全仓测试桩签名契约变更**，加形参必须同步 grep `monkeypatch.setattr(...)` + 局部 `async def *_fake*/spy*` 全部桩点（本轮 10 处适配）。
