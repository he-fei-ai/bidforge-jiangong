## 2. L2 · 编号合法性判据两套并存（脏编号被「抢救」）

### 复核结论：不是语义差异，是**缺陷**

实测 canonical 形态（`level == 编号深度`）下两套算法**逐项恒等**（depth 1..5 全等）⇒
**不是缺陷**；真实缺陷是**脏编号上两侧行为相反**：

| 存储编号 | 落库态 `stored_id_to_prefix` | 改前展示态 `format_heading_by_id` |
|---|---|---|
| `abc1.2` | `''`（fail-closed） | `'2 T'` ← **凭空造出一个章号** |
| `0.3` | `''` | `'3 T'` |
| `1.2.x` | `''` | `'1.2 T'` |
| `1.0.2` / `1..2` | `''` | `'1.2 T'` / `'2 T'` |

⇒ 同一份脏数据下**落库正文不套号、导出与前端却渲染出看似正常的编号**
（即 AGENTS §4.13 D4「落库正文 ≠ 导出成稿」的根因家族）。**分歧 5/15 形态。**

### 修法

`numbering.py` 新增公开别名 `stored_id_parts = _stored_id_parts`；
`heading_templates.outline_number_parts` 改为消费它，**保留 tail-window 的格式语义不变**
（level 模板 L2=`{num}` / L3=`{last2}` / L4=`{last3}` 本就是按层级设计的，不是缺陷）。

> 依赖方向**零新增**：`heading_templates.py` 原本就 `from app.services.numbering import
> ALPHABET, CHINESE_NUMBERS`，只是再加一个名字。

**结果**：canonical 输出逐项不变；脏编号分歧 **5/15 → 0/15**，统一 fail-closed（**不编造编号**）。

## 4. L6 · 排序键三处一致性 +「同级 level 恒等」不变式

**复核**：写侧 `sections._build_tree._sort_key` = `(sort_order, id)`；
导出侧 `export._section_sort_key` = `(sort_order, level, id)`；检测器同导出侧。
两者等价**依赖「同级 level 恒等」，而该不变式无任何断言**。

**关键发现**：该不变式是**自愈**的 —— `renumber_section_outline_ids` 把 `level` 刷成
**位置深度**（`level = new_id.count(".") + 1`，`numbering.py:338`）⇒ 任何一次重排都恢复它。
故**不改实现**（改排序键会改变脏数据下的导出顺序，属行为变更），而是**把不变式做成可执行断言**：

- `test_siblings_have_equal_level_after_renumber`：喂「同级 level 不等 + sort_order 并列」的
  脏数据，断言 renumber 后同级 level 必相等；
- `test_write_and_export_sort_keys_agree_on_canonical_tree`：canonical 树下两侧排序逐项一致；
- `test_renumber_writes_level_as_depth`：不变式的**来源**本身（防有人删掉 level 回写）。

## 5. L4 · 修复轮残留「只报不拒」→ 登记为**有意设计**并加锁

R85 遗留表把这一条列为「行为变更，需单独立项」。复核后**维持现状并加锁**：

**理由**：拒收会把「AI 修了 3 处占位、还剩 1 处」的好成果一并丢弃；「如实报告 + 转人工」
是本仓一贯纪律（宁可让人看，不静默丢成果）。把它登记为**显式契约**，
用三条护栏锁死：① 两条修复路径**都必须复检**；② 残留时**同时**置 `passed=False` 与
`generic_residual`（绝不谎报「已自动修复」）；③ **不得**出现「有残留就丢弃整棵树」的分支
（那是行为变更，须单独立项 + 显式决策，不得顺手引入）。

## 9. 本轮方法论教训

1. **A/B 与探查结论都要复核，探查代理的「11 同 4 异」实为「14 同 1 异」** ——
   差异来源是**收敛手段本身**（`_ex.` 前缀），不是语义差异。归一后逐行 diff 才是判据。
2. **`is_generic` 式断言必须能自证**：「委派函数是同一对象」在薄包装形态下恒假 ⇒ 首版即踩；
   改成「逐项输出相等（含异常类型）」后既成立又更强。
3. **「源码含字符串」在自写注释里会自咬**：死导入检查用 `"parse_fence_line" not in src`，
   被我自己写的「为什么删它」注释命中 ⇒ 改走 AST 导入节点。
4. **新写的 fail-soft 分支必须自己先跑一次异常路径**：`test_gate_never_raises` 当场抓出
   `logger.warning` 的 `%s` 占位符与实参数量不匹配（2 占位 1 实参）⇒
   **fail-soft 的日志路径本身就是会抛异常的第二现场**。
5. **字节体检要覆盖新写的每个文件**：`test_outline_closeout_r86_20261016.py` 的 docstring
   在编辑往返中丢了 2 个字符（U+FFFD）——**测试文件同样是源码**。
