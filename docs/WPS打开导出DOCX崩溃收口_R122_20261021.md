# R122 · WPS 打开导出 DOCX「文字程序意外中断」崩溃收口（2026-10-21）

## 一、问题现象

用户用 WPS 打开平台导出的 DOCX（`室外汽车吊吊装施工专项方案`，19:36 导出件
`43b4612e-..._0b355809.docx`，464KB）时弹出：

> **文字程序意外中断** —— 当前文档编辑已被意外打断，可尝试重新载入以恢复工作状态

## 二、诊断（证据链）

全量扫描 `backend/data/_exports` 37 个导出件（`_r122_docx_crash_scan.py`，
检查 ZIP 完整性 / XML well-formed / 非法控制字符 / mc:Ignorable / **OMML 空参数
元素** / 表格网格 / 关系完整性 6 类）：

| 文件 | 缺陷 |
|---|---|
| `43b4612e_..._0b355809.docx`（用户件，19:36） | **10/10 个 `m:f` 的 `m:num`/`m:den` 双空**（132 个 oMath） |
| `43b4612e_..._b7cd7252.docx`（16:37） | 同上 |
| `d5104b41_..._983a6641.docx` | 空 `m:e` + 空 num/den |
| `s5_99914b93_...docx` | 空 sub/sup + 空 num/den |

空 `CT_OMathArg`（`<m:num/>` 等）违反 OOXML schema：**Word 静默修复，WPS 直接
崩溃**——与用户现象完全吻合。段落文本残留（`'fak≥×K'`、`'p='`、`'Areq='`）佐证
公式内容已被清空。

## 三、根因（docx_math 两处叠加，缺一不可）

1. **`_parse_seq` 返回 `(节点列表, 新索引)` 二元组**，而 `_parse_required_group`
   / `_parse_script_arg` / `_parse_optional_bracket` 三个 helper 把整个元组
   **再包一层**返回；调用方（frac/sqrt/nary 分支）按 `(x, i)` 解包 ⇒
   num/den/base/sub/sup/deg 全部变成 `(list, int)` 元组。
2. **`_node_to_omml` 只接受单节点元组**：对元组型入参 `node[0]` 是 list 而非
   字符串 ⇒ 无分支命中 ⇒ `return ""` ⇒ 空 `<m:num></m:num><m:den></m:den>`。

即：**所有** `\frac{a}{b}`、`\sqrt{...}`、`\sum_{}^{}` 的分子/分母/被开方数/
上下限被静默清空——既是内容丢失缺陷，又是 WPS 崩溃根因。

历史盲区：`test_docx_math.py::test_fraction_structure` 旧断言
`"<m:num>" in xml` 对空标签 **vacuously 通过**（只查标签存在、不查内容），
15 条单测全绿仍未发现。

## 四、修复（加法式，3 处 + 1 防护网）

`backend/app/services/docx_math.py`：

1. 三个 helper 改为 `_parse_seq(...)[0]` 取节点列表（根因①）；
2. `_node_to_omml` 顶部增加 `isinstance(node, list)` 分支按 seq 语义拼接（根因②）；
3. **防护网**：`latex_to_omml` 产物若含空参数元素
   （`_EMPTY_OMML_ARG_RE` 匹配 `<m:num/>`/`<m:e></m:e>` 等）则抛
   `ValueError` ⇒ 由 `export._add_omml_formula` 既有 except 回退为 LaTeX
   原文文本——**宁可显示源码，绝不向 docx 写入会令 WPS 崩溃的 OMML**。

## 七、判据教训

① **只查"标签存在"的断言是 vacuous 护栏**——`"<m:num>" in xml` 对
`<m:num></m:num>` 恒真；内容级断言必须查子结构/文本；② **元组返回值契约**
（`_parse_seq` 返回二元组）在 helper 二次包装时被静默破坏，且破坏方向是
"返回空"而非抛异常——最危险的失败模式；③ **WPS 崩溃优先疑 OMML**：
Word 能修的 schema 违规 WPS 不一定修，导出链应对 OMML 做空参数元素
终检（本轮已内建为防护网）。
