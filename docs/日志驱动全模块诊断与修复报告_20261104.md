## 3. 逐模块机制说明（真实调用链）

### 3.1 上传解析

- 入口：`upload_outline.py` `POST /api/upload-outline/parse` → 分片落盘 → `asyncio.to_thread(parse_file_content_ex)` → `file_parser`（MuPDF/OCR/Office）→ 写 `uploaded_outlines / project_documents`。

## 6. 修复清单（文件 + 函数 + 根因 + 验证）

### FX-1 · 任务终态不可被晚到进度覆盖

- **文件/函数**：`backend/app/services/ai/task_registry.py` → `_update_task_progress_db`（`:149-168`）
- **根因**：`UPDATE task_registry SET progress=?, message=? WHERE id=?` **无 status 守卫**；而 `_write_task_terminal_db`（`:268-283`）与 `_set_task_status_db`（`:367-377`）都有 `status IN ('running','paused')`。断线兜底先写 stopped 并 pop 内存 → run_inner 收尾 `update_progress` 因 `state is None` 走免节流分支 → 覆盖已完成行；随后 completed 终态被守卫拒绝，形成 stopped + 已完成 的矛盾终态。
- **修复**：给进度 UPDATE 加同口径守卫；终态行成为唯一事实源，任何晚到进度不得再改。
- **验证**：新增 `tests/test_task_terminal_progress_guard_r179_20261104.py`（3 条：stopped 不被覆盖 / completed 不被覆盖 / running 仍可写）；相关 155 passed。

### FX-2 · 取消/异常收尾必须失效下游缓存

- **文件/函数**：`backend/app/routers/bid_analysis.py` → `event_generator.run_inner` 的 `except asyncio.CancelledError`（`:1176-1192`）与 `except Exception`（`:1193-1201`）
- **根因**：收尾失效 `_safe_invalidate_downstream` 只写在 `_run_bid_analysis_with_progress` 末尾（`:1581`），取消会从 `asyncio.gather` / `_get_missing_required` 直接抛 `CancelledError`，永不执行；与 `_safe_invalidate_downstream` 注释「停止场景同样生效」矛盾。15:40 实测 16 项已写库却无失效日志。
- **修复**：两个异常分支在 `clear_interrupted_items` 后各补一次 `_safe_invalidate_downstream(db, real_pid, scheme_id or real_pid)`，并用 `contextlib.suppress(Exception)` 保持 fail-soft，不改变任务终态。
- **验证**：新增 `tests/test_bid_analysis_cancel_invalidation_r179_20261104.py`（AST 护栏：两个分支必须含该调用）；`test_bid_analysis.py + test_cross_module_chain_20261004.py + 新增` 共 77 passed。
