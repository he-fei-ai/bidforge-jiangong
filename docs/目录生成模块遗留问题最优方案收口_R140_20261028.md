## 2. L5 落地：前端 `buildPartialOutlineHint` 消费 `partial`

### 2.1 现状取证
`buildPartialOutlineHint`（SchemeWorkbenchPage.tsx:1609-1627）声明 `partial?: boolean` 但函数体**从不读取**（死参）。两个调用方（:5708 failed 分支 / :5737 stopped 分支）都从后端 `outline_result.partial` 传入——R139 BUG-B 修复后后端断线/停止/全章失败路径**恒写 `partial=True`**，故现状 `partial` 恒为 truthy、死参无观测影响。但「声明未消费」是契约缺口：若未来某调用方传 `partial=false`（完整结果），现有文案仍说「已生成 N 个章节节点**尚未保存**」误导用户补章。

### 2.2 落地（`SchemeWorkbenchPage.tsx`，纯函数加法式）
在函数体入口新增 `partial === false` 分支 → 完整结果口径：
- title `"目录生成完成"`、content `"目录已完整生成 N 个章节节点，可直接保存使用。"`、okText `"保存目录"`、tone `"info"`。
- `partial` 为 `true` / `undefined`（旧 checkpoint 无该键）→ **保守视为部分成果**，走既有口径逐字不变（向后兼容，与 R139 断线 partial 缺键修复同口径）。
- **行为变化**：仅当 `partial === false` 时（当前无任何调用方触发）才走新文案；现有两调用方传 `partial=true` ⇒ 线上文案**逐字不变**。

### 2.3 护栏（`outlineTab.test.tsx`，+3 例）
`partial=false` → 完整口径（title/content/okText/tone）；`partial=true` → 既有「已停止/已生成部分」；`partial=undefined` → 保守视为部分成果。

## 6. 判据教训归档（本轮）

① **A/B 变异锚点必须唯一且带「语义上下文」**——M2 首版锚 `s.get("content") or ""` 在 export.py 出现**两处**（:1429 has_children 检查 与 :7117 指纹 dict），`replace(old, new, 1)` 命中**第一处**（:1429），且替换 `""  # MUTATION` 产生语法错误 → 误报 CAUGHT（rc=4 收集错误而非断言失败）。改锚为 `s.get("level"), s.get("title", ""), s.get("content") or "")`（唯一上下文）后 M2 才以 rc=1 真断言失败被抓获。**教训**：变异锚点要按「行上下文唯一」选，不能按「子串首次出现」；替换后必须回读确认命中目标行（R137 教训⑤同族）。
② **「设计正确但无测试锁」与「设计错误」是两种缺陷**——L3 的 export 缓存键**本来就是对的**（含 content_fingerprint），R139 发现 H 定性为「无测试锁」；这类项的修复 = **补护栏**（零生产改动），不是改生产。判别：先取证设计是否真错（读 WHERE/指纹 dict），再决定「补锁」还是「修生产」。
③ **死参的正确处置是「让它被消费」而非「删参」或「留白」**——L5 的 `partial` 声明未消费：删参会破坏两个调用方（能力回退），留白是契约缺口；按 R139 建议「按 partial 区分文案」让其消费，`partial === false` 走完整口径，`undefined` 保守视作部分成果（向后兼容）。**判别：死参若无消费方价值 → 删；若有语义价值（区分完整/部分）→ 接线 + 锁行为**。
④ **「显示瞬态误差」的修复优先级最低**——L1 的 `done` 计失败章只影响生成过程中的进度消息（终态 `failed_count` 正确），且修复需改 `_merge_unit_results` 契约；按「风险/收益」判定不改，留痕。**判别：先看底层数据是否已正确（是 → 显示层改动降级），再看修复是否动契约（动 → 除非用户可见价值大，否则不改）。**
⑤ **A/B 脚本的 `restore()` 必须二进制读写**——首版 `_ab_r140.py` 用 `open(r).read()`（通用换行把 CRLF 归一成 LF）+ `open(w, newline="").write()`（写回 LF），把被测生产文件 `export.py` 从 CRLF 改成 LF，引发全量 2 例字节健康红（`test_no_line_ending_or_control_damage` / `test_file_byte_health`）。**这是「测试脚本自伤生产文件」——A/B 变异必须逐字节恢复原样**（`rb` 读 / `wb` 写 + `decode`/`encode`），且每次变异后回读换行验证（本仓字节健康测试会拦截）。**教训：任何触碰生产源码的验证脚本，恢复必须「字节级」而非「文本级」；全量回归出现非本轮改动文件的字节健康红，先查自己上一步的读写是否归一了换行。**
