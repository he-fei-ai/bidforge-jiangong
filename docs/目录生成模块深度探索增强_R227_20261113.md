## 3. 修复与增强（步骤 4/5 · 落地 7 项）

### 3.1 D6 `sections.locked` 执行点（用户裁决：只拦结构变更）

**文件**：`backend/app/routers/sections.py`

**裁决语义**（用户 2026-11-13）：锁定只拦**结构变更**（移动/重排/删除），**正文与标题编辑豁免**。守卫判据用 **DB 行 `locked` 列**（非内存态），`force` 逃生门放行。

**修法**：三端点加 `force: bool = Query(False)` 锁定守卫。

- `update_section`（:907-925）：结构字段（`parent_id`/`level`/`sort_order`）∩ `fields` 且 `locked==1` 且未显式解锁（`fields.get("locked")!=0`）且非 `force` → 409（在 parent_id 校验前、R194 守卫后）。
- `delete_section`（:1351-1363）：`locked==1` 非 `force` → 409。
- `reorder_sections`（:3406-3435）：locked level-1 章新同级序号 ≠ 当前 `sort_order` → 409。

**签名顺序修复**（重要，实证 20 失败）：`force` 必须放 `db=Depends(get_db)` **之后**（函数签名末尾），否则破坏既有位置参数契约（`reorder_sections(sid, body, db)`、`update_section(sid, nid, data, db)`、`delete_section(sid, nid, db)`）。修复后签名：

```python
update_section(scheme_id, section_id, data, db=Depends(get_db), force: bool = Query(False))
delete_section(scheme_id, section_id, db=Depends(get_db), force: bool = Query(False))
reorder_sections(scheme_id, body, db=Depends(get_db), force: bool = Query(False))
```

**夹具适配**：`test_outline_r187_20261108.py` `_make_db` 手写最小 schema 补 `locked INTEGER DEFAULT 0` 列（CREATE TABLE + INSERT 6 值适配），测试意图（子树深度守卫）不变。

**护栏**：`test_outline_r227_20261113.py` `TestLockedUpdate` 6p + `TestLockedDelete` 3p + `TestLockedReorder` 3p = 12p（行为实证直接调端点函数；`_seed` 插 s1/s2 一级（s1 locked=1/s2 locked=0）+ s3/s4 s1 二级子章；`_expect_409` 捕获 HTTPException status==409）。

### 3.2 D2 `scheme_defects` 删章级联（用户裁决：标 stale 保留账本留痕）

**文件**：`backend/app/db.py` / `backend/app/routers/sections.py` / `backend/app/services/defect_ledger.py`

**裁决语义**（用户 2026-11-13）：标记 `stale`（保留账本留痕，显示层标「章节已删除」），非 status 枚举扩展。级联范围：本轮聚焦 `delete_section`（显式删章）；整表重建/快照回退路径维持登记待后续。

**修法**：

- `db.py` migrations 列表加 `("scheme_defects", "stale", "INTEGER DEFAULT 0")`（:1134-1137，幂等 `PRAGMA table_info` + `ALTER TABLE ADD COLUMN`）。
- `delete_section`：删章（含后代 `all_ids`）后 `UPDATE scheme_defects SET stale=1, updated_at=datetime('now','localtime') WHERE section_id IN (all_ids)`（:1396-1403）。scheme 级（`section_id=''`）不受影响。
- `defect_ledger.ledger_summary`（:487-516）：加法式新增 `stale` 键（`COUNT(*) WHERE stale=1`），**不改**既有 total/passed/failed 计数语义（保守原则，旧库无 stale 列默认 0 时返回体逐字一致）。

**前端**：`types/defect.ts` `DefectItem`/`DefectSummary` 加 `stale?: number`；`DefectLedgerPanel.tsx` 加 summary Tag（`defect-summary-stale`「章节已删除 {num(summary.stale)}」）+ 行徽标（`row.stale === 1` → `defect-stale-{id}`「章节已删除」，替代 fix_policy Tag）+ stale 行操作禁用（isStale 判据：验证/执行/人工接受/驳回 disabled）。

**护栏**：`test_outline_r227_20261113.py` `TestStaleCascade` 2p。

## 6. 运维与兼容性说明

- **需重启后端**（sections / db / defect_ledger 常驻）。
- **前端需重建**（outlineTreeModel / useOutlineGeneration / SchemeWorkbenchPage / OutlineLibraryEditModal / OutlineLibraryPage / defect.ts / DefectLedgerPanel）。
- **零迁移、零 DDL 破坏、零新增配置项**（`scheme_defects.stale` 为幂等 `ALTER TABLE ADD COLUMN`，旧库自动补列默认 0；`force` 查询参数加法式缺省 False）。
- **契约零破坏**：
  - `force` 参数加法式（缺省 False）且置于 `db` 之后，既有位置参数调用（`(sid, body, db)` 等）逐字不变。
  - `ledger_summary` 新增 `stale` 键加法式（缺省 0），既有 total/passed/failed 语义与旧库返回体逐字一致。
  - `PartialOutlineHint.danger` / `buildPartialOutlineHint.hasContent` 均加法式可选形参（缺省 false），既有消费分支（4 处不传 hasContent）行为不变。
  - `DefectItem.stale` / `DefectSummary.stale` 可选（`stale?: number`），旧响应无该键时前端缺省处理。
- **行为变化披露**：
  - 锁定一级章后：移动/重排/删除 → 409「章节已锁定」；标题/正文编辑豁免；`force=true` 逃生门放行。

## 8. 教训归档

1. **`force` 等新增查询参数必须放 `db` 之后**（函数签名末尾）：初版放 `db` 前破坏 20 个既有位置参数测试，签名契约被击穿——加法式参数若与位置参数共存，必须追加在末尾，且加后立即跑既有测试簇验证。
2. **「缺省行为不变」的契约要在护栏里显式钉死**：`danger: hasContent || isErr` 初版让 error 事件也触发 danger，护栏首跑抓出「缺省 hasContent 时 danger 应为 false」的契约违背——新增可选字段的默认值语义必须用「缺省入参 → 断言默认输出」的行为实证锁住。
3. **ref 锁置位点要在「事件入口」而非「state 更新后」**：F12 防双击用 ref 在弹窗入口同步置位（state 异步更新拦不住同帧双击）——同帧双击族（FE-7/FE-8 先例）统一用 ref 同步锁。
4. **R210 收口纪律实证**：R226 §7 的「维持登记」不等于「不可修」——本轮逐条重新取证后 7 项落地（含 2 项经用户裁决），证实登记结论需在「产品语义 / 跨模块契约 / 改造面」三个维度重新评估后才可定夺。
5. **并行在飞归因**：前端整体 tsc 的 6 错误（exportR234.test.ts）与后端裸切 ratchet 失败均归因并行轮在飞改动，**不代修**（AGENTS.md 纪律）——验证结果须区分「本轮触碰集」与「并行轮归因集」。
