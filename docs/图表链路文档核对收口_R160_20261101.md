## 二、本轮修复（3 项，加法式、零迁移、零 DDL、零新增配置项）

### FIX-1 · 触发关键词映射表补全（13 词）
`app/services/ai/prompts/content.py` content_generation_system「触发关键词映射表」：
- **flowchart** += 审批流程、应急响应流程、拆除顺序、材料进场检验（文档一 §1.1）；
- **architecture** += 应急组织机构、应急救援体系、岗位职责、项目班子（文档二 §1.1）；
- **comparison** += 机械设备配置、材料需求、物资需求（文档三 §1.1 资源统计面——此前
  机械/材料类在触发面上**完全缺席**）；
- **labor** += 劳动力动态曲线（文档三）；**gantt** += 关键线路（文档四）；**layout** += 施工分区（文档四）。

语义隔离裁定：「应急响应」（流程属性）只入 flowchart、「应急组织」（层级属性）只入
architecture；机械/材料（数量对比）只入 comparison 不入 labor（工种人数矩阵）——
护栏行级归属锚锁定。补充词同时与 chart_validators 已删除死表（见 FIX-3）互相印证。

## 五、判据教训归档

1. **外部设计文档 ≠ 差距清单**：四份文档的标记格式（AI_Chart HTML 注释）、渲染方案
   （Playwright 单轨）、预编排均与本仓现实形态不同且更弱——按文档动手即重复建设，
   逐项核对后真实缺口只有触发词覆盖与图后呼应两处提示词缝隙 + 一处死代码卫生。
2. **autocrlf 环境的字节体检判据**：`git show` 是 LF blob、工作树是 CRLF 检出，
   CR 计数对比必然假红（本轮首版即假红两个「BAD」）；正确判据 = git diff numstat
   规模守卫（预期增删行数之外出现整文件重写即 BAD）+ 新文件 LF 约定。
3. **文档自相矛盾处是「不做」的最强依据**：流程文档说管理章节严禁配图、架构文档说
   同一批章节是架构图强触发——两文档无法同时成立，现有调和形态不动。
4. **死代码簇是文档型指令的重复建设诱饵**：「120+ 触发词」规格头的零消费死表
   （TRIGGER_KEYWORDS）正是文档一级触发主张最容易误接的第二事实源；删除前全仓
   grep 取证（app/tests/frontend/根级脚本）+ R38 D6 同构先例 + 行锚脚本删除。
5. **冒烟样例先过真实校验器再落测试**：本轮管线冒烟首版 2 节点样例被「≥3 节点 ≥2
   连线」校验拒绝（顺带实证文档一「节点数过少不生成」的实现比探查报告记载更严），
   探针先行可省一轮红。
