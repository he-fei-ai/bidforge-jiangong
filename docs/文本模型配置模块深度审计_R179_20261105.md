## 5. 修复项清单（改了什么 / 为什么 / 如何验证 / 测试结果）

### 5.1 BUG-1：保存链路 `enabled` 显式生效
- 改了什么：
  - 新增唯一解析出口 `coerce_enabled_flag`（`provider_factory.py:532`），兼容 `bool` / `"0"` / `"false"`；`None` 表示「本次不改动」。
  - `save_ai_config` 解析并校验（`provider_factory.py:764-766`）：
    - 显式 `enabled=false` 且 `is_active=true` → `ValueError`（路由层映射 400），不静默丢弃。
    - UPDATE 增加 `enabled=COALESCE(?, enabled)`（`provider_factory.py:794`、`821`）；未提供时保留原值。
    - INSERT 增加 `enabled` 列并使用 `COALESCE(?,1)`（`provider_factory.py:857`），未提供时保持「默认启用」旧行为。
- 为什么：R175 只在独立开关接口写 `enabled`，保存接口静默忽略该字段，违反接口契约并可能让调用方误以为已停用。
- 如何验证：`test_ai_config_r179_20261105.py::TestSaveEnabled` 6 例（新建停用、默认启用、更新不覆盖、更新显式停用、直接调用拒绝、路由层 400）。
- 测试结果：全部通过。

### 5.2 BUG-2：场景路由尊重 `enabled=0`
- 改了什么：`resolve_scene_config` 在取到目标配置后先判 `enabled`（`provider_factory.py:1663-1678`），为 0 时记 warning 并 `return None`，回落主配置/降级链。
- 为什么：R175 定义「停用 = 不再参与任何真实调用」，但场景路由绕过该闸门，属跨入口口径不一致的静默失效。
- 如何验证：`TestSceneRouteEnabled::test_disabled_route_target_falls_back_to_primary`、`test_enabled_route_target_still_applies`。
- 测试结果：通过；启用配置的正常路由行为零回归。

### 5.3 BUG-3：激活即启用
- 改了什么：`toggle_config` 的激活 UPDATE 增加 `enabled=1`（`config.py:347`）。
- 为什么：旧实现可把 `enabled=0` 的配置设为当前使用，产生「当前使用 + 已停用」矛盾；且 `set_config_enabled` 又会拒绝停用当前使用配置，形成死结。
- 如何验证：`TestToggleActivatesEnabled::test_toggle_disabled_config_enables_it`。
- 测试结果：通过。

### 5.4 BUG-4：导入/覆盖保真 `enabled`
- 改了什么：
  - `_classify_import_item` 新增 `enabled` 解析字段（`config.py:540`），缺省为 `None`。
  - 覆盖写库增加 `enabled=COALESCE(?, enabled)`（`config.py:681`）。
  - 新建写库增加 `enabled` 列 + `COALESCE(?,1)`（`config.py:722`）。
  - `set_first_active` 激活首条新配置时同步 `enabled=1`（`config.py:764`）。
  - 预演结果回显 `enabled`（`config.py:894`）。
- 为什么：导出已包含 `enabled`，导入却忽略，迁移即「静默启用」；预演不回显会让用户盲确认。
- 如何验证：`TestImportEnabledFidelity` 5 例（真实导入、旧文件缺键兼容、覆盖路径、预演回显、首条激活即启用）。
- 测试结果：通过。

### 5.5 BUG-5：回滚不得制造矛盾状态
- 改了什么：回滚在应用快照后计算最终激活态（`audit.py:260-265`）；若快照 `enabled=0` 而最终为当前使用，则强制保留 `enabled=1` 并在 `warning` 中说明。
- 为什么：旧快照早于「激活」操作时，可直接把当前使用配置改回停用。
- 如何验证：`TestRollbackAndRuntime::test_rollback_does_not_create_active_disabled`（构造「停用 → 激活 → 回滚」链）。
- 测试结果：通过，且 warning 文案被断言校验。

### 5.6 BUG-6：体检与运行时统计口径

  - 体检 SQL 增选 `enabled`（`connectivity.py:383`），条目新增 `enabled` / `disabled_by_user`（`435-436`），`usable` 纳入 `enabled`（`450`），summary 新增 `disabled_by_user`（`465`）。

- 为什么：停用配置被报「可用」与真实调用链不一致；有效厂商数把仅有停用配置的厂商算作有效。

### 5.7 GAP-1：场景路由保存时明确告警

## 11. 新增配置项默认行为与向后兼容性

- **未新增任何配置开关/默认值**；`enabled` 与 `disabled_by_user` 均为**加法式响应字段**，旧前端忽略未知字段不受影响。
- `save_ai_config`：未传 `enabled` → 保持原值（UPDATE）或默认启用（INSERT），与改动前行为一致；显式传 `enabled=false` 且目标为当前使用配置 → 400（新增的显式失败，替代旧的静默忽略）。
- 导入：文件不含 `enabled` 键 → 默认启用，旧导出文件完全兼容；含 `"false"` / `0` 等可识别值 → 停用；无法识别 → 视为未提供（不改动）。
- 回滚：仅当「快照将写入 enabled=0 且最终仍为当前使用」时才强制启用并告警；其余快照语义不变。
- `toggle_config`：激活一条原本停用的配置现在会同时启用它 —— 这是对「当前使用 + 停用」矛盾状态的修正，不改变正常启用配置的切换行为。
- 场景路由：仅当目标 `enabled=0` 时新增「跳过场景路由」行为；启用配置的路由零变化。
- 体检：`usable` 对 `enabled=0` 由 `true` 变为 `false`（口径修正）；`summary.usable` 数量相应下降，`summary.disabled_by_user` 为新增计数。
