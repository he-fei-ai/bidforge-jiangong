## 1. 目标与范围

### 1.1 目标

把附件方案中**本仓尚未具备**的 omp 能力，以「引擎层适配」形式补齐，使三环节（目录生成 / 正文生成 / 审核与修复）具备：

- 统一的引擎选择与降级（omp ↔ 主链路）；
- 可观测的运行指标与成本估算；
- 可续跑的断点状态与输入指纹缓存。

### 1.2 范围

**纳入**：引擎路由、诊断预检、任务存储（3 项骨架 + 护栏）。

**不纳入（登记不做）**：

- 真实 omp 二进制安装 / provider 授权（用户决策项，本机无 `omp`/`bun`）；
- `browser`/`computer`/`web_search`/`github`/`lsp`/`debug`/`security_scan`/`generate_image`/`tts`/`learn`/`manage_skill`（R234 已登记，需平台联动）；
- 阈值动态化 `selectEngineForMessages`（本仓用**字数预算**口径，与附件的**上下文窗口比率**口径不同，不强行对齐）；
- 把 omp 反向写回主链路判据（违反本仓「omp 面绝不反向改写主链路」边界）。

### 1.3 原则

| 原则 | 说明 |
|---|---|
| 业务层不变 | 既有 SSE 主链路 / 主链目录生成 / 正文生成 / 审核修复**一行不改** |
| 双引擎可回退 | omp 不可用或失败 → 主链路兜底，结果标注 `degraded` |
| 默认关闭 | 新能力经 `prefer` / `enabled` 缺省走主链路，结果与既有**逐字节一致** |
| 加法式 | 新增键只在 omp 被选中 / 降级时出现，不覆盖既有键 |
| 分层约束 | services 禁止 import routers；路由分流由 routers 层执行 |

## 4. 落盘方案

### 4.1 分层与文件

```
backend/app/services/ai/
├── omp_engine_router.py     # 新增：引擎路由 + 降级链（决策层，纯函数）
├── omp_diagnostics.py       # 新增：预检 + 指标 + 成本（只读）
├── omp_task_store.py        # 新增：任务状态 + 输入指纹缓存（文件 JSON）
├── omp_pipeline.py          # 既有：run_full_chain / stage_is_complete / build_export_contract
├── omp_workflow.py          # 既有：OmpBatchOrchestrator（plan→execute→verify→fix）
└── ompi/                    # 既有深度层：memory / advisor / fix / task_schema
```

**命名裁决**：新模块沿用 `omp_*`（引擎级集成层，与既有 `omp_rpc`/`omp_lease` 同族）；`ompi_*` 保留给深度能力层（memory/advisor/fix/schema）。若后续要严格遵循 R234 的 `ompi_*` 命名，可整体机械改名。

### 4.2 门控与灰度

| 层 | 机制 | 默认 |
|---|---|---|
| 引擎选择 | `select_engine(prefer=...)`：`auto`（缺省）/ `omp` / `main` + `overrides[task_type]` | `auto`；omp 不可用 → main |
| 任务级灰度 | `overrides={"outline": "omp"}` 只对特定任务类型启用 omp | 空（全走 auto） |
| 诊断 | `preflight()` 只读，不改变行为 | 恒可调用 |
| 存储 | `OmpTaskStore.save/load` 由调用方决定 | 不写即无副作用 |

> **灰度路径**：先在测试环境用 `prefer="omp"` 显式走 omp；再按任务类型逐个放开（`overrides`）；最后把 `auto` 的 omp 可用性探测打开。**每一步都可单独回退**。

### 4.3 测试

- 新护栏：`tests/test_omp_engine_layer_20261113.py`（**19 passed**）——路由规则 / 降级标注 / 加法式不覆盖 / 预检结论 / 禁用工具检出 / 指标汇总 / 成本估算 / 指纹稳定性 / 存储往返 / 损坏降级 / 产物缓存。
- 回归：既有 omp 簇 **140p**（`test_omp_workflow*` / `test_omp_consistency*` / `test_omp_outline_bridge*` / `test_outline_omp_seam*` / `test_omp_content_seam*` / `test_omp_provider*` / `test_omp_task_agent*` / `test_ompi_depth*`）**零回归**。
- 静态：ruff 全过；字节体检纯 CRLF / BOM=0 / FFFD=0。

### 4.4 回退

- **单点回退**：把 `prefer` 设为 `main` 或清空 `overrides` → 全走主链路，结果与既有逐字节一致（新增键不出现）。
- **整层回退**：3 个新模块均为**未接线**的独立文件，删除即回到当前状态（无导入方、无配置依赖）。
- **数据回退**：`OmpTaskStore` 落盘文件（缺省系统临时目录）可直接删除；主库零写入。

### 4.5 风险

| 风险 | 等级 | 对策 |
|---|---|---|
| 引擎路由误选 omp 拉低质量 | 中 | 缺省 `auto` 且 omp 不可用 → main；灰度按任务类型逐个放开 |
| 诊断预检与 `check_ready` 判据分叉 | 低 | 预检**复用** `check_ready` 单一事实源，不重复实现 |
| 任务存储脏文件 | 低 | 损坏静默降级为空（对齐 `MemoryBank`）；写失败不抛 |
| 成本估算误导 | 低 | 缺省单价 0 = 未知，`rate_known=False`，**不臆造** |
| 与并行会话撞名 | 低 | 新文件独立命名；未改既有模块 |

## 5. 关键代码骨架（已落盘）

### 5.1 `omp_engine_router.py` —— 引擎路由与降级链

**契约**：

```python
ENGINE_ORDER = ("omp", "main")
DEFAULT_PREFER = "auto"
SUPPORTED_TASK_TYPES = ("outline", "content", "audit", "full")

@dataclass(frozen=True)
class EngineChoice:
    engine: str = "main"        # "omp" | "main"
    degraded: bool = False      # True = 偏好 omp 但降级到 main
    reason: str = ""

def default_omp_available() -> bool: ...          # settings.omp_task_enabled + binary_exists
def select_engine(*, task_type, prefer="auto", omp_available=None, overrides=None) -> EngineChoice: ...
def annotate_result(result, choice) -> dict: ...  # 加法式，不覆盖既有键
```

**路由规则**：`main` 恒主链；`omp` 可用则 omp、否则降级 main（`degraded=True`）；`auto` 仅对受支持任务类型且 omp 可用才走 omp；`overrides[task_type]` 优先级最高。

### 5.2 `omp_diagnostics.py` —— 诊断预检与可观测

**契约**：

```python
FORBIDDEN_TOOLS = ("bash", "exec", "eval")

@dataclass(frozen=True)
class PreflightReport:
    ok: bool; checks: dict[str, bool]; problems: list[str]; snapshot: dict
    def to_dict(self) -> dict: ...

def environment_snapshot(*, binary="", model="", tools="", workspace_root="", enabled=None) -> dict: ...
def preflight(*, binary="", model="", tools="", workspace_root="", enabled=None) -> PreflightReport: ...
def collect_task_metrics(report) -> dict: ...     # tasks/completed/degraded/paused/attempts/fix_rounds/output_chars
def estimate_cost(*, input_chars, output_chars, input_per_1k=0.0, output_per_1k=0.0) -> dict: ...
```

**要点**：`preflight` 把 `OmpTaskAgent.check_ready` 的异常转成结构化 `checks`（不抛）；工具白名单检出 `bash/exec/eval`；成本缺省单价 0（`rate_known=False`）。

### 5.3 `omp_task_store.py` —— 任务存储与输入指纹缓存

**契约**：

```python
_FP_SEP = "\x1f"

def input_fingerprint(*parts) -> str: ...                       # sha256 前 16 位，字段分隔防歧义
def cache_key(*, scheme_id, stage, inputs="") -> str: ...

class OmpTaskStore:
    def __init__(self, path: str | None = None): ...
    def save(self, task_key, state) -> bool: ...                 # 记 updated_at
    def load(self, task_key) -> dict | None: ...
    def clear(self, task_key) -> bool: ...
    def is_resumable(self, task_key) -> bool: ...                # 排除 failed/abandoned/completed
    def cached_artifact(self, task_key) -> dict | None: ...      # 仅 completed 且产物非空
```

**要点**：纯 JSON 文件，线程锁；损坏静默降级；写失败不抛（对齐 `ompi_memory.MemoryBank`）。
