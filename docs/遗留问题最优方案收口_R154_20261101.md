3. **本会话 git stash 往返的行尾损害（自查自纠）**：取证惰性告警是否既有时执行了 `git stash`/`stash pop`——autocrlf=true 使 pop 把 ~37 个预 stash 为 LF 的工作区文件改写为 CRLF（stash 时 warning 列表即受损集）。全量首轮以 2 失败暴露：① r57 字节锚 `SchemeWorkbenchPage.tsx`（T_TOUCHED 纯 LF 契约）；② 我自身在 `sse_checkpoint` 的裸 `.rowcount`（R13 集中化扫描器，与 R152 F5 同款被拦——修走 `safe_rowcount` 唯一出口）。行尾按 **r57 T_TOUCHED 清单 + R152 F6 归一裁定**恢复 5 文件纯 LF（SchemeWorkbenchPage / content_format_contract / test_numbering_unification / ContentGenerationTab / UploadParseTab），内容零变化（孤立 CR/替换符全 0 复检）；其余被翻转文件无契约要求、自持 CRLF 留痕。**教训：多会话未提交仓库里 `git stash` 等于对全部工作区文件做一次 autocrlf 重写——取证优先用只读手段（wmic/python 单跑），禁用 stash。**
4. **「孤儿失败主动认领」的镜像面**：全量首轮 2 失败中 1 项（rowcount）是本轮自身引入、1 项（r57 字节锚）是本会话 stash 事故所致——两项都**不归因并行会话**（双向佐证：违反项 ∈ 本轮改动/操作集合）。归因纪律要双向使用：既不越界认领别人的，也不把自己的推给别人。

## 七、判据教训归档

1. **薄包装重构是「给大函数补 finally」的最小损伤路径**——重排 500 行缩进 vs 改名单行 + 20 行包装，后者 diff 可控、锚点可升级；重构后**必须回扫 `inspect.getsource(<原函数>)` 型源码锚**（r149 指令锚当场被抓）。
2. **「同族回扫」在实施前做（省一半工作）**——L-6 回扫发现正文 Agent 早已传 timeout ⇒ 缺陷只在目录侧；L-4 回扫发现两族 Agent 共用 `workspace_root_for` ⇒ 一次修复两处接线。
3. **无夹具依赖的测试触碰真实 app.db 会把退出挂住**（R138 教训⑦第三形态）——凡在测试里触 `update_progress`/审计类带副作用的注册表 API，要么带 db_conn 夹具要么打桩其 DB 写。
4. **F821 是作用域判断的免费验证器**——「finally 里引用的变量在不在本函数」不需要人肉核对，ruff 当场给答案；先跑 ruff 再跑测试省一轮困惑。
5. **「真机验收」类遗留的收口时机 = 依赖修复合入后的第一个窗口**——R129 修完 docx_math 当天即可 COM 复验，拖到 R154 才收口让「WPS 兼容未知」状态多挂了 9 轮。
