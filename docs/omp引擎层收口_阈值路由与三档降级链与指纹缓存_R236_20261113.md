## 0. 结论摘要（TL;DR）

1. **R235 遗留登记的 4 项「可落地」缺口本轮全部收口**：阈值动态化（§5.4）、
   三档降级链（§5.6，中间档 `local` 此前缺失）、输入指纹缓存（G-2，彼时
   `omp_task_store` **零消费点**）、诊断补面（§5.12 的 Session 快照与错误归一）。
2. **FIX-1 · 阈值路由**：新增 `omp_threshold.py`（纯函数、零依赖）——
   按「上下文窗口 × 任务比率（正文 0.7 / 一致性 0.85 / 编排 0.8）」判定
   `main`（≡ 附件的 chat）/ `omp` / `local`；**只做引擎层判定，不动主链字数判据**
   （主链按 `WORD_BUDGET_TIERS`，两套口径互不干扰）。
3. **FIX-2 · 三档降级链**：引擎路由的 `ENGINE_ORDER` 由 `("omp","main")` 补为
   `("omp","local","main")`；`prefer="omp"` 不可用时**先降级 local**、再兜底 main。
   ⚠️ `auto` **不**自动落 local（平台主链强于单次对话，auto 落 local 会掉质量）——
   默认行为**逐字节不变**。
4. **FIX-3 · 路径 B 的平台侧执行器**：新增 `omp_workflow.platform_executor` ——
   用**平台 AI 链**当「本地 LLM」跑同一套 plan→execute→verify→fix（不依赖 omp 进程）；
   本地档**没有文件工具语义** ⇒ CONTEXT/PLAN **内联进 prompt**；产物仍写回工作区，
   编排器的产物回收 / verify / fix 链路与真 omp 档**完全一致**。
5. **FIX-4 · 输入指纹缓存接线**：`OmpTaskStore` 此前**零消费点**；现接入编排器——
   命中且产物非空 ⇒ **零 AI 调用**直接复用（`phase="cache_hit"`），完成后回写状态与
   产物（断点续跑的状态前提）。`store=None`（缺省）⇒ 完全不做缓存，行为不变。
6. **FIX-5 · 诊断补面**：新增 `session_snapshot()`（二进制是否在位 / 模型 / 工具白名单 /
   超时 / 工作区隔离口径，**不含密钥**）与 `serialize_error()`（类型 / 消息 / 分类 /
   可行动建议，分类复用 `classify_error` 单一事实源），并挂到诊断端点。

## 2. 定罪明细

### 2.1 FIX-1 · 阈值路由（附件 §5.4）

**问题**：附件要求「prompt 超上下文阈值才切 Agent 文件模式」，本仓此前**没有**该判定；
R235 曾以「口径不同」登记不做 —— 但那是把**附件的上下文窗口比率**误当成要替换
**主链字数判据**。实际上两者回答的是**不同问题**（主链判「正文是否达标」，
阈值判「这次该不该走 Agent 档」），完全可以并存。

**落地**（`backend/app/services/ai/omp_threshold.py`，纯函数零依赖）：

```python
DEFAULT_THRESHOLD_RATIOS = {"content": 0.7, "audit": 0.85, "planning": 0.8,
                             "outline": 0.8, "default": 0.8}

get_agent_threshold(*, context_limit, task_type="", ratios=None) -> int
select_engine_for_messages(*, task_type="", context_chars=0, context_limit=0,
                           omp_available=True, local_available=True,
                           prefer="", ratios=None) -> dict
```

**判定顺序**：显式 `prefer` → 上下文窗口未知（`<=0` ⇒ 不臆造阈值，走 main）→
未超阈值（走 main）→ 超阈值（`omp` → `local` → `main` 兜底）。
**非法比率**（>1 / ≤0 / 非数）⇒ 回落 `default` 0.8。

**同源读取（避免双份副本）**：`content` 比率在调用方**未显式传入** `ratios` 时，读平台
配置 `agent_engine_context_threshold_ratio`（并行轮次 R237 的旋钮）⇒ **配置一份、
常量一份**的漂移在结构上不可能发生；配置缺失/非法 ⇒ 回落默认表 0.7；调用方显式传
`ratios` 时以传入值为准（测试与脚本可覆盖）。

### 2.2 FIX-2 · 三档降级链（附件 §5.6）

**问题**：`ENGINE_ORDER` 只有 `("omp","main")` 两档，**缺中间档**（本地编排原语）。

**落地**：
- `ENGINE_ORDER = ("omp", "local", "main")`（`main` ≡ 附件的 `chat`）；
- `select_engine(..., local_available: bool = True)`：
  - `prefer="local"` ⇒ 恒 local；
  - `prefer="omp"` 且 omp 不可用 ⇒ **先降级 local**（`degraded=True`），local 亦不可用
    ⇒ 兜底 main；
  - `prefer="auto"` ⇒ **行为不变**（omp 可用 ⇒ omp；否则 main）。⚠️ auto **不**自动落
    local：平台主链强于单次对话，auto 落 local 会掉产物质量。

### 2.3 FIX-3 · 路径 B 的平台侧执行器

**问题**：路径 B 此前只有「注入 `executor_fn`」这一**接口**，仓内没有「不依赖 omp 进程
也能跑」的**平台侧执行器** ⇒ 路径 B 无法在生产真正落地（CI/灰度/降级都缺执行体）。

**落地**（`omp_workflow.platform_executor`）：

- 输入：`(spec, prompt, workspace)`；输出：产物文本（并写回 `spec.output_file`）；
- **无文件工具语义** ⇒ `CONTEXT.md` / `PLAN.md` 内容**内联进 user 消息**（否则模型
  看不到上下文 —— 这是路径 B 与真 omp 的**语义差异**，必须在代码里显式补）；
- 角色 `system_prompt`（事实铁律 / 工作区红线）与自定义 override **叠加**（不被覆盖）；
- 产物写盘复用 `_write_file` ⇒ **路径守卫（越界拒绝）仍然生效**；
- 场景打标 `scene="omp_local_executor"`（已登记 `provider_factory.KNOWN_SCENES`，
  否则「场景模型路由」静默失效 —— AGENTS §4.5 铁律）。

### 2.4 FIX-4 · 输入指纹缓存接线（G-2 + §5.3）

**问题**：`omp_task_store.OmpTaskStore` 自落地起**零消费点**（服务层就绪 ≠ 功能可达，
本仓头号反模式）。

**落地**（`OmpBatchOrchestrator(store=..., scheme_id=...)`）：

- 缓存键 = `omp_task_store.cache_key(scheme_id, stage, inputs)`，其中 `inputs` 绑定
  「上下文摘要 + task_id + output_file + instruction」；
- 命中且产物非空 ⇒ **直接复用**（`phase="cache_hit"`、`attempts=0`）⇒ **零 AI 调用**；
- 执行前落 `status="running"`（断点续跑的状态前提），完成后落
  `status="completed"` + `artifact.payload`（失败/暂停落 `degraded`/`paused`）；
- `store=None`（缺省）⇒ **完全不做缓存**（行为与引入前逐字节一致）。

### 2.5 FIX-5 · 诊断补面（附件 §5.12）

**落地**（`omp_diagnostics`）：

- `session_snapshot()`：二进制是否真在位（`binary_exists` 实测）、模型、工具白名单、
  工作区根、RPC/任务超时、工作区保留口径、`workspace_isolated=True`（既有契约），
  **不含密钥**；
- `serialize_error(exc)`：类型 / 消息（截 500）/ 分类（**复用** `classify_error`
  单一事实源）/ **可行动建议**（限流 → 降并发；超时 → 提超时或缩小上下文；
  JSON → 查产物格式；工具 → 查工具与工作区；未知 → 看 backend.log）；
- 诊断端点 `GET /api/v1/omp/diagnostics` 增加 `session` 字段。

## 8. 教训归档

1. **「登记不做」的理由要经得起再问**：R235 以「口径不同（上下文窗口比率 vs 字数预算）」
   登记不做阈值路由 —— 但两个口径回答的是**不同问题**（达标 vs 走哪档引擎），
   **并存即可**。登记项的理由若只是「看起来不一样」，就该再核一次。
2. **「服务层就绪 ≠ 功能可达」**：本仓头号反模式，本轮再次命中 ——
   `OmpTaskStore` 自落地起**零消费点**，躺了整整一天没有任何测试能发现
   「没人用它」。**可达性**要单独造护栏（编排器接线 + 命中路径断言）。
3. **注入式接口 ≠ 可用实现**：路径 B 此前只有 `executor_fn` **接口**，仓内却没有
   「不依赖 omp 进程也能跑」的**执行体** ⇒ 路径 B 在生产不可用。接口齐了不等于
   路径通了。
4. **语义差异要显式补**：真 omp 有文件工具语义（自己 read CONTEXT/PLAN），路径 B 没有
   ⇒ **必须把交接文件内联进 prompt**，否则本地档「看不见上下文」却表面正常。
5. **降级链的中间档不能省**：两档链（omp→main）缺了「omp 挂了但仍想用 Agent 语义」的
   落点；补上 `local` 后，`prefer="omp"` 的降级不再是「直接掉到主链」。
6. **auto 不等于「自动挑最好的」**：auto 落 local 会掉产物质量 ⇒ auto 保持不变，
   local 档由**显式指定**或**阈值命中**进入（默认值兼容优先于「链更完整」）。
7. **场景打标是硬约束**：新增 AI 调用点若漏 `scene=`，「场景模型路由」会**静默失效**
   （配了也不生效）—— 本轮在写执行器时同步登记 `KNOWN_SCENES` 并加护栏。
8. **既有护栏红先问「锁意图还是锁实现」**：三档链落地后，并行轮次的两条「全等/具体落点」
   断言变红 —— 重锚为**相对顺序**与**降级语义**（意图保留、强度不减），优于删测试。
