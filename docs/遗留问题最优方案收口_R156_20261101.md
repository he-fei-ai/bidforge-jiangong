## 二、修复项

### FIX-1a（P2）· L-7 后果面：正文终态落库 0 行守卫（幽灵成功 → 显式失败）

**位置**：`sse_handlers.py` `_persist_content_once`（正文生成 UPDATE + commit 唯一终态写点，retry_db_op 包装内）。

**修法**：`await db.execute(...)` 后走 `safe_rowcount` 唯一出口（R13 纪律：aiosqlite execute 可能返回 None；R72 纪律：影响行数有语义必须校验）；`_n < 1` 抛领域异常 `RuntimeError("章节已不存在（生成期间可能被删除），正文未落库")`（SSE 上下文不可用 HTTPException）→ gen_one except 判该章失败、checkpoint 如实记失败、done_ids 不收录。

**语义**：0 行 = 章节在生成期间被删（409 守卫前置判定的 TOCTOU 残窗 / 外部脚本直改库）。旧行为：静默假成功 + checkpoint 污染 + 断线重挂永久跳章；新行为：该章显式失败、可重生成。retry_db_op 仅重试 `is_retryable_db_error`（sqlite3.OperationalError），RuntimeError 立即穿透不重试——确定性失败不烧预算。

### FIX-1b（P3）· 同族回扫：charts.py 两处正文回写补行数面

- `fix-mermaid` 写回（charts.py:612 区）：既有 R13 判空 + 新增 `safe_rowcount < 1 → RuntimeError`（外层既有 rollback 收口，响应 `content_updated=false` 如实）；
- `generate-ai-image` 回写（charts.py:779 区）：既有 R13 判空 + 新增 `safe_rowcount < 1 → HTTPException 503`（与既有 None 守卫同文案族：「配图已生成但正文回写失败（章节已不存在）」）。

## 六、判据教训归档

1. **「留痕维持」判定的前提要用当前代码重验，且要区分「判定本体」与「判定后果」**——L-7 的结构性收口确实该单独立项，但其**后果面**（幽灵成功）用既有 R13/R72 纪律即可收口；R149 只判了「结构性」就整项搁置，漏了便宜面。
2. **「同族修一处漏一处」第四次命中**——R149 FIX-D 给目录保存侧补了 safe_rowcount 期望行数守卫，正文终态写（sse_handlers）与图表回写（charts）两处同族漏网；同族回扫应在修复轮内做完（本轮即为补课轮）。
3. **死字段要区分「垃圾」与「未完成移植」**——D6 字段带设计意图注释 + 9 处真实内容填充 + 0 消费：删除（R152 F2 先例）只适用于无意图注释的死形参；本例最优解是接线立项而非删除。
4. **轮次编号避让的时机**——开局核查空闲不等于全程空闲（R153 教训⑤再验证）；本轮盘点耗时较长，收尾写产物前重查 AGENTS.md 顶部才撞见 R155-O 占号，产物尚未外发即改号，损失为零；**建第一个产物文件前必须重查一次**。
5. **行尾归一在 E2E 验证脚本里也会漏**（R137 教训⑨第 N 次命中）——本轮给 3 个夹具补 rowcount 的首版脚本没按 CRLF 归一锚点，`count==0` 静默 SKIP（`str.replace` 无匹配无声 no-op 的孪生形态）；**替换类脚本必须「命中数≠1 即中止」**，本次靠 SKIP 打印才暴露。
