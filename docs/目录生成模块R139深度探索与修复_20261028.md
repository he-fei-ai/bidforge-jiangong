## 4. 修复项清单（本轮落地）

### 4.1 BUG-C1（P2 · stage_runner 异步观测回调被静默丢弃）
- **位置**：`app/services/agent/stage_runner.py:310-368`（`emit_activity`/`emit_event`/`record_retry`）+ 6 处调用点（:403/:424/:455/:473/:510/:518）。
- **根因**：`run_stage` 的 `on_activity`/`on_event` 类型为 `Callable[[dict], Any]`（允许异步）；旧实现 `emit_event` 直接 `on_event(event)` **不 await** —— 调用方传 `async def` 时返回的协程**永远不执行**：① `RuntimeWarning: coroutine ... was never awaited`；② 观测事件（touchActivity/emitMonitorEvent 同族）**静默丢失**，测试/宿主收不到任何活动回调。实测基线：`test_技术评分单链_六阶段端到端` 抛该警告；`outline_agent_event_stream` 生产侧 `_emit_event` 是同步（未触发），故属**潜在缺陷前置修复**（一旦生产接线 async 回调即触发）。
- **修法**：`emit_activity`/`emit_event` 改为 `async def`，内部统一 `await _maybe_await(on_*(event))`（与 run_stage 既有 `build_retry_prompt`/`continue_task` 同一出口）；`record_retry` 改 `async def`；6 处调用点全部 `await`。同步回调（生产默认 `_emit_event`/`_emit_activity` 形态）经 `_maybe_await` 逐字不变（`inspect.isawaitable(None)` 为 False，不 await）。
- **护栏**：`test_async_on_event_and_on_activity_are_awaited`（async 回调，断言 events/activities 完整收到）+ `test_sync_callbacks_unchanged`（同步回调逐字不变，与既有 `test_观测回调_收到_retry_与_阶段流转事件` 同构）。
- **A/B**：M1 回退 `on_event(event)` 不 await → 护栏 **CAUGHT**。

### 4.2 BUG-B（P1 · 断线路径 partial 缺键）
- **位置**：`app/routers/sse_checkpoint.py:172-190`（`_checkpoint_partial_outline`）。
- **根因**：`_checkpoint_partial_outline` 是**客户端断开**（GeneratorExit → finally 兜底）的**唯一**收尾出口，旧实现只写 `{event,task_id,outline}`（+可选 failed_*），**从不写 `partial=True`**；而显式停止路径 `_finish_stopped_with_partial`（sse_handlers.py:2278）恒写 `partial=True`。断线重挂接时 `_attach_checkpoint_result`（:9441）按 `_CHECKPOINT_KINDS` 白名单（含 `partial`）回传，缺失时前端 `buildPartialOutlineHint`（SchemeWorkbenchPage.tsx:1609）拿到 undefined ⇒ 把「用户断开时只生成了一部分」当成「完整目录」展示，用户可能把半份目录当完整保存（**R89 S3 注释「同口径带 partial」的承诺就此落空**）。
- **修法**：本函数语义即「部分成果」，到达写库时 outline 或 failed_chapters 必非空（空则早退不写），**恒置 `payload["partial"] = True`**，与 `_finish_stopped_with_partial` 同口径、不再分叉。
- **护栏**：`test_disconnect_path_writes_partial_flag` / `test_disconnect_path_failed_chapters_only_also_partial` / `test_disconnect_path_no_data_writes_nothing` / `test_reattach_roundtrip_keeps_partial_flag`（端到端：写 → 读回 → `_attach_checkpoint_result` 白名单回传，`partial` 必须存活）。
- **A/B**：M2 移除 `partial=True` → 护栏 **CAUGHT**。

## 10. 判据教训归档（本轮）

① **「同一语义两条路径必然漂移」再次验证**——`_finish_stopped_with_partial`（停止）与 `_checkpoint_partial_outline`（断线）都是「带部分成果落 checkpoint」，前者写 `partial=True`、后者不写，BUG-B 正是分叉产物；凡两条路径共享一个契约，护栏必须锁「契约字段在两条路径都存在」。② **「异步回调不 await = 协程泄漏 + 静默丢失」是双症状**——运行时只看到 RuntimeWarning（测试可过），事件丢失却无感；凡回调类型标注为 `Callable[[...], Any]`，实现必须统一走 `_maybe_await` 或显式拒异步。③ **「计算了但从未存储」必须拆开取证**——发现 A 的 `checkpoint_failed` 看似「计算后未存储 + 白名单漏键」双重缺陷，但逐条推演发现：该键仅在写入失败时置位，写入失败⇒无可重挂成果⇒白名单缺键无影响；`status=degraded` 已单独持久化。**判据是「键在何时置位 + 失败时是否还有可重挂的东西」**，而不是「键是否进白名单」。④ **变异会改变缺陷的「表现形态」**——M1 把「不 await」改回后，缺陷从「警告」变成「测试断言失败」，两者都是 CAUGHT；A/B target 必须断行为锁（events 列表内容），不能只断「不抛异常」。
