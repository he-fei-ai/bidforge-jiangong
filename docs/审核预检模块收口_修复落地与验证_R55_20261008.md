# 审核与预检模块收口 · 修复落地与验证（R55 · 2026-10-08）

## 1. 任务计划与执行路径

按七步执行：①功能清单/依赖/风险盘点 → ②架构与现状分析 → ③缺口与技术债识别 →
④增强（补齐缺口 / 组件级交互测试 / 跨模块接线）→ ⑤缺陷修复 → ⑥逐项基线对比 +
端到端验证 → ⑦本报告。全程零新增依赖、零数据迁移、**零新增配置项**，返回契约
全为加法式。

## 2. 模块现状（架构结论，均有代码依据）

- **三层审核**：确定性规则引擎 `services/preflight_engine.py`（CMP/STD/SAF/CON/TRC/DLV

  ＋ 就绪度聚合 `routers/compliance.py::_readiness_overview_compute`（六维加权

- **自动修复双链路**：单条 `/plan→/apply→/rollback`；批量
  `/collect→/stage→/confirm`（`routers/review_autofix.py` +
  `services/review_autofix.py`）。能力表 `_CAPABILITY` 为唯一事实源。

### 7.2 F6（原 §6.6 实证升级）· api/index.ts 两条 SSE 语句被展开成裸 CR/LF
- R55 只把「文本编辑工具会展开转义字面量」记成**工具教训**；本轮字节体检发现它
  **已经落在文件里**：`parseSseEventBlock` 的
  `block.replace(/\r\n/g, "\n").replace(/\r/g, "\n").split("\n")` 与
  `const separator = /\r\n\r\n|\n\n|\r\r/;` 里的转义成了**裸 CR/LF 字节**
  （工作树 CR=6、其中 3 处孤立 CR；HEAD blob 为 0）。
  JS 正则字面量内不允许出现行终止符 → **SyntaxError**，`api` 模块整体编译不过，
  SSE 正文进度流全断。属 P0 级（虽未上线，但下次前端构建必炸）。
- 为什么 R55 没抓到：本机无 Node，`tsc --noEmit`/vitest 一条都没跑；而护栏锁的是
  「符号在位」—— 符号在位与「字面量是否被展开」**正交**，纯静态 parity 锁的盲区。
- 修复：按 HEAD 的**转义文本**形态逐字节还原两条语句（锚点 count==1、还原后
  全文 CR 字节必须为 0 才写盘）。现 `api/index.ts` CR=0 / 71904 字节。
- 加固：新增 `TestFrontendByteIntegrity` 4 例 —— ① 6 个被改动前端文件无孤立 CR、
  无 NUL/BEL/FF、无 U+FFFD；② 两条 SSE 语句的**转义文本**各在位 1 次且 api 全文
  CR=0；③ 收尾行必须像收尾行（截断形态）；④ 新增 describe 各 1 次 + 用例总量
  不缩水（`it(` ≥ 20/30、`expect(` ≥ 80）。

- ⚠️ A/B 顺带测出一条**判据边界**（已写进护栏 docstring 防后人「去重」）：

增量，**没有整文件重写**。→ 刻意不做「统一行尾」改动（纯 churn）。唯一有意义
