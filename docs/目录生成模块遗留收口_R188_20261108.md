## 五、L6 逐章断点续跑 · 最优方案（分阶段，本轮不落地）

**现状证据**：`checkpoint_schema.py:46` 白名单只有 `event/partial/outline/review/failed_chapters/failed_count/auto_confirm`；`sse_checkpoint.py:179`、`_sse_outline_review.py:189-195`、`sse_handlers.py:2251` 三处 payload 均无「已完成章节集合」；前端 `useOutlineGeneration.tsx:367-479` 三个终态分支都只回填 + 保存，再点生成 `sse_handlers.py:1923` 窗口循环从 0 起全量重跑。

**分阶段方案**：
1. **阶段一（可低风险先做）**：checkpoint payload 加法式写 `done_indexes`（一级章**序号索引**，不用标题作键——`sanitize_outline_title` 会剥离不可见字符且可能重名），同步 `checkpoint_schema.py` 白名单 + `CHECKPOINT_FIELD_TYPES` + `tools/generate_checkpoint_schema.py` 生成 TS；前端 stopped/failed 分支据 `done_indexes.length` 提示「已完成 N 章，仅 M 章需补生成」。零状态机变化。
2. **阶段二**：后端 `sse_handlers.py:1923` 窗口循环起点按 `done_indexes` 过滤，跳过已完成章；必须配套 `resume` 的新 SSE 参数与幂等写（重复保存走 `saveOutline` 整表替换，天然幂等但会清正文，提示文案必须保留）。
3. **阶段三**：前端「继续生成」按钮 + 后端 resume 契约 + E2E 竞态复现（取消风暴、多标签页）。

**为何本轮不落地**：阶段二/三改动涉及 SSE 契约、checkpoint 白名单 parity（R77/R66 护栏）、前端三分支状态机与配额计费语义，需要独立轮次的 A/B 与生产灰度；用棘轮把「当前不续跑」的待决策态固化，比塞进本轮更安全。
