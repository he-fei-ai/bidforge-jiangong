## 1. 第一优先 · 敏感信息外发

### 1.1 脱敏接线补齐（BUG-1）

**改了什么**

新增 `backend/app/services/prompt_material_guard.py`，把「围栏 → 脱敏 → 预算」收敛为唯一公共入口：

| 函数 | 作用 |
|---|---|
| `redaction_enabled()` / `injection_defense_enabled()` / `context_budget()` | 三个开关的唯一判断源（禁止各链路自行 `getattr`） |
| `govern_text(text, labels=…)` | 分段资料：围栏 → 脱敏 → 预算 |
| `govern_blob(text, label)` | 单块资料：整段围栏 → 脱敏 → 预算 |
| `redact_outbound_messages(messages)` | **出站单点兜底**：只对 `role=user` 脱敏，返回原对象（开关关闭时） |
| `_repair_closing_fence()` | 预算截断丢失围栏闭合标记时补回 |
| `log_governance_posture_once()` | 启动期一次性打印治理姿态；未开启脱敏时 WARNING |

接线点：

| 链路 | 文件:函数 | 注入字段 |
|---|---|---|
| 正文生成 / 目录审核 | `routers/_sse_outline_review.py::_guard_external_material` → `govern_text(budget=False)` | 各分段外部资料 |
| 事实提取 | `services/facts_extractor.py`（原 `guard_material` 分支）→ `govern_blob` | `material` |
| 投标分析 | `services/bid_analysis_service.py::build_item` → `govern_blob` | `__CONTEXT__` 项目资料 |
| 招标分段提取 | `services/bid_section_extraction.py::build_extract_messages` | 招标文件分段原文 |
| 招标分段合并 | `services/bid_section_extraction.py::build_merge_messages` | 分段识别结果 JSON |
| 上传目录识别 | `routers/upload_outline.py`（`raw_text[:6000]` 前） | 上传文档正文 |
| **其余全部链路**（一致性审计 / 合规预检 / 导出 / 目录主生成…） | `services/ai/provider_factory.py::chat_with_fallback` → `redact_outbound_messages` | 任意 `role=user` 消息 |

**为什么**

* 逐点接线会漏（一致性审计、合规预检、目录主生成等文件本轮禁改或为他人占用）；
* 出站单点收口保证「任何发往外部 AI 的用户资料原文」都过同一判据，且**只改出站副本、不回写库内原文**（用户上传文档保持完整）；
* 采用出站兜底 + 链路线下围栏/预算，两侧互不冲突：围栏在文内、脱敏幂等（已替换的不再匹配）。

**如何验证**

`tests/test_prompt_material_guard_r175.py::test_redaction_disabled_keeps_text_bytewise`（关闭=逐字节相同）、
`test_redaction_enabled_masks_credentials_but_keeps_numbers_and_units`（`sk-`/URL 口令消失，`JGJ 120-2012`/`10.5m`/`320 万元`/`180 日历天`/人名保留）、
`test_build_item_chain_redacts_project_material`、`test_bid_section_extraction_chain_redacts_tender_text`、
`test_redact_outbound_messages_covers_user_role_only`。

**测试结果**：14/14 通过。

**脱敏判据补强**：`prompt_governance.py::_SENSITIVE_PATTERNS` 新增「数据库/消息队列连接串」形态
（`postgres://user:pass@host`、`redis://:pass@host` 等）。实测原清单只覆盖 `http(s)`，
`postgres://admin:P@ssw0rd@host` 会漏脱敏 —— 上传资料里常见此类配置截图文本。

### 1.2 脱敏接线覆盖表

|---|---|---|---|

| 合规预检 / 审核修复 | 章节正文 | **出站兜底** | 同上 |

| 目录主生成（`_sse_outline_build.py`） | 章节/资料 | **出站兜底**（禁改文件） | 同上 |

### 1.3 默认值处理（行为变更声明）

**未改变任何默认值**：`PROMPT_REDACT_SENSITIVE=false`、`PROMPT_INJECTION_DEFENSE=false`、`PROMPT_CONTEXT_BUDGET=0`。
默认状态下所有链路输出**逐字节**与修复前一致（`test_govern_blob_disabled_is_identity` 断言）。

**唯一「藕合」保留**：`redaction_enabled() = prompt_redact_sensitive OR prompt_injection_defense`。
理由：修复前「注入防护开启即顺带脱敏」，若改成纯独立开关，已有用户会**静默失去**既有脱敏（回归）。
该判定被 `tests/test_prompt_module_regression_20260925.py::test_on_redacts_credentials_but_keeps_standards` 锁定。

**风险提示（不开启时显式告知）**
* 启动日志：`log_governance_posture_once()` 打 WARNING「脱敏未开启…原文会原样发往外部 AI」；
* 诊断接口：`GET /system/governance/posture` → `redaction_notice` 非空；
* 配置说明：`.env.example` 已写清风险与回退方式。

### 1.4 治理开关持久化（BUG-2）

**改了什么**：`routers/system.py`

| 端点 | 变化 |
|---|---|
| `GET /system/governance` | 以库为准（`load_governance_settings`），回填 `settings`；返回**仍为原 2 字段**（不破坏前端 parity） |
| `PUT /system/governance` | 2 字段各自 `save_runtime_setting(...)` 落库（`ai_runtime_settings`）+ 更新内存；字段改为 `Optional`（省略 = 保持当前值） |
| `PUT /system/governance/redaction`（新增） | `{enabled: bool}` 落库并更新内存 |
| `GET /system/governance/posture`（新增） | 诊断：脱敏状态 / 风险提示 / `persisted` |
| `load_governance_settings()` | 启动回放（`main.py` lifespan 调用），单键失败仅告警 |

**为什么**：旧实现只写内存，重启静默回默认 —— 用户以为「已开启防护」实则已关闭（安全假安全感）。
复用既有运行时设置表，避免新建表 / 迁移。

**为什么新增独立脱敏端点**：`test_governance_field_parity_20261011` 双向锁死「后端 Pydantic 模型字段 == 前端接口字段」，前端本轮禁改；把新字段塞进 `GovernanceSettings` 会直接打破护栏。独立端点既满足运行时开关需求，又保持既有契约。

**如何验证**：`test_governance_persists_across_restart`（PUT → 清空内存模拟重启 → GET 仍读到库值）、
`test_governance_partial_put_keeps_other_flags`（只传一个字段不重置另一个）。

**测试结果**：通过；`test_governance_field_parity_20261011` 4/4 通过。

**行为变更**：
1. 治理开关现在**重启后仍生效**（旧：重启即失效）。这是修复目标，显著变更。
2. `PUT /governance` 省略字段 = **保持当前值**（旧：省略 = 重置为 0/False）。如需旧语义请显式传值。
3. **回退方式**：删除 `ai_runtime_settings` 中 `prompt_context_budget` / `prompt_injection_defense` / `prompt_redact_sensitive` 三行，即回到 `.env` 默认；不影响任何业务数据。

## 2. 第二优先 · 治理覆盖面

### 2.1 六链路统一治理（P2-3）

**改了什么**：见 §1.2 前 7 行，全部改为走 `prompt_material_guard`（services 层唯一公共函数）。

**截断优先级**（`prompt_governance.CONTEXT_PRIORITY`，由 `apply_context_budget` 水填）：全局事实(P0) > 章节定位(P1) > 资料摘要(P2) > 知识库(P3)；P0 段有 `min_ratio=0.2` 保底，不会被整段清空。单块资料（`govern_blob`）无标签时按整体预算截断，尾部截断后自动补回围栏闭合标记。

**测试结果**：预算关闭时恒等（`test_govern_blob_disabled_is_identity`）；既有预算测试（`test_prompt_limits_sink_20261006` 等）全绿。

### 2.2 硬编码提示词收编（BUG-3）

| 原位置 | 新注册 key | 调用方 |
|---|---|---|
| `routers/bid_analysis.py:193` `SEGMENT_MERGE_PROMPT` | `bid_segment_merge_system` | `segment_merge_prompt()`（调用时取） |

## 3. 第三优先 · 模板治理与一致性

### 3.1 JSON 修复族（P3-5）— 部分完成

**已做**：`services/ai/json_response.py` 删除已漂移的内联 `JSON_REPAIR_PROMPT`。
渲染异常时改为**用注册表通用模板**（`json_schema_fix_system`）做朴素占位符替换，全仓只保留一份正文；注册表缺失才抛 `ValueError`。

**未做（保留 3 份注册模板）及原因**：`outline_json_fix_system` / `facts_json_fix_system` / `json_schema_fix_system`
各自编码**不同的目标 schema 与修复约束**（目录树结构 vs 事实表结构 vs 通用 JSON）。强行合并为一份会增加通用提示词长度、
削弱针对性约束，属行为变更且缺少回归保护，风险高于收益。已保留单一**兜底**来源（消除第二事实源），
三份正文仍在编辑器可见、契约可校验。

### 3.2 注释与实现矛盾（BUG-4）

| 位置 | 修正 |
|---|---|
| `schema_sql.py` `prompt_audit_logs` 表注释 | 原文称「不复制完整提示词正文」，实际 `audit_service` 存 before/after 全文快照（供回滚）。**以实现为准改注释**，并标注合规审阅口径；未改实现 —— 回滚能力依赖全文快照，删掉才是功能倒退。 |
| `json_response.py` 内联兜底注释 | 原称「正常链路消费 outline_json_fix_system」，实际 R38 后默认 `json_schema_fix_system`。随内联兜底整体删除。 |

### 3.3 变量契约增强（P3-7）

4 条新模板均声明 `requires`：`bid_segment_merge_system` → `["TASK_LABEL","TASK_PROMPT","SEGMENTS"]`；其余 3 条 → `[]`（显式"不接受任何外部插值"）。
契约表 `PROMPT_VARIABLE_CONTRACTS` 同步登记 4 条。今后若给静态模板加占位符而漏登记，
启动期 `check_prompt_variables` 报 `used_not_declared`（可配 `PROMPT_STRICT_VARIABLES` 阻断启动），
而不是运行期静默空串。

**测试结果**：`test_missing_variable_template_is_detected` 通过。

## 4. 遗留项

### 4.1 `<<FUZZY_FILL>>` 对 DB 定制不生效（V1）— 确认为缺陷，已修

**证据**：`prompts/content.py::_wrap_fuzzy_fill` 仅在 `_reg` 注册期调用；`get_prompt` 读到 DB 定制内容后直接返回（`_cache.get_prompt`），标记原样下发模型。

**测试**：`test_db_customized_marker_is_expanded_on_read` 通过（标记消失且规则段确有内容）。
