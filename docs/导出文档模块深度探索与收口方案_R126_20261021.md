### 1.2 探针实测（本轮取证，`artifacts/r126/probe_math_converters.py`）

- `\sqrt[3]{x}` ⇒ `<m:rad><m:e>[3]</m:e></m:rad>` + 游离 `x`：
  **被开方数跑根号外、m:e 内容错位**（比 R122 留痕的"度数未进 m:deg"更重——结构错误）；
  根因：`_TOKEN_RE` 的 brace 类只含 `{}`（docx_math.py L396 附近），`[` 落 `char` 分支 ⇒
  `_parse_optional_bracket`（L583）成为**死代码**（判据 `tokens[i]==("brace","[")` 永不成立）。
- `\sum_{i=1}^{n} x_i` ⇒ body 渲染为 `x`+`i` 两个平排 run：`_parse_seq` 遇 `_` 只产
  `script_marker` 占位（L484–487），而 `_node_to_omml` 对 `script_marker` **无分支 ⇒ return ""**（L758）⇒
  **上下标内容被静默丢弃**（R122 §六已知局限②实证仍在，且非仅"拍平"——`_` 标记后的内容 run 还在、
  语义已错乱）。同类丢失存在于一切"组内带脚本"写法（`\frac{x_i}{y_j}` 等，`_parse_required_group`
  直接 `_parse_seq` 不跑 `_attach_scripts`）。
- ~~本机 COM 注册探测保留作下线背景~~：本机 `Word.Application`/`KWPS.Application`/`KET.Application` 均注册、PATH 无 libreoffice——原 A 项拟为 PDF 链补 WPS 策略；用户指令改为**整体删除 PDF 链**，该取证转入下线影响面盘点（不再需要转换策略代码）。
