**结论（"是否会因文件本身打不开"）**

- 正常路径（无悬挂运算符公式、封面/页眉无控制字符）**未发现确定性导致 Word/WPS 拒开的 XML 缺陷**：ZIP 完整性 `testzip=None`（实测），无手写 `numId`/`styleId`，无 SVG/EMF，无 ContentTypes 缺项，落盘时序正确。
- 唯一"产物级"高风险是 **D1**：`m:boxPr` 含 schema 不允许的 `m:alignment`/`m:border`。LXML 不校验 schema（所以本仓测试全绿），但 Word 打开时会按 OMML schema 校验，典型表现为"发现不可读内容，是否修复？"并丢弃该公式；WPS 可能直接拒绝该公式（个别版本会拒开整份文档，**待实测**）。
- 其余高风险都是 **B 类（拿不到完整文件）**：D2 直接 500、D6 并发删除导致 404/中断、D7 磁盘损坏。
- D16/D18 属 **C 类**：文档能打开但内容缺失，且会被缓存固化。

## 3. 原子替换与并发分析

### 3.1 写入 → 改名 → 交付时序（已核实）

| 阶段 | 位置 | 说明 |
|---|---|---|
| 唯一临时名 | `export.py:4161` | `f"{scheme}_{cfg8}_{content8}.{uuid4().hex}.tmp.docx"`，并发互不覆盖 |
| 在飞登记 | `export.py:4155-4156` | 保护 `replace → INSERT → commit → GC` 窗口，防止跨配置并发导出被误判孤儿 |
| 落盘 | `export.py:2769-2770` | 先 `_normalize_docx_strict_sequence(doc)` 再 `doc.save(tmp)` |
| 原子替换 | `export.py:4188-4194` | `os.replace` 最多 3 次、退避 0.3/0.6/0.9s，仅捕 `PermissionError` |
| 降级 | `export.py:4195-4209` | 3 次失败 → `out_path = tmp_out_path`、`cacheable = False`，**不写缓存行**（避免 `result_path` 永久指向 `.tmp`） |
| 异常清理 | `export.py:4167-4182` | 取消 / 普通异常都 `unlink(missing_ok=True)` + 注销在飞 |
| 缓存写入 | `export.py:4245-4250` → `3850-3910` | `INSERT OR IGNORE → commit → prune → commit`（双提交） |
| 交付 | `export.py:4270-4274`（未命中）/ `4137-4141`（命中） | `FileResponse` **懒加载**，handler 返回后才打开文件 |
| 终局 | `export.py:4228-4234`、`4266-4269` | 留痕 → GC（protect 本次产物）→ 注销 |

### 3.2 结论与缺陷

1. **无"半成品被改名"路径**：`doc.save` 完成才 replace；异常/取消会删 tmp。单测 `test_export_atomicity_r1_20261005.py`（11 passed）覆盖。
2. **同名并发**：`out_path` 由 `config_hash + content_hash` 决定，同内容必同路径；同配置并发由进程内锁 `export.py:4102`（键 `("docx", scheme_id, config_hash)`）串行化，不同配置走不同路径，`os.replace` 原子。**正确**。
3. **锁表有界淘汰的代价**：`export.py:3966-3967` 到 512 项时 `clear()`，可能让两个同键请求各持一把锁 → 去重失效（各自构建）。注释已声明"不影响正确性"（唯一约束 + 原子替换仍在），属可接受降级，但**成本会翻倍**（AI 生图计费）。
4. **进程内保护不跨进程**：`_EXPORT_INFLIGHT_PATHS`（`export.py:3808`）与 `_EXPORT_BUILD_LOCKS`（`3781`）都是进程内。若将来 uvicorn 多 worker / 多实例共享 `EXPORTS_DIR`＋同一 SQLite：GC 与 prune 的保护全部失效，**可能互删对方产物**。当前部署单进程则无此问题（**待验证部署形态**）。
5. **`_prune_export_cache` 缺失"正在读取"保护（BUG-6）**：
   - `_export_cache.py:299-302` 只保留"当前 protect + top-5 可用行"；
   - `311-321` 对 `stale_ids` 直接 `unlink`，**不查在飞集合**；
   - 而命中响应用 `FileResponse(cached[0])` **懒加载**（`export.py:4137-4141`），handler 返回时文件还没被读；
   - 触发链：方案缓存 > 5 行 → 请求 A 命中较老行（返回中）→ 请求 B 完成导出并 persist → `_prune_and_commit`（`export.py:3881-3883`）删除该行与其文件 → A 流式读取时文件已消失 → 用户拿到 404/传输中断/0 字节。**该路径当前成立**。
   - 对比：`_gc_orphan_exports` 已用 `live + protected + inflight + .tmp TTL` 三重收窄（`_export_cache.py:391-416`），prune 未对齐，属**判据分叉**。
6. **`.tmp` 残留回收**：`_ORPHAN_TMP_TTL_SECONDS = 600`（`_export_cache.py:333`），GC 对 `.tmp` 宽限 600s 后清理（`414-416`）；正常落盘成功的 tmp 已被 replace，不存在；降级返回的 tmp 在 600s 内不会被删（覆盖 `FileResponse` 懒读窗口）。**成立**，但若大文件弱网下载 > 600s 仍可能被 GC 删除（极端，**待验证**）。
7. **取消后的残留**：取消分支 `4171-4173` 删 tmp；但**已经在跑的 `asyncio.to_thread(_build_docx_sync)` 无法真正打断**，线程会跑完并写 tmp（下次 GC 兜底）。属资源浪费，不留坏产物。

## 7. 缺口清单

1. **导出后读回校验缺失**：落盘后没有 `zipfile`/OPC/`document.xml` 结构自检，也没有 OMML schema 校验；`_cache_row_viable` 亦只查大小。（`export.py:2769-2783`、`_export_cache.py:258-275`）
2. **无真实导出进度**：后端无 SSE/轮询进度；前端百分比是估算（`SchemeWorkbenchPage.tsx:4875-4898`）。
3. **多进程部署无保护**：进程内锁/在飞集合不跨 worker（`export.py:3781/3808`）。
4. **PDF 转换无取消**：`_convert_docx_to_pdf`（`4292`）为同步 COM/LibreOffice 调用，取消点只在段边界。
5. **`docx_repair` 为空目录**：`backend/app/services/docx_repair/` 无实现（R168 声称"合并"未落地，抽查证实为空）。
6. **`export_audit.py` 疑似死代码**：与生产版本号不一致（22 vs `_EXPORTER_VERSION="23"`，`export.py:359`），仍有测试锚定它（**建议清理，待复核**）。
7. **`/export/docx/v2` 不存在**：路由表 `402/428/445/515/1014/1030/1049/1074/1090/4064/4077/4445/4654`，无 v2；R173/项目记忆中的 v2 口径已过期。
8. **前端渲染轨无字节校验**：`export.py:2850-2856` 只验 dataURL 前缀。
9. **全局事实失败无阻断提示**：仅响应头（见 D17）。
10. **无"空章节/无章节"拦截**：grep 全仓无对应分支；空内容可产出一份只有封面目录的文档并缓存。
