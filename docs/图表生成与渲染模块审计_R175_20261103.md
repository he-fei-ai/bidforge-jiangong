### 3.3 哪一类最脆弱

**甘特图最脆弱（证据最硬）**：
1. **校验与渲染容错不等价且必然触发**：`normalize_gantt_plan` 用 `id/name/task/title` 兜底后只要求 id（`chart_validators.py:934-953`），而渲染器明确跳过无 name 任务并在全空时 `return None`（`mermaid_gantt.py:302-304`、`:344-345`）。这是四类里唯一「校验 true ⇒ 渲染 None」的**无条件**错配（JSON 载荷不走 HTTP，与外部引擎无关）。
2. JSON 甘特无 HTTP 引擎可用，`_render_gantt_with_dependencies` 与 `_render_gantt_image_v2` 之外没有第三层。
3. `raw_tasks[:30]` 静默截断（`mermaid_gantt.py:287`、`:299`），校验器不设上限、无日志。
4. 无日期任务统一落 `day=1/1`（`:306-311`），图面所有任务重叠且无告警。

次脆弱为 **架构图**：JSON 单渲染器 + 自动拆图复杂路径；`architecture-beta` Mermaid 在 PIL-only 环境必然失图（`mermaid_renderer.py:637` 分支只吃 JSON）。流程图链路最长（HTTP + PIL + JSON 双模 + repair），但兜底层数最多，实测未见「校验过而渲染空」；劳动力图归一器覆盖面最广（支持 `trades` 等别名），反而最稳。

## 6. 去重与并发分析

### 6.1 去重键

| 层 | 键 | 语义 | 判定 |
|---|---|---|---|
| 磁盘缓存 | `md5(chart_type|code|allow_pil|skip_http|v7)`（`mermaid_renderer.py:840-865`） | 跨请求复用 | 写侧漏 `skip_http`（BUG-01） |
| 内存 LRU | 同上（含 version） | 进程内复用 | 正确；HTTP 成功路径不回填（D-03） |
| 导出预渲染 | `(chart_type, raw_code)`（`export.py:3418-3480`） | 同一图只渲染一次 | 正确 |
| 正文去重 | `(sec_id, chart_type, _norm_code(code))`（`export.py:2429`） | 同节同码只插一次 | 正确；**跨章同码不去重** → 两张同内容图各占一号 |
| 前端图复用 | `_norm_code(code)`（无 chart_type） | 复用浏览器出图 | 现有类型下无碰撞；若未来同码跨类型则误用 |

结论：去重键**包含必要上下文**（章节、类型、allow_pil、版本），未发现「不同章同图被误去重」；「同章同码重复」已收口。跨章同码重复属产品取舍（保留章归属），建议在报告中记为决策点而非缺陷。

### 6.2 并发

| 项 | 现状 | 证据 | 风险 |
|---|---|---|---|
| 导出渲染并发 | `ThreadPoolExecutor` 上限 4 + `asyncio.to_thread`，取消时 `cancel_futures` | `export.py:3433-3480` | 合理，不阻塞事件循环 |
| 单图预算 | HTTP 20s 总预算、单次 8s、最多 2 次 | `mermaid_renderer.py:381-485` | 注释「最多重试 2 次」实为 2 次尝试，措辞偏差（D-04） |
| 单飞（in-flight） | leader 渲染、follower 最多等 120s，超时自渲染 | `:1014-1045` | **BUG-01 副作用**：`skip_http=True` 时 leader 写入 `http=1` 槽，follower 查 `http=0` 槽必 miss → 返回 `None`，预览并发下出现**假失败 500** |
| 线程安全 | 磁盘/内存均 `RLock`；`_evict_if_needed` 在锁内重入安全 | `:758-780`、`:867-917` | 无死锁 |

## 9. 确定 BUG 清单（4 项）

### BUG-175-01（P1）磁盘缓存 `skip_http` 写侧丢失 → 跨轨污染 + 自身永不命中 + follower 假失败

- **代码自相矛盾**：`_cache_key` 把 `skip_http` 拼进键（`mermaid_renderer.py:840-865`，默认 `skip_http=False` → `http=1`；`True` → `http=0`），文档字符串也明确声明「必须拼入缓存 key，避免 PIL 降级图被不降级导出命中」（`:852-855`）。
  然而 `get()`（`:867-880`）与 `set()`（`:897-916`）**都不接受 `skip_http`**，`get_or_render` 读取用 `cache_key`（`:1003`），写入却调用 `self.set(... chart_type=..., allow_pil=...)`（`:1057-1058`）→ 永远写 `http=1` 槽。
- **触发源**：前端预览固定 `skip_http: true`（`frontend/src/components/MarkdownRenderer.tsx:365`）→ `charts.py:92/:137` 透传 → 写错槽。
- **实测（§10 V-01）**：`get_or_render(skip_http=True)` 后缓存目录只出现 **1 个** PNG（文件名即 `skip_http=False` 的键）；随后 `get_or_render(skip_http=False)` 命中该文件（`stats hits=1`），两次字节逐字节相同。
- **后果**：
  1. 预览产物（PIL）被后续正式导出当作「允许 HTTP 的最优产物」直接命中，绕过 HTTP 原生渲染（前端未提供 `fe_images` 时直接进 DOCX）。
  2. `skip_http=True` 自身永远读不到磁盘缓存 → 进程重启后每次预览都重新渲染（性能回退）。
  3. 单飞 follower 查 `http=0` 槽必 miss，leader 成功时 follower 仍 `return None`（`:1042-1045`）→ 并发预览同一图会误报 500。
- **修复方向**：`get()/set()` 增加 `skip_http` 形参并透传；`get_or_render` 写入时传 `skip_http`；补 3 条回归（写读对称、跨轨不串、并发 follower 共享成功结果）。

### BUG-175-02（P2）渲染器版本号未随架构样张 v2 升级 → 旧图永久命中

- `_RENDERER_VERSION = 7`（`mermaid_renderer.py:140`），版本沿革注释止于 R77（`:118-137`）。
- 实测提交史：`_RENDERER_VERSION = 7` 由 `3848b0d`（2026-10-15，收口 R54–R77）引入；**2026-10-20** 的架构样张 v2 批次 `3a822a3`（R91–R111）改动 `mermaid_architecture.py` 93 行、`mermaid_renderer.py` 10 行、`chart_validators.py` 17 行，**但未改版本号**（`git log -S "_RENDERER_VERSION = 7"` 仅命中 3848b0d）。
- 磁盘缓存键 = `md5(...|v7)`，跨重启持久；`clear_render_cache` 无业务调用（D-01）→ 升级前已缓存的架构图会**永久**返回旧配色/旧版式。
- 连带：DOCX 导出缓存指纹也取 `_RENDERER_VERSION`（`_export_cache.py:99-100`、`:194`，注释 `:181-191` 明确「渲染器逻辑变了但版本号没变 → 旧图被烤进二进制」）→ 旧图进一步被固化。
- **修复方向**：`7 → 8`，并把「改动任何 mermaid_* 出图逻辑必须 bump」写入 PR 清单；建议加一条测试：`_RENDERER_VERSION` 变更时快照文件同步（弱约束）。

### BUG-175-03（P2）甘特图校验放行 ⇔ 渲染必空（校验/渲染容错度不等价）

- 校验：`normalize_gantt_plan` 对任务 `name` 使用 `id/task/title` 兜底、允许空 name（`chart_validators.py:934-953`），`validate_gantt_plan` 只查归一失败与 id 重复（`:976-1017`，注释自称「与渲染侧一致」）。
- 渲染：`_render_gantt_image_v2` 先 `if not name: continue`（`mermaid_gantt.py:302-304`），随后 `if not tasks: return None`（`:344-345`）。
- 实测：`{"tasks":[{"id":"t1"}]}` → `validate=true`、`render=None`；`{"tasks":[{"id":"t1"},{"id":"t2"}]}` 同样。
- 后果：该块在生成期被判「合法」→ 写入 `chart_predictions`（status=generated）→ 导出预渲染拿到 None → 默认模式静默跳过（不占号、无占位、无用户提示），图表清单却显示已配图。属「确定少图」而非跳号。
- **修复方向**（择一，建议前者）：校验端要求 name 非空（或要求全部任务都有 name），与渲染端一致；同时为 >30 截断加 WARNING。

### BUG-175-04（P3）图题「折叠空白」被实现为「删除空白」

- `_RE_WS_RUN = re.compile(r"\s+")`（`content_blocks.py:188`）；`_clean_chart_title` 文档字符串写「折叠空白」（`:585`），实现却是 `.sub("", raw)`（`:587`）；`_title_candidate` 同样 `.sub("", ...)`（`:592-593`）。
- 实测：`_clean_chart_title("Site Layout Plan 施工平面布置")` → `"SiteLayoutPlan施工平面布置"`；`_title_candidate("BIM 技术应用流程")` → `"BIM技术应用流程"`。
- 后果：英文单词/中英混排图题连写，DOCX 题注与正文引用不一致；中文标题不受影响，故长期未被发现。
- **修复方向**：改为 `re.sub(r"\s+", " ", raw).strip()`（折叠为单空格），同步修正两处调用与文档字符串。
