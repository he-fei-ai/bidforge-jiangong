## ① 技术方案

### G1 · 编排选中事实 → 全文强注入（机制二缺口）

**易标思路**（基线报告 §二）：编排 AI 只看标题列表挑事实（`formatGlobalFactTitlesForPrompt`，CG:134），程序按选中标题取**完整事实**注入当前章节（`resolveGlobalFactsByTitles` CG:171 → `appendSelectedFactsMessage` CG:125），标题白名单钳制编造。

**本软件现状差异**：D1 编排产 `fact_titles` 仅作软建议文字（`content_plan.py`，调用点 `sse_handlers.py:6530-6739`）；注入内容完全由程序 2-gram 预筛 + `fact_injection_audit`（总量 6000/单条 300）决定，选中标题与注入结果无因果。

**方案**（加法式、复用既有注入通道，不新造消息装配）：
1. `content_plan.py` 新增纯函数 `resolve_selected_fact_rows(titles, all_fact_rows)`：按标题在**全量事实集**内精确匹配（白名单钳制，编造标题丢弃），命中的事实行返回完整文本；
2. `sse_handlers.py` R58 注入点：当 `content_plan_stage_enabled=True` 且新开关 `content_plan_selected_facts_inject=True` 时，把选中事实全文并入注入集合——**选中标题对应事实豁免 `per_fact=300` 单条截断**（仍受总量 6000 预算与 `fact_injection_audit` 审计记录约束，审计新增 `selected` 标记），与 2-gram 预筛集合取**并集**（预筛兜底不摘除，避免编排失败/漏选时倒退）；
3. 两开关任一为 False（默认）：装配路径逐字节不变。

**备选与取舍**：a) 把注入完全交给编排选中集（易标原样）——否决：编排失败或 LLM 漏选时注入面反而变窄，本软件预筛是 R58 验证过的底线通道；b) 提高 per_fact 全局预算——否决：影响所有事实的成本与缓存前缀稳定性，只对"编排明确选中"的少数条目豁免才是最小改动面。

### G2 · 全文整卷合并修复模式（机制六缺口）

**易标思路**（基线报告 §六）：持久 Agent 拿 `global-facts.md` + `technical-plan.md`（小节 HTML 标记）两个工作区文件多轮自主修改；程序校验**未知小节/缺小节/非空改空**后**只回写变化小节**（CG:5490/5507/5579）。

**本软件现状差异**：已有分章工作流式"全文一致性 Agent 修复"（`repair_agent.py:1-8` 扫描→仲裁→逐章最小修改→`repair_validator` 二次校验→快照+确认/回滚），**每章只见本章上下文**，跨章联动改写（如同一工期口径散落 8 章）只能逐章独立修；无整卷可见的合并修复模式。历史轮曾拒绝照搬持久 Agent 会话基建（`sections.py:1665`"本软件无此设施，照搬成本/风险过高"），本方案遵守该边界——**不引入 Electron 式持久会话**，用"单次/少轮整卷往返 + 程序级小节闸门"实现同等安全性。

**方案**（新服务 `consistency_fullbook_repair.py`，默认关闭）：
1. **工作区文本装配**（纯函数，可单测）：把冲突涉及小节 ± 邻近上下文与全量事实渲染成带 `<!-- §:section_id -->` 标记的整卷文本 + `global_facts` 段（对应易标两文件思路的内存态等价物，不落盘 md）；
2. **AI 返回**按小节标记分块的修订稿（`collect_json_response` 契约，复用 1 生成+2 修复兜底）；
3. **程序闸门**（对齐 CG:5490 语义、逐条护栏）：未知 section_id 拒绝 / 声明处理的小节缺任何一块拒绝 / 非空改空拒绝 / 未声明修改的小节原文回退（= 只回写变化小节，对齐 CG:5507 writableIds）；图表围栏与保护区间复用 `content_shrink.collect_protected_ranges` 同族校验，触碰即整块拒绝；
4. **回写**复用既有快照 + `repair_record` + 用户确认/回滚路径（`repair_agent.py:4-6` 同语义），导出缓存失效沿用既有修复写库通道；
5. 接线：`routers/consistency_repair.py` 加 `mode=fullbook` 参数 + `sse_handlers.py:7612` 自动阶段按 `consistency_fullbook_repair_enabled`（默认 False）分流，False 时逐字节走现链。

**备选与取舍**：a) 移植持久 Agent 多轮会话——否决（成本高、`sections.py:1665` 既有裁定、且 SSE 后端无会话基建）；b) 仅把逐章修复的上下文从"本章"扩到"本章+冲突对手章"——列为实施期降级备选：若整卷往返的 token 成本实测超阈值（DoD 记录），可先落该降级版，开关同名。

### G3 · 成稿后跨章节字数批量调度（机制五缺口 · 弱）

**易标思路**：成稿后收集 under/over 章节，按 10 一批全局调度扩/缩（`TOTAL_WORD_ADJUSTMENT_BATCH_SIZE=10`、单节仍 ≤3 轮，CG:28-45）。

**本软件现状差异**：单节扩写（R66 续写）/缩写（`content_shrink.py:29-30`）齐备，全文层面只有预检**检出**（`preflight_engine.py:1076-1080` DLV-08、`word_audit_summary` L129），处置为人工引导（`review_autofix.py:263-274` `_manual`）。

**方案**（新函数 `word_adjust_batch`，挂正文生成收尾 `sse_handlers.py:7781` 总字数统计之后）：
1. 开关 `word_adjust_batch_enabled`（默认 False）：从 `word_audit_summary(tolerance)` 取偏离章清单（under：低于触发线；over：高于 1.15 收敛线），按目录 `sort_order` 排序、每 10 章一批、**批间串行批内并发**（并发度复用 `REPAIR_CONCURRENCY` 同族信号量）；
2. under 章调既有续写链（`should_continue_round` 封顶 ≤3 轮）、over 章调既有 `shrink_content_rounds`（≤3 轮、保护区间拒绝）——**零新 AI 交互形态**，只补调度器；
3. 全程写审计事件（批次、章、前后字数、轮数），失败章不重试超轮即止（与现链一致）；DLV-02/08/16 检出语义不变（调度后再预检即达标或残留明示）。

**备选与取舍**：把调度做进审核页手动按钮——留作后续可选 UI 项，本轮不扩前端边界（引入原则"架构兼容"优先）。

## ④ DoD 验收标准（量化可核对）

- **零回归硬条件**：三开关默认关闭下，后端全量 pytest 不低于 R121 基线口径（9380+ passed / 18 skipped / 1 xfailed 全绿）；前端 vitest 全量 79 files / 1373 tests 绿（偶发子进程抖动按 R119 规程单独复跑定性）；`tsc --noEmit` EXIT=0；ruff 改动文件 All passed；护栏测试证明关闭态提示词装配逐字节等价。
- **G1（开启态）**：编排选中 N 条标题 → 注入审计中 `selected=true` 条目 N 条、完整文本未被 300 字截断、编造标题 0 进入注入（白名单用例断言）；总注入字符 ≤6000 预算不破。
- **G2（开启态）**：构造 3 章联动冲突样例 → 整卷修复后仅变化小节回写（未声明小节逐字节=原文）；四种越界（未知 ID/缺节/非空改空/触碰图表围栏）逐一被拒且状态标 failed、快照可回滚；单轮 token 实测记录（超预算阈值则启用 ①-G2 降级备选并写明）。
- **G3（开启态）**：偏离章清单按目录序 10 章一批（批数=ceil(偏离章/10)）、每章扩/缩 ≤3 轮、批间串行证据（事件时间戳）；调度后 DLV-16 达标率不低于调度前。
- **A/B 变异**：M0 GREEN + 各变异全 CAUGHT + SHA restore 全 OK + AB_EXIT=0。
