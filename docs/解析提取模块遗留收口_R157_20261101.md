## 二、FIX-1 · L1-full：双上传入口收敛到 `useDelayedCallback`（R144 教训①根因级收口）

**修法**：新增 `frontend/src/hooks/useDelayedCallback.ts`（`schedule(fn)` = 赋值前 `clearTimeout` 旧 timer 再登记、卸载 effect 自动清理、回调置空；`clear()` 幂等供显式调用），两入口全部改接 hook；删除两份手工 `uploadTimerRef`。回调以 schedule 时刻闭包执行（与既有行为逐字等价）；页面卸载清单中 `uploadTrigger.clear()` 与各 AbortController 清理并列（幂等双保险），Tab 依赖 hook 卸载自清理。

## 三、FIX-2 · TD-7：解析链路结构化事件（module='parse'，四事件族）

**修法**：`global_facts_docs.py` 新增 `_log_parse_event()`（照搬 task_registry 已验证形态：**函数内局部导入** observability 避免环、**`get_conn()` 独立连接** —— log_event 内部 commit 所传连接，若传请求级 db 会把失败路径上半截事务提前固化；fail-soft 绝不阻断解析主链路）。接线四处：

| 事件 | 级别 | 接线点 | 语义 |
|---|---|---|---|
| `parse.failed` | WARNING | `_mark_parse_failed`（单一咽喉，SELECT 增取 project_id） | 覆盖单份/批量全部失败路径；失败率可按事件盘点 |
| `parse.done` | INFO | `parse_document` 成功尾部 | 时长/字数/截断态（批量刻意不逐单发，防刷屏） |
| `parse.aborted` | WARNING | `parse_document` 的 ParseTargetGoneError 分支 | 并发删除中止率可见 |
| `parse.batch` | INFO/WARNING | `parse_all_documents` 结果装配后 | 一批一条汇总（parsed/failed/truncated/reconciled） |

零新增配置项、零 DDL、零新依赖；E2E 实证：两份伪造 PDF 的失败在真链发出 `parse.failed`（咽喉生效）。
