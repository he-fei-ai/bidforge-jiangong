## 二、架构设计（四层分层，显式化）

```
业务层（outline / content / facts / review / export ...）
    │  新代码 import ai_gateway；存量直接调 provider_factory 亦完全兼容
    ▼
ai_gateway（业务调用层门面 · 新增）
    │  chat / stream_chat / request_json / chat_tools / refresh / gateway_snapshot
    ▼
provider_factory（编排层：场景路由 → 候选链 → 门禁 → 退避/对冲/降级 → 记账）
    │  + SCENE_TIERS 分档路由继承 + 瞬态指数退避 + ai.degraded 降级告警
    │  + chat_stream_with_fallback（业务级流式）
    ▼
providers/*（厂商适配层，既有 20+ 厂商 preset）
    │  + VendorHTTPError（继承 httpx.HTTPStatusError，携带 status + Retry-After）
    ▼
error_taxonomy（错误分类单一事实源 · 新增叶子模块，零依赖）
```

### 2.1 统一接口（`app/services/ai/ai_gateway.py`）
- `chat(messages, *, scene, ...)` → `chat_with_fallback`（透传，返回 str）；
- `stream_chat(messages, ...)` → 归一化事件流 `{"type":"delta","text",...}` / `{"type":"done","text","usage","finish_reason","degraded_normal",...}`；
- `request_json(messages, validate_fn, ...)` → `collect_json_response`（JSON 模式不被厂商支持时既有链路自动回退普通模式 + 围栏/正则提取）；
- `chat_tools(...)` → `chat_with_tools`（Agent 工具循环）；
- `refresh()` → 配置热更新聚合入口：立即失效主配置/降级链/场景路由/环境/运行时开关五类缓存（与 `save_ai_config` 写路径的自动失效互补，供库被旁路修改时强制生效，不必等 300s TTL）；
- `gateway_snapshot()` → 实时状态只读快照（在飞计数 / 并发档位 / 熔断状态 / 分档表）。

### 2.2 流式归一化
厂商间 SSE 差异（OpenAI `chat.completion.chunk` vs Anthropic `content_block_delta`/`message_delta`）由适配层抹平为纯文本增量（既有），新网关再封装为统一事件。**部分增量产出后断流 = 整体失败**（不换候选重拼 —— 避免跨厂商拼接文本；已产出的前缀不可撤回，唯一正确语义是消费方整体重试）；**零增量产出**时流失败 → 同候选普通请求回退（`degraded_normal=True`）→ 仍失败才换下一候选。流式能力记忆（连续失败 → TTL 内直走普通请求）与 chat 链路共用。

### 2.3 瞬态指数退避（`_attempt_candidate`）
- 触发面：`error_taxonomy.TRANSIENT_CLASSES = {rate_limit(429), server_error(5xx), timeout, network}`；基线显示这两类占可归因失败 43%。
- 策略：同候选**严格一次**重试；延迟 = `Retry-After` 头优先（`VendorHTTPError.retry_after`），否则 `1.0s × 2^(n-1)` 带 ±30% 抖动，**封顶 8s**；`Retry-After` 超过封顶 → 不等待直接换候选（等不起）。
- 与既有机制的关系：退避成功 → 整条链零扰动（**不进配额冷却、不记熔断失败**）；退避后仍失败 → 走原失败路径（配额冷却 120s + 熔断 429 加倍冷却 + 换候选）。非瞬态（401/402/403/404/余额耗尽/JSON 不兼容）零重试（R109 实证口径不变）。
- 边界：`_best_partial` 在手时不退避 —— 截断重试后失败的既定契约「半截 > 拿不到，立即返回」不被追加等待（`test_retry_failure_returns_best_partial` 锁定）。
- 零新增配置项：`_TRANSIENT_RETRY_MAX=1` / `_TRANSIENT_BACKOFF_BASE=1.0` / `_TRANSIENT_BACKOFF_CAP=8.0` / `_TRANSIENT_BACKOFF_JITTER=0.3` 均为模块常量。

### 2.4 智能路由：场景分档 + 锚点继承（`SCENE_TIERS`）
- 四档：`complex`（目录族/整卷合并，强模型）、`throughput`（正文族/批量提取，高性价比）、`precision`（审核/一致性/裁决，高精度）、`light`（低频辅助，轻量）；覆盖 `KNOWN_SCENES` 全部 35 个场景（双向一致护栏）。
- 继承规则：场景无显式路由 → 继承**同档锚点**（`TIER_ANCHOR_SCENES`：outline_draft / content_draft / compliance_check / chart_fix）的路由配置；显式路由永远优先；本场景即锚点不自继承；跨档不传播；无锚点路由回落主配置（与引入前逐字一致）。用户只需每档配一个锚点，30+ 场景逐个配置的负担降为 4 个。
- 语义裁定：`test_ai_config_security_routing::test_put_then_resolve_and_clear` 的旧断言「其他场景不受影响」随分档继承更新为分层语义（同档继承 + 跨档隔离双锁），并在测试内注明裁定理由。

### 2.5 降级告警（`ai.degraded`）
主配置未胜出（失败/熔断/被实时成功率后置/对冲落后）时，发一条 system_logs `WARN` 结构化事件（`event="ai.degraded"`，detail 含 primary/winner/attempts_failed/hedge_used），三个调用链（chat / tools / stream）全部接线；前端与运维首次可感知「正在用备用模型扛量」。纯通知 fail-soft。

### 2.6 既有机制（本轮验证保留，未改动语义）
全局自适应并发（`ResizableSemaphore` + 429 降档棘轮防护）、per-provider 熔断（429 加倍冷却）、配额冷却（120s + 10s 探测）、对冲请求（20s）、JSON 模式中英双语兼容、流式能力记忆、审计三链路（ai_audit_logs + system_logs ai.call + /ai/stats）。

## 四、改造前后对比

**机制级（429 风暴对照实验，`TestConcurrencyAndStorm::test_429_storm_backoff_keeps_fallback_idle` + E2E E5）**：同一批 10 路 429 故障（每任务首发 429 一次、退避后自愈）——
- 退避开启（R150）：全部 10 任务主候选自愈成功，**降级候选调用 0 次**；
- 退避关闭（= 旧行为）：10 任务全部打穿主候选，**降级候选被调用 10 次**（每次都是真实候选切换 + 对冲窗口暴露）。
即：同规模 429 风暴下，降级链压力 10 → 0。E2E E5 进一步验证 6 路并发风暴全自愈 + 审计「6 失败 + 6 成功」成对落库 + in_flight 零泄漏。

**基线采集能力**：`/ai/stats` 新增 `by_provider[].p95_duration_ok` 与 `by_error_class[]`（failed_calls / skipped_calls 分列 + 中文标签）——「429 一共多少次 / 谁在拖慢交付」从「原文 TOP8 截断」变为结构化口径。**生产环境的「成功率提升 / 成本下降」需重启后端生效后复跑 `_r150_ai_inventory.py` 对比**（本报告第一节即改造前基线快照）。

## 五、运维与行为变化

- **需重启后端**（`provider_factory` / `providers/*` / `usage` 常驻）；**前端零改动、无需重建**（`ai.degraded` 走既有 system_logs 通道；新键为后端统计面）。零迁移、零 DDL、零新增配置项。
- **行为变化（3 处，均为修复目标内的预期变化）**：
  1. 429/5xx/超时/网络抖动的候选调用，同候选退避（≤8s）后重试一次再降级 —— 429 风暴下主候选自愈率上升，降级链/配额冷却触发次数下降；
  2. 配了「场景模型路由」锚点场景后，同档未配置场景自动继承（此前必须逐场景配置）；
  3. 主配置未胜出的调用现在留 `ai.degraded` WARN 告警（可观测面新增，不影响调用结果）。
- **流式网关**（`ai_gateway.stream_chat`）为**新增能力**，当前无业务调用方（正文生成仍走 `chat_with_fallback` 收全量语义），供后续增量输出类需求接入；语义（含「部分增量断流=整体失败」）已由 F 组护栏锁定。
- 回退方式：本轮全部为加法式，回退=还原四个生产文件（provider_factory / error_taxonomy（删）/ providers/base / openai_compatible / anthropic_compatible / usage.py / ai_gateway（删））。

## 六、判据教训归档

1. **换异常基类必须先扫「类型捕获点」** —— `VendorHTTPError` 首版用裸 `RuntimeError` 基类，`openai_compatible.stream()` 的 stream_options 降级重试按 `httpx.HTTPStatusError` 捕获 → 降级链被打死（既有护栏 `test_ai_config_request_mode` 双用例当场抓住）。最终定为**继承 `httpx.HTTPStatusError`**：旧捕获点（`.response`）与新网关字段（`.status/.retry_after`）两通。凡「新异常替换旧异常」，先 grep 旧类型的所有 `except` 再动手。
2. **「横切增强」与「既定快速退出契约」冲突时，增强让位** —— 退避曾插入在 `_best_partial` 返回路径之前，把「截断重试后立即返回半截正文」变成「再等一轮」。判据：退避只服务「两手空空、即将失去候选」的失败；已握可用输出时不追加等待。
3. **A/B 锚必须断「定义处调用形态」且每次改源码后复核锚点命中数**（R149 教训③再验证 + 本轮 ruff --fix 后主动复核 ANCHORS_OK）。
4. **并发实验的状态键必须是「被调参数」本身而非共享序号** —— 假 Provider 的失败脚本用全局计数/脚本 pop 时，gather 交错会让「每任务失败一次→重试成功」的配对不可复现；改为按消息内容记忆失败后确定化。
5. **E2E 打桩要封死「桩外泄漏」**：patch `_build_provider` 会连带把降级链里的内置兜底（agnes）也变成假实例并抢先胜出（审计名错位、断言漂移）—— 需同时钉空 `_fallback_chain` + 打桩 `decrypt_api_key`，把实验收敛到单候选确定语义。
6. **既有护栏断言与新语义冲突时**：逐条裁定「哪层契约该让位」，把新语义分层写回测试（同档继承 + 跨档隔离双锁）并在测试内注明裁定理由，而不是静默改断言。
