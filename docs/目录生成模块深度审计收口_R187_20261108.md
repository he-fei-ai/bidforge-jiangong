**核心不变量（用户点名的「目录编号子承父系 / 目录编号·等级正传」）**：
- 唯一存储态 = `outline_json.id` 点分路径（`1` / `1.1` / `1.1.1`），`level` = 点分段数，`parent_id` = 树父；
- 写路径统一经 `normalize_outline` → `renumber_outline`；展示态由前端按 `storedIdParts` 渲染，**不另存一套编号**；
- 正文 Markdown 子标题编号是**独立命名空间**，由 `renumber_section_body_subheadings` 对正文重排，不写回 `outline_json`（R76/R118 已闭环）。

### 2.4 风险点

1. **编号命名空间分叉**：任一写路径绕过 `renumber` 或重排异常被吞 → 脏/重复 id 落库，前端双重编号、正文/导出编号分叉。
2. **层级上限漏算子树**：只看「新父 level+1」不看被移动子树高度 → `level=4` 入库但三级界面不渲染。
3. **状态机谎报成功**：checkpoint 写失败 / 审核超时被写成 `completed` + `passed=True`。
4. **跨模块字段层级错位**：`issue_counts` 生产在 `quality.continuity` 下，消费在顶层。
5. **进度可见回退**：切档重置 `last_p` 与 `max(p,last_p)` 地板语义相反。
6. **编码**：不可见/控制字符标题零清洗；子进程 GBK 输出 / UTF-8 解码致护栏假红。
7. **缓存/并发**：导出指纹不含 `outline_json`；同型并发生成为「抢占」而非互斥（产品决策）。
