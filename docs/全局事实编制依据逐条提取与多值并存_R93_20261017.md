## 1. 根因链（为什么界面上只剩一部规范）

1. **提示词层**：`analysis.py` P14 令所有规范统一命名 `name="执行标准"`
   （「同类事实同名」纪律本身没错，错在下游把同名当同键折叠）。
2. **键归一层**：`normalize_key("执行标准")` → 全部落到同一 `fact_key`
   `execution_standard`。
3. **合并去重层**：`merge_and_deduplicate` 按 fact_key 聚类，N 部规范变成
   「**1 条事实 + N-1 个矛盾候选**」（`has_conflict=1`）——其余规范被伪装成
   需人工裁决的「矛盾」。
4. **注入门层**：注入门 `has_conflict=0 AND is_resolved=1 AND …` 使整行失去
   注入资格 → 正文也只用得上那一条。
5. 附加缺口：标准图集 / 勘察报告 / 法规依据根本不在提取名称表与语义区关键词
   内，多数直接漏提。

## 2. 方案：多值并存（清单型）事实 + 值域限定键

- **判据单一事实源**（`facts_extractor.py` 新增段）：
  `BASIS_COEXIST_CATEGORY="basis"`、`BASIS_COEXIST_KEYS`（6 键白名单：
  compilation_basis / execution_standard / tech_standard / acceptance_code /
  standard_atlas / legal_basis）、`is_basis_coexist_item`（category ∪ fact_type
  ∪ 键白名单三路并集）、`basis_scoped_key` / `basis_base_key`。
- **值域限定键**：并存簇内每条唯一取值独立成条，
  `fact_key = {base}::{md5(_norm_value(value))[:8]}`。同一部规范跨段落/跨次
  提取 → 同后缀 → 依旧收敛为一条；`basis_scoped_key` 幂等（二次 merge 不叠
  双后缀）。
- **merge 分簇**：`merge_and_deduplicate` 中并存条目先行摘出、清矛盾标记、
  独立成键；单值型事实原路径逐字不变。
- **persist 历史兼容**：`persist_extraction` 对「改判前已确认的裸键行」按
  `basis_base_key` 回查再比值——同值（`_norm_value` 口径，与值域标签同源，
  「GB 50300-2013 / GB50300-2013」记法变体收敛）→ 跳过插入并解除 is_stale；
  异值 → 并存为独立事实正常插入，**绝不**回写已确认行的 conflict_keys。
