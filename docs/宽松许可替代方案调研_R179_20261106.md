## 5. PyMuPDF 专章（裁定：保留，不换库）

### 5.1 具体义务

1. **随包分发**：分发包内含 AGPL-3.0 作品（PyMuPDF）。按 AGPL §5/§6，整个组合作品需以 AGPL 授权并提供对应源码；用户有权反向工程、再分发。
2. **网络服务**：AGPL §13 要求「与用户通过网络交互」时提供 Corresponding Source。本软件定位含「部分对外提供服务」；该场景启用时适用性需另行评估，本条裁定不自动覆盖。
3. **商标/署名**：需保留版权声明与许可证文本；不可暗示 Artifex 背书。
4. **商业许可替代**：Artifex 提供商业许可，可解除上述义务（需采购）。

### 5.2 历史方案与裁定结果

用户已裁定：以下三条方案全部不执行，PyMuPDF 保留。表格仅作为历史记录保留。

| 方案 | 做法 | 优点 | 缺点/风险 | 适用判断 |
|---|---|---|---|---|
| **A. 换成宽松许可** | PDF 主通道改为 `pdfplumber`（文本+表格）+ `pypdfium2`（渲染）+ `pypdf`（回退/加密）；表格质量不足再按需引入 `camelot-py` | 彻底移除 AGPL；三者均已在依赖树/可直接引入；许可干净 | `find_tables` 几何重建无等价物 → 表格保真与速度下降；现有「MuPDF 第一道安全闸门」失效（20KB 畸形 PDF 在回退通道可放大到 39.7s，见 [file_parser.py](file:///j:/编程/专项方案工具箱/backend/app/services/file_parser.py#L1350-L1361) 注释）；需重建解析基线 | **不执行**（用户裁定 2026-11-06：保留 PyMuPDF） |
| **B. 隔离为可选外部组件** | PyMuPDF 不随包分发，改为「用户自装的可选插件」，且以独立进程/子进程调用，主程序不 `import pymupdf` | 分发包不含 AGPL；主程序可保持闭源 | 「独立作品」主张需法务确认；若 PDF 解析是核心卖点，功能默认缺失；独立进程仍可能被认定为组合作品 | 不执行（用户裁定 2026-11-06） |
| **C. 采购商业许可 / 整体 AGPL** | 购买 Artifex 商业许可；或接受 AGPL 并把整套产品开源 | 保留现有解析质量；改动最小 | 商业许可成本；整体开源与商业定位冲突 | 不执行（用户裁定 2026-11-06） |

## 6. 只能自研重写的部分（不要为凑方案硬换库）

1. **标段 AI 识别 + 合并规则**（`bid_section_extraction` 的提示词、区间并集、去重重编号）：无库可替代。
2. **上下文提示语拼装与事实预算**（`bid_section_context` + `facts_builder`）：提示词语义不可外包；token 计量只可旁路。
3. **查重主判定**（骨架掩码 + Dice/containment 双阈值 + 分档 + 倒排剪枝）：换任何度量都会翻转历史结论；库只能做召回/加速。
4. **事实别名表与 id 归一**：业务知识，必须自研；rapidfuzz/pypinyin 仅辅助。
5. **编号重排与连续性校验**（`numbering.py`）：业务规则，无库。
6. **围栏保护切分（fence-aware）**：现有 `fence_common.fence_char_ranges` 是 CommonMark 口径的自研实现，任何分块库都不提供；换库也必须保留。
7. **PDF 的 `find_tables` 几何表格重建 + 跨页续表拼接**：无等价库；换 pdfplumber 后需自研等价后处理。

> 这与「A 类文件必须自研重写」并不矛盾：第 1/2/4/5/6 项本来就该自研，换库既无必要也无收益；第 3/7 项可以「库做脏活、自研做判定」，反而是降低重写工作量的正确姿势。
