## 2. F1 · 正文提示词前缀稳定化（P0）

### 2.1 问题（附证据）

正文首轮 messages 的**唯一**组装点 `routers/sse_handlers.py:5416`（R56 编号；现为 `_build_generation_context` 内）长年是：

```python
messages = [{"role": "system", "content": sys_prompt},
            {"role": "user",   "content": user_content}]   # 一条大字符串
```

两处同时破坏请求前缀：

1. **system 自首字符起就逐章变化** —— `render("content_generation_system", section_number=…, standards_text=…, subheading_rule=…, **_ck_kwargs)`，四个入参全是逐章量；
2. **user 串里稳定块被排在差异之后** —— `content_runtime.py` 的拼接顺序是
   `上级章节链 → 上级要点 → 同级章节 → 当前章节编号 → 当前章节 → 目标字数 → 前序结尾 → 全局事实 → 知识库 → 生成标准块`，
   即**最重的项目概述 / 施工内容 / 全局事实 / 项目知识库**排在逐章差异之后。

按《（四）》§五的判据 —— 「缓存看的是前缀，不只是意思差不多」—— 于是**同一方案每换一章，前缀整体失效**：
几十万字方案里同一份项目概述、施工内容、全局事实、知识库被反复**全价**计费。文档实测第二次请求
`cached_tokens=19442 / prompt_tokens=19737`，输入成本约为首次的 1/9。

### 2.2 落地（新增配置项 1 个，默认 True）

| 位置 | 内容 |
| --- | --- |
| `app/config.py:516` | `content_stable_prefix_enabled: bool = True`（关闭即**逐字**回到旧形态，可瞬时回退） |
| `app/services/content_runtime.py:112` | `resolve_system_variables()` —— 决定注入 system 的逐章变量取值（纯函数） |
| `app/services/content_runtime.py:138` | `build_chapter_extras_block()` —— 从 system 剥离的逐章内容**原样**补给模型 |
| `app/services/content_runtime.py:165` | `build_chapter_layered_messages()` —— 分层消息构造器 |
| `routers/sse_handlers.py:5385-5460` | 开关读取（`_:5385`）、变量决策（`_:5392`）、显式 render（`_:5413`）、分层装配（`_:5449`） |

分层后的 messages：

| 序 | 角色 | 内容 | 同一方案内稳定性 |
| --- | --- | --- | --- |
| 0 | system | 仅整案常量（逐章变量注入空串） | **全章一致** |
| 1 | user ① | 方案名称/类型/项目概述/**施工内容**/**全局事实**/**知识库**/生成标准块 | **全章一致** |
| 2 | user ② | 上级章节链 / 上级要点 / 同级章节 | 同父章节一致 |
| 3 | user ③ | 当前章节编号/标题/目标字数/前序结尾 + **【本章编写定位】**（编制依据 / 子标题编号规范 / 本章检查点） | 每次请求唯一 |

**信息零丢失**：system 里被清空的变量一字不差地落到 user ③；且变量**照传**（注入空串而非不传），
故模板占位符既不残留（避免 `{section_number}` 原样下发）也不会被 `_render_by_line` 整行丢弃。

**回退路径完整保留**：开关为 False 时走原 `build_chapter_user_content`，提示词与本项引入前逐字一致。

### 2.3 附带的正确性修复

- 提示词治理（G5 预算 / G6 注入防护）原先只作用于 `messages[-1]`；分层后改为**逐条 user 治理**
  （G5 本就按「【标签】：」独立切片预算，分段裁剪与整串裁剪同判据；单条 user 时行为逐字节不变）。
- `user_content` 在治理后**回同步**，避免续写轮拿到未被治理的原文（旧实现只有一条 user，天然一致）。

## 3. F2 · 一致性定点编辑接入统一 JSON 修复通道（P1）

### 3.1 问题

`services/consistency_edits.py` 旧实现自己 `extract_json` + `json.loads`，**一次机会**：模型只要多输出一句
解释、多一层代码块包裹、少一个逗号 → 该章直接放弃定点编辑 → 回落**整章重写**。

## 4. 本轮撞出的 3 个真实回归（全部已修）

> 三项都是**跑回归撞出来的**，不是审出来的 —— 与 R54 §F7 同型。

### 4.1 【静态护栏退化】`**` 展开把 render 调用点变成检测盲区（P1）

改 F1 时我把逐章变量收进 `_sys_vars` 后用 `**_sys_vars` 展开，检查点变量改用**字典推导**生成。
结果 `tests/test_outline_generation_fixes_20260926.py::TestRenderDynamicBlindspots` 立刻红：
`sse_handlers render(content_generation_system) **<unresolved> × 2` —— 该调用点此前的**存量盲区**反而增加，
从此**漏传模板变量再也测不出来**。

**修法**：三个逐章变量改回**显式关键字**书写（`section_number=_sys_vars["section_number"]` 等，
`sse_handlers.py:5413`），检查点变量保留「逐条 Subscript 赋值」的可静态解析形态（`_:5399`）。
决策逻辑仍走纯函数（可单测），两不误。

**副作用（正面）**：盲区由 2 条降到 **0 条**。按护栏自身设计（「新增盲区需改造为可静态解析形态，
或同步登记并说明理由」）**同步注销快照条目**并在原地写明理由。

> ⚠️ 纪律：**不要用 `**kwargs` 展开去追求代码简洁 —— 那是拿静态检测能力换行数。**

### 4.2 【契约变更】定点编辑多了一次 AI 调用（P2 · 有意变更并披露）

`tests/test_prompt_techdebt_r38_20261003.py::TestRepairRewriteHardCap` 两个用例断言调用**总次数**（1 / 2），
修复轮使其变成 2 / 3。

**判断：保留增强。** 成本上，定点修复只是「一次输入请求（含章节原文）+ 极小输出」；
而它争取省掉的是一次**整章重写**（重新输出数千字）。超长章场景更关键 —— 重写被硬上限禁止，
定点编辑是唯一通道，旧行为等于「必然失败 → 人工」。

**处置**：把测试从「裸计数」升级为**语义判据**（见下），并显式注明 R57 契约变更。

### 4.3 【可观测性缺口】定点编辑与整章重写共用一个 scene

为让 4.2 能用语义而非计数断言，把定点编辑的 scene 拆为独立的 `consistency_repair_edits`
（`consistency_edits.py:246`），并登记到 `provider_factory.KNOWN_SCENES:1351`（原 `consistency_repair`
中文名同步细化为「·整章重写」，避免界面出现两个同名项）。

收益不仅是测试：`/ai/stats` 从此能分别观测两条路径的成功率与成本（此前混在一个场景里）。
存量 `ai_scene_routes` 行不受影响（`scene_routes` 有白名单外兜底分支）。

> ⚠️ 教训：本仓 `TestKnownScenesDrift` / `test_prompt_known_scenes_parity` 是**AST 双向**护栏，
> scene 必须以**字符串字面量**书写 —— 我最初用常量 `CONSISTENCY_EDITS_SCENE` 传入，立刻被判
> 「登记了却没有调用点」。已改为直接写字面量。

## 7. 本轮最大教训（三条）

1. **【重犯 · 行尾污染】** R56 §F6 已记「编辑工具会把行尾再处理一遍，损坏会留在生产文件里」，
   本轮我又用文本工具改了 4 个 CRLF 仓库文件 → **每行被写成 `\r\r\n`**（工作树 loneCR 由 0 变成行数）；
   随后的自救脚本又把孤立 `\r` 连同换行一起吃掉 → 4 个文件 `py_compile` **全部挂掉**，
   最后由 `git checkout` + 字节级重放脚本恢复。
   **判据已固化**：E 组字节体检 + A/B M7（注入污染即红）。
   **行动纪律**：CRLF 仓库里的 `.py` 一律用**字节级补丁脚本**改（锚点 `count == 1` + 改后体检）。

2. **【静态护栏不可替代】** 用 `**kwargs` 展开让代码变短，代价是该 render 调用点**退出静态检测范围**，
   漏传变量从此测不出来（4.1）。**「能静态判定的形态」本身就是设计目标**，不是风格偏好。

3. **【埋在闭包里的逻辑无法验证】** F1 的变量决策最初写在 `sse_handlers` 的闭包里，
   A/B 变异它时**没有任何测试会红** —— 护栏看着覆盖了，实际是盲区。已下沉为
   `resolve_system_variables` / `build_chapter_extras_block` 两个纯函数（可单测、可 A/B）。
