## 第二部分 · 本轮引入方案（value_kind 消费侧收口）

### 2.1 设计原则

1. **判据同源**：口径前缀只保留**一份**字面量（`facts_builder._REQUIREMENT_KIND_PREFIX`），其余模块 import，绝不复制（本仓最高频反模式）。
2. **行为不变性**：`value_kind` 缺席的历史行 / `fact` 行 / `''` 行，在**每个**消费点渲染与判定**逐字/逐结论不变**（fail-open）。
3. **安全方向**：危大参数提取排除 `requirement` 行（防误报），但**不放松**真实事实参数的判定（反向锁）。
4. **零迁移**：`value_kind` 列 R80 已建 + `_migrate` 幂等补列。

### 2.2 改动清单（文件：函数级）

| # | 文件 | 函数/位置 | 改动 |

| G1 | `backend/app/services/facts_extractor.py` | `_BRIDGE_COLUMNS` + `load_resolved_facts_for_scope` | 列清单尾部追加 `value_kind`；返回 dict 增 `"value_kind"`；docstring 返回字段清单同步 |
