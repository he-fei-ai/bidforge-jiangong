## 一、结论

R135 Agent 目录生成的**无技术评分单链**（initial-outline → children_generation →
outline_review）此前已接线并测试通过；本轮**最小接线**把六阶段骨架补成单一事实源、
给技术评分三阶段加**保守门禁**（防其落入 `_continue_task` 终态分支的静默误路由），
默认行为逐字不变（`outline_agent_enabled=False` 死代码保 legacy；Agent 分支默认走
无技术评分单链）。

## 二、改动清单

### 1. `outline_agent_flow.py`（已提交基线 `9827a45` 之后的工作树文件）

| 改动 | 位置 | 说明 |
|------|------|------|
| `_OUTLINE_FLOW_STAGES` 六阶段骨架 | 模块常量（`NO_TECHNICAL_SCORE_MODE` 之后） | 单一事实源，与 `validation.STAGE_OUTPUT_FILES` 六键逐字一致（前两个连字符、后四个下划线）；护栏锁 `set(...)==set(...)` |
| 保守门禁 | `run_outline_agent` 入口（docstring 之后、`ws = Path(...)` 之前） | `if not NO_TECHNICAL_SCORE_MODE:` 抛 `NotImplementedError`（文案含「技术评分」「门禁」）。默认 `NO_TECHNICAL_SCORE_MODE=True` ⇒ 门禁关闭、零影响；置 False ⇒ fail-fast 阻断误路由 |
| docstring 更新 | 模块「单链范围」+ `run_outline_agent` | 明示技术评分三阶段**未接线**（本仓无技术评分数据源 `score_mapping`/`scoreDirectoryPlan`），接线需独立立项 |
| `from typing import Any` 移除 | 导入 | 既有未使用导入（ruff F401），随本文件一并清理 |

**为什么最小接线不实现技术评分路由**：技术评分三阶段的提示词构造器
（`create_score_planning_prompt` / `create_leaf_allocation_prompt` /
`create_leaf_adjustment_prompt`）虽已就位，但依赖 `technical-score-groups.json` /
`leaf-allocation-context.json` 等技术评分数据源——本仓 `build_outline_review_context`
恒 `no_technical_score_mode=True`、`scoreDirectoryPlan` 恒空（已登记有意偏离）。
假造未接线的路由会产生「schemas 按技术模式建、流程走无评分」的错配，故只补骨架 +
门禁，不引入未使用模式。
