## 三、功能架构与现状（9 维）

1. **上传**：`upload_outline.parse_outline`（目录识别单文件）与 `global_facts_docs.upload_documents`（项目资料批量落盘）双入口；均做扩展名白名单（`SUPPORTED_EXTENSIONS`）、大小上限、文件头签名校验（`signature_valid`）。
2. **格式识别**：扩展名 → 文件头嗅探（`_sniff_type`）→ OLE/ZIP 双向纠错（docx↔doc、xlsx↔xls）→ 14 种格式分派。
3. **内容解析**：pdf/docx/txt/md/csv/xlsx/图片/legacy-word 各自解析器；图片与扫描件 PDF 走本地 OCR 或 MinerU 云端兜底。
4. **信息保存与分类**：`project_documents` 存原文 + 解析态；`doc_categories.py` 单一事实源按文件名规则分类；`update_document_category` 白名单校验。
5. **错误处理**：`ParseError` → 用户可读文案；R13 守卫统一 None 游标→503、0 行→404/409/503；解析失败落 `parse_status='failed'` + 原因持久化。
6. **工作流程**：上传（不解析）→ 单份/批量解析 → 四层存储 →（可）AI 提取事实 → 目录/正文生成。批量解析入口先做 `parse_status` 自修复（`_reconcile_parse_status_all`）。
7. **AI 调用**：仅目录识别兜底与事实抽取；parse 端点本身无 LLM。
8. **数据链与存储**：`uploaded_outlines`（目录识别）→ `project_documents`（项目资料）→ `global_facts`/`doc_chunks`/`facts_extracted_chunks`（四层）。跨模块：解析改源文本 → `_mark_project_facts_stale` + `_invalidate_project_export_caches`（L1100）。
9. **容错/缓存/并发/日志/配置/测试**：R13 守卫、引用计数锁、截断诊断回传、断点续传、G6-min 批解析日志（L1359/1456/1534）；配置 `OCR_*`/`MINERU_*`/`upload_*`/`pdf_text_max_pages`；测试覆盖 `test_file_parser.py`(65+)、`test_upload_parse_*`、`test_import_parse_*`、`test_doc_pipeline.py` 等数十文件。

## 六、修复项清单（含代码方案）

### FIX-1（G-1）后端解析假成功窗口
**文件**：`backend/app/routers/global_facts_docs.py`
**函数**：`_persist_parse_result`（L1031）
**改法**：在 `cur is None` 分支之后、`db.commit()` 之前插入：
```python
if safe_rowcount(cur, what=f"落库解析结果 {doc_id}") != 1:
    logger.warning("解析结果落库 0 行生效（目标文档可能已被删除），正文未写入：%s", doc_id)
    return False
```
**原理**：`safe_rowcount` 把负 rowcount 归一为 0（与 `_r13_write` 同口径）；0 行即视为未生效，由调用方 `parse_document`→503、`parse_all_documents`→计入 failed 兜底。
**验证**：
- 新增 `test_returns_false_when_zero_rows_updated`（不插入目标行 → UPDATE 命中 0 行 → 断言 `ok is False`）。
- 既有 `test_returns_true_on_success`（真实行 → 1 行 → `True`）不受影响。

### FIX-2（G-2）前端批量解析提醒未透传
**文件**：`frontend/src/pages/schemeWorkbench/useDocumentWorkflow.tsx`
**函数**：`handleParseDocuments`（L315 内结果处理块，L348–373）
**改法**：抽取 `note = typeof data.note === "string" && data.note ? data.note : undefined`；在成功/告警文案末尾 `if (note) detail += `；${note}``；按 `isWarning` 选 `msg.warning`/`msg.success`。
**原理**：`parse_all_documents` 在 `parsed>0` 时回传 `note`（资料全集已变、需重提事实）与 `stale_facts`；此前前端只消费 `parsed/failed_count/truncated_count/reconciled_count`，漏掉运营提醒。
**验证**：
- 新增 `useDocumentWorkflowRace.test.tsx` 两例：① mock 回传 `note` → 断言 `msg.success` 文案含「AI 提取事实」「请重新执行」；② 无 `note` → 断言精简文案 `解析完成：成功 2 个文档`（向后兼容）。
