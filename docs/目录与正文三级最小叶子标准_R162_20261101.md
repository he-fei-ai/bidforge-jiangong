# 目录与正文「三级最小叶子」标准 R162（2026-11-01）

> **用户指令**：目录树生成的层级「至 L3 级，不显示也不生成 L4」——与 R151 硬性标准
> （一级下 3~5 个二级、二级下 3~5 个三级、三级下 4~6 个四级；四级为最小叶子）冲突；
> 裁定为**方案A**：目录树管到 L3 为止，「L3 下 4~6 个四级」的数量控制**从目录树校验移除、
> 转入 L3 叶子节的正文生成提示词**，并按方案A 执行修复与加固。
> **取代关系**：本报告取代 `docs/目录与正文强约束四级标准_R151_20261031.md`
> （R151 的「L4 为最小叶子」标准已翻转，原文仅作历史存档）。
> **轮次编号**：R162（避让并行会话已占用的 R160/R161）。

## 一、生产根因取证（翻转的直接依据）

只读实测生产库方案的三级树：**182 节点 = 9 L1 / 31 L2 / 142 L3**，L4 为 0。
在 R151「四级最小叶子」判据下：

1. **142 个 L3 全部违规**（每个 L3 下 0 个 L4 < 下限 4）——目录树全量红点、正文前置
   闸门直接拒绝，用户无法生成正文；
2. 合规修复轮 `fix_outline_compliance` 触发 AI 补齐四级时，**120s 超时即终局 failed**
   （超时块此前 `return None, info` 直接终结，不进入第二轮）；
3. 修复提示词注入现有目录上限 **12000 字符**，182 节点树 JSON ≈3~4 万字符，**被截断成
   残树**喂给模型。

三个因素叠加，形成「模型自然产出三级树 → 判违规 → AI 修复超时/截断 → failed」的死循环。
翻转方向为**放宽**（旧合规四级树在新判据下仍合规），因此**零数据迁移、零 DDL**。

## 二、R151 → R162 标准差异

| 维度 | R151（2026-10-31） | R162（2026-11-01，现行） |
| :-- | :-- | :-- |
| 最小叶子 | L4（正文写作单位） | **L3**（正文写作单位） |
| 层级上限 | L4，严禁 L5 | L4（**仅兼容层**，不作数量校验），严禁 L5 |
| 数量硬约束 | L1→3~5 L2、L2→3~5 L3、**L3→4~6 L4** | L1→3~5 L2、L2→3~5 L3（**L3 下不校验数量**） |
| L4 数量控制 | 目录校验（`CHILDREN_MIN[3]=4`） | **正文提示词**：L3 叶子节组织 4~6 个四级要点 |
| 判据常量 | `CHILDREN_MIN={1:3,2:3,3:4}` | `CHILDREN_MIN={1:3,2:3}`、`LEAF_LEVEL=3` |
| 禁 L5 | L4 挂子级 → `depth_exceeded` | 同（L4 兼容层不得再挂子级） |
| 数量校验作用域 | `2 <= level <= 4` | `2 <= level <= LEAF_LEVEL(3)` |

现行判据唯一事实源：`backend/app/services/outline_rules.py`（`OUTLINE_MAX_LEVEL=4`、
`LEAF_LEVEL=3`、`CHILDREN_MIN/MAX={1:3,2:3}/{1:5,2:5}`）。树形 `validate_outline_nodes`
与 DB 行 `validate_section_rows` 共用同一常量与违规码（`depth_exceeded` /
`too_few_children` / `too_many_children` / `numbering_mismatch`），文案唯一出口
`format_violations_message`（「目录结构不合规，请先修复目录」）。

1. **旧三级方案恢复可用**：182 节点三级树的 142 处红点自动清零，正文生成闸门放行

6. **L4 兼容层保留**：既有 L4 数据/手工新增/上传解析仍可存在与编辑，仅不作数量校验。

## 八、判据教训归档

1. **标准翻转 = 全链回扫，而非只改判据**：树判据、DB 行判据、提示词、Agent Schema、
   骨架、修复轮、前端镜像、导出行为锁八面必须同时翻；只改 `outline_rules` 会留下
   「提示词仍要求 L4、骨架仍产 L4」的第二事实源（R159 教训③同族）。
2. **放宽型翻转让旧数据自动合规，是零迁移的前提**：翻转前先证「旧合规四级树在新判据下
   仍零违规」，否则必须配迁移脚本（R151 是收紧型，才需要清洗二段式）。
3. **超时/截断是「模型产出与判据冲突」的放大器**：修复轮超时必须可续轮、注入上限必须覆盖
   真实树规模（182 节点 ≈3~4 万字符），否则判据冲突会静默升级为 failed。
4. **E2E 打桩落在被调方实际读取点**：E2 把 `collect_json_response` 打桩为抛错函数，
   才能证明「纯三级树直通」是**零 AI 调用**而非「AI 恰好返回合规」。
5. **`os._exit` 前必须显式 flush**：重定向到文件时 stdout 为块缓冲，判定行会全部丢失
   （本轮 E2E 首跑 0 行判定的直接原因）。
6. **全量失败的字节体检属数据层，不得放宽断言**：`export.py` 裸 LF 按 HEAD 约定
   归一 CRLF（autocrlf 环境下改判据是错误层面，R161 教训②同源）。
