## 四、修复项清单（17 项定罪，全部落地）

> P 级：P1 = 数据丢失 / 核心功能破坏；P2 = 明显缺陷影响用户体验；P3 = 边界/健壮性。

### P1（1 项）

**D-A · `list_sections` 方案 SELECT 缺 `name`/`type` ⇒ 工作台头部方案名/类型恒空白**
- 根因：`sections.py` `list_sections` 的 `SELECT ... FROM schemes` 列清单漏掉 `name`、`type` 两列；`scheme` 子集缺字段，前端 `SchemeWorkbenchPage` 只从本响应 `setScheme`，方案名/类型恒空白。
- 修法：SELECT 补 `name, type`（`sections.py:426-431`）。
- 护栏：`test_outline_r218::TestListSectionsAndTitleCap::test_scheme_select_includes_name_type`。

### P2（3 项）

**C-1 · `_UNIT_TAIL_CHARS` 缺 11 量词 ⇒ 「3 条施工便道」数字被静默丢弃**
- 根因：`3 条施工便道` 正文首字「条」不在表内 ⇒ 整行被判标题、数字 3 被丢弃（成稿标题「条施工便道」）。
- 修法：补「条口道节排列面孔眼遍趟」11 量词（`content_blocks.py:305`）+ 精准豁免表（`_UNIT_TAIL_EXEMPT_NEXT`，:309-336）——只豁免「编号+明确普通名词」形态（`3 条件`/`3 节点`），其余新量词**宁误判正文不误判标题**（正文误判=内容保留；标题误判=数字丢+编号错乱，危害更大）。
- 护栏：`TestUnitTailQuantity`（行为级 `条施工便道`→True / `条件`→False / `节电池`→True / `节点`→False + 源码棘轮 11 量词在表）。

**D-B · create/update 标题长度无上限 ⇒ save-outline 400 卡死死循环**
- 根因：`OUTLINE_TITLE_MAX_LEN` 只在 save-outline / 上传口判红；create_section / update_section 两条手工写路径裸奔——超长标题落库后，点「保存目录」被 400 卡死且不回滚坏行（死循环）。
- 修法：create（`sections.py:776-780`）与 update（`:922-925`）补 `> OUTLINE_TITLE_MAX_LEN` 拒绝（400，绝不静默截断）。
- 护栏：`TestListSectionsAndTitleCap::test_title_length_cap_both_paths`（count≥2）+ `test_outline_title_max_len_value`（==200）。

**D-C · `buildTree` 漏映射 `generation_standard`/`last_generation_standard`/`word_status` ⇒ 刷新后章节级覆盖回显丢失**
- 根因：前端 `buildTree` 只映射部分字段，章节级生成标准覆盖（「沿用方案（X）」回显）刷新后丢失。
- 修法：`workbenchTypes.ts:34-36` `OutlineNodeInput` 声明 3 字段；`outlineTreeModel.ts:81-83` `buildTree` 映射。
- 护栏：前端 `outlineR218.test.ts` D-C（`?raw` 源码断言）。

### P3（13 项）

**N1 · heading_v1 L1 `min(30)` 硬钳 ⇒ 31+ 章重复章号**
- 根因：`min(30, counters[0])` 硬钳在 30 ⇒ 第 31/32/… 章标题字面相同（都「第三十章」），跨章撞号。
- 修法：字表内中文、超出回退阿拉伯（第31章），与 V2 同口径（`heading_v1.py:43-46`）；V1 生产调用点=0（仅 heading_standard 再导出 + 测试），R210 L1-9 护栏锁定导出链不得用 V1。
- 护栏：`TestHeadingV1ChapterBeyondThirty`（行为 31→第31章 / 35→第35章 + 源码棘轮 `min(30` 不得回流）。

**N2 · 结构自检两处局部 `_collect_mounted` 同构重复 ⇒ 复用模块级**
- 根因：`_outline_structure_report`（:2567）/ `_repair_outline_structure_numbering`（:2658）的局部 `_collect_mounted` 与模块级 `_collect_section_ids` 同构（R216 收口漏结构自检路径）；模块级版更健壮（跳过非 dict）。
- 修法：两处统一复用 `_collect_section_ids`（`sections.py:2570` / `:2654`）。
- 护栏：`TestSectionTreeBuild::test_structure_report_reuses_collect_section_ids` / `test_repair_structure_numbering_reuses_collect_section_ids`（`def _collect_mounted` 不得回流）。

**N3 · `_sort_children` 无深度护栏 ⇒ 脏数据深链 RecursionError**
- 根因：递归排序无深度上限，>200 层 parent_id 链式成链（非成环）撞 Python 递归上限抛 RecursionError，整棵树 500。
- 修法：`_TREE_SORT_MAX_DEPTH = numbering._MAX_TREE_DEPTH`（单一事实源，:29-32）+ `if _depth > _TREE_SORT_MAX_DEPTH` 告警停止深入（:227-233，fail-soft）。
- 护栏：`TestSectionTreeBuild::test_sort_children_depth_guard` + `test_sort_children_reuses_numbering_max_depth`。

**N4 · `_STRIP_NUMBER_RE` 缺 Unicode 罗马/中文大写 ⇒ 双重编号叠写**
- 根因：`Ⅰ. 总则`/`壹、总则` 不在剥离类 ⇒ 显示层再套一层（「Ⅰ. Ⅰ. 总则」）。ASCII 罗马（`I.`）**刻意不剥**（与导入识别侧一致，防「I 型钢」误剥）。
- 修法：补 Unicode 罗马（`Ⅰ-Ⅿ`/`ⅰ-ⅻ`）+ 中文大写（`壹贰叁肆伍陆柒捌玖拾佰仟零貳參陸`），仅后接分隔符才剥（`numbering.py:158-159`）。
- 护栏：`TestNumberingRomanAndUppercase`（行为 Ⅰ./壹./貳.→剥，Ⅳ级/I. 总则→不剥 + 源码棘轮）。

**O-1 · all_failed 出口漏 `failed_count` ⇒ 前端统计 0**
- 根因：R216 补 `resumed_chapters`/`level1_*` 时遗漏该键；checkpoint_schema 白名单已登记，前端按 `typeof evt.failed_count === 'number'` 读取，缺失则失败章数显示 0。
- 修法：`_fail_payload`（`sse_handlers.py:2497`）+ `_fail_event`（`:2532`）补 `"failed_count": len(failed_chapters)`。
- 护栏：`TestAllFailedExitCounts`（count≥2）。

**O-2 · checkpoint SQL 硬编码终态字面量 ⇒ 与常量双来源**
- 根因：SQL `status IN ('stopped','failed')` 与 `_RESUMABLE_TASK_STATUSES` 同义但两份来源；状态集合演进只改常量则 SQL 漏接（续跑取数/复用判据漂移）。
- 修法：参数化 `_status_ph = ",".join("?" for _ in _RESUMABLE_TASK_STATUSES)` + `status IN ({_status_ph})` + `(scheme_id, *_RESUMABLE_TASK_STATUSES, ...)`（`sse_checkpoint.py:278-285`）。
- 护栏：`TestCheckpointStatusParameterized`（参数化在 + 硬编码字面量不得回流）。

**O-3 · 子目录提示词事实行与指纹计算二次独立查询 ⇒ 指纹失源**
- 根因：两次查询中间隔着 L1 AI 调用窗口，期间事实行可变 ⇒ 指纹记录旧事实、子目录提示词用新事实，陈旧复用防护失效（复用章不含新事实，指纹却「匹配」放行）。
- 修法：复用指纹侧 `_fp_facts_rows`（`_outline_facts_rows = list(_fp_facts_rows)`，`sse_handlers.py:2015`）——「指纹所比对 = 提示词所注入」。
- 护栏：`TestSubdirectoryFactsReuseFingerprintRows`。

**O-4 · 全续跑轮次 `continue` 跳过 `sub_done` ⇒ 进度滞后**
- 根因：本轮全是续跑章、无 AI 调用，但 `len(full_outline)` 已含续跑预填充，前端进度停在上一轮。
- 修法：`continue` 前补 `_prog["sub_done"] = len(full_outline)`（`sse_handlers.py:2334`）。
- 护栏：`TestFullResumeRoundSubDone`（count≥2）。

**C-2 · 编排提示词注入存储态编号 ⇒ 与正文提示词形态分叉**
- 根因：`_prompt_number` 是存储态（"3.2.4"），正文提示词（R214 FIX-1）已转展示态（"2.4"），唯独编排提示词仍直传存储态 ⇒ 同章节两个提示词两个编号形态，模型易把前者当正文子标题号写入内容。
- 修法：`stored_id_to_display(_sec_stored) or _sec_stored`（fail-safe，不注入空号），`section_number=_sec_display`（`content_plan.py:311/:324/:331`）。
- 护栏：`TestContentPlanDisplayNumber`。

**C-3 · `_sec_no`/`_sec_prefix` 脏数据无兜底 ⇒ 空/脏编号透传提示词**
- 根因：`_section_outline_number` 已按 `stored_outline_id` 判非法→""，旧实现仍把空/脏值透传给提示词 ⇒ 模型拿不到合法编号却被告知「当前章节编号」为脏值。
- 修法：以 `_sec_stored` 非空为合法性判据（与 `_section_number_for_prompt` 同源），非法时统一注入 `SECTION_NUMBER_MISSING`（`sse_handlers.py:4907-4920`）；合法时行为逐字不变。
- 护栏：`TestSectionNumberMissingFallback`（源码）+ `TestSectionOutlineNumberFailClosed`（判据行为）。

**C-4 · `_TABLE_CAPTION_RE` 与导出侧双实现漂移 ⇒ 预览/成稿表号叠写**
- 根因：正文侧只认半角空格/半角数字/无「格」字/无零宽 ⇒ 「表６-１」「表格 6-1」正文预览不剥、成稿剥（同段两套表号叠写）。
- 修法：`_TABLE_CAPTION_RE` 补全角 `０-９`、「格」字、零宽（`\u200b-\u2060\ufeff`），与 `_export_docx_parts._LEADING_TABLE_NUM_RE` 对齐（`content_blocks.py:147-153`）。
- 护栏：`TestTableCaptionRegexAligned`（9 案例两侧行为逐字一致 + 源码棘轮）。

**D-D · 前端零消费 `unmounted_count` ⇒ 导出/重排对成环章节静默缺章**
- 根因：`/export-tree`（R216）与 `/reorder` 回传 `unmounted_count`，前端零消费 ⇒ 成环/悬挂章节从树上消失却无提示。
- 修法：`exportTree`（`useOutlineActions.tsx:269`）+ `reorder`（`useOutlineTreeEdit.tsx:322`）消费 `outlineUnmountedNotice(data)`（与 R213 FIX-12 同口径，不阻断）。
- 护栏：前端 `outlineR218.test.ts` D-D。

**D-E · 前端零消费 `empty_top_chapters` ⇒ 快照回退空壳章无提示**
- 根因：快照回退响应含 `empty_top_chapters`（空壳一级章），前端零消费。
- 修法：`restoreOutlineVersion` 消费（`OutlineVersionsPanel.tsx:102-103`，>0 时 WARNING，不阻断回退）。
