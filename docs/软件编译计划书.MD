## 1. 编译目标

### 1.1 目标产物

| 产物 | 形式 | 说明 |
|------|------|------|
| 后端服务 | Python 包 + SQLite 数据库 | FastAPI 应用，编译 = 安装依赖 + 生成数据目录，无传统编译步骤 |
| 前端静态资源 | Vite 构建产物 `frontend/dist/` | 开发用 Vite Dev Server，生产用静态文件由后端托管 |
| 数据库文件 | `backend/data/scheme_assistant.db`（WAL 模式；`database_url` 见 `config.py:28`，`data/app.db` 为 0 字节历史遗留文件） | 启动时自动迁移 + 幂等补列，无需手工建库 |
| 一键启动 | `start_all.bat` | 5 阶段：清端口 → 装依赖 → 起后端（`start_backend.ps1`）→ 前端 → 探活开浏览器；配套 `stop_all.bat`、`cleanup_guard.ps1`（30 秒孤儿进程清理） |

**运行环境要求**：

- 操作系统：Windows 10/11 或 Linux
- Python：**3.12+**（CI 主腿 3.12，观察腿 3.14；`.python-version` = 3.14；生产实测 3.14.4；`requires-python = ">=3.12"`，见 `backend/pyproject.toml:18`）
- Node.js：**20+**（CI 固定 22）
- 内存：≥ 4GB（推荐 8GB）
- 磁盘：≥ 2GB（含依赖缓存与数据文件）
- 数据库：内置 SQLite（WAL 模式），随应用编译，无需单独安装

### 1.2 必需软件

| 软件 | 版本要求 | 用途 |
|------|---------|------|
| Python | **3.12+**（推荐 3.14.x，与生产一致） | 后端运行环境 |
| Node.js | **20+**（推荐 22，与 CI 一致） | 前端构建 |
| npm | 随 Node.js 附带 | 依赖安装 |
| Git | 2.30+ | 版本管理 |

### 1.3 可选软件（仅特定导出/解析功能需要）

| 软件 | 版本要求 | 用途 | 未安装时的降级行为 |
|------|---------|------|-------------------|
| LibreOffice | 7.x+ | 批量转换 | 不影响 DOCX/PDF 导出；`.txt` 导出直接由 Python 生成，不受影响 |
| Microsoft Word 或 WPS | 最新版 | COM 自动化导出 PDF | 未安装时 PDF 按钮返回 `PDF_COM_UNAVAILABLE` 错误 |
| Legacy Office（旧版 Office） | 2010+ | `legacy_office` 服务（soffice 自动探测 + Word/WPS COM 兜底） | 自动跳过，走其他导出通道 |
| Tesseract OCR | 5.0+ | 扫描 PDF 转图片 | 未安装时自动检测并提示，不影响其他功能 |
| RapidOCR | `rapidocr_onnxruntime==1.2.3`（`requirements-ocr.txt`） | 本地中文 OCR | 同上，未装则不启用 |
| Docker | 20.x+ | 自行编写镜像定义（仓库当前未提供，见 3.3） | 不影响本地编译 |
| Visual C++ Redistributable | 2015-2022 | `python-multipart` 依赖 | 缺失时 pip 安装失败，见 5.2 |

> 注：v5.4 起 `pywin32` + `docx2pdf` 已从核心依赖移到 `requirements-windows.txt`（仅 Windows 导出链路需要）；项目不使用 Redis/消息队列（全库无引用）。

### 3.1 方式一：一键启动（推荐，Windows）

```bash
# 双击 start_all.bat 或在命令行执行
start_all.bat
```

脚本会按以下顺序执行（5 阶段，任一阶段失败立即中止并打印原因）：

| 阶段 | 动作 | 产物/日志 |
|------|------|----------|
| 1 | 清理被占用端口（8000/5175） | 进程查杀记录 |
| 2 | 后端依赖强校验（`import fastapi,uvicorn,aiosqlite,pydantic` → 整包导入图） | 失败则打印缺失包名 |
| 3 | `start_backend.ps1` 单进程启动后端（**无 `--reload`**，`--timeout-graceful-shutdown 30`），探活 `/api/v1/health` | `logs/backend.log`（5MB×3 轮转） |
| 4 | 前端 `npm install` + `npm run dev` | 5175 端口 |
| 5 | 全链路探活并打开浏览器 | `http://localhost:5175` |

> 配套：`stop_all.bat` 停止；`cleanup_guard.ps1`（`-Clean`/`-Shutdown` 模式，按命令行指纹门禁）清理占端口残留、泄漏 `pytest`/测试 worker 树、绑定失败的后端 python。**优先用 stop_all/cleanup_guard，不要手工 taskkill**（见 5.9）。

### 5.7 Windows 环境铁律（违反必踩坑）

| # | 铁律 | 原因 |
|---|------|------|
| 1 | **编码铁律**：所有源文件必须 UTF-8 with BOM | 未带 BOM 中文注释被 Python/gbk 解码 |
| 2 | **输出铁律**：cmd 脚本用 `chcp 65001 >nul` + `set PYTHONIOENCODING=utf-8` | 防止 GBK 编码异常 |
| 3 | **命令铁律**：不用 `head` / `tail`，用 PowerShell `Select-Object -First/-Last` | 避免命令不存在 |
| 4 | **文件名铁律**：产物用纯 ASCII（`wb_04_*`），中文放正文 | Word XML 包含中文路径 |
| 5 | **路径铁律**：不用 `/tmp`，用 `tempfile.mkdtemp()` | 跨平台路径兼容 |
| 6 | **重跑铁律**：连续失败 2 次停 60s 再用新编号 | 防止文件句柄占用 |
| 7 | **导入铁律**：`import` 放文件顶部 | `__init__.py` 会破坏模块导入 |
| 8 | **死循环铁律**：必须有失败计数器和退出路径 | 防止不可中断循环 |

| 问题 | 原因 | 解决方案 |
