## 二、功能清单与数据链（代码依据）

解析提取模块端到端链路：

```
选择文件
  → 前端三段预检（类型/单文件大小 → 累计总量 200MB → 文件数 20）
  → POST /documents/upload（流式落盘原文层 raw：MD5/SHA256 + meta + documents_index.json）
  → POST /documents/parse/{id} 或 parse-all
      → file_parser 按扩展名分派（docx/pdf/md/txt/xlsx/xls/csv/图片/doc/wps 等 14 种）
      → OCR / MinerU / legacy_office 兜底
      → parse_status 写 success/failed（唯一合法值 pending/success/failed）
      → md_structured：pages/tables/images/formulas 结构化
      → doc_chunker：section/table/image/semantic 四类块 + source_ref 溯源
      → 解析层 parsed 落盘（_parsed.md/_pages.json/_tables.json/_images.json/_meta.json）
      → 语义层 semantic 索引 + 四层入库 doc_chunks
  → 自动分类（doc_categories 关键词）→ 用户可在列表手动改判 PATCH /documents/{id}/category
  → 提取层：bid_analysis_items / global_facts → doc_extractions + extracted/*.json
  → 监控：/system/activity SSE+轮询，documents 段统计总数/成功/失败/积压/失败率
```

## 四、缺口与技术债清单

| 编号 | 缺口 | 影响 | 优先级 |
|------|------|------|--------|
| D5 | 表格分隔行正则过严：列分组量词 `+` 使单列分隔行 ``| --- |`` 不匹配；`-{2,}` 使单横线 ``|:-:|`` 漏判（GFM 合法为一个或多个 `-`） | **单列表格整表漏抽**（材料表/设备表常见单列） | 高 |
| D6 | 表格标题候选把纯标记行（页注释、`[IMAGE:..]`）与混排标记行整行当标题 | 表格 title 出现 `<!-- page:2 -->` 等标记文本，下游引用/展示污染 | 高 |
| E1 | 公式只在单行内 search，跨行/多条 `$$...$$` 全部漏抽，且公式原文混入页文本 | 结构化 formulas 缺失、页文本含 LaTeX 噪声；**联动：`$$` 行被当成后续表格标题**（修复实测发现，新增守卫） | 高 |
| E2 | /system/activity 无文档解析统计，批量上传后解析失败率/积压不可见 | 监控盲区，故障发现晚 | 中 |
| 测试债 | 分类 Select 下拉改判、compact 展开/收起、监控面板均无组件级交互测试 | 交互回归无护栏 | 中 |

技术债复核（此前疑似项，经核实**非缺陷**，避免重复劳动）：三侧扩展名集合无漂移；xlrd 缺失有 openpyxl/CSV 兜底与明确告警；三段预检配额为保守兜底而非无上限。

### D5 · 表格分隔行正则

[md_structured.py L31](file:///j:/编程/专项方案工具箱/backend/app/services/doc_pipeline/md_structured.py#L31)

```python
# 旧：r"^\|?\s*:?-{2,}:?\s*(\|\s*:?-{2,}:?\s*)+\|?$"
_SEP_ROW_RE = re.compile(r"^\|\s*:?-+:?\s*(\|\s*:?-+:?\s*)*\|?$")
```

- `+` → `*`：单列分隔行可匹配；
