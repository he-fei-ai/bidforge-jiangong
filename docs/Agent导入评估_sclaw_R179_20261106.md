## 6. 反向结论：不建议引入的部分

### 6.1 明确不建议引入

| 能力 | 为什么不建议 |
|---|---|
| `.sclaw` 客户端本体 | 无源码、无授权、含凭据与用户会话。**裁决 1：可本机使用，但不得搬运 / 分发 / 进入交付物**；「原样引入」仍然禁止。 |
| `portable-agent` 整仓内嵌 | 自有代码（裁决 2），但形态是 CLI 单机、路径依赖 workspace，整仓塞进 FastAPI 服务层会引入不必要耦合；**改为按需摘取**。 |
| `core/generate.py` 调度模型 | 单轮工具循环（`max_steps=12`）与 Phase F 的分区混合生成不是同一层；借它会拉低现有编排。 |

| `core/facts.py` 事实引擎 | 参数表与单位换算为硬编码常量；本仓 `facts_builder.py` 已有预算、账本与交叉校验。 |
| `core/readers.py` 解析器 | 明确不做 PDF/扫描件（`:29`），弱于本仓 `file_parser.py` + `ocr.py`。 |

### 6.2「看着能做，其实做不了」

1. **全过程编排 / 规划**：`core/loop.py` 是单轮工具循环，最多 12 步（`config.py:30`、`loop.py:44`、`:89-90`），没有 planner、没有任务图、没有阶段门禁、没有审批节点。它不能贴到四阶段流水线上做调度。
2. **长期记忆**：`workspace/MEMORY.md` 只有 202 字节模板；`AGENTS.md:5` 说明这几个 md 只是「每轮开头注入的用户上下文」，不是可写入、可检索、可衰减的记忆系统。`README.md:203` 还明确「上下文不做压缩」。
3. **工具生态**：只有 5 个本地工具，MCP `servers=0`；没有权限模型、没有工具级审批、没有并发隔离。
4. **PDF / 扫描件解析**：`core/readers.py:29` 明确放弃，直接 skipped。
5. **图表**：无任何渲染路径。
6. **多模型治理**：单 provider + 环境变量；无供应商注册、无并发闸门、无用量与成本统计。
7. **评分项 / 废标条款覆盖**：无该概念。
8. **并发与预热**：无异步、无并发上限、无预热编排。
9. **SSE 流式**：`core/llm.py` 有流式客户端，但领域生成 `core/generate.py` 是同步逐段，无事件流契约，不能直接对接本仓 SSE。

### 6.3 可复用边界（`portable-agent`，裁决 2 落地）

**可复用（逐个点名）**

| 模块 | 可复用什么 | 替代本仓哪块 / 补哪个空缺 | 准入 / 限制 |
|---|---|---|---|
| `agent.py` | CLI 骨架：argparse 子命令、REPL、`--no-tools` 断电开关、配置打印掩码 | **补空缺**：本仓目前没有统一的「本机运维/诊断 CLI」入口（`backend/tools/perf/` 只是基准脚本），可用该骨架改造为 `tools/` 下的诊断 CLI，替代「临时脚本 + 手工命令」 | 准入 P-1、P-3；持续限制 P-4 |

**`agent.py` 的边界（必须同时成立）**：它是**工具壳**——只提供子命令入口、参数解析、输出打印与掩码。**不承担智能体调度**（不引入 `core/loop.py` 的循环、不做 planner、不接管任务状态机），**不接入正文生成链路**（不参与大纲→事实→正文→审核任何一段的生成或续写），**不替代 Phase F 的分区混合生成**（Phase F 的段级路由与混合策略仍由本仓 `section_router.py` 等承担，CLI 只调用、不实现）。越出这条边界即视为超出 §6.3 的复用范围。

**不可复用（明确划界）**

- `core/loop.py` / `core/generate.py` 的**调度模型**：单轮工具循环、串行逐段，与 Phase F 的分区混合生成不是同一层，接入会降级现有编排。
- `core/docx.py` / `core/review.py` / `core/facts.py` / `core/readers.py` 的**领域实现**：均弱于本仓对应模块，只作设计参考。
- **提示词与文档模板**：不复用原文，只提炼抽象机制（见 §6.4）。
