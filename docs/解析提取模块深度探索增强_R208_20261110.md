## 七、教训归档

1. **「像素闸」不等于「内存闸」**：闸门写在哪里不重要，**它在数据流的哪一段
   生效**才重要 —— R203 的 `convert().resize()` 把闸门放在了「全尺寸解码」
   之后，闸门约束输出却放任峰值。**验证必须追踪底层库的调用时机**
   （本轮用 monkeypatch `Image.Image.load` 记录 load 时机当场抓实），
   而非只看输出尺寸。
2. **孪生实现要一起修**：R203 BE-13 修了 `delete_doc_tree` 却漏了
   `delete_project_docs_root`（同一对孪生）；R203 BE-17 修了 5 处 commit
   裸奔却漏了 `purge_document` 与 `_mark_parse_failed`。
   **「同族」不是「同名」—— 发现一个就要 grep 全族**。
3. **「教训只在同类一侧落实」的第三次实证**：FactsTab 内联的文档列表是
   DocumentParseList 的**副本**，R191 C-F3 与 R203 FE-5 两轮都只落在
   DocumentParseList 一侧 ⇒ 副本里两个缺陷活了两年。
   **组件副本必须成对锁**（本轮已让两侧门禁口径逐字一致并双向断言）。
4. **零 DOM 覆盖的组件 = 缺陷隐身区**：FactsTab 的行内文档列表整块无 DOM
   断言 ⇒ FE-1/FE-2 两个 P1 长期存活。**组件级测试要覆盖「按钮门禁」与
   「回调参数」两类行为**，而不只是渲染。
5. **静态源码锁必须用 AST 而非字符串**：本轮两处护栏用
   `"ignore_errors=True" not in src` 判定，当场**假红** —— 因为函数注释里
   引述了该字面量。判定「代码结构里有没有某个调用形态」必须走 AST。
6. **组件级测试找按钮必须精确匹配**：Tab 级按钮「② 解析文档」与行内按钮
   「解析」同名，`includes` 匹配会命中前者 ⇒ 点错按钮 + 断言错 disabled 态
   （本轮当场抓红）。可见文本查找须用 trim 后**精确相等**。
7. **护栏样例必须先跑一遍被测函数**：BE-11 行为测试首版用伪造 PNG 字节配
   `.xlsx` 扩展名 → 被 `signature_valid` 拒绝 → `saved` 为空 → IndexError。
   样例要满足**真实签名约束**（R203 教训⑤的再次实证）。
8. **既有护栏红先问「锁意图还是锁实现」**：FE-8 给 guard 补用户反馈后，
   R191 的 C-F9 源码锁（字面量 `if (...) return;`）变红 —— 该护栏锁的是
   **「三条防重入 guard 存在且消费对应 ref」**这一**意图**，实现形态变化
   不违背意图 ⇒ **重锚到意图并加强**（补 msg.info 断言），不删测试。
   本轮**两次**触发该判定（R191 C-F9 + R193 源码棘轮切片起点），两次都是
   **重锚到意图**、断言强度不减。
9. **同名标识符在不同作用域可能是不同类型**：本仓的 `msg` 有**两个**——
   FactsTab 的组件 prop（`{success, error}`）与 `DocumentWorkflowDeps.msg`
   （`{success, error, warning, info}`）。改反馈调用前必须先确认是哪一处，
   否则 TS2353 会**连带击穿仓库内「守 tsc 退出码」的护栏**
   （`test_review_autofix_closeout_r55::test_tsc_no_emit`）——
   本轮即由此被抓。**一次类型错误会跨模块放大成别处的红灯。**
10. **A/B 脚本自身也会被本轮教训反噬**：① 锚点**非唯一**（孪生实现的短锚点
    命中 2 次 → 断言失败**中断整轮**，只跑完 5/15）；② 变异**打偏**（摘的
    是日志行而非护栏真正断言的 `await db.rollback()` → 护栏仍绿 → 误判
    MISSED）。⇒ 变异必须摘掉**护栏断言的那个东西**，且**单变异异常不得
    中断整轮**（记 ERROR 继续）。
