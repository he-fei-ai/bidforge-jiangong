## 二、Word 2010+ 专有扩展规避方案（核心）

### 2.1 实测取证（本轮探针实拍）

python-docx 1.2.0 默认模板构建的 `word/document.xml` 根元素：

```xml
<w:document xmlns:wpc=".../wordprocessingCanvas"      ← Word 2010+ 画布
            xmlns:wps=".../wordprocessingShape"        ← Word 2010+ 图形
            xmlns:wpg=".../wordprocessingGroup"        ← Word 2010+ 组合
            xmlns:wpi=".../wordprocessingInk"          ← Word 2010+ 墨迹
            xmlns:w14=".../word/2010/wordml"           ← Word 2010+ 主扩展
            xmlns:wp14=".../wordprocessingDrawing"     ← Word 2010+ 绘图
            mc:Ignorable="w14 wp14">
```

历史轮次只清了标题样式里的 `<w14:textFill>`（R117 FIX-6），**根元素声明从未清理**；
`word/settings.xml` 还含两个 w14 元素（`<w14:docId>`、`<w14:defaultImageDpi>`）。

### 2.2 修复实现：`backend/app/services/docx_namespace.py`

落盘后 zip 级逐部件清理（`sanitize_docx_file`，原子替换 + Windows 3 次有界重试）：

1. 根元素删除「未使用」的 2010+ 命名空间声明（w14/wp14/w15/w16*/wpg/wps/wpc/wpi）
   ——**仅当前缀在部件其余部分零引用**（元素标签或属性名），绝不删仍被引用的声明（防 XML 损坏）；
2. `mc:Ignorable` 剔除被删前缀，列表为空整属性删除；`mc` 无引用时连 `xmlns:mc` 删除；
3. 防御性删除 `w14:paraId/textId/anchorId/editId` 残存注释属性；
4. `word/settings.xml` 定点清除 `<w14:docId>`/`<w14:defaultImageDpi>`（均为可选注释性设置：
   docId 由 Word 自行再生成；defaultImageDpi 只影响缺 DPI 图片的假设值，本仓插图一律显式 EMU 定尺寸）；
5. **刻意不动**：`theme*.xml`（其内部 a14/adraw 属 DrawingML 主题定义，独立部件、
   被 styles.xml 关系引用，动它收益为零风险为正）、`w10/v/o/mo/mv`（Office 2003~2008
   遗留命名空间，非「Word 2010+ 扩展」范畴）。

配套只读校验 `check_docx_file`：报告残留的 2010+ 声明 / Ignorable / 专有元素 / 注释属性。

## 四、导出后校验（需求四·导出后校验）

新增 `backend/app/services/export_validate.py`，在 `doc.save` 之后双闸校验：

```
_build_docx_sync
  ├─ _backfill_cross_reference_fields(doc)          （R128）
  ├─ validate_document(doc)                          ← 段落级（save 前，计数进统计/日志）
  │    · Markdown 残留：#标题行 / **加粗 / 反引号 / GFM 分隔行 / ![]() / []()
  │    · HTML 标签残留（判据懒导入 export._AUDIT_RULES，唯一事实源）
  │    · HTML 实体残留（&nbsp;/&lt;/&#xx; …）
  │    · 占位符残留（××/【待补充 + TODO/TBD/FIXME）
  │    · 标题大纲映射（Heading 1~9 → level+text）
  ├─ _log_fix_stats() / _normalize_docx_strict_sequence(doc) / doc.save(out_path)
  ├─ sanitize_docx_file(out_path)                    ← Word 2010+ 命名空间清除
  ├─ check_docx_file(out_path)                       ← 命名空间回潮校验
  └─ 返回 fix_stats（ns_parts_sanitized / postcheck_* / ns_clean / outline_entries）
       → X-Fix-Stats 响应头 → 前端 exportResponse.ts（fixStatsParts 成功文案 /
         fixStatsWarnings 告警回流）＋ INFO 日志大纲映射
```

**设计原则**（对齐导出前体检「只体检、不篡改」）：校验失败不阻断交付、不改写产物，
只产出结构化计数与样例供前端提示与人工回查。

**「标题映射真实页码」的诚实结论**：无渲染引擎（本机无 Word/WPS/LibreOffice 离线
渲染）时无法离线计算真实页码；本仓采用 OOXML 标准路径——标准 TOC 域 +
`updateFields=true`，Word/WPS **打开即自动刷新出真实页码**（跨软件兼容的唯一可靠
做法）；本轮额外产出标题大纲映射（层级+标题，日志留痕 + 计数透出）供目录收录范围
核对。真实页码离线回填列为已知限制（需引入渲染引擎，独立排期）。

⚠️ **教训留痕**：`outline_map`（中文标题）**刻意不进** X-Fix-Stats 响应头——HTTP 头
只允许 latin-1，中文标题导致 starlette `init_headers` 抛 `UnicodeEncodeError`、整条
导出 500（本轮首跑实拍，23 个用例失败的根因）；只透出 `outline_entries` 条数。

## 十一、配置项与兼容性说明

**零新增配置项**。全部新能力随 `_EXPORTER_VERSION=30` 生效：
- 命名空间清除与导出后校验内建于构建链路（fail-soft，无开关）；
- matplotlib 为可选依赖：未安装时公式降级链自动跳过图片级（行为与 v29 一致）；
- v29 及更早缓存行由内容指纹（含 exporter 版本）自然失效，首次导出全量 miss 一次（预期）；
- 前端新键为加法式：旧前端忽略未知键不抛错（护栏锁定）。

## 十二、已知限制与刻意不改（留痕）

1. **真实页码离线回填**：需渲染引擎，本机无 Word/WPS/LibreOffice CLI；TOC 域 +
   updateFields 已覆盖「打开即得真实页码」（见 §四）；
2. **正文标题 `#` 语法**：与文本编号契约冲突，刻意不改（§3.1）；
3. **图表类型收窄**：既有 7 类比需求更宽，收窄是回归，不改；
4. **`w10/v/o/mo/mv`/theme 内部扩展**：非 Word 2010+ 范畴/独立部件，刻意不动；
5. **export.py 四层拆分**：R128 既定遗留，独立排期。
