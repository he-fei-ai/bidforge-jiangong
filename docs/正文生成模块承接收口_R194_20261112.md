## 五、修复项清单（16 项，file:line 为落地时位置，行号以当前合并树为准）

### FIX-1（P2）早期停止/异常路径终态载荷 NameError
`_stopped_payload`/`_error_payload`（sse_handlers 薄包装）在 `progress is None` 时调用 `_progress_now()`，
而该名字只在 try 内 :3391 才 def 绑定——字数分配 AI 调用期间点停止（`raise CancelledError`）与准备阶段
任何异常（章节树/事实/知识库装配）都会**先于 def 执行**到达终态 yield → 闭包单元为空 → NameError →
终态事件（含 failed_sections 明细）整体丢失，前端只见流错误。B1 拆分注释明载同形纪律
（`_word_tol 提前置 None`），`_progress_now` 漏了同形处理——R167 BUG-1「分支条件绑定 + 无条件引用」家族。
**修**：`_word_tol` 旁预绑定只读版 `_progress_now`（`_prog`/`_monotonic_progress`/`_weighted_progress`
均已 try 前就绪），try 内真实版重绑定，行为与拆分前逐字一致。
护栏：源码锁（预绑定版在薄包装 def 之前 + 恰两份 def + 首份不写 progress_max）；既有
terminal_payload 24 例全绿（monkeypatch 掩盖 NameError 的旧假绿由源码锁补位）。

### FE-13（P2）重挂/手动接管回填 activeTaskIdRef——控制按钮可达性
断线重挂路径 `taskId = hit.taskId` 只赋局部变量、手动接管（useUnknownTaskRecovery）同样不回填

### FE-16（P3）刷新接管/手动接管终态消费 content_result——三路恢复口径统一
