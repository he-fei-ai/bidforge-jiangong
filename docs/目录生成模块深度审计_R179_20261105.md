## 3. 深度探查结果（按维度）

### 3.1 目录树构建
- `_build_tree`（sections.py:103）以 `(sort_order, id)` 稳定排序，父子关系完全由 `parent_id` 决定；编号不来自任何字段拼接，因此「子承父系」结构性成立。
- 孤儿节点（`parent_id` 指向不存在行）被当作根节点处理（sections.py:150 附近），会在重编号时获得新的章号；属防御性兜底，非本轮缺陷。

### 3.2 章节编号与多级同步
- `renumber_outline_nodes`（numbering.py:229）按深度分配 `id` 与 `level`，并校验 `id` 深度与 `level` 一致；层数上限 3 由 `normalize_outline` 先裁剪。
- `renumber_section_outline_ids`（numbering.py:299）从 DB 行重建树后统一回写 `outline_json.id`/`level`/`sort_order`，`level = id.count(".")+1`，不会出现「id 与 level 双轨」。
- 实测层级完整率：40/40 = 100%（见 §4）。

### 3.3 结构写入口是否都触发重算
- `create_section`:651、`update_section`:876、`delete_section`:1000、`save_outline` 之后 `:1451`、`reorder_sections`:1975 均调用 `renumber_sections_after_reorder`；随后统一 `_renormalize_all_section_contents`。
- 结论：不存在「改了标题/位置但编号不重算」的漏调入口；`update_section` 纯改名分支只做本章规范化（不影响编号），已在注释中说明。

### 3.4 DB 子章节与正文 Markdown 子标题编号冲突
- 「本章有 DB 子章节时，正文子标题降级」在落库侧（numbering.py:478 起）与导出侧（export.py:2885 附近）均已实现，判据同为 `has_children` + 配置 `body_subheading_demote_with_children`。
- 但两侧的**前缀处理与重复标题处理**此前不一致（详见 §5），造成同一章「落库正文编号」与「导出成稿编号」错位。

### 3.5 AI 调用与提示词
- 正文生成提示词通过 `content_runtime.py` 注入章节编号、上级链路与子标题规则；目录生成终态在 `sse_handlers.py:1883` 与 `_sse_outline_review.py:1320/1387` 统一 `normalize_outline`，AI 返回的局部编号不会落库。
- 发现一处「提示词示例泛化」问题（示例固定写 `1.1`，未按本节前缀举例），因函数最终会重写编号，仅记为遗留建议，未改动（改动会牵动现有提示词断言）。

### 3.6 数据链与存储
- 章节编号唯一事实源：`sections.outline_json.id`；`level` 为派生冗余列，由 `renumber_*` 同步写入，读侧（导出、正文规范化）均以 `outline_json.id` 为主。
- 正文子标题编号**不单独存列**，而是以 Markdown 标题文本持久化，因此「重规范化幂等性」是数据正确性的前置条件（见 §5 BUG-A）。

### 3.7 路由与接口
- `/sections` 增删改、`/reorder`、`/save-outline`、`/adjust-outline` 全部走重算+重规范化；`/reorder` 仅支持同父兄弟排序（前端也只实现了兄弟交换），跨父级移动由 `update_section` 承担。
- `reorder_sections`:1906 对入参做完整性校验，按 DB 中 `parent_id` 分桶计算兄弟序号，避免全局序号破坏层级。

### 3.8 跨模块传递
- 导出目录与正文标题：导出侧 `heading_gen` 计数器与 `outline_json.id` 在重编号后一致；`write_section` 用标题前缀解析与树计数双路，均来自同一树。
- 事实/审核模块使用 `outline_json.id` 作为章节定位，不受本轮修复影响。

### 3.9 容错 / 缓存 / 并发 / 日志 / 配置
- 缓存：6 个结构写入口均调用导出缓存与一致性扫描缓存失效（sections.py:656/919/1005/1453/1980/2138）。
- 容错：`load_scheme_section_index` 读取失败返回空索引，`normalize_section_content_subheadings` 对无法解析的 `outline_json` 采用 fail-soft 跳过。
- 并发：目录生成期间存在单飞/并发闸门；本轮未改动状态机。
- 日志：本轮在 `numbering.py` 关键分支补了口径说明注释，便于后续排查「双重前缀」类问题。
- 配置：本轮**未新增配置项**。

### 3.10 编号「正向传递」的两个实测缺陷（本轮修复对象）

**BUG-A：落库侧未剥离源文自带的字母序前缀，导致双重前缀与非幂等无界增长**

- 落库侧 `numbering.py:587` 旧代码：`pure = _strip_title_number(...)`，`_strip_title_number` 不识别 `a、` 这类字母序前缀；
- 导出侧 `export.py:2885`：`pure = strip_subitem_ordinal_prefix(_strip_title_number(...))`；
- 复现（降级模式，AI 正文含 `## a、吊顶`）：
  - 第 1 轮落库 → `## 1）、a、吊顶与内装接口`（导出为 `1）、吊顶与内装接口`）；
  - rel≥1 子标题每轮再叠一层：`### a、c、末端点位` → `a、a、c、末端点位` → `a、a、a、c、末端点位`；
  - `_renormalize_all_section_contents` 在**每次拖拽/保存**后都会执行，因此编号会无界增长并写回 DB。
- 影响：正文内容被持续污染；前端预览与导出成稿不一致；编号唯一性被破坏。

**BUG-B：落库侧未排除「任意位置与章节标题同文本」的重复子标题，导致后续编号整体错位一格**

- 导出侧 `export.py:2861-2867` 在编号前剔除重复标题块；
- 落库侧只做「开头重复标题」剥离（`_strip_duplicate_leading_title`），中间位置的重复标题仍占号；
- 复现：正文 `施工准备 / 施工工艺（与章节同名）/ 质量控制`：
  - 落库：`4.1 施工准备`、重复标题 `4.2`、`4.3 质量控制`；
  - 导出：`4.1 施工准备`、`4.2 质量控制`；
- 影响：同一章落库编号比成稿整体后移一格，校验器因与落库侧同源而**报通过**（假绿）。

## 5. 修复项清单

### BUG-A（高）落库侧补齐字母序前缀剥离，消除双重前缀与无界增长

- **改了什么**：`backend/app/services/numbering.py:587`，在 `renumber_section_body_subheadings` 中把
  `pure = _strip_title_number(...)` 改为
  `pure = strip_subitem_ordinal_prefix(_strip_title_number(...))`；并在 `numbering.py:525` 的局部导入中引入 `strip_subitem_ordinal_prefix`。
- **为什么**：与 `export.write_section`（export.py:2885）同口径，保证落库正文与成稿编号一致，并使重规范化幂等。
- **如何验证**：`tests/test_outline_body_subheading_sync.py:310`（降级模式单重前缀）、`:325`（连续 3 轮幂等）。
- **测试结果**：通过；语料幂等率由 2/4 提升到 6/6。
- **关键函数**：`numbering.renumber_section_body_subheadings`、`content_blocks.strip_subitem_ordinal_prefix`（content_blocks.py:1231）。

### BUG-B（中高）落库侧排除任意位置的同名子标题，消除编号整体错位

- **改了什么**：`backend/app/services/numbering.py:549-563`，在 `_strip_duplicate_leading_title` 之后新增 `_sec_title_norms` 过滤：把「类型为 heading 且归一化文本等于章节标题（裸标题/展示标题/纯标题任一）」的块**排除在编号计数与重写之外**（保留原行，不删正文）。
- **为什么**：导出侧会整块剔除这类重复标题（export.py:2861-2867）；落库侧若继续占号，其后所有子标题整体后移一格，形成「预览 ≠ 成稿」。
- **如何验证**：`tests/test_outline_body_subheading_sync.py:345`；端到端 `tests/test_export_numbering_parity_20261006.py:303`。
- **测试结果**：通过；后续编号与导出逐字一致。
- **关键函数**：`numbering.renumber_section_body_subheadings`、`content_blocks._norm_heading_text`（content_blocks.py:1207）。
