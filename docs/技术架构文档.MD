### 2.3 设计模式与亮点

#### 2.3.1 Provider 工厂模式

**意图**：统一封装多平台 AI 调用，支持动态切换与扩展。

**核心组件**：

- `ProviderFactory`：根据配置创建 Provider 实例
- `AIProvider` 抽象基类：定义 `chat()` / `stream_chat()` 接口
- `ProviderConfig`：平台配置（api_key / base_url / model / 协议类型）
- **24 个平台预设**（`provider_factory.py` 实测键名）：deepseek / qwen / zhipu / moonshot / doubao / kimi / minimax / baichuan / iflytek / spark / yi / stepfun / minimax-text / openrouter / groq / ollama / siliconflow / together / perplexity / mistral / cohere / azure-openai / bedrock / nvidia …


**亮点**：

- 支持 24 个预设平台 + 任意 OpenAI 兼容端点
- 支持运行时热切换（界面配置即时生效）
- 支持流式输出（SSE）
- 支持图像生成（`image_providers/` 注册 **7 家**：agnes / baidu / dashscope / hunyuan / stepfun / volcengine / zhipu，见 `__init__.py` 注册表）
- 图像引擎 `image_engine` 自动裁剪 2K 边长、最多 2 张、30s 超时

#### 2.3.2 策略模式：可插拔审核维度

**意图**：审核维度可独立开关、独立评分，支持动态配置。

**核心组件**：

- `Dimension` 数据类：定义维度 id、名称、权重、检测函数
- `RuleRegistry`：注册/管理所有维度
- 六维：completeness(25) / compliance(20) / safety(20) / consistency(15) / traceability(10) / deliverability(10)

**亮点**：

- 权重可调（1~100），总分归一化到 100
- 维度可独立启用/禁用
- 支持新增维度（向 `RuleRegistry` 注册即可）

#### 2.3.3 队列模式：并发任务管理

**意图**：AI 生成任务排队执行，防止超发与资源竞争。

**核心组件**：

- `llm_tasks` / `task_registry`：任务注册与排队
- `LLMTaskQueue`：并发控制（默认 2 并发）
- `TASK_REGISTRY`：任务状态查询（SSE 进度推送）

**亮点**：

- 支持优先级（大纲 > 正文 > 图表）
- 支持取消（前端停止 → 后端中断）
- 支持重试（网络超时自动重试 1 次）
- 事实抽取分块合并：`GLOBAL_FACTS_LLM_CONCURRENCY=4` + 跨方案 `GLOBAL_FACTS_MAX_CONCURRENCY=8` + 队列上限 64（超载返回 `FACTS_OVERLOADED`）

**核心机制**（实测参数）：

- 超时：请求 900s / 每供应商累计 1800s 自动切换

- 熔断：连续失败 **5 次（10 秒窗口）** → OPEN，冷却 **15 秒**半开探测（429 加倍 ≤120s）；全部供应商另有全局快断 **2 次 / 60 秒**；状态持久化 `ai_provider_state` 并暖机恢复
- 并发：全局 5 / 每模型 3，抖动 0~500ms
- 可观测：`ai_config_audit_logs` / `ai_runtime_settings` / `ai_scene_routes`（七场景）

#### 2.3.7 提示词预算与留痕裁剪（v5.4 新增）

**意图**：防止提示词超长导致截断黑箱——超预算时**成对、可追溯**地裁剪，而不是无声截断。

- **预算器**：`PROMPT_TEXT_BUDGET=3000` / `PROMPT_DICT_BUDGET=4000` / `PROMPT_OVERVIEW_BUDGET=1800` / `PROMPT_HEADING=400` / `PROMPT_JSON=1000`（`services/ai/prompts/_limits.py`、`_metrics.py`）
- **留痕**：裁剪必挂 `clip_text_notice`（谁被裁、裁多少、为何）；围栏必须成对（`围栏裁剪` 检测未闭合 ```/引号）
- **截断棘轮**：历史最大截断量只降不升（棘轮回归测试锁死）
- **字典裁剪顺序**：按注入价值排序（`_norm_dicts` 归一词典优先级）
- **契约校验**：G4 变量契约启动期双向校验（模板声明 `requires` ↔ 实际占位符）；`PROMPT_CONTRACT_FAIL_FAST` 默认关
- **审计**：每次调用写 `prompt_audit_logs` 快照，`/api/v1/prompts/audit-logs` 可查、可回滚

#### 2.3.8 缺陷账本与修复权分离（v5.4 新增）

**意图**：修复建议（AI 可提）与修复执行（人工确认后才落值）权责分离，防止 AI 静默改写正文。

- **三态**：`建议`（AI 生成 diff）→ `待确认`（人工审核）→ `执行`（落库 + `fix_decisions` 记账）
- **载体**：`scheme_defects`（缺陷）+ `fix_decisions`（决策）+ `verify`（修复后复检）
- **入口**：工作台「审核→修复」页签（`DEFECT_LEDGER_ENABLED`，default **OFF**）；未开开关时路由 404
- **定向修复**：`review_autofix` 按严重度分批：`plan`（计划）→ `apply`（应用）→ `rollback`（回滚），六阶段收集与确认（`collect`/`stage`/`confirm`/`repairs`）

#### 2.3.9 连接池取消安全（v5.4 新增）

**意图**：SQLite 单文件下解决并发读写与取消竞态。

- **读写分离**：读池只读查询 / 写池 `BEGIN IMMEDIATE`（目录写锁），避免升级锁死锁
- **取消安全**：`CancelledError` 不吞、不回滚到错误计数；回退逻辑与写池同构（精确归还，不重算总数）
- **收尾**：`close_db()` 在 lifespan 关闭期排干双池，避免句柄泄漏
- **WAL 模式**：读不阻塞写；`busy_timeout` 防 `database is locked`
- **事实写租约**：`facts_write_leases` + `facts_chunk_failures` + `facts_cross_conflicts` 记账跨方案写冲突

### 3.4 状态管理方案

**方案**：React Hooks + Context（轻量级，无 Redux）

- **`useState` / `useEffect`**：组件本地状态
- **`useContext`**：全局状态（方案数据、用户配置）
- **`useRef`**：可变值（SSE 连接、定时器）
- **自定义 Hooks**：
  - `useSchemeLiveTask`：SSE 连接生命周期管理（断连退避、全局重连态）
  - `useContentGeneration`：流式生成 + 打字机效果
  - `useAiConfigGovernance`：AI 配置治理（七场景路由）

**亮点**：

- 无全局状态库，体积小、上手快
- 自定义 Hooks 封装复用逻辑
- `useRef` 避免闭包陷阱（SSE 连接、定时器）

### 3.5 SSE 流式处理

**协议**：`text/event-stream`，自实现（`StreamingResponse`，无 sse-starlette）

**事件类型**：`progress`（进度）/ `content`（内容块）/ `error`（错误）/ `done`（完成）

**处理器**（`src/utils/sseFormat.ts`）：

- `parseSSEChunk()`：分块解析
- `formatProgress()`：进度格式化
- `handleStreamContent()`：流式内容累积

**亮点**：

- 断线重连（指数退避 + 全局重连态）
- 取消请求（`AbortController`）
- 检查点恢复（`sse_checkpoint` 进度落库，刷新不丢）

### 6.1 统一响应格式

```json

  "message": "success",
  "data": {}
```

**错误码**：`0` 成功 / `400` 参数错误 / `401` 未授权 / `404` 不存在 / `500` 服务错误 / 自定义业务码（`AI_UNAVAILABLE`、`PDF_OCR_UNAVAILABLE`、`PDF_COM_UNAVAILABLE`、`FACTS_OVERLOADED` 等）。

```text
Authorization: Bearer <API_AUTH_TOKEN>
```

- `API_AUTH_TOKEN` 为空时**不鉴权**（启动日志会声明）

## 7. 性能优化

### 7.1 数据库优化

| 策略 | 实现 | 效果 |
|------|------|------|
| **WAL 模式** | `PRAGMA journal_mode=WAL` | 读写不阻塞 |
| **读写分离连接池** | 读池只读 / 写池 `BEGIN IMMEDIATE` | 消除升级锁死锁（取消安全、`close_db` 收尾） |
| 连接池 | `aiosqlite` 连接池（复用连接） | 减少连接开销 |
| 索引 | 关键字段索引（`scheme_id` / `section_id` / `project_id`） | 查询加速 |
| 批量插入 | `executemany` 批量插入 | 减少 IO |
| 事务优化 | 单事务多操作，减少提交次数 | 降低 fsync 开销 |
| 父子链完整性扫描 | `documents/{id}/completeness` + `freshness`（只读不回填） | 提前发现断链 |
| 事实写租约 | `facts_write_leases` 防跨方案写冲突 | 记账可追溯 |

### 7.2 应用层优化

| 策略 | 实现 |
|------|------|
| **异步全链路** | `async/await` + `aiosqlite` + `aiohttp/httpx` |
| **连接复用** | `http_pool`（aiohttp keep-alive 连接池） |
| **提示词预算** | 预算器 + 留痕裁剪（防超长重试） |
| 生成并发 | 内容生成并行（章节级并发） |
| 流式响应 | SSE 流式，避免长请求阻塞 |
| 结果缓存 | `consistency_scan_cache` 一致性扫描缓存 |
| 导出缓存 | `_export_cache` 保留 5 份/方案，`config_hash` 失效 |
| 静态资源 | 生产环境 FastAPI 直接托管 `dist/` |
| 代码分割 | 路由级 `React.lazy()` + `Suspense` |
| 熔断暖机 | `warmup_*_from_db` 启动恢复熔断/供应商状态 |

### 7.3 前端优化

| 策略 | 实现 |
|------|------|
| 虚拟滚动 | Ant Design Table `virtual` + 固定高度表体（`ReadinessDashboard` / `ReviewWorkflowPanel` / `ReviewTab` / `ComplianceRepairDrawer`，无 react-window 依赖） |
| 防抖节流 | 输入防抖、滚动节流 |
