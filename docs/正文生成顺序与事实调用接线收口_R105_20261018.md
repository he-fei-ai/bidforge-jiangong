# 正文生成「顺序留痕 + 全局事实调用」接线收口（R105 · 2026-10-18）

> **用户指令**：聚焦【正文生成模块】增强（顺序生成 / 全局事实调用 / 上下文注入 / 提示词增强 / 生成后校验 / 衔接 / BUG 修复 / 验证回归 / 输出物九节）→ 审计确认绝大部分需求早已落地，**决定性缺口**为正文线 R102 四个收口函数「服务层就绪、sse_handlers 调用点断线」；留痕可见面经用户确认选**后端留痕 + SSE 终态载荷**（前端零改动）。

## 2. 接线实施（五处 + 一处产 BUG 修复）

文件：`backend/app/routers/sse_handlers.py`（主战场）、`backend/app/services/content_utils.py`、`backend/app/services/facts_builder.py`。

### G1 · 生成后顺序校验留痕
- `generate_content` 闭包容器：`_dispatched_order` / `_expected_order` / `_fact_audit_by_leaf` / `_order_warned`（与 total/done_ids 同区预初始化）。
- 期望序：`facts_rows` 加载后 `_expected_order[:] = [leaves 目录 DFS 序 id]`（空章节早退分支在其之前 → 没派发就不建期望序，终态 `order_check` 为空 dict，载荷与引入前同构）。
- 派发序：`guarded_gen` 内 `async with _run_semaphore:` 过闸即 `_dispatched_order.append(leaf_id)`（口径=启动序：Semaphore FIFO 放行序=协程创建序=目录 DFS 序；与 as_completed 完成序无关，锁死既有 test_per_task_semaphore 口径）。
- 校验：唯一拼装点 `_content_ckpt_payload` 调 `verify_generation_order(dispatched, expected)` → `_ckpt["order_check"]`；失守 WARNING 经 `_order_warned` 一次闸点名 `first_mismatch_index / missing[:5] / unexpected[:5]`。
- 终态三拼装点同键（R66/R74 纪律）：completed / stopped / error 均带 `order_check`；checkpoint 面另带 `fact_mapping`（全量）与 `fact_injection_summary`。

### G4 · 「章节 → 所需事实」映射表
- `chapter_fact_mapping(leaves, facts_rows)` 全量表进 checkpoint（DB 面可取证；与逐章注入共用 `_filter_facts_rows` 单一判据，天然 parity，零第二套归类）。
- SSE 终态只带 `summarize_fact_mapping(mapping, audits)` 汇总（`content_utils` 本轮新增纯函数：sections / sections_with_facts / sections_without_facts / fact_refs / budget_dropped_total / budget_dropped_sections；脏入参降级带 `degraded=True`）——防长方案把几十 KB 全量表塞进事件。

### G3 · 事实注入审计（单一出口）
- 正文事实渲染三分支（core / chapter / plain）由裸 `_render_facts_text` 改走 `fact_injection_audit` 出口：`rendered_text` 与旧实现**逐字节一致**（默认参数 max_total=6000/per_fact=300 同值、core 侧 leaf=None 即 relevant_to=None），只多带回预算丢弃审计视图。
- `_build_generation_context` 在 `_sec_facts` 计算处按叶子记录 `_fact_audit_by_leaf[leaf_id] = {injected_facts, rendered_chars, budget_dropped, budget_dropped_count}`（丢弃标题三段合并去重）。
- `_persist_section` 把本章留痕合并进落库报告新键 `fact_audit`（word 收尾块后、`dict(report)` 合并式，后续块天然保留；不改 error/warning 计数）。
- `_render_facts_text` import 保留为对外 re-export（4 个测试文件经 `sh._render_facts_text` 取用），带 `# noqa: F401` 与说明；`generate_content` 内**零裸调用**（护栏源码锁）。

### G5 · 前驱叶子承接注入
- `nodes_map` 构建处新增 `_dfs_leaf_ids`（复用 `_parent_ids` 筛文档序叶子）+ `_leaf_pos` 索引 + `_prev_leaf_tail_for(leaf)` 助手：开关 `content_prev_leaf_context`（本轮起真正生效）、**严格只取直接前驱**（前驱无正文回落空、不回溯、不 Fabrication）、正文优先 `generated_contents`（实时）回落启动时 DB 快照、异常 fail-soft WARNING。
- 双装配调用点各传 `prev_leaf_summary=_prev_leaf_tail_for(leaf)`（分层版进任务差异段、非分层版进 user 尾段，均为既有服务层行为）；缺省空串输出逐字一致。

### arity 产 BUG 修复
`facts_builder._render_facts_text` L292：`for _g, c, _cf in prepared` → `for _g, _ft, c, _cf in prepared`（与 L319 消费循环同构）。

## 4. 运维与已知面

- **需重启后端**（sse_handlers / content_utils / facts_builder 常驻）；前端零改动（仅存量 untracked 测试文件补类型守卫）；**无需清库、零迁移、零 DDL**。
- 顺序失守的可观测面：backend.log WARNING（一次闸）+ checkpoint / 终态事件 `order_check`；逐章事实留痕：`last_generation_report.fact_audit` + 终态 `fact_injection_summary` / `fact_mapping_stats`。
- `content_prev_leaf_context=False` 可整段回退承接注入（提示词逐字回到引入前）；G3 审计无开关（渲染逐字节一致故无行为面，留痕纯加法式）。
- **重要发现归档**：arity 漏改说明工作树存在「未提交并行改动带活 BUG」的风险面；本轮以端到端护栏（非仅源码锁）捕获，含事实行的正文生成路径自此进入 test_perf_baseline + R105 双护栏覆盖。
- 遗留登记（不在本轮接线，属行为变更须先补行为测试）：R99 登记的 `export_audit.py` 生产不可达（6 项独有能力）仍承接；前端如需展示 `order_check`/`fact_mapping_stats`（当前仅后端+日志面消费）另起轮次。
