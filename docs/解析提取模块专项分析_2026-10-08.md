## 三、功能清单 / 相关代码 / 依赖 / 风险 / 验证方式

### 3.1 功能清单（端到端链路）

```
选择文件
  → 前端三段预检（类型/单文件 30MB → 累计 200MB → 文件数 20，上限经 /system/upload-limits 下发）
  → POST /api/v1/global-facts/upload-documents（流式落盘原文层：MD5/SHA256+meta+documents_index.json）
  → POST /api/v1/global-facts/documents/{id}/parse（单份）｜/documents/parse-all（批量）
      → file_parser 按扩展名分派（docx/pdf/md/txt/xlsx/xls/csv/png/jpg/jpeg/bmp/tiff/doc/wps，14 种）
      → OCR / MinerU / legacy_office 兜底；编码回退 utf-8-sig → gbk → gb18030 → utf-8(ignore)
      → 四层存储：doc_storage raw/parsed/extracted/semantic + 分块 doc_chunker + 结构化 md_structured
      → parse_status 写 success/failed（合法值 pending/success/failed）；截断/告警持久化 parse_truncated/parse_warnings
  → 自动分类（doc_categories 关键词，9 类含「其他」）→ 列表内人工改判 PATCH /documents/{id}/category
  → 提取层：/bid-analysis（18 项/13 分组）与 global_facts → doc_extractions + extracted/*.json
  → 下游：目录生成 build_project_brief、正文生成 project_brief 注入、一致性扫描、导出缓存失效
  → 监控：/system/activity SSE+轮询 documents 段（总数/成功/失败/积压/失败率）
另有一条并行入口：POST /api/v1/upload-outline/parse（目录识别：上传→识别→save-as-outline/save-as-library）
```

### 已核实**非缺陷**（本轮对抗测试逐一验证）
- UTF-16 编码文本 → 拒绝/告警（`test_csv_utf16le_rejected_as_binary`、`_decode_text_ex` 告警），非乱码静默入库；
- 空 ZIP（0 条目）→ 放行后按缺 `word/document.xml` 解析为空文本；文档解析路径按 `len(text.strip())<10` 判 failed（`global_facts.py` L3499）；
- Big5 → GBK 误读产生乱码但有显式告警（编码回退链设计取舍）；
- ZIP 条目>2000 / 单条目压缩比>200 → ParseError（`_guard_zip_archive`）；
- 空文本上传（0 字节）→ 400；损坏 docx → 空文本 + 响应 `empty_text/warning`（`upload_outline.py` L290-298）。

- **修复**：L172-175 全部改为双反斜杠（`\\frac / \\varphi / \\times / \\text / \\lambda / \\leq`），
  渲染后保持单反斜杠 LaTeX 原义、控制字符清零。
