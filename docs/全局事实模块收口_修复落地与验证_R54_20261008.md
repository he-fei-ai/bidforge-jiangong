## 3. 架构与现状分析（要点）

1. **双命名空间**：方案私有行（`scheme_id=?`）+ 项目共享行（`scheme_id=''`）。读取作用域的唯一谓词 `_FACT_SCOPE_PREDICATE`（global_facts.py:495-496）+ 装配出口 `_fact_scope_where`。本轮之前该谓词有 **7 份内联副本**，其中 `/adjust` 那份还**少了共享半句**（F3）。
2. **分类两套正交体系**：`category`（23 类，落库/分组用）与九大章节 + 四维（`chapter/fact_attr/source_kind/is_shared`，供章节视图与完备度用）。读路径一律「**库值优先**」→ 任何改值/改名/改分类的写路径都必须重派生，否则旧维度会被当权威一直带下去（F2 的病根）。
3. **安全红线**：注入门控单一事实源 `_FACTS_INJECT_WHERE = has_conflict=0 AND is_resolved=1 AND is_simulated=0 AND is_stale=0`；不变式 `is_simulated=1 ⟹ is_resolved=0`；17 类安全关键名单；未裁决冲突不可确认。
4. **写入面收口**：`GLOBAL_FACTS_INSERT_SQL/COLS` 为唯一 INSERT 源，手工行 `_manual_fact_row`、分组重建 `_GROUP_REBUILD_SQL` 均为别名；R13/G-04 约定 `_require_fact_write_cursor`（游标空→503）、`_assert_fact_write_applied`（rowcount=0→409）、多语句写必须显式 `rollback`。
5. **AI 调用**：抽取走 `sse_handlers /generate-facts`（分块增量 + `facts_extracted_chunks` 进度）；`/adjust` 走「AI 只产出**待确认计划**、用户确认后再应用」的两步式，绝不让 AI 直接写库（与 `facts_patches`/`facts_enrich` 同一取舍）。
6. **容错/缓存/并发/日志/配置**：读路径 fail-soft（游标空/查询失败按口径降级，但**必须留日志**）、写路径 fail-loud；导出缓存经 `invalidate_export_cache`；本轮**零新增配置项**（见 §7）。
7. **测试方式**：后端把路由函数**当普通 Python 函数直接调用**（传 `db=`），配 `aiosqlite :memory:` + `SCHEMA_SQL` + `_migrate`（`tests/conftest.py:23`，`row_factory=aiosqlite.Row` 与生产一致）；前端 vitest + @testing-library/react，`confirmDialog`/`preview`/`apply` 全部依赖注入以便组件级驱动。

## 5. 修复项与优化项清单（文件 / 关键函数）

### F2（P1）冲突裁决换值后未重派生维度 —— `global_facts.resolve_conflict`(2095)

第 4 条「改事实取值」的写路径漏了维度重算门。修法：把「判据 + 应用」收敛进 `_rederive_dimension_columns`（1265）单一出口，`resolve_conflict` 与条目级更新、分组重建三条路径共用；SET 片段与占位符**同源生成**（先追加维度赋值、再补 WHERE 的 fact_id，避免「N 个 ? vs M 列」静默错位）。
行为影响：仅在新值/新名/新分类确实变化时才重写 `chapter`/`fact_attr`；**值不变（前端「保留当前值」）时不覆盖人工归类**。向后兼容。

### F1（P2）`/chapters` 把事实名当取值 —— `list_facts_by_chapters`(899)

旧实现 `dims = _fact_dimension_fields(r, r["name"], r["name"], …)` → 同一行在 `GET /global-facts` 判 `quantitative`、在 `/chapters` 判 `qualitative`；且行内不写 `name` 键，`chapter_field_completeness` 看不到事实名 → `covered_fields` 偏低、`missing_fields` 虚高（本端点最核心产出）。
修法：统一走 `_fact_name_value`（252）解名/值 → 再喂派生；`_chapter_stats_for_items` 由 2 次调用收敛为 **1 次**（4 遍全表扫描降为 2 遍）；响应补 `by_fact_attr` / `by_source_kind`（加法式字段）。

### F3（P2）`/adjust` 作用域 + 丢弃可观测 —— `adjust_facts`(2521) / `_validate_adjust_ops`(2412)

* 作用域退回 `_fact_scope_where`，项目共享事实可见可改；`add` 不再能造出同名第二份。
* `_validate_adjust_ops` 新增 `existing_keys=` / `ignored_out=`（默认 `None`，既有调用方逐字不变），丢弃理由收敛为**封闭 6 枚举**：`op_not_object / unknown_fact_id / no_effective_change / missing_name_or_value / duplicate_fact_key / unknown_op`。
* 响应加 `ignored` / `ignored_count`（加法式），并 `logger.warning` 记条数。**前端接线已完成**（§5.优化-②）。

### F4（P3）`/adjust` 批量原子性 —— `_apply_item_updates(..., commit=)`

G-04 注释宣称「整批原子提交」，实际每条 update 内部各自 commit → 中途 500 会留下**半截生效**。修法：循环内传 `commit=False`，由 `adjust_facts` 末尾统一 commit / `except: rollback`。新关键字参数默认 `True`，**其余调用方行为零变化**。

### F5（P2）`persist_extraction` 跨 namespace 去重 —— `facts_extractor.py:2437-2462 / 2499-2555`

方案级提取只查方案私有行 → 项目共享层已确认的同 `fact_key` 事实不参与去重，两份取值不同的同名事实**同时满足注入门控** → 正文自相矛盾、界面显示重复事实。
修法：新增 `shared_protected_by_key`（只读项目共享层 + `_is_protected`），命中共享行时同值→清 `is_stale`、异值→回写冲突候选到共享行（**绝不用新值覆盖用户已确认值**）。
⚠️ **刻意未改**：删除候选 `non_protected_ids` 仍只从方案私有 `existing` 计算 —— 否则一次单方案重提取会删掉项目共享事实，波及同项目其它方案。日志补「其中 N 条命中项目共享事实」。

### F6（P3）作用域 SQL 与名/值解析收敛 —— `_FACT_SCOPE_PREDICATE` / `_fact_scope_where` / `_fact_name_value`

7 份内联作用域副本（`list_facts`、`_load_fact_rows`、`adjust_facts`、`ack_fact_stale_batch`、`clear_all_facts`×2、`batch_resolve`×2）收敛为 **1 处字面量**；粗体事实行的正则从 2 处收敛为 `_fact_name_value` 单出口（`_RE_BOLD_FACT_LINE` 引用计数锁死）。片段与旧字面量逐字一致，**行为零变化**。

### F7（P2，本轮新增）`scheme → project` 反查与「行形态取值」收敛

* **发现过程**：全量首跑里 `test_con06…` 失败日志暴露 `resolve_scheme_project_id` 抛 `KeyError: 0`（桩库返回 dict 行）。追下去后确认 `SELECT project_id FROM schemes WHERE id=?` 在 `global_facts.py` 内**逐字重复 9 次**，取值清一色位置索引 `row[0]`；两处「为取 project_id 再查一次 global_facts」的二次 SELECT 也属同一形态。
* **危害面**：生产 `aiosqlite.Row` 键位皆可 → 线上不报错；一旦行形态换成 Mapping，`prow[0]` 抛 KeyError，而这些反查**全在 fail-soft 分支里**：① `resolve_scheme_project_id` 吞成 `""` → 项目共享事实从正文注入/目录/导出/预检作用域整体消失；② `_invalidate_fact_scope_cache(db,"","")` 因 `not project_id` **静默 return** → 项目下全部方案 `facts_updated_at` 不推进，「事实已变更」标记永久停在旧值（用户看过期正文零提示）。
* **修法**：`facts_extractor` 新增 `row_field(row, key, index=0)`（Mapping 按键名、Row 键名优先、序列按位兜底、绝不抛）与 `SCHEME_PROJECT_ID_SQL` 常量，`resolve_scheme_project_id` 改用两者；`global_facts` 新增三态出口 `_scheme_project_id(db, scheme_id) -> str | None`（`None`=方案不存在、`""`=存在但未绑定项目），9 处副本全部改走出口，2 处二次 SELECT 改为复用已在手的首查行；`_resolve_project_id`（documents 域）保留自身 503 文案，仅把 SQL 换成常量、取值换成 `row_field`（判定口径逐字不变）。
* **兼容性**：404/409/400 分支口径不变；唯一行为改进是游标为 None（R13）时从「AttributeError→500」改为本文件既有约定的 **503**，且不降级成 404。
