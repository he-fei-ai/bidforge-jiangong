## 三、两个真实缺陷（生产取证 + 导出 DOCX 复现）

### 3.1 形态 A · 图题假表格包裹图表（sections `3c150ba0`「井道尺寸垂直度验收」）

AI 把流程图包进单列「图题假表格」：

```
| 图 9-1 井道垂直度检测示意图 |     ← 图题行（单格）
| :---: |                           ← 分隔行
| ```mermaid                        ← 开启行（管道前缀 → parse_fence_line 判非围栏）
flowchart TD
 A[设定底部基准点] --> B[顶部架设激光垂准仪]
 ...
``` |                              ← 闭合行（信息串「|」非空 → R76 判据判「非闭合」，被当成 lang="|" 的代码围栏开启）
```

**修复前的成稿后果**（`artifacts/r220_export_test/d5104b41_a0b4093e.docx` 同批取证）：

1. **图表从不渲染** —— `| ```mermaid` 不解析为围栏 → 无 chart 块 → `chart_predictions` 查无此图（登记侧同盲）；
2. **Mermaid 源码泄漏进成稿** —— 以「3 行伪表格 + 裸段落」形态原样印刷（`flowchart TD`、`A[设定底部基准点] --> B[...]` 直接可见）；
3. **图注段被吞进代码块** —— ` ``` |` 被 `read_fenced_block` 当成 `lang="|"` 的围栏开启，`注：图中流程展示了…` 一行被困其中；
4. **图题困在表格单元格里** —— 导出图题吸收（`_extract_figure_caption` 只认段落）够不着 → 该图即使借图渲染也会缺题/重号。

### 3.2 形态 B · 文档围栏包裹正文 + 内嵌图表（sections `a0b4093e`「专职安全员现场巡查职责」）

AI 把**整段正文**包进 ```` ```markdown ```` 文档围栏，段中还有 ```` ```chart-json ```` 图表：

```
```markdown                      ← 外层文档围栏（AI 误包）
### 8.1.2 专职安全员现场巡查职责
专职安全员是本项目现场安全管控的第一责任人…
1. 每日定点巡查与动态监测
```chart-json                    ← 内嵌图表（被外层围栏遮蔽）
{"type":"flowchart","title":"专职安全员日常巡查流程",…}
```                              ← 该闭合行被外层围栏「消费」
```

**修复前的成稿后果**（导出 DOCX P1248 实证）：

1. **正文整体退化为一个 run-on 纯文本段** —— 标题/列表/表格结构全丢，`###` 标记原样印刷；
2. **内嵌图表丢失** —— 解析与登记两侧都看不见（`iter_inline_chart_fences` 走到外层文档围栏即整块跳过其内容）。

### 3.3 根因共性

两类形态的根因同构：**AI 输出的围栏位置/包裹形态超出解析器判据**，而解析器（导出侧）与登记扫描器（`iter_inline_chart_fences`）对同一畸形**一起失明** —— 图表既不渲染也不登记，「图表清单、导出预检、成稿」三处同时缺图且零信号。

## 四、修复方案

### 4.1 唯一修复出口：`content_blocks.normalize_chart_fence_shapes(content) -> str`

**硬约束**：只原地重写/置空标记，**绝不增删行** —— 保住 `renumber_section_body_subheadings` 的 `src_line` 行号契约（R192 FIX-R1 数据损坏家族的防线）；幂等（修复后文本二次进入零改动）。

| 形态 | 处理 |
|---|---|
| A 图题假表格 | 开启行剥前导管道 → 正常 ```` ```mermaid ````；闭合行归一为裸围栏；图题行去管道还原为段落（既有 `_extract_figure_caption` 立即吸收为图表 `title`，源文自写图号前缀同时被剥）；分隔行置空 |
| B 文档围栏包裹 | **仅当**围栏体内确实嵌有图表家族开启行才解包（纯 ```` ```markdown ```` 代码样例零触碰 —— numbering「围栏内标题不参与重编号」契约不受影响）；只把外层开/闭围栏行置空；外层闭合定位带**嵌套穿透**（体内带语言标签的围栏行深度 +1、裸围栏在嵌套层 -1，深度归零的裸围栏才是外层闭合）—— 内嵌图表自己的闭合行不会被误抹 |

### 4.2 三处消费方接线（杜绝「登记侧修了、导出侧没修」分叉）

| 消费方 | 位置 | 作用 |
|---|---|---|
| 导出/预览解析 | `content_blocks._parse_content_blocks`（`normalize_raw_content` 之后） | 成稿渲染恢复图表 |
| 登记侧扫描 | `_chart_pipeline.iter_inline_chart_fences`（唯一事实源入口） | `chart_predictions` / 图表清单 / 导出预检 / 配图上限恢复可见 |
| ordinal 改写锚点 | `_apply_chart_fence_edits` + `_rewrite_code_block` | 与扫描侧在**同一份修复后文本**上计数 → fix-mermaid 按序号精确改写不漂移 |

### 4.3 导出器版本 bump

渲染产物对含畸形形态的正文发生字节变化 → `_EXPORTER_VERSION` **24 → 25**（旧缓存整体失效，既有护栏 `test_exporter_version_unchanged_with_justification` 按「行为变更轮必须 bump 且带理由」重锚）。

## 七、遗留登记（记录以免重复排查）

1. **前端预览（marked.js）仍把畸形形态渲染为代码块** —— 本轮只修后端解析/登记/导出三侧；前端预览与成稿在畸形正文上存在预览/导出分叉（成稿已恢复图表，预览仍显示源码）。根治需前端 `marked` 渲染层同步（独立前端轮）。
2. **存量 DB 行的 chart_predictions 不回填** —— 修复后导出渲染已恢复（块内联码优先），但历史行的登记仍缺（图表清单/预检不可见）；重新保存该章或重跑提取即自然补齐，不做数据迁移。
3. **`register`（登记侧）对修复后文本的 ordinal 与「未修前正文」的 fix-mermaid 前端锚点**：前端 `data-fix-ordinal` 由预览接口下发，其扫描同样经 `iter_inline_chart_fences`（已接线）→ 口径一致，无遗留。
4. **AI 输出纪律**（提示词侧）：两类畸形形态的根治上限是提示词约束（「不要把正文包进 ```markdown 围栏」「图题不要写成表格行」），本轮未动提示词（改动会变更 AI 可见文本，需配提示词回归，登记待专项轮）。
