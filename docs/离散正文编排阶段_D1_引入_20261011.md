# 离散正文编排阶段（D1）引入 · 2026-10-11

> 本轮为「参考软件深度探索与引入方案」中 D1 的独立授权轮。
> 目标：把参考软件 `contentGenerationTask.cjs` 的 `planOne`/`planAll`（正文生成前先由独立 LLM 步产出结构化编排决策）引入本软件，**严格默认关闭、加法式、零破坏既有行为**。

## 1. 设计定位（关键纪律）

- **只做软建议，不硬限制**：编排决策（写作聚焦 / 建议素材 / 建议事实 / 是否表格）作为「建议优先使用」注入生成阶段，**不**收窄模型可用素材/事实范围。
- **刻意回避 R57 已论证的「预编排=陈旧结论陷阱」**：本软件在 R57 已删除 `content_orchestration_system`（独立预编排），本项不重新引入硬约束。
- **编排失败绝不阻断正文生成**：任何 LLM/JSON 异常都回退为「无编排」（空 `plan_json`），生成链路照常。
- **缺省逐字不变**：`content_plan_stage_enabled=False` 时，不触发任何额外 LLM 调用、不改正文提示词、不写非空 `plan_json`；既有 7263 测试基线不受影响。

## 3. 工作流程（开启后）

```
目录树 → 收集叶子 →【D1 离散编排步】（每章 1 次 LLM 调用）
  → ContentPlanData{写作聚焦, 建议素材名, 建议事实标题, 是否表格}
  → 软建议注入「本章任务差异段」 →【正文并发生成】→ 落库（plan_json 随正文）
审核/配图/一致性审计 链路不变。
```

- **候选池过滤**：`ContentPlanData.validate` 只保留落在 `knowledge_names`/`fact_titles` 候选池内的名称，防止模型编造候选外条目。
- **落库**：`plan_json` 随每章正文写入 `sections`，供前端展示「本章编排决策」与审计。

## 5. 残留与后续

1. **仅稳定前缀模式注入**：软建议注入 `build_chapter_extras_block` 产出的「任务差异段」，仅在 `content_stable_prefix_enabled=True`（默认）时生效；非稳定前缀模式（`content_stable_prefix_enabled=False`）不注入——该模式默认关，影响面为零。
2. **未做硬限制**：参考软件 `planOne` 会用编排结果硬收窄知识库/事实范围。本项按 R57 纪律只给软建议，未收窄——若后续确需「硬收窄」增强，应作为独立子轮并复用 `apply_unique_edits` 式唯一命中机制，且保持默认关。
3. **成本提示**：开启后每章多 1 次 LLM 调用（token 与延迟上升），属用户显式选择；编排失败自动回退不额外计费。
4. **D2（知识库 AI 四步提取）** 仍按原方案列为独立授权轮，本轮未涉及。
