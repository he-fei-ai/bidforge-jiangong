## 7. 即使重写代码、仍属共同来源的部分

以下内容即使把 Python 代码完全重写，只要取值/语义不变，仍与对方共享来源，不能据此主张独立：

1. **阈值常量族**
   - `400000 / 0.8 / 0.12 / 0.25 / 0.35 / 1.1`（分段器；本仓 `bid_analysis_service.py:1582-1592` ↔ `userTextSplitter.cjs:1-6`）
   - `6`（标段依据条数上限；本仓 `bid_section_context.py:45` ↔ `bidSectionContext.cjs:9`）
   - `75% / 8 字符 / 6~12 分块`（表格覆盖判定；本仓 `file_parser.py:1093-1094`、`:1114`）
   - 其余散落在 `config.py` 与提示词中的数字（如条数、字数）为**待逐项确认的候选**，本轮未逐一取证，不在结论中先验认定。
2. **正则语义**
   - `repairInvalidJsonStringEscapes` 的字符集合与顺序（`json_response.py:171` ↔ `aiService.cjs:640`）
   - PDF 归一化/重复压缩/去重指纹的正则族（`_PDF_INFORMATIVE_RE`、`_compact_dedup_probe`、`_RW_URL_RE` 等）
   - 标段行号/标题归一化的匹配规则（`bid_section_extraction.py:41-56` ↔ `bidSectionExtractionTask.cjs:25-40`）
3. **提示词原文**
   - §8 抽样的 8 个模板：3 个逐字/近逐字（#1-#3）、2 个术语替换（#4-#5）、2 个骨架/数据结构复用（#7-#8）、1 个局部逐字后扩展（#6）。
   - 提示词是独立可版权作品；改控制流不改变提示词的来源。
4. **接口/数据结构**
   - `mode/granularity/operations/operation/target_text/anchor/content`
   - `writing_focus`、`sections`、`patches`、`target_fact_id/name/value`
   - `yibiao-asset://` URL scheme（功能标识）

结论：想主张「独立实现」，必须同时满足「代码重写 + 提示词重述 + 阈值/正则重新推导并有依据 + 无第三方标识残留」。只做前两项仍不足。

## 10. 最容易被忽略的风险点

1. **`docs/reference_research/` 是最大的隐藏分发风险**：5 个文件、约 335 处对方 JS 源码摘录（`function `/`const`/`require(` 命中 335），会随仓库 tarball、源码包、镜像一起被分发。即使现在删除，git 历史仍保留；公开发布前必须重写历史。
2. **测试里的自认**：`test_bid_response_domain_20260930.py:407-419` 函数名就是 `test_ratio_constants_match_reference`，docstring 写「分段比例必须与易标 userTextSplitter.cjs 逐值一致」并列出 6 个常量名与取值。这是本仓自己写下的同源证据，重写时必须同步改掉断言与命名，而不是删除断言。
3. **`config.py` 注释是对方法的路线图**：`L93` 直接写对方文件路径 `convert.mjs::withLegacyWordDocxFile`；`L767`、`L800`、`L806`、`L813` 等写 `contentGenerationTask.cjs:134/171/125/5490/5507/5579`。只中性化代码、不清理这些注释，仍然等于自证。
4. **前端用户可见 Tooltip**：`ContentGenerationTab.tsx:162` 直接向终端用户展示「对齐 OpenBidKit 的任意点续写」。这既是来源自认，也可能被理解为对方背书。优先级应与 A 类并列。
5. **提示词是独立作品**：很多团队认为「Python 代码是我们自己写的」就安全；但 §8 的 #1/#3 是整段逐字，改代码不会改变提示词的衍生属性。
6. **AGPL §13 的触发条件是网络服务，不是分发**：即使只在自己服务器上给客户用网页，也触发「向用户提供对应源码」义务。
7. **B 类不是免责区**：B 类文件是在可读源码的前提下写的，且常量、正则字符集、函数顺序多处一致。法律上「独立创作」看的是表达是否相似与接触可能，不看作者自评的 A/B/C。
8. **`yibiao-asset://` 是功能标识而非普通字符串**：`content_utils.py:342` 的正则把它当 URL 前缀；改名要同步提示词、渲染器、测试，漏一处就残留证据（或功能失效）。
9. **没有 LICENSE/NOTICE 不等于没有义务**：它只说明本仓未授予他人权利，不能对抗入向 AGPL；同时会让「我们许可客户使用」这件事本身缺少依据。
10. **AGPL-3.0 only + §7(b)**：任何未来换许可证、闭源化、商业授权谈判，都必须先解决 NOTICE 保留与 only 版本约束；不能靠升级到「or later」绕开。
