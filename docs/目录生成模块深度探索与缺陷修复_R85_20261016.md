## 3. 已修复缺陷（全部先复现、后修、再 A/B 反验）

### BUG-A · 泛化标题「词干 + 纯序号」变体覆盖不全（P1 · 用户症状直接复发路径）

**复现**：`_apply_title_updates` 端到端，把占位名改写成下列任一变体时
`applied=1 / rejected=0`，且复检 `generic_residual=0`（闸门报「干净」）：

| 改写目标 | `is_generic_title` 改前 | 改后 |
|---|---|---|
| `专项方案6` / `专项六` / `专项措施6` / `措施3` / `内容2` | **False** | True |
| `专项6` / `总体实施策划` / `总体实施策划（2）` | True | True（不变） |

**根因**：`GENERIC_TITLE_PATTERNS`（`outline_quality.py:103`）是**字面量枚举**，
`^专项\d+$` 只覆盖「专项 + 阿拉伯数字」一种形态。

**修法**：升级为**结构判据**（`outline_quality.py:157-176`）——
`GENERIC_STEM_ORDINAL_RE` 全串锚定 `^(词干闭集)(序号)?$` + `GENERIC_BARE_STEMS` 裸词干窄白名单，
经 `_is_stem_ordinal_generic` 接入 `is_generic_title` **单一出口**（检测侧与回写红线同时收紧，不会分叉）。

**误伤实测 0/15**：合法标题 `专项施工方案 / 专项方案编制依据 / 监测措施 / 施工要求 / 技术要求 /
安全要求 / 应急预案 / 6项施工措施 / 深基坑支护（2）/ 施工工艺技术 / 工程概况 / 安全生产管理 /
内容简介说明 / 3D打印施工方案 / 十二层平面布置` 全部 `False`。
（`^…$` 全串锚定 + 词干闭集 ⇒ 真实复合标题**结构上不可能**命中。）

### BUG-B · 「（N）」冲突后缀正则值域缺中文数字与 4 位数字（P1）

**复现**：`_TRAILING_COUNTER_SUFFIX_RE = [（(]\s*\d{1,3}\s*[)）]\s*$` ⇒

| 标题 | 改前 检测 | 改前 回写红线 | 改后 |
|---|---|---|---|
| `总体实施策划（三）` | MISS | **放行** | 拒收 |
| `监测措施（1234）` | MISS | **放行** | 拒收 |
| `监测措施（2）` | 需碰撞 | 拒收 | 拒收 |

⇒ AI 换一种数字写法即可**同时绕过检测侧与回写红线**，用户症状原样复发。

**修法**（`outline_quality.py:60-73`）：值域补中文数字（一~十，规范「第N章」用汉字 ⇒
AI 消歧用汉字同样常见）与 4 位数字；判定刻意**只认「整组位于标题末尾」**。
`_norm` 随之归一，中文数字后缀的冲突碰撞判定得以生效（实测 `钢内支撑安装` + `钢内支撑安装（三）` 现在报 `conflict_suffix`）。

**刻意保留的既有分工（R79）**：检测侧仍要求「去后缀基名与其它节点碰撞」，
防误伤 `深基坑支护（2）` 这类合法部位限定标题；回写红线只看形态。已加锁防止后人「顺手统一」而放宽检测侧。

### BUG-C · `duplicate_scheme` 不重排章节编号 ⇒ 副本一落库即编号全错（P0）

**复现**（`schemes.py` 复制路径 + `_build_tree` 排序键 `(sort_order, id)`）：

```
SOURCE: [('A 章','1'), ('B 章','2')]
COPY  : [('B 章','2'), ('A 章','1')]      ← 顺序翻转，编号与位置全错
```

**根因**：`outline_json.id` 是章节编号的唯一权威（前端树 / `{section_number}` / 导出标题 /
导出预检 `_detect_section_number_mismatch` 全读它），而复制路径把 `sort_order` 与
`outline_json` **逐字复制**、只重映射 UUID。`sort_order` 一旦并列（历史脏数据 / 外部脚本直改 /
旧版 reorder 只带部分 id），次级键就是 **UUID** ⇒ 源方案靠 UUID 恰好排出的顺序，
在副本上换成随机 UUID 后**必然可能翻转**。唯一暴露口是导出预检的编号错位告警。

**修法**（`schemes.py`）：落库后**同一事务内**调唯一事实源 `renumber_sections_after_reorder`
（create/update/delete/reorder 四条结构路径同一出口），编号由副本自身位置派生。
fail-soft（失败只 WARNING，绝不阻断复制）。
正文子标题重排**刻意不接**（副本 `status="empty"`、正文不复制，接了只是白跑全表扫描）。
对**干净**数据是恒等变换（护栏 `test_copy_of_clean_scheme_is_unchanged` 锁定）。

### BUG-D · `create_section` / `update_section` 用单轮档剥离 ⇒ DB 标题残留并污染提示词（P1）

**复现**：

```
三档口径：single='1.1 工程概况'   tree='工程概况'   all='工程概况'
[create_section]  stored title = '1.1 工程概况'      ← 残留一层
[save-outline]    stored title = '工程概况'          ← 干净（tree 档）
[update_section]  stored title = '2.3 支护施工'      ← 残留
```

**危害**：① 同一目录经两条路径落库**标题形态分叉**；
② 残留串经 `sse_handlers` 的 `{section_title}` **原样**注入正文生成提示词，
与权威 `{section_number}` 并列出现 —— 模型同时看到「当前章节：1.1 工程概况」和「章节编号：1」，
自相矛盾的章节标识会直接影响正文质量。

**修法**（`routers/sections.py:15-40`）：标题写入路径统一改 **tree 档**
（与 save-outline / upload_outline 落库 / `renumber_outline_nodes` 目录树入口同口径），
并删掉 `json_response` 侧的同名导入（避免 F811 遮蔽与「同一判据两份副本」）。
对已干净标题 tree 档是**恒等变换**（护栏 8 例锁定）⇒ 前端单轮剥离、导出剥净档全部不受影响。

### BUG-E · `test_no_bak_files_in_repo` 遍历全仓 ⇒ 阻断整条后端全量（P0 · 测试基础设施）

**复现**：`os.walk(REPO_ROOT)` 单次 **>120s 未完成**；探针定位到
`backend/data/projects/<pid>/documents/**`（四层存储运行时产物）已膨胀到 **29,472 个目录**。
本护栏无限期挂起 ⇒ **整条后端全量 pytest 从此跑不完**（R84 的 32 分钟全量基线不再可复现），
且挂起是**最坏的失败形态**（既不报错也不出结论，只能靠外部 kill）。

**修法**（`tests/test_deprecated_and_bak_guards_20261004.py`）：
按「该目录只可能装运行时/生成物，永远不会是源码」排除 `data` / `logs` / `artifacts` /
`.trash` / `.ruff_cache`；**源码与文档全量扫描范围一字未弱化**
（实测 `backend/app`、`backend/tests`、`frontend/src`、`docs`、`tools`、`chart-gap-filler`
无任何真实源码路径被新排除名遮蔽，只有本就已排除的各类缓存）。
另加 `_MAX_WALK_DIRS = 20000` 预算锁：超限即**先变红**而不是先挂起。

**结果**：该文件 **>120s（挂起）→ 2.24s passed**。

## 8. 本轮方法论教训（登记以免重复踩）

1. **A/B 的「没抓到」必须先证伪变异本身，再指控护栏。**
   本轮 M5 连报 3 次 MISSED，前两次的真因都不是护栏：
   - 第 1 次：node id 漏了 `tests/` 前缀 ⇒ pytest `rc=4 "no tests ran"` **假 CAUGHT**（同 R84 踩过的坑）；
   - 第 2 次：`__pycache__/*.pyc` 失效判据基于 (mtime, size)，A/B 同一秒内写变异并起子进程 ⇒ 子进程读到**旧内容**；
   - 第 3 次：纪律在源文件里是**一整行**，只替换行首会留下行尾残留（仍含「（N）」+「必须改写」）⇒ 护栏照样通过。
   ⇒ 纪律：**整行型纪律必须整行删**；变异后**立刻清 pyc**；`rc=4/5` 一律不算 CAUGHT。

2. **单看一个词是假判据。** F 组最初断言「渲染结果含『泛化』或『占位』」，
   纪律行被删一半后残留句里的「这类**占位**名」仍让它通过 ⇒ 假护栏。
   修法：判据改为**同一条规则行内**「（N）」与禁止/改写祈使词的**共现**，
   并把「判据自证」做成测试内联用例（`test_discipline_judgment_is_discriminating`），
   让假绿在**测试自身**里可复现，不必等下一次 A/B。

3. **要按 `_reg(...)` 逐块核对，不能只 grep 行号。** 初次 grep 显示「纪律遍布 8 处」，
   按 `_reg` 归属映射后才发现 `outline_patch_system` / `outline_recognition_system`
   **零纪律** —— 行号落在哪个模板里必须先确认。

4. **`"（N）" in text` 这类「源码含字符串」判据在本仓反复失效**（AGENTS §5.14）；
   提示词类判据必须**先渲染再断言**，且断言要与风险同构。

5. **静态护栏本身是性能敏感代码**（AGENTS §4.17.3 同族，本轮第二次撞上）：
   `os.walk(REPO_ROOT)` 在四层存储膨胀到 2.9 万目录后从「可用」变成「挂起」。
   写递归扫描前先量耗时，并给扫描**加预算锁**：超限先变红，好过挂起。
