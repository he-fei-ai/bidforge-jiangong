## 0. 开篇整体结论

提示词模块是**全仓治理成熟度最高的模块之一**：74 条模板全部经 `_reg()` 注册（55 条包内 + 19 条投标分析惰性注册），有真实的版本控制（审计快照 + 回滚 + CAS 并发保护）、启动期变量契约校验（70+ 条契约）、保存期静态体检、运行时指标埋点，限定测试基线 **711 passed / 11 skipped / 0 failed**。

但仍存在三个实质性缺口：

1. **治理接线面缺口（最该修）**：注入防护围栏 + 凭据脱敏 + 上下文预算分配，全仓**只在正文生成一条链路接线**（`sse_handlers.py:3617-3618`），且两个开关**默认关闭**（`config.py:966-984`）。目录生成、事实提取、投标分析、上传目录识别、一致性扫描、审核预检、图表修复 **6 大链路的外部资料注入全程无围栏、无脱敏、无统一预算**——上传的招标/项目资料若含凭据，默认原样外发给第三方 AI API。
2. **散落硬编码 4 处**：`SEGMENT_MERGE_PROMPT`（`routers/bid_analysis.py:193`）、`_SYSTEM_EXTRACT`/`_SYSTEM_MERGE`（`services/bid_section_extraction.py:183/229`）、OCR 提示词（`services/ocr.py:279`）**未注册**——编辑器不可见、无 DB 覆盖、无契约校验、无变更审计。另有 1 处已注册但保留字面量回退的双源（`bid_analysis_service.py:415` STABLE_SYSTEM_PROMPT ↔ `bid_analysis_system`，`:881-884` 注册、`:938-948` 回退）。
3. **模板重复度低但修复族有 4 份近义实现**：3 份注册模板（`outline_json_fix_system` / `facts_json_fix_system` / `json_schema_fix_system`）+ 1 份内联兜底（`json_response.py:74` JSON_REPAIR_PROMPT），分工是刻意的（R38 P1-c），但内联兜底与注册版措辞已漂移，属维护债。

**敏感信息进 prompt 的路径**：API 密钥**不会**进 prompt（仅出现在 HTTP `Authorization` header，`image_providers/dashscope.py:87` 等）；但**用户上传资料原文**（tender_text / material / raw_text）在默认配置下**无脱敏直达外部 AI**，脱敏函数 `redact_sensitive` 唯一接线点受默认关闭的开关保护。

确定 BUG：**4 项**（均为证据确凿的缺陷/缺口，无幻影项）；待验证：**4 项**。

### 3.2 截断策略总评

- **两套机制并存**：①组件级字符硬切（`[:N]`，占绝大多数点位，可能截在半句/半条 JSON——低优先级债）；②统一预算分配器 `prompt_governance.allocate_context_budget`（优先级水填：全局事实 > 章节定位 > 资料摘要 > 知识库，`prompt_governance.py:38-62`；段内边界感知截断 `truncate_to_boundary`）。
- **机制②默认关闭且仅单点接线**：`_apply_prompt_context_budget` 唯一消费点 `sse_handlers.py:3618`（配置 `prompt_context_budget=0` 关闭，`config.py:978-984`；运行时开关 `routers/system.py:348-400` GET/PUT `/system/governance`）。
- **砍掉关键信息的风险**：默认配置下无优先级保护，但组件级硬切的上限量级（1500/3000 字）实测不触顶；开启预算器后 P0 段有 min_ratio=0.2 下限保底（`prompt_governance.py:255-262`），不会整段清空。截断埋点 `record_token_budget_truncated` 已接线（`:305-311`，BUG-D6 已修）。
- **上下文组装分散度**：正文 user 上下文已下沉单一函数 `services/content_runtime.build_chapter_user_content`（`sse_handlers.py:3409-3415` 注释）；目录侧分散在 `sse_handlers.py` / `_sse_outline_build.py` / `_sse_outline_review.py` / `outline_title_fix.py` 四处各自拼装 project_facts（同口径但四份代码），属轻度分散。
