## 1. 新表 DDL

### 1.1 `scheme_scoring_items`

```sql
CREATE TABLE IF NOT EXISTS scheme_scoring_items (
    id TEXT PRIMARY KEY,                 -- sha1(project_id|source_doc_id|norm(item_no)|norm(item_name))
    project_id TEXT NOT NULL,
    source_doc_id TEXT DEFAULT '',       -- project_documents.id；空串 = 来源不可定位
    source_name TEXT DEFAULT '',         -- ✅ 加法式新增（仅展示用）：源文件名
    item_no TEXT DEFAULT '',             -- 评分项编号（原文口径，可空）
    item_name TEXT NOT NULL,             -- 评分项名称（原文口径，非空才入库）
    score REAL,                          -- 分值；NULL = 原文未给分值（不按 0 处理）
    score_raw TEXT DEFAULT '',           -- 原文分值片段，如 "10分"
    criteria TEXT DEFAULT '',            -- 评分标准/得分要点原文摘录
    is_primary INTEGER DEFAULT 0,        -- 1 = 主评分项（高分值/否决项/关键技术项）
    page_ref TEXT DEFAULT '',            -- "docid#page:N"；无页码证据时为空串
    page_num INTEGER,                    -- 冗余便于前端展示；无证据为 NULL
    source_quote TEXT DEFAULT '',        -- 证据原文摘录（≤120 字）
    status TEXT DEFAULT 'active',        -- active | stale
    created_at TEXT DEFAULT (datetime('now','localtime')),
    updated_at TEXT DEFAULT (datetime('now','localtime'))
);
CREATE INDEX IF NOT EXISTS idx_scoring_items_project ON scheme_scoring_items(project_id);
CREATE INDEX IF NOT EXISTS idx_scoring_items_doc ON scheme_scoring_items(project_id, source_doc_id);
```

- 唯一性：主键 `id`（确定性哈希）。同一评分项重复出现由 `normalize_and_validate` 去重。
- 软删除：无删除。重新抽取按 `id` UPSERT；**仅当本次 run = `success`** 才把本次未覆盖的旧行标 `stale`。
- 外键：不建（表自包含；`project_id` 缺失不影响 read 路径）。回滚：`DROP TABLE IF EXISTS ...`。

## 2. 数据契约（字段语义 / 空值语义）

| 字段 | 业务含义 | 空值语义 |
| --- | --- | --- |
| `id` | 确定性幂等键 | 不可空 |
| `source_doc_id` / `source_name` | 来源文档 | `''` = 来源不可定位（**不编造**） |
| `item_no` | 编号 | `''` = 原文未编号 |
| `item_name` | 名称 | 非空才入库 |
| `score` | 分值数值 | `NULL` = 原文未给分值 |
| `score_raw` | 分值原文 | `''` = 原文未写分值 |
| `criteria` | 评分标准原文 | `''` = 无细则 |
| `is_primary` | 是否主评分项 | 0 = 普通细项 |
| `page_num` / `page_ref` | 页码/定位 | **允许空**：`NULL` / `''` |
| `source_quote` | 证据片段 | `''` = 无证据 |
| `status` | 行状态 | `active` 参与校验；`stale` 为本次成功 run 未覆盖的旧行，不参与 |

`score_band`（**不落库，报告期计算**）：
`ratio = score / Σ(有效分值)`；`high: ratio ≥ 0.15`；`low: ratio < 0.05`；其余 `mid`。
任一分值缺失 → 该项 `mid`；全部缺失 → 全部 `mid`。

报告状态与空值：

- `status ∈ ok | partial | undetermined`；评分项状态 ∈ `mapped | missing`；章节侧标签 `extra`；来源侧 `unmatched`。
- **`undetermined` ⇔ `coverage_rate = null`**，且 `items` 中**不得出现任何 `missing`**。
- `undetermined_reason ∈ no_extraction | extraction_failed | empty_items`。
- `partial`：成功来源正常 `mapped/missing`；`unmatched[]` 携带失败来源与原因。

```python
@router.post("/api/v1/projects/{project_id}/scoring-items/extract")
async def extract_scoring_items(project_id, body=None, db=Depends(get_db)):
    if project not exists: raise HTTPException(404, "项目不存在")
    doc_ids = (body or {}).get("doc_ids")
    if doc_ids is not None and not list[str]: raise HTTPException(400, "doc_ids 必须是字符串数组")
    # v1：不因 doc_ids 改变扫描范围
    if project_id in _ACTIVE_EXTRACT: raise HTTPException(409, "评分项解析正在进行，请稍后重试")
    _ACTIVE_EXTRACT.add(project_id)
    try: return await _do_extract(db, project_id)
    finally: _ACTIVE_EXTRACT.discard(project_id)

async def _do_extract(db, project_id):
    sources = await select_scoring_sources(db, project_id)      # 关键词 ≥2 的页块 + ±1 页
    if not sources:                                             # 解析不到 = failed，不是 5xx
        insert_run(status="failed", error="未定位到候选页块"); return 200 undetermined 语义
    batches, overflow = plan_batches(sources, max_chars=60000, max_docs=4)   # ≤2 批
    raw, failed, ok_batches = [], list(overflow), 0
    for batch in batches:
        try: raw += await extract_batch(batch, timeout=120); ok_batches += 1
        except Exception as e: failed += 该批文档 + 原因; errors.append(e)   # 单批失败不整体失败
    items = await normalize_and_validate(project_id, raw, page_index=每文档页块)
    run_status = "success" if ok_batches 且无失败
               else "partial" if ok_batches
               else "failed"
    await persist_items(db, project_id, items, run_status=run_status)  # UPSERT + stale 标记
    await insert_run(db, run)
    await db.commit()
    return 200（失败也 200，避免把部分成果吞掉）
```

## 4. 匹配算法伪代码

### 4.1 归一化（唯一出口）

```python
def norm_title(s):
    s = unicodedata.normalize("NFKC", s)          # 全角→半角
    s = s.casefold()
    s = re.sub(r"^\s*(?:第[一二三四五六七八九十百]+[章节]|[0-9]+(?:[.．、）)]|\s*、))", "", s)  # 序号前缀
    s = re.sub(r"[#>*`|_~\-—\[\]()（）【】:：,，。；;、'\"“”‘’!！?？\s]+", "", s)
    return s

def keywords(s): return {t for t in TOKEN_SPLIT.split(s) if len(t)>=2 and t not in STOPWORDS}
def jaccard(a,b): return len(a&b)/len(a|b) if a and b else 0.0
```

停用词只从 keyword 分词中剔除，**不影响 exact/contains**。

### 4.2 四级匹配

| 步骤 | 条件 | 置信度 | method |
| --- | --- | --- | --- |
| S1 精确 | `norm_title(item_name) == norm_title(title)` | 0.95 | `exact` |
| S2 包含 | 互为子串，较短串 ≥4 字且 `len(short)/len(long) ≥ 0.60` | 0.85 | `contains` |
| S3 关键词 | 内容 token Jaccard ≥ 高档 0.65 / 中档 0.55 / 低档 0.45 | `min(0.90, 0.50+0.40*J)` | `keyword` |
| S4 评分标准回退 | `criteria` 与章节正文共享 ≥2 token 且 Jaccard ≥ 高档 0.45 / 中档 0.40 / 低档 0.30 | `min(0.50, 0.30+0.40*J)`，`needs_review=true` | `criteria` |

每个 (评分项, 章节) 只取命中的**最高一级**，不叠加。

### 4.3 目标节点与多对多

```python
leaf = {节点 | 无子节点}
for item in items:
    for sec in sections:
        m = match_one(item, sec, section_text, cfg)
        if item.score_band == "high" and sec not in leaf: continue    # 高档只接受叶子
        elif 命中父节点且父节点有子节点: 允许（聚合覆盖，后代不进入 extra）
    if 无候选: status="missing"; suggestion=新建议章节
    else:
        ranked = sort(cands, by=(-confidence, -level, sort_order))
        primary  = ranked[0]           # 一个评分项命中多章节 → 全量保留，primary 唯一
        item.status="mapped"; also_section_ids = ranked[1:]
        item_counts[primary.section_id] += 1
# 多个评分项命中同一章节：item_count 累加；
#   过载阈值 = max(3, ceil(item_count_total / leaf_count))，仅提示 overloaded，不改 mapped
```

### 4.4 `extra` 判定（只查叶子）

```
extra = 节点满足全部条件：
  1) 无子节点；
  2) 未被任何评分项命中（primary / also 均算命中）；
  3) 任一祖先未被命中（祖先命中 → 该子树视为已覆盖）；
  4) norm_title(title) 不在结构白名单（默认：附图/附表/附件/封面/目录/编制说明/编制依据/参考文献）；
  5) 不是纯占位/泛化标题（复用 outline_quality.is_generic_title）。
```

白名单来源：`settings.scoring_extra_whitelist`（逗号分隔）。

### 4.5 `undetermined` 的返回路径（锁死）

- 无 items（未抽 / 失败 / 成功但 0 条）→ `status="undetermined"`、`coverage_rate=null`、
  `items=[]`、`missing=[]`、`extra=[]`，**不得** 0% 或任何 `missing`。
- 有 items 但目录为空 → `status="ok"` 或 `"partial"`，全部 `missing`、`coverage_rate=0.0`（确实缺章，不是无法判定）。

## 5. 前端调用时序

### 5.1 面板加载（`OutlineTab.tsx` 编制要求卡片之后）

```
mount / schemeId 变化（且 projectId 存在）
  → GET /api/v1/schemes/{schemeId}/scoring-coverage

点击「解析评分项」→ POST /projects/{projectId}/scoring-items/extract（loading）
  → 按响应 status 刷新面板（failed 也刷新，展示失败来源）
```

