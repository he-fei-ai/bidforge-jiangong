## 十一、教训归档

1. **「模板实例化空 `__original_id` 被短路」是「真值要求过严」的 P1 数据丢失形态** —— `is_new and original_id and not local_` 的 `and original_id` 把空串（合法兜底来源）误判为「无主键非兜底」，落进 new_inserts 整批删旧章。修复用 `(original_id or "")` 把「空串」与「local_ 前缀」统一为「非兜底」，与 upload_*/AI 调整同口径。
2. **编号全角归一必须在「剥除 + 存储」两侧同口径** —— 旧实现 `_STRIP_NUMBER_RE` 只认 ASCII 数字，AI/上传全角编号从剥除侧漏过成双重编号；`_stored_id_parts` 原样放行全角与前导零，与导出 int 渲染分叉 ⇒ preview≠成稿。R216 用 `_FULLWIDTH_DIGITS_TRANS` + 前导零折叠在单一入口归一，R208 解析侧 raw_id 同口径，两侧收敛。
3. **SSE 停止/截断/复用信号必须「每条出口」对齐** —— R216 发现 oneshot 收尾、all_failed、error（在线+异常）、刷新接管四处各自漏信号：停止无人消费（C3）、陈旧复用防护被绕过（C5）、目录树无高亮（C5）、重挂窗口无法停止计费任务（G5）。修复时每条出口逐一补，且指纹只进 checkpoint 不进前端 SSE 白名单（R210 纪律）。
4. **读路径/回退路径的口径分叉是「单一事实源」纪律的缺口** —— 不可达节点只在 list_sections 单点统计（R210），reorder/export-tree 漏；级联清单在 schemes.py 与 projects.py 两份演进漏 4 表；快照回退不回写 status。R216 收口为模块级唯一实现 / 单一事实源 import / services 与前端头部 Tag 同不变式。
5. **前端「文案指向不存在的入口」是隐性可用性缺陷** —— `useOutlineGate` 引导「AI 调整目录」，但该前端入口零按钮零调用（后端 `/adjust-outline` 存活但前端未接）。修复改为可执行指引，避免用户按文案找不到功能。
6. **「同族漏改」第三次实证（G5）** —— `activeTaskIdRef` 重挂回填在正文链（R194 FIX-13）与未知态手动接管已修，本链（目录生成）漏改，断线重挂窗口内停止按钮读空 id。修复时 grep 全部「重挂回填」消费方，确认三处同口径。
7. **「半成品改动」会跨轮次变成别人的 P1 基线红** —— R216 SSE-7 给输入指纹追加第 11 part 时引用了定义在另一闭包的 `_facts_char_rows`，ruff F821 当场抓红但属 CI 静态检查、运行期才 NameError；该缺陷由并行轮次 **R217 FIX-1** 定罪并修复（§十.1）。⇒ 新增「指纹 / 信号」类改动必须**同一轮内跑一次 ruff F821 + 运行期路径实证**，不能只靠源码锁护栏；报告署名须按代码标记与独立报告核对，避免把并行轮次的修复记成本轮成果。
8. **全量 pytest 会派生前端 vitest 子进程** —— 本仓 `pytest tests/` 内含跨端 / 端到端测试，会自行拉起 `vitest --reporter=basic` 子进程（本次 PID 16636 的父进程即 pytest 28592）⇒ 全量回归耗时远大于定向簇，且 `| tail` 缓冲下全程无输出。判定「是否卡死」应看 CPU 时间 / Responding 与子进程树（本次 CPU 778s、Responding=True），而不是只看墙钟时长；占用探针同时要区分「他人在飞」与「本会话派生」。
9. **`| tail` 会把 pytest 的失败退出码换成 tail 的成功退出码** —— 首跑 20 failed 却被任务框架报成 `exit code 0`。全量回归必须「输出重定向到文件 + `echo $?`」或 `${PIPESTATUS[0]}`，并**以 summary 行为准**；后台任务的「完成通知」不等于「测试通过」。
10. **定向簇全绿 ≠ 全量全绿，且「加法式改动」也会让护栏过期** —— 287 定向 + 40/11 护栏全绿，但全量照出 14 个稳定红，其中 2 个是 R216 自身真实回归、2 个是锁实现的护栏被全角归一 / 新增分支撑破。每轮收口**必须跑一次全量**，不能拿定向簇替代。
11. **前后端同源正则必须成对改** —— R216 只改了 `numbering.py::_STRIP_NUMBER_RE` 没同步 `outlineNumbering.ts::LEADING_NUMBER_RE`，parity 护栏当场抓红。凡「后端有 parity 测试锁逐字符一致」的常量，改动必须一次改两侧并跑 parity 测试。
12. **「空主键纳入兜底」与「消费式认领」会二次撞车** —— R216 的 P1 修复让空 `__original_id` 进入结构感知匹配器；目录库路径已用另一个 matcher 消费式认领并**明确放弃**了同名节点，`sections` 侧再兜底就把它匹配回同一旧主键 ⇒ 400。修法不是回退 P1，而是让调用方显式声明「我已认领」（`skip_fallback_match`），把「谁来负责匹配」变成接口契约而非隐式推断。
13. **判定全量结果要同时看「显式退出码 + summary 行」，并排除退出后的噪音** —— 首跑踩了 `| tail` 掩盖退出码，重跑又在输出尾部出现 pytest `atexit` 清理临时目录被 safe-delete 守卫拦截的 `SystemExit: 1`（`Exception ignored in atexit callback`）。后者发生在测试进程收尾之后，不影响 `PYTEST_EXIT=0` 与 `11943 passed`；若只 `tail -25` 看末尾极易误判为失败。另：`20 failed → 19 passed + 1 skipped` 与 `11924+19=11943`、`20+1=21` 的数字自洽，是「没有用例被悄悄丢掉」的低成本交叉校验。
