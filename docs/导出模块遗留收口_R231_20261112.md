## 二、落地明细

### B5 混合矩阵（`app/services/docx_math.py`）

1. `_MATRIX_ENV_RE` 体捕获 `(.+)` → `(.+?)` 非贪婪（整式 fullmatch 语义不变）。
2. `latex_to_omml` 混合路径：`finditer` 按矩阵环境位置分段——环境段产 `m:m`（`_matrix_to_omml`）、环境外片段经 `_inner_nodes_xml`（不挂悬空占位）解析后以 `_strip_omath_shell` 剥壳并入同一 `m:oMath`；无矩阵时走原路径逐字节不变。
3. **片段不挂悬空占位框**（宁漏勿误）：`x = \begin{matrix}...\end{pmatrix}` 的 pre 片段 `x =` 单独判悬空会误挂「待填」框——混合形态下右值就是矩阵。
4. 新增 `_strip_omath_shell` / `_inner_nodes_xml` 两个辅助。

实测：`K\begin{pmatrix}a&b\\c&d\end{pmatrix}\delta` → 单 oMath 内 [K, 矩阵, δ] 并列且 XML 良构；双 bmatrix → 2 个 m:m 同 oMath；整式幂等；`docx_math` 既有 18p 零回归。

### B7 图片回滚清理 relationship（`app/routers/_export_docx_parts.py`）

`_DocxBodyRollback` 新增 `_doc_part` 快照；`rollback()` 删除每个新元素时遍历其 `a:blip r:embed` 引用并 `del doc.part.rels[rId]`——只删**本次新增元素**引用的 rel（既有图绝不受影响）。实测：rollback 后保存产物 `word/media/` 为空；对照组不删 rel 则 media 在。

### B8 列表缩进口径单源（`app/services/content_blocks.py`）

1. 循环级新增 `_vis_indent = expandtabs(4) 视觉缩进`（单一定义点）。
2. list_item 两分支（无序 :1557 / 有序 :1575）`"indent": indent` → `"indent": _vis_indent`。
3. 续行合并判据复用同一 `_vis_indent`（消除解析层内部两口径）。
4. 原始字符口径 `indent` 变量随之零消费，赋值删除。
5. 导出侧 `// 2` 不动：2 空格→1 级（语义不变）、1 tab→2 级（**不再拍平**）、4 空格→2 级（保序代价，混用 2/4 空格的宽度算法归版式专项）。
6. **行为改进披露**：与列表项同视觉缩进的行（`\t- 甲` + `\t同层段落`）旧口径因 tab=1 使 `4>1` 误判「更深」而误并入列表项——新口径同级不合并（Markdown 正确语义）。

实测：tab/双 tab/4 空格/2 空格四形态层级全对；`test_export_nested_ordered_list` 42p 零回归。
