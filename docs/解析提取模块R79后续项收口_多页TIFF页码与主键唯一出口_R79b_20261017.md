## 1. 本轮改动（2 处生产代码 + 1 份护栏）

### 1.1 【S1 · P2 · 多页 TIFF 缺页码标记 ⇒ 溯源失真】

- 位置：`backend/app/services/file_parser.py::_parse_image_ocr`（多页 TIFF 分支）。
- 症状：帧识别结果 `parts.append(res.text)` 后 `return "\n".join(parts)`
  —— **没有任何 `<!-- page:N -->` 标记**，全部帧内容被 `md_structured` 归到第 1 页。
- 影响链（逐级）：
  - `md_structured.parse_markdown_structured` 的表格/图片**按页关联**失效；
  - `project_documents.page_count` 落库值为 1，完整性报告 `total_pages` 失真；
  - `doc_chunks.page_num` 全部错位，`/documents/{id}/chunks?page_num=` 过滤失准；
  - 目录识别（上传 TOC）按页聚合时多页内容混作一页。
- 为什么此前没被发现：PDF 两条通道（`_parse_pdf` / `_pdf_ocr_fallback`）一直走
  `_add_page_markers`（`file_parser.py:401` 单一出口），**只有图片通道是漏网点**；
  且 `test_file_parser.py` 64 例无 TIFF 多帧页码断言。
- 修法（复用唯一出口，不另造格式）：帧号即页号，`pages.append((idx + 1, res.text))`，
  出口改 `return _add_page_markers(pages)`；`OcrUnavailableError` 分支的 `parts`
  判空同步改为 `pages`（保持同一变量口径）；部分帧失败时缺帧**不生成**页码标记。
- 向后兼容：单帧图片路径不变（不进本分支）；多帧文本内容逐字不变，仅新增标记行。

### 1.2 【S3 · P2 · 重置重跑手拼主键 + INSERT 不带 domain 列】

- 位置：`backend/app/routers/bid_analysis.py::_reset_items_for_rerun`。
- 症状：`pk = f"{project_id}_{def_['item_id']}"` 手拼主键；补齐记录的 INSERT
  **不带 `domain` 列**（且未探测 `_bid_analysis_item_cols`）。
- 为什么现在必须修：scheme 域下二者与唯一出口**逐字相同**（当前无行为差异），
  但 `EXTRACTION_DOMAINS` 已支持非 scheme 域，`build_item_pk` 对非 scheme 域生成
  `{project_id}__{domain}__{item_id}` —— 一旦该域可执行，本路径补的行
  **主键与唯一出口不同、且 domain 为空** ⇒ 同一条提取结果出现两行（读侧按
  `build_item_pk` 查询读不到，且域过滤失效）。这正是本仓 §4.3/§4.15反复记账的
  「同一判据两份副本」在主键命名空间上的复发。
- 修法：主键改 `build_item_pk(project_id, iid, get_item_domain(iid))`；
  INSERT 与 `_update_item_status`（AI 写路径）**同口径**：先 `_bid_analysis_item_cols(db)`
  探测，有 `domain` 列则带列写入、否则走旧库降级分支（与既有兼容策略一致）。
