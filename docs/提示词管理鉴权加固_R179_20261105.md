# 提示词管理接口鉴权加固（R179 · 2026-11-05）

## 1. 现状取证结论

### 1.1 仓内已有鉴权层

- **全局 API 鉴权中间件**：`backend/app/middleware.py:48` `ApiAuthMiddleware`。
  - `settings.api_auth_token` 为空（默认）→ **完全放行**（`middleware.py:64`）；
  - 非空 → 除豁免路径外一律要求 `X-API-Key` 或 `Authorization: Bearer`，
    使用 `secrets.compare_digest` 常数时间比较（`middleware.py:74-81`）。
  - 实现上按「全路径」生效，并不限于注释里写的 `/api/v1/*`。
- **错误响应惯例**：`HTTPException(status, "中文文案")` → FastAPI 统一输出
  `{"detail": "..."}`（`middleware.py:84-86` 亦为此格式）。本次照抄惯例，未引入 RFC 9457。
- **来源 IP 惯例**：`audit_service.client_ip_of`（`backend/app/services/audit_service.py:168-181`）
  —— 仅当 ASGI 直连对端命中 `settings.trusted_proxy_ips` 时才采信 `X-Forwarded-For`。

### 1.2 原来哪些端点裸奔

- `backend/app/routers/prompts.py:67`（改动前）
  `admin_prompts_router = APIRouter(prefix="/admin/prompts", tags=["prompts-admin"])`
  —— **零依赖、零中间件专属校验**。
- 因此当 `API_AUTH_TOKEN` 为空（本机单机默认）时，任何可达网络的客户端都能调用
  `POST /admin/prompts/sync-from-code`，且 `?force=true` 可**直接覆盖用户在后台编辑的提示词**
  （`prompts.py` 原 447 行起，`force` 分支调用 `_up(key, code_content)`）。
- 覆盖范围：该 router 下当前**唯一**端点为 `POST /admin/prompts/sync-from-code`。
  `system_metrics_router`（`/system/prompt-metrics`、`.../reset`）不在 `/admin/*` 命名空间，
  本次未纳入（见 §8 遗留项）。
- 前端调用点：`frontend/src/api/index.ts:1165-1169` `promptsApi.syncFromCode`，
  仅此一处访问 `/admin/prompts/*`；本地经 Vite 代理转发（后端直连对端为回环）。
  本机单用户运行模式即「前端 localhost:5175 → 代理 → 后端 127.0.0.1」。

## 2. 方案与默认行为

新增独立依赖 `require_admin_access`（`backend/app/services/admin_auth.py`），
以 **router 级依赖**挂到 `admin_prompts_router`（`prompts.py:72-76`），一次覆盖该组全部端点，
新增端点自动继承。

| 配置 | 来源 | 结果 |
| --- | --- | --- |
| `ADMIN_API_TOKEN` 为空（默认） | 回环 `127.0.0.1` / `::1` / `::ffff:127.0.0.1` | 放行 |
| `ADMIN_API_TOKEN` 为空（默认） | 非回环（含 `testclient`、`0.0.0.0`、`127.0.0.2`） | **403** |
| 非空 | 无凭据 / 错凭据 | **401**（附 `WWW-Authenticate: Bearer`、`Cache-Control: no-store`） |
| 非空 | `X-Admin-Token: <token>` 正确 | 放行 |
| 非空 | `Authorization: Bearer <token>` 正确 | 放行 |
| 非空 | 任意来源 | 放行（显式配置 token 即表示允许远程管理） |

- **fail-closed**：默认不再受来源网络暴露影响——本地零变化，暴露到局域网/公网时管理面默认关闭。
- **不信任 `X-Forwarded-For`**：仅当直连对端命中 `TRUSTED_PROXY_IPS` 才采信（复用既有口径），
  否则伪造 `X-Forwarded-For: 127.0.0.1` 仍判非回环。
- **常数时间比较**：`hmac.compare_digest`，且先编码为 `bytes`（非 ASCII 凭据返回 401 而非 500，
  与 `test_api_auth_middleware.py` 已锁定的同类回归一致）。
- **状态码选择**：来源不被允许用 403 而非 401，避免触发前端 `authGuard` 的 401 全局短路
  （该短路会拦截后续所有请求）。

## 7. 前端是否需要改

- **本地默认配置：不需要任何改动**（回环来源放行，`syncFromCode` 行为与改造前一致）。
- **配置了 `ADMIN_API_TOKEN` 时**：给出最小方案并已落地——
  `frontend/src/api/index.ts` 新增 `getAdminToken()`（构建期 `VITE_ADMIN_TOKEN` →
  `localStorage.admin_token`），**只**在 `promptsApi.syncFromCode` 请求上注入
  `X-Admin-Token`，不随全站请求外发，缩小凭据暴露面。
- 类型与 lint 均通过（`tsc --noEmit` 0 error、定向 eslint 0 error），未引入 `any`/断言压制。

## 8. 遗留项

1. **token 的分发与轮换**：无管理 UI 录入入口，当前依赖 `VITE_ADMIN_TOKEN` 构建期注入或
   `localStorage.admin_token`；建议后续在安全设置页提供录入与清除，并明确轮换流程
   （构建期注入需重新构建前端）。
2. **代理场景**：默认不信任 `X-Forwarded-For`。反向代理后部署管理面时，需同时配置
   `TRUSTED_PROXY_IPS`（用于来源判定）与 `ADMIN_API_TOKEN`（远程管理凭据），否则 403 属预期。
3. **`/system/prompt-metrics` 组**：`GET /system/prompt-metrics`、`POST /system/prompt-metrics/reset`
   不在 `/admin/*` 命名空间，本次未纳入闸门；其中 `reset` 会清空进程内计数器，建议后续批次评估纳入。
4. **与 `API_AUTH_TOKEN` 的交互语义**：二者独立比较；同时启用时若用
   `Authorization: Bearer <api_token>` 调管理接口，会因与 `ADMIN_API_TOKEN` 不匹配而 401，
   推荐管理面统一使用 `X-Admin-Token`。
