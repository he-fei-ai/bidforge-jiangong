## 4. 修复项清单（16 项）

### FIX-1 · P1 目录库套用同名节点 → 整个套用 400 失败

- **文件**：`app/routers/outline_library.py`（`apply_library_and_save`）、新增 `app/services/outline_matcher.py`
- **根因**：R203b #20 为「套用目录库保留正文」引入了「归一化标题 → 首个 DB 主键」的一维字典，**无消费、无结构维度**。目录库标准骨架里「施工准备」同时出现在多章之下是常态 → 两个同名节点被注入**同一个** `__original_id` → `_save_outline_to_db` 的重复主键闸门 400 → **整个套用失败**（把「静默丢正文」升级成了「硬失败」）。
- **实证**（本轮 RED→GREEN）：旧实现 `HTTPException 400: 目录中存在重复的章节主键 sec-old-1`。
- **修法**：抽出**结构感知匹配器** `services/outline_matcher.py`（标题路径 → 同父同层 → 同层 → 全局同名，**消费式**，标题强制相等），目录库套用改用它注入 `__original_id`。同名节点各认领各的旧章节 ⇒ 不撞主键。
- **向后兼容**：正常（无重名）目录的匹配结果与旧实现逐字一致（同一标题 ⇒ 同一旧章节）；仅在**旧实现会 400 或会错配**的形态下行为改变。

### FIX-2 · P2 目录库跨父级同名 → 正文张冠李戴

- **同 FIX-1 一次改动收口**：匹配器优先按**标题路径**（祖先行标题元组）认领，与旧章节的真实位置对齐。
- **实证**：旧实现把「第 1 章下的『施工准备』正文」搬到「第 2 章下的同名节」上（`upload_outline` 路径 2026-10-04 已修，library 路径漏改 —— 典型**孪生实现漏改**）。

### FIX-3 · P1 前端「导入目录 / AI 调整目录」保存清空全部正文

- **文件**：`app/routers/sections.py`（`_save_outline_to_db`）
- **根因**：`_save_outline_to_db` 只认 `__original_id`（DB 主键）匹配旧章节；而导入识别 / AI 调整目录回传的节点**根本没有 DB 主键**（前端 `outlineToTreeNode` 造 `upload_<位置路径>` 临时 key）⇒ 全部 `is_new` ⇒ 旧章节进 `to_delete` ⇒ **已生成正文被整批级联删除**（用户表现为「导入一次目录，之前写的正文全没了」，即便导入的目录一字不差）。
- **修法**：落库口增加**标题路径兜底匹配** —— 对「**不带 `local_` 前缀**（非用户手工新增意图）且未携带可识别 DB 主键」的节点，用同一匹配器消费式认领旧章节 ⇒ 保留 content / word_count / status。
- **反例护栏**：`local_` 前缀节点（用户手工新增同名章节）**不参与**兜底 ⇒ 新建而非合并。
- **向后兼容**：常规「前端保存目录」节点携带 DB 主键 ⇒ 走原路径，行为逐字不变。

### FIX-4 · P2 目录库入库闸门（标题超长 / 空标题 / 不可见字符）

- **文件**：`app/services/outline_utils.py`（新增 `normalize_outline_for_library` 单一入口）、`app/routers/outline_library.py`（create/update）、`app/routers/upload_outline.py`（save-as-library）
- **根因**：三条入库路径只做「三级裁剪 + 编号重排」，不清洗、不校验 ⇒ **库里能存、套用时被拒**（且错误文案说的是「编号校验未通过」，归因误导）；零宽字符标题原样入库并随目录库导出进 .md/.txt。
- **修法**：统一走 `normalize_outline_for_library`（解析 → 清洗不可见字符 → 裁剪+重排 → `validate_outline_numbering`）⇒ 入库即以**可行动 400** 拒绝（标题需非空且 ≤200 字、编号须合法）。

### FIX-5 · P2 导出侧 L1 章号硬钳 30 → ≥31 章标题字面重复

- **文件**：`app/services/ai/heading_v2.py`（`_format_number`）
- **根因**：`n = max(1, min(30, c[0]))` ⇒ 第 31/32/… 章标题**字面完全相同**（都是「第三十章」），三章的正文子标题前缀全部塌缩为 `30`（跨章撞号）。`numbering.stored_id_to_display` 与前端 `formatOutlineTitle` **都有**超限回退，只有导出侧没有 ⇒ 三方口径分叉。
- **修法**：与 `numbering.py:470` 逐字同口径 —— 字表内用中文数字，超出回退阿拉伯数字（第31章），**绝不产出重复章号**。

### FIX-6 · P2 上传目录落库无写锁

- **文件**：`app/routers/upload_outline.py`（`save_as_outline`）
- **根因**：本路径是「读旧快照 → 标题匹配 → 整表写」复合写操作，但**全程无写锁**（全仓 `BEGIN IMMEDIATE` 仅 4 处，唯独缺这条整表重建路径）。autocommit 下 SELECT 不开事务 ⇒ 两路并发各自基于同一旧快照组装；行数校验（`_r13_write`）挡得住「少行」，挡不住「两路都只 INSERT 新节点、to_delete 为空」⇒ 同方案两套重复章节。
- **修法**：在**首个决策读之前**显式 `BEGIN IMMEDIATE`（调用方已开事务时沿用其事务），与 `sections._save_outline_to_db` 同口径；位置在 AI 调用之后（AI 调用期间不得持锁）。

### FIX-7 · P2 快照回退不清 chart_predictions → 孤儿登记

- **文件**：`app/services/outline_versions.py`（`_restore_locked`）
- **根因**：回退是整表重建（`DELETE FROM sections WHERE scheme_id=?`），但**未清** `chart_predictions` ⇒ 回退前存在、回退后不存在的章节留下孤儿行（图表面板幽灵条目、导出指纹被污染）。同族三条路径（删除单章 / save-outline / upload 整表重建）都显式清理，唯独本路径漏接。
- **修法**：补一条按 `scheme_id` 的清理（表缺失时跳过，不阻断回退）。

### FIX-8 · P3 空标题穿过全部闸门落库

- **文件**：`app/services/outline_utils.py`（`validate_outline_numbering`）
- **根因**：判据只查标题长度上限；`detect_generic_titles` 对空标题 `continue` 跳过；`_detect_empty_top_chapters` 只覆盖「一级且无子节点」⇒ `title=""` 且带子节点的节点可穿过全部闸门落库（前端树里是无名节点、导出成稿出现空标题行）。
- **修法**：判据增补「标题 strip 后为空」⇒ 与标题超长同口径、同可行动文案（400）。

### FIX-9 · P3 拖拽重排 executemany 无行数校验

- **文件**：`app/routers/sections.py`（`reorder_sections`）
- **根因**：完备性校验只保证「id 集合相等」，不保证「期间没被并发删改」；命中行数少于预期时**排序只应用了一部分**却仍返回 `{"ok": true}`（静默错误）。同文件 `renumber_sections_after_reorder` / `_repair_outline_structure_numbering` 均已走 `safe_rowcount` 单一出口，唯独本处是裸 executemany。
- **修法**：行数不符即 **409** 中止（事务随连接归还回滚，不留半套顺序）。

### FIX-10 · P3 罗马数字编号形态整行漏识

- **文件**：`app/services/file_parser.py`（`_OUTLINE_PATTERNS`）
- **根因**：R208 收口了「全角点号 / 中文数字分隔符 / 中文数字+空格」三形态，但**罗马数字**（`I. 总则` / `Ⅱ 施工部署`）仍整行漏识 ⇒ 导入目录少一层章节。
- **修法**：新增两条 pattern（ASCII 大写罗马数字 / Unicode 罗马数字），**插在兜底条之前**（兜底条保持末位，既有 9 条相对顺序逐字不变）；误伤防护：ASCII 分支只认点号/顿号分隔（不认空格，避免英文句子 "I am a worker" 被当编号行）、只认全大写。

### FIX-11 · P3 编排提示词章节编号恒为空（改名残留漏改）+ 前端测试基础设施假红

- **文件**：`app/services/content_plan.py`；`frontend/src/tests/outlineNumberingR87.test.ts`
- **根因（后端）**：R182 把生成期编号字段改名为 `_prompt_number`，`content_plan.py:290` 未同步（仍读不存在的 `outline_number` / `number`）⇒ 编排提示词的「【章节编号】：」恒为空串（该功能默认关闭，故零现网影响）。属本仓反复出现的「**改名未全仓 grep**」缺陷族。
- **根因（前端）**：R88 已把 5 处动态 import 合并为一次 `beforeAll` 预热，但预热目标仍是 **12k+ 行的页面组件** ⇒ 目录簇 15 文件并行跑时该 import 的 transform 成本再次突破 120s ⇒ 基线出现 **1 个 suite 假红**（隔离跑全绿）。现改为：行为断言直接 import 真实实现模块（`pages/schemeWorkbench/outlineNumbering`，页面第 296 行的 import 源），页面「确实接线」由**静态源码断言**锁定 ⇒ 覆盖面不降（行为 + 接线双锁），耗时 10.9s → **2.15s**，假红根除。

### FIX-12 · P1 正文 L7 字母编号第 53 项起塌缩为 `az`（R203b #18 只修了前端，后端三处各自实现）

- **文件**：`app/services/numbering.py`（新增唯一实现 `alpha_label`）、`app/services/content_blocks.py`、`app/services/ai/heading_v2.py`、`app/services/ai/heading_templates.py`
- **根因**：R203b #18 把前端 `outlineNumbering` 的 L7 改为「Excel 式双字母续编」，但**正文侧三处**（`content_blocks` / `heading_templates` / `heading_v2`）各自持有一份 `_alpha_label`，且都是 `min(l7-1, len(ALPHABET)-1)` ⇒ **第 53 项起恒为 `az`**（第 27 项正确、第 28 项起错误）。属本仓反复出现的「**同一功能 N 份实现、只修了一处**」缺陷族。
- **修法**：`numbering.py` 新增 `alpha_label(n)`（Excel 续编唯一实现：1→a、26→z、27→aa、52→az、53→ba），三处改为薄包装引用它；`ALPHABET` 保持 52 项、前 52 项与旧实现**逐字等价**（向后兼容）。护栏逐位比对 1..64。

### FIX-13 · P3 超三级目录被折叠时**不可观测**（用户不知目录被裁剪）

- **文件**：`app/services/outline_utils.py`（新增 `outline_depth_stats`）、`app/routers/sections.py`
- **根因**：目录限三级是硬性裁剪（第四级标题并入父节点 description），但落库响应**不告知**用户「你的目录被裁掉了」⇒ 用户以为四级目录已保存。
- **修法**：**加法式**回传 `clamped_depth` / `clamped_nodes`（不阻断保存 —— 400 会打断前端「仍然保存」的确认流程）。

### FIX-14 · P1 断点续跑的 checkpoint **归属错** ⇒ 「断点续跑」在生产**从未生效**

- **文件**：`app/routers/sse_checkpoint.py`（新增 `_load_resumable_outline_checkpoint`）、`app/routers/sse_handlers.py`
- **根因**：R203b #21 的续跑读的是**本次** `task_id` 的 checkpoint，而 `task_registry.register_task` 每次请求都生成**新 uuid** ⇒ 上次的成果落在**上次任务行**上，本次恒读到空 ⇒ `_resumed_indices` 恒空 ⇒ R203b #21 自己写下的验收锚（「断线后重新生成，已有 children 的章跳过 AI 调用（日志『断点续跑』）」）在生产**零命中**（全仓日志检索无该行）。
- **修法**：新增「按方案取**最近一次被中断任务**的目录成果」取数入口（`_load_resumable_outline_checkpoint`）。安全边界：
  - 只取 `status IN ('stopped','failed')` 的任务 —— **completed 任务不参与** ⇒「跑完后重新生成」仍是全量重算（既有行为不变）；
  - 排除本次任务自身（`exclude_task_id`）；
  - 脏 JSON / 异 kind / 空 outline 一律跳过并留痕，不抛异常（fail-soft ⇒ 续跑失败自动退回全量生成）。

### FIX-15 · P1 断点续跑「**漏章 / 重复章**」（窗口无界 + 首单元短路）

- **文件**：`app/routers/sse_handlers.py`
- **根因**：续跑章的过滤发生在**单元切片之后**，而批循环的窗口扩张有两个缺陷：① 「本轮首单元全已续跑」时 `continue` **短路**了窗口扩张 ⇒ 本轮后半程的章永不被调度（**漏章**）；② 窗口扩张以 `_total` 为界（**无界**）⇒ 窗口可能跨过轮次边界，把下一轮的章提前调度（**重复章**，该章在下一轮再被调度一次）。两者在旧实现里被「续跑恒不触发」掩盖，一旦 FIX-14 让续跑真正生效就会**立刻引爆**。
- **修法**：窗口扩张显式收敛到**本轮边界** `_round_end = min(batch_start + _round_step, _total)`（`while` 条件与 `_w_idx` 取值范围**两处同改**，只改一处会被另一个兜住 —— 见 A/B 变异 M2b 的教训）；「空单元」不再短路窗口扩张（空单元只是不占窗口位）。

### FIX-16 · P1 断点续跑「**章序错乱**」⇒ 目录编号整树错位

- **文件**：`app/routers/sse_handlers.py`
- **根因**：续跑章在「预填充」阶段就 `append` 进 `full_outline`，非续跑章在批循环里才 `append` ⇒ 两者交错时 `full_outline` 的**物理顺序 ≠ level1 章序**；而目录编号由**位置**推导（`renumber_outline` 按序赋值 id/level）⇒ 续跑的第 2 章排到首位就会变成「第 1 章」，整树编号错乱。
- **修法**：新增闭包 `_reorder_full_outline()` —— 按节点对象身份映射回 level1 索引后**稳定**重排（`list.sort` 稳定 ⇒ 同索引节点保持相对次序；节点对象同一 ⇒ 无副本、无副作用）；在「每窗归位后」与「编号重排前」各调一次（部分成果快照同样受益）。**仅在确有续跑章时执行** ⇒ 无续跑时行为逐字不变。

- **效果复算锚**：
  1. 目录库套用含同名子节的目录 → **不再 400**，同名节点各成一行、正文保留；
  2. 前端「导入目录（智能识别）」后点保存 → 已生成正文**不再被清空**（`cleared_content_sections` 不再出现）；

  7. 快照回退 → `chart_predictions` 无孤儿行；
  8. 拖拽重排遇并发删除 → 409「目录在保存期间被并发修改」；
  9. 导入含 `I. 总则` 的文档 → 该行不再整行漏识；
