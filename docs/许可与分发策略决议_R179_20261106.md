# 许可与分发策略决议（R179 · 2026-11-06 · 第 2 版）

> 性质：决议记录。本版取代第 1 版「仅内部使用、不对外分发」的定位。本轮仅改本文档，未修改任何源码、测试、配置，未 commit。
> 适用范围：本仓库（`j:\编程\专项方案工具箱`）全部代码、文档、构建产物与交付物。

## 一、定位

本软件定位为三句：

1. **内部使用**：组织内部日常使用不设许可限制（A 类衍生内容在内部使用时不产生对外义务）。
2. **可对外分发**：允许向外部单位分发源码、二进制、安装包、镜像与随附文档。
3. **部分对外提供服务**：允许将部分能力以网络服务形式提供给组织外用户。

## 二、结论（硬门禁）

1. **当前代码状态不满足上述定位。** 依据：8 个 A 类文件与 2 段逐字提示词是 AGPL-3.0 演绎物（F2、R1、R2），AGPL 的传染面是整个组合作品，而不是被移植的那几个文件。
2. 在完成第四章路径一 / 路径二 / 路径三**任一**的**全部最小完成条件**之前：**不得对外分发，不得对外提供服务**。这是硬门禁，不是建议。
3. AGPL §13 要求向网络交互用户提供**整个组合作品**的对应源码（backend + frontend + 构建脚本 + 迁移脚本），不是只提供触发 §13 的那部分功能或模块。
4. 新定位下**不存在**「内部使用即可豁免」的表述：一旦对外分发或对外提供服务，A 类文件与提示词的义务立即生效，不因主体日常是内部使用而免除。

## 四、三条路径（按新定位重写）

三条路径是**互斥的放行依据**：任选其一执行到底；在一条路径完成前，不得以另一条路径「正在进行」为由发布。

### 路径一：取得书面许可

最小完成条件（缺一不可）：

1. 许可范围逐项覆盖：8 个 A 类文件、8 段提示词（扫描报告 §8 的 #1–#8）、`docs/reference_research` 的摘录、本仓后续修改与再分发。
2. 许可文本**显式覆盖「再分发」与「网络服务」两种使用**；只写「允许使用」「允许修改」不足以放行对外分发或对外服务。
3. 写明是否免除 AGPL §7(b) 归属要求；若未免除，仍须在分发物与网络服务中保留 `NOTICE` 归属。
4. 留存可核验的授权凭证（书面文件、签署主体、生效范围与期限）。
5. 授权范围之外的组件仍按各自原许可处理。

代价与限制：谈判周期与结果不由本方控制；许可范围写不全（例如漏掉再分发或网络服务）时，该路径不成立，仍需路径二或路径三。

### 路径二：整体 AGPL 合规

最小完成条件（缺一不可）：

1. 仓库根目录放 `LICENSE` 与 `NOTICE`；`NOTICE` 保留原作者、原仓库链接、邮箱与版权声明。
2. 整个组合作品以 **AGPL-3.0-only** 授权；对方是 `only`，**不接受 `or-later`**，不得改为 MIT、闭源或商业专有许可。
3. 向网络交互用户提供**完整对应源码**（§13）：UI 内提供「源代码」入口，或随服务提供可下载的完整源码包，覆盖 backend、frontend、构建脚本与数据库迁移脚本。
4. 保留所有源文件的版权头与归属声明。

代价与限制：整套实现对外公开，方案生成本身的差异化不再受保护。**选这条路后「内部使用」不再是中间态**——不能「内部按闭源跑、对外时再切 AGPL」，因为产品一旦对外分发或对外服务，整个组合作品即处于 AGPL 义务之下。

### 路径三：重写到可主张独立

最小完成条件（缺一不可）：

1. 重写 8 个 A 类文件（代码级 5 个 + 提示词级 3 个）。
2. 按功能规格**重述** 8 段提示词，不是换词、不是调序、不是改字段名。
3. 重新推导阈值、常量与正则并留下推导依据，证明取值来自本仓需求而非照抄。
4. 删除 `docs/reference_research` 摘录，清理全部「移植 / 对齐 / 对方行号」注释，同步改写 `backend/tests` 中的同源自证断言与命名。
5. 以重写 git 历史的方式清除历史中的摘录（`git log -- docs/reference_research` 返回空）。
6. 留存 clean-room 记录：谁写、何时写、是否接触过对方源码。

两条硬约束：

- **只清理注释不算重写。** 注释不改变法律状态，A 类代码与提示词原文仍在。
- **B 类不是免责区。** B 类是在可读源码前提下写的，且常量、正则字符集、函数顺序多处一致；「独立创作」看表达相似与接触可能，不看自评的 A/B/C。

**诚实限制（必须写入决策记录）：重写不保证最终能主张独立。** 阈值、正则、常量的共同来源痕迹可能仍被认定为演绎；届时只剩路径一或路径二，不得以「已重写」作为放行依据。

## 七、不做的事

1. 本决议**不构成法律意见**，也不构成**许可豁免**。
2. 本决议不预先授权任何一次具体发布；每次发布都必须重新通过第六章门禁。
3. 本决议不新增 `LICENSE`/`NOTICE`（除非按路径二执行），不改变任何组件的授权状态。
4. 本决议不要求、也不允许为「看起来合规」而删功能、降级功能或关闭开关。
5. 本决议不消灭第五章任何一项残留风险；风险仍然存在，只是尚未对外释放。
6. 本决议不包含「内部使用即可免责」的表述；新定位下不存在该豁免。
