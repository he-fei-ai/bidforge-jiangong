## 5. 登记待裁决项（各带可执行方案与触发判据，非「以后再说」）

### 5-1 · R210 D-1 「同一事实」判据主口径收敛 + AI 落库同名闸门

- **现状**：T-01 闸门（`global_facts.py:924`）按**名称** `_norm_fact_text`（去空白+小写）；XV 校验器（`facts_cross_validators.py:468/:744`）按 **fact_key**；持久化（`facts_extractor.py:3351`）按 **key**。`_norm_fact_text` 与 `normalize_key` 是**两种不同归一**；AI 落库路径无同名闸门。
- **影响**：同一事实在「注入闸门 / 跨段校验 / 持久化」三处可能被判为不同结论；AI 落库可能绕过同名防重。
- **需产品裁决的口径问题**：**主口径用 fact_key 还是名称归一？AI 落库是否也按主口径加同名闸门？** 改闸门语义即改用户可感知行为（去重/冲突判定边界）。
- **可执行方案（一旦裁决）**：
  1. 选主口径（建议 fact_key + `normalize_key` 单一出口，因 fact_key 是跨模块稳定标识）；
  2. `_assert_no_conflicting_injectable_duplicate` 改委托 `normalize_key`；
  3. AI 落库路径（`persist_extraction` / 相关入口）加同名闸门；
  4. 三处判据统一后补贯通护栏「同一事实三处同结论」。
- **触发判据**：产品给出主口径选择，或出现「同一事实在注入与跨段校验结论不同」的用户报障。

### 5-2 · R210 D-4 分类×分页接口扩展

- **现状**：`list_facts`（`global_facts.py:1098`）签名只有 scheme_id/project_id/limit/offset，**无 category 入参** ⇒ 按分类过滤需接口面扩展。
- **影响**：前端无法按分类分页拉取事实列表。
- **可执行方案（一旦裁决）**：`list_facts` 加 `category` 入参（可选，默认不过滤）+ 前端传参 + 测试；零契约破坏（加法式入参，未传时行为不变）。
- **触发判据**：产品要求按分类分页展示事实列表。

### 5-3 · R211 D-1 超长闭合围栏截断上限

- **现状**：`fence_common.find_unclosed`（:84）无行数上限（能判闭合），`content_blocks.read_fenced_block` 有截断上限 ⇒ 分叉存在，但既有护栏锁「太远即截断」意图。
- **影响**：超长围栏在正文生成侧可能被截断（用户长代码块/表格块），而闭合判定侧能判闭合。
- **需产品裁决**：**截断上限是否放宽？** 放宽影响长文档性能/内存。

### 5-5 · R212 D-2 SAF-03/SAF-06 关键词分叉（AuditRule 字段增设）

- **现状**：引擎 `SAF03_TITLE_KEYWORDS`（`preflight_engine.py:558`）= 组织机构/应急组织/领导小组/指挥，**不含「职责」**；注册表 SAF-03 keywords（`audit_rules.py:410`）含「职责」。SAF-06「预警值」被登记为标题覆盖词而引擎侧属正文阈值词（`SAF06_THRESHOLD_KEYWORDS`，`:566`）。

## 8. 教训归档

1. **「已有值不覆盖」≠「改值后须重算」** —— `apply_fact_dimensions` 语义是「已有值不覆盖」，用于「改 value 后维度须重算」场景会静默保留旧维度（错上加错）；**新增强制覆盖函数而非复用非覆盖函数**，避免伪修复。
2. **同族实现必须一次 grep 全族** —— F1 取证确认「同一事实」判据三处实现分叉（`_norm_fact_text` / `normalize_key` / key），新增/改动前先 grep 同族、优先复用既有出口（承 R209 教训③）。
3. **「各自全绿」不等于「链通了」** —— 本轮 F1/F2 聚焦受影响文件全绿 + 事实簇与基线一致，但跨模块接缝（事实 → 正文 → 审核 → 导出）需贯通护栏才算数（承 R210-R212 教训①）；本轮的 F1/F2/F5 均已在各自模块内护栏，跨模块接缝登记见 §5-1。
4. **前端读源码走 vite `?raw` 导入**（承 R210-R212 教训⑤）—— 本轮未做跨端源码断言，若后续做须避开 `node:fs`。
5. **行尾权威是 `.gitattributes`**（承 R210-R212 教训④）—— audit.ts / ReadinessDashboard.tsx 归一为 LF 无 BOM 的依据是 `.gitattributes`（`*.ts`/`*.tsx`/`*.md` `eol=lf`），不是「文件当前长什么样」。
