### 2.1 工作台窄屏左栏塌陷（根因判断被推翻）

- 原问题（基线 `6b62044`）：
  - `frontend/src/pages/schemeWorkbench/SchemeTreePanel.tsx:91`、`FactsCategoryPanel.tsx:22`、`tabs/ImportTab.tsx:129` 三个左栏都写死 `width: 300`（当前 HEAD 分别为 `:92`、`:23`、`:130`）。
  - 左栏同时 `flexShrink: 0`，窄屏下不肯收缩。
- 用户可见现象：390px 视口下，左栏占 300px，右侧 Tab 内容区只剩约 20–40px（`index.css:1357` 注释记录），表格/正文实际不可读。
- 第一版改法（A 批 `4061cfd`）：`index.css` 在 `@media (max-width:768px)` 内把 `.swb-workbench-main` 改为 `flex-direction: column`，左栏 `width:100%`（当前 `index.css:1359-1363`）。
- **被推翻的判断**：堆叠后“宽度”问题消失了，但面板高度只剩 62px——只剩卡片/面板标题栏，目录树完全不可见。实测：
  - 390×844：`sideH=62`，树 `scrollHeight=0 / clientHeight=0`；
  - 768×1024：树 `sh=0 / ch=0`，面板同样只剩标题栏（该次 JSON 未单独落 `sideH`；62px 是 390 档的实测落值）。
  - 根因不是宽度，而是 A 批自己引入的 `max-height:38vh` + `flex:0 0 auto`：内层面板滚动区是 `flex:1`（`flex-basis:0%`），在“高度 auto + max-height”的父级里拿不到可分配空间，父级高度退化为标题栏的 62px。
- 最终改法（验收补丁 `8baa255`）：给**确定高度**，不是 `max-height`：

  ```css
  .swb-workbench-main > .swb-side-panel {
    width: 100% !important;
    height: 38vh !important;
    max-height: 38vh;
    flex: 0 0 38vh !important;
  }
  ```

  当前位于 `frontend/src/index.css:1362-1370`，注释在 `:1364-1366` 明确记录“实测会塌成只剩标题栏（62px）”。

## 6. 诚实边界

1. 布局与暗色结论来自 **mock fixture + Vite dev proxy**，不是真实业务链路。
   - mock 返回的是合成数据（固定的项目、目录、19 章进度、健康状态），不能代表真实返回长度、真实错误、真实分页/空态。
   - Vite 的 `/api/v1` 代理会改变连接与流的行为（见下），浏览器看到的是“代理后的后端”，不是生产直连。
2. SSE 只验证了“端点不可达”，没有验证“流中途断 TCP”。
   - 手段：CDP `Network.setBlockedURLs(["*sse/generate-content*"])` 直接让请求失败，属于“连接建立不了/立刻失败”。
   - 没有覆盖：流已经建立、已经收到若干事件后，TCP 被切断或 chunked 流被截断。
   - 原因：Vite dev proxy 会把“半截 chunked 流”归一成一次干净的 EOF，前端看到的是一条正常结束的响应，无法复现“流中途断”。因此本轮的重连/未知态证据只对“端点不可达”成立。
   - 要验证真正的中途断流，至少需要：
     1. 绕过 Vite，浏览器直连后端（或使用可注入故障的代理，如 toxiproxy）；
     2. 在后端发出 N 个事件后强制关闭 socket / 丢弃后续包（防火墙 drop、`iptables`、或后端测试钩子）；
     3. 同时观察：`EventSource.onerror` / `readyState`、前端是否进入“重连中”、重连失败后是否进入未知任务态、后端任务是否继续跑并计费、重新接管是否能拿到终态；
     4. 对“断流后任务仍 running”的场景验证生成守卫不会让用户重复发起。
3. 数值来源与时间
   - 浏览器数值来自 2026-11-07 22:02–23:11 的自动化运行；本文档写作时环境已关闭，没有重跑。
   - `tsc` / `vitest` 数值来自 2026-11-08 12:16–12:21 的落盘日志，运行对象是 `26cc86a`；`7153c24` 只改了 docs，不改变前端代码结论。
4. 亮/暗数值
   - 布局数值不随主题变化；暗色只影响颜色。表中“亮/暗”若只给一组数，表示两主题实测布局相同，颜色差异另见 2.2。
