## 6. 分期实施

### Phase A：文种标签引擎（已放行）

目标：在不改变旧输出的前提下，提供结构化 `GenreTag` 与三态结论。

改动：

- 改 `backend/app/services/scheme_classification.py`：新增 `TriState`、`GenreTag`、`build_genre_tag()`；**不改** `classify_scheme` / `evaluate_hazard_level` 的既有返回键与行为。
- 新增 `backend/app/services/genre_rules.py`：第三层规则（编制主体、论证前置、禁止表述），每条输出 `rule_id / layer / conclusion / evidence / clause_ref`。
- 新增 `backend/app/services/genre_assist.py`：仅在规则零命中且参数缺失时调用 LLM；输出 `source="llm_suggested"`，不得写入危大等级。
- 改 `backend/app/routers/schemes.py`：`GET /api/v1/schemes/{id}/genre`、`POST /api/v1/schemes/{id}/genre/evaluate`；写 `schemes.scheme_classification_json`（列已存在，不动 `db.py`）。
- 开关 `genre_tag_enabled` 默认 `false`；关闭时新路由返回与现状一致（零差异）。

验收口径：

1. 阈值边界表驱动：基坑 3.0/5.0m；模板支撑 5/8m、10/18m；荷载 10/15 kN/㎡；起重量 100/300kN。逐项断言 `is_hazardous/is_oversize` 与 `rule_trace` 中的 `rule_id`。
2. 缺失参数 → `undetermined` + `missing_params`；不得返回 true/false。
3. 模糊名称走 LLM：断言 `source="llm_suggested"` 且 `hazard=undetermined`，规则记录保留。
4. 变异验证：阈值常量改动 1 个单位，边界用例必须变红；恢复转绿。
5. 兼容：旧 `classify_scheme` 输出键集合逐字不变，旧调用点零回归。

风险/回退：阈值只取存量 `HAZARD_THRESHOLDS`；新代码纯加法；开关关闭即回到现状。

遗留待决（本轮不修）：`scheme_classification.py:865-870` 的"缺失参数→保守判危大"旧路径。

### Phase B：模板实例化 + 节点双标签（已放行）

目标：给模板节点增加可选元数据，并用已确认事实实例化。

改动：

- 改 `backend/app/services/outline_templates.py`：新增 `TEMPLATE_FACT_DEPS`；节点构造器支持可选 `content_type / fact_deps / placeholder`，缺省时输出与现状逐字一致。
- 新增 `backend/app/services/outline_instance.py`：`instantiate(template_key, facts_snapshot)`，只消费 `is_resolved=1 且 has_conflict=0` 的事实；未命中节点 `fact_status="missing"`。
- 改 `backend/app/routers/schemes.py`：`POST /api/v1/schemes/{id}/outline/instantiate?dry_run=true`。
- 元数据写入现有 `sections.outline_json` 节点 dict；**不新增列、不动 `db.py`**。
- 开关 `outline_instantiate_enabled` 默认 `false`。

验收口径：

1. 事实存在 → 节点出现具体值并带 `fact_source_ref`。
2. 事实缺失 → `fact_status="missing"`，不得输出"根据实际情况确定"。
3. 元数据覆盖率 100%：每节点必须有 `content_type ∈ {experience, standard, calculation, schedule, verification}`。
4. 变异：删除某 `fact_dep` 后对应用例必须红；恢复转绿。
5. 开关关闭时与既有 AI 目录生成输出零差异。

风险/回退：模板元数据需逐类人工复核；开关默认关闭，停用即回退。
