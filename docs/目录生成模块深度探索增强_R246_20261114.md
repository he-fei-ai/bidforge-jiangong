## 二、探查结果

### 2.1 模块边界与关键锚点

- 模板注册表：`backend/app/services/outline_templates.py` —— `BUILDERS`（48 键）、`build_outline` / `match_template` / `list_templates`。
- 连续性判据：`backend/app/services/outline_quality.py::check_outline_continuity`（产出 `duplicate_titles` / `generic_titles`）。
- 自动确认：`backend/app/services/outline_auto_confirm.py::evaluate`（`duplicate_titles` 为**硬阻断**，`ready=False`）。
- 目录重排：`backend/app/services/ai/json_response.py::renumber_outline`（薄包装，唯一实现在 `backend/app/services/numbering.py::renumber_outline_nodes`）。
- 正文子标题编号：`backend/app/services/numbering.py::renumber_section_body_subheadings`、`normalize_section_content_subheadings`；算法本体 `backend/app/services/content_blocks.py::_compute_subheading`。
- 模板数据（标题字符串所在）：`_outline_tpl_generic_a.py`、`_outline_tpl_generic_b.py`、`_outline_tpl_other_hazard.py`、`_outline_tpl_scaffold.py`、`_outline_tpl_lift_demolition.py`（均在 `backend/app/services/` 下）。

### 2.2 核心缺陷：12/48 内建模板被 auto-confirm 硬阻断

48 个内建模板经 `renumber_outline` 后，**12 个模板**被 `check_outline_continuity` 判为 `duplicate_titles` 非空；由于 `outline_auto_confirm.evaluate` 把 `duplicate_titles` 作为硬前置，这些模板套用后会在 **8 秒自动确认路径**上被阻断（`ready=False`），前端只能走人工确认。

根因：模板标题跨父子 / 跨章重复（如 `green` 模板四节都叫「技术措施 / 控制指标」；`emergency` 的「风险辨识 / 应急领导小组 / 信息报告 / 专项应急处置措施」与其他章节同名），而 `check_outline_continuity` 的 `duplicate_titles` 是**全局、跨层**判据。这是数据层缺陷，不是判据缺陷。

### 2.3 其余面排查结论

- 目录树构建（`_nine_chapter` / `_chapter` / `S` / `C`）、多级编号同步（`renumber_outline_nodes`）、正文子标题编号（`_compute_subheading` 相对深度 + 单调收敛 + E3 节内命名空间）、AI 提示词（`_reg` 注册链）均正常。
- 长方案分步生成状态、并发、缓存、日志在本模块未发现独立缺陷；DB 子章节与正文子标题的 E3 隔离（`has_db_children` → `N）` / `字母、` 命名空间）在探针中验证成立。
- 标题重命名只改**模板数据标题字符串**，未触碰 `description`、判据、auto-confirm 行为；`test_default_build_outline_is_unchanged` 只锁节点键集、`test_outline_templates_have_scope_anchor` 锁提示词锚点，均不受影响（既有测试不锁标题值）。

## 七、遗留问题与后续建议（步骤 7）

1. **4 个环境型失败**：`PermissionError` 写 `backend\data\_exports` 与 `backend\data\projects`（DENY ACL）。需管理员为这两个目录授予写权限，或把 `data` 根指向可写路径；与本模块缺陷无关，不影响结论。
2. **判据语义（登记，不做）**：`duplicate_titles` 为全局跨层判据，未来若需允许「不同章节合法同名」（如多个章节的「施工风险辨识」），应把判据改为「同父兄弟重复」而非全局同名。此为行为变更，超出本轮「数据层修复」授权，登记为后续候选。
3. **护栏韧性**：A 不变式（48 模板无重复/泛化标题）已把 `duplicate_titles` 判据与模板数据解耦，后续模板编辑若引入重复标题会被护栏在 CI 拦下，无需人工排查。
4. **建议后续**：在 auto-confirm 端到端（前端触发 → SSE → 8 秒确认）再补一条 UI 级探针，覆盖「模板套用 → 自动确认成功」的完整链路（本轮已覆盖服务层全链 + 前端单元，未覆盖浏览器级 SSE 冒烟）。
