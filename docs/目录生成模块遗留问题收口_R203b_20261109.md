## 修复项清单（7 项）

### #15 · 环/悬挂节点自动处置（P2）

- **文件**：`app/routers/sections.py`（`_repair_outline_structure_numbering`）
- **根因**：`_build_tree` 对 parent_id 成环的组件判「谁都不是根」→ 静默丢弃；repair 只处理可达树，环内节点永久缺章。
- **修法**：repair 先检测不可达节点（与 `_outline_structure_report` 同口径：全表 id − 树内可达 id），把 `parent_id` 清空重挂为根，再 renumber。**保数据不丢章**。
- **向后兼容**：正常树无不可达节点 → 零行为变化。

### #16 · numbering_mismatch UUID/垃圾 id 盲区（P3）

- **文件**：`app/services/outline_quality.py:694`
- **根因**：`_DOT_ID_RE.fullmatch(nid) and nid != path` 只对点分 id 判错位，UUID/垃圾 id 不报。
- **修法**：判据改为 `not _DOT_ID_RE.fullmatch(nid) or nid != path`——非点分 id（renumber 未能归一）本身即错位。
- **语义**：`check_outline_continuity` 在 normalize 后调用，合法 id 必为点分路径。

### #17 · 空章不静默成功（P3）

- **文件**：`app/routers/sse_handlers.py:2293, 2313`
- **根因**：空章（ok 但零子章）计入 `failed_chapters` 但终态仍可 `completed`，前端仅靠 `failed_count` 弱信号。
- **修法**：`final_status` 与 `event_name` 双口径——有空章时降为 `degraded`（TERMINAL_TASK_STATUSES 既有分支）。全章失败仍走 error/failed，停止仍走 stopped。
- **向后兼容**：`degraded` 是既有终态（R187/R188 引入），前端已识别。

### #18 · L7 字母编号超 z 折叠（P3）

- **文件**：前端 `outlineNumbering.ts`（`alphaLabel`）+ 后端 `heading_v2.py`（`_alpha_label`）+ `heading_templates.py`（`_alpha_label`）
- **根因**：三处各有独立 L7 实现，均钳制在 z 或越界回退 "a"。
- **修法**：Excel 风格双字母续编——1→a, …, 26→z, 27→aa, 28→ab, …。三处统一同口径。
- **验证**：前端 80/80 + 后端 88/88 全绿。

### #19 · 窗口内 prior_chapters 跨章去重（P3）

- **文件**：`app/services/ai/prompts/outline.py`（`outline_sublevel_system`）
- **分析**：窗口内并发单元的提示词在 AI 调用前已构建（gather 语义），无法共享彼此结果。这是**并发与上下文完整性的设计取舍**（窗口=1 可完全共享但失去并发收益）。
- **修法**：提示词第 3 条追加「同一窗口内可能有其他章节同时生成，其小节不在此列表中——请基于'其他章节标题'推断各章可能的子节，主动规避跨章重复」。审核重复标题重检兜底不变。

### #20 · 套用目录库保留正文（P2）

- **文件**：`app/routers/outline_library.py`（`apply_library_and_save`）
- **根因**：目录库节点 id 是编号（1/1.1）而非 sections 主键，`_save_outline_to_db` 按 `__original_id` 匹配时全部 is_new → 整表重建级联删除正文。
- **修法**：调用 `_save_outline_to_db` 前，按归一化标题匹配已有章节（与 `upload_outline._norm_title` 同口径），命中则注入 `__original_id = DB 主键`。匹配不到 → 正常 INSERT。
- **验证**：181/181 全绿。套用目录库后已生成正文不再丢失。

### #21 · checkpoint 逐章断点续跑最小改进（P3）

- **文件**：`app/routers/sse_handlers.py`（stepwise 批循环前 + 批循环内）
- **修法**：
  1. 批循环前读取上次 checkpoint 的 `outline`，按归一化标题匹配当前 L1 章节，已有 children 的直接复用（`_resumed_indices`）。
  2. 批循环内过滤 `_resumed_indices`——已续跑章跳过 AI 调用。
  3. 进度 `sub_done` 用 `len(full_outline)`（含续跑章节）。
  4. 续跑失败 fail-soft 回退全量生成。
- **效果**：断线/停止后重新生成，已有 children 的章不重复烧配额。
- **向后兼容**：无 checkpoint → `_resumed_indices` 为空 → 行为逐字不变。
