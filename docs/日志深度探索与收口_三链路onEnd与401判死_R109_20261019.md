## 三、本轮修复

### FIX-1 · P0 · 正文链/事实链 on_end 宽限回收接线

**根因**：R106 FIX-6 给目录链 `with_heartbeat(..., on_end=_stream_end_guard(_stream_holder))` 补了断连回收，但**正文链（L7888）和事实链（L8345）漏接**。后果：客户端断连后，`mark_stream_ended` 永不触发，`reap_orphan_tasks` 的 `_abandoned()` 判据因 `stream_ended_at` 缺失而豁免——内存态永远 `running`，只能重启进程。

**修法**：
- `sse_handlers.py` generate_content：在 `_stats_provider` 后加 `_content_holder: dict = {}`；`event_stream` 内 `register_task_exclusive` 后写 `_content_holder["task_id"] = task_id`；返回处加 `on_end=_stream_end_guard(_content_holder)`。
- generate_facts：同理加 `_facts_holder`，复用既有 `_facts_task_id[0]` 模式。

**验证**：AST 锁 `test_content_chain_has_on_end`（3 处 with_heartbeat 全有 on_end）+ `_content_holder["task_id"]`/`_facts_holder["task_id"]` 赋值存在；R106 护栏 41 例全绿。

### FIX-2 · P1 · HTTP 401 纳入非重试永久错误

**根因**：`provider_factory.is_non_retryable_error` 只认 HTTP 402/403/404，漏了 **HTTP 401**。agnes 令牌失效（`HTTP 401: 该令牌状态不可用`）被当作瞬态错误，不触发配额冷却、不进连击判死，每次请求都白打一次 HTTP——生产实证 49 连败。

**修法**：`provider_factory.py` L1771：
- 判据加 `"HTTP 401"`
- 文本签名加 `"令牌状态不可用"`, `"token status"`, `"invalid token"`, `"unauthorized"`

**效果**：401 后该 provider 进入 120s 配额冷却窗口，冷却内直接跳过（记 `circuit_skipped`，不发请求）；`_is_quota_error` 自动覆盖（401 走 `is_non_retryable_error` 分支）。429 限流仍走退避路径不变。

**验证**：`test_http_401_is_non_retryable`（401/402/403/404/中文令牌不可用全 True；429/网络错误 False）+ `test_401_triggers_quota_cooldown`。
