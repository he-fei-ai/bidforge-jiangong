### 1.2 B-02 扫描失败不写缓存

**改了什么**（[consistency_scanner.py](file:///j:/编程/专项方案工具箱/backend/app/services/consistency_scanner.py)）
- `SCAN_CACHE_FORMAT_VERSION = "v2"`（[L65](file:///j:/编程/专项方案工具箱/backend/app/services/consistency_scanner.py#L65)），`ctx_hash = f"{ctx_hash}|v2"`（[L752-L753](file:///j:/编程/专项方案工具箱/backend/app/services/consistency_scanner.py#L752-L753)）→ **历史 v1 假缓存一次性整体失效**。

- `_scan_batch` 返回 `(out, failed)`；失败章 `failed.add(sid)` 且 `out.pop(sid)`，`_save_cached_rows` **只写成功章节**。
- 返回体新增 `failed_sections`、`partial`（[L841-L854](file:///j:/编程/专项方案工具箱/backend/app/services/consistency_scanner.py#L841-L854)）；空方案返回同样带 `failed_sections: [] / partial: false`（[L733-L734](file:///j:/编程/专项方案工具箱/backend/app/services/consistency_scanner.py#L733-L734)）。

**为什么**：旧实现把 AI 失败当「0 冲突」写入缓存，之后同内容永久命中 → 静默零冲突。这与「已检」的可信度直接冲突。

**如何验证**：新增 [test_consistency_scan_optimization.py](file:///j:/编程/专项方案工具箱/backend/tests/test_consistency_scan_optimization.py#L344-L396) 的 `TestScanFailureCache::test_failed_scan_does_not_poison_cache`：mock 批扫与单章均抛异常 → `partial=True`、`failed_sections` 覆盖 4 章、缓存行 0；**二次调用 `cached==0`**（不命中假缓存）。

**对存量方案重检的影响**
- 第 1/2 类：此前被误判 block/high 的存量方案，重检分数将**上升**，等级可能从 C/D 回到 B/A —— 这是修正误报，不是放宽标准（法定标题本身就是合规写法）。
- 第 3 类：同一冲突不再双计，一致性维度**最多回升 8 分**。
- 第 5/6 类：此前长方案或扫描失败的「可交付」结论会变为**不可放行**（`incomplete`）—— 这是本轮最希望发生的方向。
- 第 7/8/9 类不改变评分，只改变状态与展示真实性。
- 第 4 类提升「可修」覆盖率，不改变判定。
- 第 10 类新增响应键，旧消费方无感；正文回滚场景才会置 true。

## 补充：D-16 一致性批扫覆盖校验（2026-11-04）

### 1. 覆盖校验判据（按章节 ID 逐个比对，不比数量）

| 层 | 判据（[consistency_scanner.py](file:///j:/编程/专项方案工具箱/backend/app/services/consistency_scanner.py)） |
|---|---|
| 提示词层 | 批扫 system/user 要求返回 `{"scanned_sections":[章节ID...],"conflicts":[...]}`，`scanned_sections` 必须列出**实际检查过的全部章节 ID**，漏列即漏答 |
| 解析层 | `ai_scan_batch` 的 validator 强制 `conflicts` 与 `scanned_sections` **同为 list**；缺任一字段 → 重试 1 次后仍不合法则返回 `None`，走逐章回退 |
| 覆盖判定 | `covered = {str(x).strip() for x in scanned_sections} ∩ {sec["id"] for sec in batch}`，与请求集合**集合相等**才算完整覆盖 |
| 自相矛盾 | 冲突行的 `section_id` 落在 `batch_ids - covered`（没声明检查却报了冲突）→ 整批不可信，返回 `None` |
| 归属校验 | 冲突行缺 `section_id` / 指向批次外章节 / 非 dict → `_group_batch_rows` 返回 `None` → 整批作废 |
| 调用侧 | `requested = {sec["id"] for sec in batch}`；`covered = requested & set(grouped)`；`missing = [sec for sec in batch if sec["id"] not in covered]` |

### 2. 缺失时的三种处理分支

| 分支 | 触发条件 | 动作 |
|---|---|---|
| ① 少量缺失 → 只补扫 | `missing` 非空且 `len(missing)/len(batch) < 0.5` | 保留已覆盖章节结论，仅对 `missing` 逐章 `_scan_one`（`raise_on_failure=True`） |
| ② 整批 / 大面积缺失 → 整批回退 | `covered` 为空，或 `len(missing)/len(batch) ≥ COVERAGE_WHOLE_BATCH_FALLBACK_RATIO（0.5）` | `out.clear()` 丢弃半批结论，**逐章重扫整批**（含原本已覆盖章），不拼半批结果 |
| ③ 无法补全 → 可见化 | 单章补扫/重扫抛异常 | 该章不产出结论、计入 `failed_ids`；返回 `partial=true` + `unscanned_sections`（与 `failed_sections` 同源）列出全部未扫描章 |

批调用异常或 `ai_scan_batch` 返回 `None` → 旧逐章路径（同一 `_scan_one`），失败同样计入 `failed_ids`。

### 3. 缓存写入门槛

- 只写 `scanned_rows` 内的章节，即**本次实际产出结论**的章节；缺失章 / 失败章不在字典中，不会以 `rows_json='[]'` 落库。
- 少量缺失时，补扫成功的章节才进入 `scanned_rows`，最终按「本次有结论的章节」逐行写入。
- 无法补全时 `scanned_rows` 为空 → `_save_cached_rows` 直接返回，**缓存 0 行**。
- `ai_scan_batch` 不再为未声明章节预填空列表（旧实现的 `{s["id"]: [] for s in sections}` 正是「漏答 = 0 冲突」的源头）。
- 本次**未改动** `compliance.py`：D-16 全部落在扫描器与其提示词。

### 4. 缓存版本：升 v3（同一张表、同一常量）

- 与 B-02 是**同一张表** `consistency_scan_cache`、**同一个键**（`section_id` + 带版本后缀的 `context_hash`）、**同一个常量** `SCAN_CACHE_FORMAT_VERSION`；不存在第二张缓存或第二个版本常量。
