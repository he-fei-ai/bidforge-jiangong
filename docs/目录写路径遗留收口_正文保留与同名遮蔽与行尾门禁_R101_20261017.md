## 2. 探查结论（根因链，均有代码依据）

### 2.1 四项遗留的根因

**遗留 1（P0）· 上传路径自动改写标题导致已生成正文丢失。**
`upload_outline.save_as_outline` 的正文保留按「归一化标题相等」匹配旧章节
（`_take_from` 强制 `_norm_title(cand) == expected_nt`）；而落库前自动外科式重写
（R89 起）会**改写标题** ⇒ 改写后的新标题在旧库中找不到同名行 ⇒ 匹配全部落空 ⇒
旧章节进入 `final_section_ids` 之外 ⇒ 被级联删除（`to_delete` → `_collect_subtree`
→ 级联清图表预测），已生成正文**不可恢复**（当时只能计入 `cleared_content_sections`
如实回报）。

**遗留 3（P1）· `sse_handlers.py` 历史遗留同名遮蔽。**
`CONTENT_REQUEST_TIMEOUT` / `CONTENT_TOTAL_TIMEOUT` 在 `sse_handlers.py` **模块级被定义两次**：

- 早处（约 L222-226）**过期字面量** `300` / `660`；
- 下方「配置配了不生效」修复块（约 L337-339）`int(settings.content_request_timeout)`
  / `int(settings.content_total_timeout)`。

按执行顺序，**后者静默覆盖前者** ⇒ 同名遮蔽，`settings` 环境变量绑定虽已修好，
但文件内仍留一份过期常量，语义含混。此前 R65 遮蔽锁刻意把该文件排除在外（注释
「纳管需单独立项」）。

**遗留 2（加固）· 行尾 / BOM 漂移无门禁。**
R101 收口时曾把 `sse_handlers.py` 整体改写行尾（HEAD 全 CRLF → 工作区全裸 LF），
触发字节体检红。全仓普查（`git ls-files backend` 过滤 `.py`）确认：**44 个既有
`backend/*.py` 本就含裸 LF、6 个带 BOM、0 个孤立 CR** ⇒ 不能做全仓「必须 CRLF /
禁 BOM」的一刀切；应只拦「与 HEAD 不一致的漂移」。

**遗留 4（加固）· 裸词干意图未锁。**
`GENERIC_STEM_ORDINAL_RE` 的序号分组**刻意可选**（AGENTS R85 记录在案），故裸词干
「专项」「步骤」「流程」「要求」「说明」… 单独成句即判占位；而 `GENERIC_BARE_STEMS`
是被 R85 护栏锁定的**6 词封闭白名单**（`test_bare_stem_whitelist_is_narrow` 锁精确
相等）。二者**不是等号关系**：白名单是正则裸词干分支的**真子集**（6 ⊂ 16）。R85
只锁了「白名单窄」，**未**锁「裸词干整体判占位」这一意图 ⇒ 后人可能朝两个方向
「修正」：把正则序号改**必选**（**减少**检出）、或把白名单扩到与正则相等（收进
「要求/说明/流程」等可能构成正常章节名的词）。探针实测（本轮）：

```
'步骤'→True  '流程'→True  '工序'→True  '要求'→True  '说明'→True
'方法'→True  '保障'→True  '安排'→True
'施工要求'→False '监测措施'→False '工序流程'→False '质量保障措施'→False
'进度安排'→False '内容简介说明'→False '深基坑支护'→False '专项施工方案'→False
'专项6'→True '专项方案6'→True '措施三'→True '内容2'→True '措施１'→True
```

### 2.2 审计发现的其余缺陷（本轮一并修）

- `upload_outline.save_as_outline` **零占位闸门**（与 `config.outline_autofix_generic_on_save`
  注释声明的「四类写入口全覆盖」不符）。
- `generic_autofixed` 在 `frontend/src` **零消费** ⇒ 自动改写**静默生效**。
- 自动外科式重写存在**双轨实现**（`sections` 内联 vs 可复用实现）⇒ 口径分叉风险。

## 3. 修复方案（逐条：文件 / 关键函数 / 代码依据）

### 3.1 遗留 1（P0）· 自动改写不再丢正文 + 结构指纹守卫

**文件 1** · [upload_outline.py](file:///j:/编程/专项方案工具箱/backend/app/routers/upload_outline.py)
`save_as_outline`：

- 在自动改写**之前**，按「**子节点索引路径**」快照原标题（与标题文本无关，不受任何
  改写影响）：新增 `_norm_title` + `pre_nt_index: dict[tuple, str]` + `_snapshot_titles`。
- `collect_rows(nodes, parent_id, path_parts, idx_path=())` 新增 `idx_path`；
  **匹配身份** `mnt = pre_nt_index.get(idx_path + (i,)) or nt`（展示/落库标题仍用改写后
  `title`）——「匹配身份」与「展示标题」**解耦**，改标题不再等于丢正文。
- 四个桶与 `_take_from` 全部改用 `mnt`；子树递归传 `path_parts + ((mnt,) if mnt else ())`
  与 `idx_path + (i,)`。

**文件 2** · [outline_title_fix.py](file:///j:/编程/专项方案工具箱/backend/app/services/outline_title_fix.py)
`autofix_generic_titles_on_save`：

- 新增 `_tree_shape(nodes)`（目录树**形态指纹**：只记每节点子节点数，标题/id 不参与，
  返回纯 tuple）。
- 改写前后比对：`_fixed` 为 `None` 或 `_tree_shape(_fixed) != _shape_before` ⇒ **整条丢弃**
  改写结果、按原样保存（`logger.warning`）。结构错位会令 upload 路径的索引路径映射
  整体张冠李戴（把正文挂到别的章节），比丢失更糟，故 fail-closed。

**契约**：受 `settings.outline_autofix_generic_on_save`（默认 True）门控；`hits` 空即原样
返回（零 AI 调用）；任何异常 fail-soft；返回 `(重写后目录, 残留明细, 改写条数)`。

### 3.3 遗留 2（加固）· `.git/hooks/pre-commit` 行尾/BOM 漂移门禁

**文件** · `.git/hooks/pre-commit`（未受版本控制）

在原「ruff I001 只查不改」段之后**追加**第二段门禁，只拦三类**回归**（对合法文件
零误伤）：

1. **行尾漂移**：`git show HEAD:path` 为**纯 CRLF**（裸 LF 数 = 0 且 CRLF 数 > 0）而
   `git show :path`（索引版）含裸 LF ⇒ 拦截（即 `sse_handlers.py` 那一类回归）。
2. **新增文件带 UTF-8 BOM**：HEAD 无该文件（新增）且索引 blob 以 BOM 开头 ⇒ 拦截。
3. **孤立 CR**：任何行尾风格下 `\r` 后未跟 `\n` ⇒ 拦截。

> ⚠️ 关键实现订正：`git show` 的**索引版**是 `:<path>`，即 `rev` 传**空串**
> （`f"{rev}:{path}"`）；传 `":"` 会拼成非法的 `::path`，静默返回 None ⇒ 整段失效。
> 本仓 `core.autocrlf=true` 但 blob 仍保留原始行尾（实测 `git show HEAD:` 的
> `sse_handlers.py` = 8626 CRLF、`upload_outline.py` = 795 裸 LF），故漂移判据成立。

## 7. 遗留与后续建议

1. **`core.autocrlf=true` 与 blob 保留原始行尾并存**：本仓 blob 既有纯 CRLF 也有纯 LF。
   本轮漂移门禁**只拦回归**、不做全仓归一；若后续要做整仓 EOL 统一，应**单独立项、单独
   提交**（与功能改动完全分离，同 R101 整仓 I001 处置纪律）。
2. **`pre-commit` 未受版本控制**：团队协作下门禁易丢失，建议把钩子内容纳入 `scripts/`
   并由安装脚本写入 `.git/hooks`。
3. **`GENERIC_BARE_STEMS` 与正则裸词干分支的真子集关系**：本轮已双向加锁，但两处仍是
   两份清单；若未来引入更多「裸词干即占位」的词，**只动正则词干表**、白名单保持 6 词封闭，
   并按 §3.4 的 D 组护栏复核。
4. **上传路径「按索引路径还原原标题」依赖结构一一对应**：已由 `_tree_shape` 守卫兜底；
   若未来自动重写实现改为「重建新树且允许增删节点」，本守卫会 fail-closed 丢弃改写结果，
   属预期行为（宁可原样保存，不可错配正文）。
