## 七、教训归档

1. **「护栏验证必须真开浏览器」** —— jsdom 与真实浏览器对 DOMPurify 的 foreignObject 处理**结论一致**（都清空），但若只跑 jsdom 单元测试会误判为「环境限制」并带病上线；本轮用真实浏览器 http 页取证后否决首轮方案，改为输入侧闸 —— **对「第三方库清洗行为」的结论必须有浏览器级证据**；
2. **A/B 锚点会被并行会话演进作废** —— 12 变异 3 轮才 12/12：M2（护栏自身强度不足：except Exception 吞断言）、M6/M10/M8（R199/R200/R211 已演进实现）—— **A/B 锚点必须按执行时刻的真实源文本取，护栏强度必须免疫「异常被吞」型吞没**；
3. **静态源码锁被自己的修复说明触发**（R166 教训 3 第三现）—— config 注释诚实化时引用旧字面量导致 F2 护栏自咬，注释措辞须拆开连写字符；
4. **前端注释里 `on*/javascript:` 的 `*/` 会提前终止块注释**（TS1127 Invalid character 的真实根因，Python 字节级 UTF-8 检查看不出）—— 注释中写正则/模式串须空格断开 `*/` 序列；
5. **字节锁的期望值随仓库行尾规范演进**（R199 教训 4 的延伸）—— renormalize 提交后 CRLF 例外清单过期，重锚判据 = 「当前 HEAD 实测 + .gitattributes 规范」双对照。
