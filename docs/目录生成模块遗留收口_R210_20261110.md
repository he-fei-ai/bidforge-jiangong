## 2. 落地修复明细

### FIX-1 · P3 L1 一级章数上限（成本失控防护）

- **文件**：`app/config.py`（新增配置）、`app/routers/sse_handlers.py`
- **根因**：`level1 = obj.get("outline", [])` 之后**直接进入逐章循环** ⇒ AI 幻觉出「几百个一级章」时，分步链路会**逐章**发 AI 调用（成本与时长爆炸），且导出侧章号早已越界。
- **修法**：
  - 新增配置 `outline_max_level1_chapters`（默认 **40**；`0` = 不限，回到旧行为）；
  - `OUTLINE_MAX_LEVEL1_CHAPTERS = max(0, int(settings.outline_max_level1_chapters))`（import 期固化，与同族常量同口径）；
  - 超限时**截断保留前 N 章**（fail-soft，不整链失败）+ WARNING；
  - SSE 终态加法式回传 `level1_truncated`（丢弃章数）/ `level1_total`（原始总章数）—— **未截断时不出现该键**（既有响应逐字节不变）。
- **为什么默认 40 而不是更大/更小**：任何真实专项方案一级章 ≤ 15（九大章节标准骨架约 9~12），40 远高于合理值，**只对「幻觉输出」触发**；既挡住成本失控，又不误伤正常方案。

### FIX-2 · P3 读路径暴露「不可达节点」

- **文件**：`app/routers/sections.py`（`list_sections`）
- **根因**：`_build_tree` 对 `parent_id` 成环（自父 / 2 点环 / 3 点环）或悬挂（父 id 不存在）的节点**整体不可达** —— 它们既不是根、也不在任何 children 下 ⇒ **树里看不到**；但 DB 里确实有这些章节行（现实来源：手工改库 / 旧快照回退 / 方案复制 / 早期无环检测的写入）。此前只有「结构自检」（`_outline_structure_report`）与「严格模式导出守卫」会提示，**读路径零信号** ⇒ 用户看到的目录比库里少几章却毫无察觉。
- **修法**：`list_sections` 在返回前做一次「全表 id − 树内可达 id」自检，**加法式**回传 `unmounted_count`（不阻断、不改树），并在有不可达节点时打 WARNING（含前 10 个 id）。自检整体 try/except ⇒ 失败不影响章节列表。
- **实现约束**：可达 id 的收集**复用模块级 `_collect_section_ids`**（既有同口径 helper），不自带第三份等价实现（见 §4.1 R2）。

### FIX-3 · P1 断点续跑「陈旧复用」防护（输入指纹）

- **文件**：`app/routers/sse_handlers.py`、`app/routers/sse_checkpoint.py`
- **根因**：R209 让断点续跑真正生效后，「复用上次成果」自带**时效性风险** —— 用户中断后改了项目资料 / 提取了新事实再重新生成，被复用的章仍是**旧快照** ⇒ 目录与最新资料不一致，而界面只显示「目录生成完成」，**用户零感知**。
- **修法**：
  - 新增 `_outline_input_fingerprint(*parts)`：对「方案名/类型 + 项目资料摘要 + 编制依据 + 项目事实 + 施工内容清单」取 sha256 前 16 位（字段间用 `\x1f` 分隔，避免 `"ab"+"c"` 与 `"a"+"bc"` 同串）；
  - 上下文装配解包后即计算 `_outline_fp`，写入 checkpoint（`input_fingerprint` 键）；
  - 续跑时：checkpoint 的指纹 **与本次不一致 ⇒ 不续跑**（全量重算）+ INFO 留痕；
  - **向后兼容**：旧 checkpoint **没有**该键 ⇒ 不比较、照常续跑（行为不变）。
- **边界**：指纹是**内部判据**，**不进前端白名单**（不进浏览器）；`input_fingerprint` 只写入 `task_registry.checkpoint_json`，续跑时由后端直读该列。

### FIX-4 · P3 断点续跑可见信号（`resumed_chapters`）

- **文件**：`app/services/checkpoint_schema.py`（白名单单一事实源）、`frontend/src/types/checkpointSchema.ts`（**由 `tools/generate_checkpoint_schema.py` 重新生成**）、`frontend/src/pages/schemeWorkbench/workbenchTypes.ts`、`frontend/src/pages/schemeWorkbench/useOutlineGeneration.tsx`、`app/routers/sse_handlers.py`、`app/routers/_sse_outline_review.py`
- **根因**：后端日志早有「目录断点续跑：N/M 章复用上次成果」，但 SSE 事件与前端提示卡**零信号** ⇒ 用户不知道「这次接着上次跑、省了多少配额」。
- **修法**：
  - SSE 终态加法式回传 `resumed_chapters`（**未复用时不出现该键**，既有响应逐字节不变）；停止态与断线重挂路径同口径（`_partial_holder` 携带 → `_finish_stopped_with_partial` 写入 checkpoint）；
  - `checkpoint_schema.CHECKPOINT_KINDS["outline_generation"]` 登记 `resumed_chapters`（int）⇒ 断线重挂也读得到；前端 TS 由生成器重新产出（护栏 `test_checkpoint_schema_matches_generated_ts` 会拦漂移）；
  - 前端三条路径（在线 completed / 在线 stopped / 断线重挂）统一提示「已复用上次中断生成的 N 章（跳过对应 AI 调用）」。
- **实现约束**：停止态出口（`_finish_stopped_with_partial`）写 checkpoint 时必须**在成果字段写入之后**再拷贝载荷，否则 checkpoint 丢 `outline`（见 §4.1 R1）。

### FIX-5 · P1 停止态 checkpoint 成果完整性回归修复

- **文件**：`app/routers/_sse_outline_review.py`
- **根因**：FIX-3/FIX-4 引入 `_ckpt_payload = dict(payload)`（用于给 checkpoint 单独加指纹而不污染 SSE 载荷）时，拷贝点写在 `payload["outline"] = outline` **之前** ⇒ 落库 checkpoint 丢 `outline`/`failed_count` ⇒ **断线重挂读不到任何目录成果**。
- **修法**：拷贝点移到成果字段写入之后；指纹仍只进 `_ckpt_payload`（不进 SSE 载荷）。
- **护栏**：`TestStoppedCheckpointIntegrityR210`（2 条）+ A/B M5/M6。

## 5. 登记项的可执行方案（不是「以后再说」）

1. **L1-1 提示词编号口径（需产品裁决）**
   - 现状：提示词的子标题示例用**存储态**（`3.2.1`），落库/导出产出**展示态**（`2.1`）。

### 6.5 本轮回归的取数纪律（并发会话污染 → 冻结快照隔离）
