## 4. 功能架构与现状分析

### 4.1 上传

- **上限**：分块读取（1MB/块），超 `MAX_UPLOAD_BYTES`（默认 30MB）即 413 拒绝；`finally` 关闭句柄；累加先收集后 join（避免 bytes O(n²)）。
- **三段前端预检**：单文件体积 / 累计体积 / 文件数，均在发请求前执行，早退路径**不置位在飞 ref**（R203 FE-1 修复：旧实现置位后三段预检含裸 return，ref 永久为 true，上传入口卡死）。
- **后端配额**：`upload_max_bytes` / `upload_max_total_bytes` / `upload_max_files_per_request` 运行时动态读（R191 H1）。

### 4.2 格式识别

- **双向纠偏**：`parse_file_content_ex` 按扩展名 + 真实类型（OLE/ZIP 魔数）判定，`signature_valid` 校验前 16 字节；空文件 / 未知扩展名 / 签名不符均 400 拒绝。
- **图片扩展名单一事实源**：R243 把 `.png/.jpg/.jpeg/.bmp/.tiff/.tif/.webp` 收敛到 `file_parser.IMAGE_EXTENSIONS`，OCR 路由与置信度惩罚共用同一对象（修复 `.tif` 漏扣噪声分）。
- **嗅探优先**：无后缀/改名文件以 `diag.file_type` 为准（修正落库 `file_type` 与 `is_image` 判定分叉）。

### 4.3 内容解析

- **编码回退链**：UTF-16（BOM/无 BOM 探测）→ `utf-8-sig` → `gbk` → `gb18030` → `utf-8(errors="ignore")`；GBK/GB18030 成功时补「可疑码点占比」闸门（Big5/Shift-JIS 乱码定向告警）；孤立 CR（旧式 Mac 行尾）还原为换行并告警；不可见/零宽/NBSP 归一。
- **DOCX**：正文块递归下沉 `w:sdt` 内容控件、页眉/页脚/脚注/尾注部件收集（`PARSE_DOCX_PARTS=0` 可回退）；透明容器 `mc:AlternateContent` / 修订 `ins`/`del` / `customXml` 递归下沉。
- **PDF**：解页 + 截页告警（页数上限）；加密 PDF 告警；OCR 兜底（无文本层）。
- **Excel/CSV**：多 sheet 合并 + 行数截断告警；表头智能识别；`_md_cells` 转义竖线、`_md_separator` 补 GFM 对齐行。
- **图片 OCR**：`_split_tiff_frames` 多帧 TIFF 逐帧识别；`pytesseract` 带 `timeout`。

### 4.4 信息保存与分类

- **目录识别**：`simple_parse_outline` 处理全角点号 / 年份 / 量词 / 日期形态误判；`normalize_outline` 三级裁剪 + 编号重排 + 补全 children/level。
- **分类**：`apply_category_auto_classify` 按「专指 → 泛指」关键词序列自动纠正 `category`；`ensure_schedule_fact` 保证工期存在；`_FACT_TYPE_TO_CATEGORY` 统一映射；`CATEGORY_TITLES` 单一事实源供分组/聚合共用。
- **保存**：`save-as-outline` 带类型闸门、竞态守卫、空壳章闸门、标题快照匹配（改标题不丢正文）、元数据继承、递归后代删除；`save-as-library` 带 `normalize_outline_for_library` 单入口、`upload_id` 存在性校验、零行写守卫。

### 4.5 错误处理

- `ParseError` 直达用户；库异常收敛为「文件解析失败，请确认文件未损坏且格式受支持」；AI 兜底失败 `fail-soft` 回退规则法并留 WARNING 堆栈。
- 解析诊断（`parse_warnings` / `truncated` / OCR 兜底 / 加密 PDF / 编码风险 / 截断）全链路透传：`parse` 响应、`diagnostics` 端点、文档列表、前端 `summarizeUploadOutlineResult`。

### 4.6 工作流程

- 分步工作流 ①上传保存（仅存文件）→ ②批量/单份解析 → ③AI 提取事实 → ④分类/确认。前端 `useDocumentWorkflow` 统一 handler；目录识别走 `useOutlineActions` → `uploadOutlineApi.parse`。
- 防重入：上传/解析均用 ref 同步读写 + state 双防线（R191 C-F9）；预览/管线用请求序号 + 当前文档 id 双条件守卫（R203/R208）。

### 4.7 AI 调用

- 目录识别 AI 兜底：`collect_json_response(..., scene="outline_recognition", repair_key=OUTLINE_REPAIR_KEY, timeout=300)`；截断留痕（`truncated_chars` / `used_ai_fallback` 回传）；`govern_blob` 治理外部不可信原文。
- 占位标题自动重写：与 `sections._save_outline_to_db` 共用 `autofix_generic_titles_on_save` 单一实现，失败 fail-soft 不阻断保存。

### 4.8 数据链与存储

- `uploaded_outlines`（目录识别）与 `project_documents`（资料）分表；解析结果 `raw_text` 存全文（TEXT 容量足够），`parse_warnings` 持久化并回放入口。
- 四层产物（原文/提取/交叉校验/质量）由 `doc_pipeline` 管理；`save-as-outline` 整表重建时按标题路径匹配保留旧章节正文（不丢已生成正文）。

### 4.9 路由与接口

- `POST /api/v1/upload-outline/parse`、`GET /{id}/diagnostics`、`POST /{id}/save-as-outline`、`POST /{id}/save-as-library`。
- `POST /api/v1/global-facts/documents/upload-documents`、`/documents/{id}/parse`、`/documents/parse-all`、`GET /documents`。
- 响应契约对齐：前端 `uploadOutlineApi.parse` 读 `id/outline/confidence/file_name/truncated_chars/used_ai_fallback/parse_warnings/reorganize_report/empty_text/warning`，与后端逐字段一致。

### 4.10 容错 / 缓存 / 并发 / 日志 / 配置

- **并发**：逐文档 `asyncio.Lock`（`_doc_parse_guard` 引用计数 + 回收）串行化同文档解析；`save-as-outline` `BEGIN IMMEDIATE` 写锁。
- **缓存**：导出缓存按输入指纹 + 版本失效；解析产物 `parse_status` 自修复（`_reconcile_parse_status`）。
- **日志**：AI 兜底失败 / 截断 / 编码风险 / 保存拒绝均留 WARNING 堆栈或定向告警。
- **配置**：`upload_max_bytes` / `upload_max_total_bytes` / `upload_max_files_per_request` / `outline_ai_fallback_max_chars` / `outline_check_generic_titles` / `PARSE_DOCX_PARTS`（环境变量）。

### 4.11 测试方式

- 后端：pytest（`--basetemp` 指向工作区内避免沙箱拦截 `%TEMP%`）；HTTP 级用 `httpx ASGITransport`。
- 前端：vitest + `@testing-library/react`（真实渲染 + `renderHook`）。
- 静态：`ruff` / `tsc --noEmit`；字节体检（生产源纯 CRLF、新测试/文档纯 LF、BOM/FFFD/孤立 CR 为 0）。

## 9. 遗留问题与后续建议

1. **真 OCR 引擎授权**：本机 OCR 引擎可用性依赖系统 Tesseract/RapidOCR 安装；建议 `/api/v1/diagnostics/capabilities` 前置提示启用方法。
2. **前端 tsc 大仓基线**：`tsc` 在本会话 EXIT 0；但并行会话在途改动较多，跨会话全量 `tsc` 结果需在收口后复核。
3. **`scale` 分类预留**：`CATEGORY_TITLES` / `_CATEGORY_ORDER` 含 `scale`（工程规模与地质参数），但 `_FACT_TYPE_TO_CATEGORY` 无 fact_type 映射到它；当前为预留位，建议后续事实类型注册时明确归位或移除。
4. **前端两处 accept 同步**：`uploadAccept.ts` 与后端 `SUPPORTED_EXTENSIONS` 必须同步；建议加前端「扩展名子集 ⊇ 后端支持集」契约护栏（后端已建 `IMAGE_EXTENSIONS` 子集断言，前端可镜像）。
5. **全量后端回归 11 红**：均既有基线（prompt/import/review 面 + node_modules EPERM），与本模块触碰集零交集；下轮收口时需与并行轮次共同确认为非回归。
6. **四层产物孤儿清理**：`ingest_upload` 后若上传失败，需确认孤儿原文层/索引条目的 GC 仍可用（R191 已建，后续按导出孤儿 GC 同口径复核）。
