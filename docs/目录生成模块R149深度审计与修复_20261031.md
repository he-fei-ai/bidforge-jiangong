## 四、修复项清单（12 项）

### FIX-A（P2）· 围栏派生标题编号三侧分叉（导出侧过滤，与落库 D-8g 对齐）

**根因**：R117 起 ```` ```markdown ```` 围栏被递归解析，围栏内 `## 标题` 打 `_from_fence=True` 进入 blocks。R118 落库侧刻意排除（编号不占号、源行不动 = D-8g 契约），但导出**预检**（`_detect_duplicate_sections`）与**写稿**（`write_section`）两处把**全量** blocks 传给 `number_body_subheadings` ⇒ 围栏标题在成稿里占号、预览/落库不占号。实测：同一章落库 `2.2 资源配置`、成稿 `2.3 资源配置`——预览=落库≠成稿。

**修法**：`content_blocks.select_numbering_blocks()`（新增，块选择唯一实现：`heading` 且非 `_from_fence`）+ 三处调用点收口（numbering 落库 / export 预检 / export 写稿）。选导出侧过滤而非落库侧纳入：落库纳入会把编号写进围栏内源行，破坏 R118 D-8g 契约（有测试锁定）；导出过滤后成稿与预览逐字一致，围栏标题保留原文不占号。

**护栏**（A 组 5 例）：落库↔导出同编号、选择器语义、真实 DOCX 字节（围栏标题无编号、后一真标题不顺移）、预检判重宇宙排除围栏、三处静态锚。

### FIX-B（P2）· 分步生成「停止」丢弃同窗后续单元已完成成果

**根因**：`sse_handlers.py` 外层归位循环遇第一个 stopped 单元即 `break`——同窗后续单元的结果在 `asyncio.gather` 返回时已就绪（tokens 已消耗），却被静默丢弃；与本函数下方注释「部分成果快照含**本窗各单元**已完成的章节」及 2026-09-26「单元内不丢已完成」修复同族矛盾。用户停止后拿到比实际已完成更少的目录，且 `failed_chapters` 无记账。

**修法**：`break` → `continue`（记 `_stopped_in_unit` 后继续归位后续单元）。章序不变式不破坏：单元按章序排列、逐单元按序归位，编号由位置推导（缺章顺移，与删章同语义）。单元内 prefix-only 语义维持（post-stop 章节真实返回 "stopped"，无产出可丢）。

**护栏**（B 组 2 例）：窗内第 3 章 stopped、第 4 章已完成 ⇒ stopped 产物 = `[第1章,第2章,第4章]`；反向锚：无停止时 4 章全量完成不变。

### FIX-C（P2）· 目录标题换行零清洗（唯一拦截在 title_fix 重写出口）

**根因**：全仓唯一换行拦截在 `outline_title_fix.py`（重写出口拒收），而 AI 生成/上传识别/目录库/手工保存主写入链路均不清洗。`"工程概况\n（一）编制依据"` 原样落库：前端树两行渲进一个节点、DOCX 标题段内嵌换行、剥编号正则按 `^` 只命中第一行；占位检测 `_STRIP_RE` 剥空白 ⇒ 检出/复检全部「看不见」（静默穿透）。

**修法**：`numbering.sanitize_outline_title()`（CR/LF 折单个空格，与 title_fix 拒收红线同字符集）+ 三处接线：`renumber_outline_nodes(strip_titles=True)`（树入口 = normalize_outline 全部调用方）、`create_section`、`update_section`（手工单章）。无换行时恒等快路径。

**护栏**（C 组 3 例）：normalize_outline 树清洗+编号照常、幂等/恒等、create/patch 端到端。

### FIX-D（P3）· `_save_outline_to_db` 批量写零行数校验（REST-vs-REST 并发静默少写）

**根因**：主保存函数 `executemany` UPDATE/INSERT 与级联 DELETE 全部不看行数——预取快照与写库之间目标章节被并发删除（多标签页 A 删 B 存）时静默少写、响应仍 ok。同文件 `renumber_sections_after_reorder` 有 R89 N2 守卫、`upload_outline._r13_write` 已确立「None→503 / 行数不足→409」口径，本函数是唯一未回灌的整表重建路径（R144 教训④「写库只判 None 不判行数」家族）。

**修法**：三处批量写补 `safe_rowcount` 期望行数断言（≠ 预期 → WARNING + **409 中止**，抛出点在 commit 之前、未提交语句由 get_db 归还连接统一回滚）；`chart_predictions` DELETE 无行数预期不做断言。

**护栏**（D 组 4 例）：更新少写 409、级联删除少删 409 + 回滚后数据完好、正常保存反向锚、三处调用形态静态锚。

### FIX-E（P2）· outline Agent baseline 目录跨任务共享（agent 开关默认关）

**根因**：`outline_agent_flow.py` `baseline_dir = ws.parent / "baseline"` 恒为固定名 `DATA_DIR/agent_workspaces/baseline`——所有任务共享同一 manifest + 原件副本库：① 并发时后到任务的 `_save()` 按自己陈旧引用集清副本 → 前任务 `restore()` `FileNotFoundError` → 整任务失败；② 顺序复用时 `restore()` 把前序任务登记**复活**进本任务工作区（restore 对不存在文件也重建）→ 跨任务输入污染。seed 文件名固定（响应文件要求.md 等）必然互踩。对照 `content_agent/repair.py:199` 早已是 `<task_id>_baseline`（每任务独立）——outline agent 是唯一偏离者。

**修法**：`baseline_dir = ws.parent / f"{task_id}_baseline"`（单行，对齐 repair.py；暂停/恢复后 manifest 仍随任务持久生效）。

**护栏**（E 组 1 例）：调用形态静态锚（正向 + 负向锚完整赋值语句，防被注释误伤）。

### FIX-F（P2）· Agent 初始指示词宣称「响应文件要求.md 是唯一依据」，但该文件只在 requirements 非空时落盘（agent 开关默认关）

**根因**：`build_task_instruction` 无条件宣称「严格按照响应文件要求.md 组织一级目录，它是唯一依据」，而 `seed_files_from_context` 只在 requirements 非空时写该文件。方案未填编制要求时模型 read 必然 is_error → 凭概述/经验生成（与「唯一依据」声明矛盾）或反复重试烧 turn 预算。

**修法**：`build_task_instruction` 新增 `has_requirements: bool = True`（默认 ⇒ 既有调用方/测试逐字不变）；为空时改为「本次未提供响应文件要求.md，请以项目概述.md 与专业经验组织一级目录」；`run_outline_agent` 按 `requirements_text` 实况传参。

**护栏**（F 组 3 例）：默认逐字不变锚、空 requirements 指示词与 seed 文件一致、接线静态锚。

### FIX-G（P3）· `_stored_id_parts` 前导零 / 全角数字不 fail-closed（D-8a 注释自declared口径有洞）

**根因**：D-8a 注释声称「含 0 号段一律非法」，实际只拒字面 `"0"`：`"01.02"` → `stored_id_to_prefix` 产出 `"02"` 写进落库正文（导出端按整数计数器给 `2.1` ⇒ 文本级分叉）；`_DOT_PATH_RE` 用 `\d`（匹配 Unicode Nd 含全角），`"１２.３"` 的全角段原样带进编号文本，与前端 `outlineNumbering.ts` 判据分叉。

**修法**：`_DOT_PATH_RE` ASCII 化（`[0-9]`）+ 每段前导零判据（段长>1 且首字符为 0 → 非法）。canonical 数据（renumber 唯一产出形态）逐字不变。

**护栏**（G 组 3 例）：canonical 反向锚、5 种脏形态参数化 fail-closed、脏编号不再污染落库正文。

### FIX-H（P3）· 审核/补齐/修复/标题重写四处 AI 调用不响应停止（最长白烧 180s）

**根因**：生成期所有 AI 调用走 `_await_with_stats(..., task_id=task_id)`（点停止 → `register_child_task` 子任务同步取消）；而 `_review_and_fix_outline` 内的审核调用、`_do_fix` 修复轮、`_try_outline_patch` 补齐、三处 `_try_outline_title_fix` 是裸 `asyncio.wait_for(collect_json_response(...))` ⇒ 停止后这些调用继续烧完 `OUTLINE_REVIEW_TIMEOUT(+FIX_TIMEOUT)` 才在出口被丢弃。

**修法**：模块级 `_stoppable_outline_collect(task_id)` 包装器（内部仍走 `collect_json_response`，共享 `_ensure_user_message` 守卫不破；`task_id` 为空返回裸 collect ⇒ 历史直调方/单测逐字不变）+ `_review_and_fix_outline`/`_try_outline_patch` 新增 `task_id: str = ""` 形参 + 入口停止闸门 + 两个生成器调用点传参。CancelledError 交由生成器外层既有 CancelledError 分支（带 `_partial_holder` 成果）收尾，与生成期停止语义同口径。

**护栏**（H 组 4 例）：入口闸门行为、包装器 task_id 传递、空 task_id 恒等、全链静态锚（定义处调用形态 + 使用点 + 补齐 + 两调用点）。

### FIX-I（P2）· `save-as-outline` 非 list 真值载荷静默清空整方案（破坏性数据丢失 + 假成功）

**根因**：入口只拦「空」，不拦非 list 真值；`normalize_outline` 对非 list 恒等返回（契约由调用方负责报错），`collect_rows` 对 dict 迭代出字符串键 → 0 节点 → `to_delete` = 全部旧章节 → sections + chart_predictions 级联 DELETE → 响应 `ok: True, count: 0`。对照 `sections._save_outline_to_db:1176` 有同文案 400 守卫——独立实现漏抄。

**修法**：`normalize_outline` 之前补 `isinstance(outline, list)` 400 守卫（与 `_save_outline_to_db` 同文案同口径）。

**护栏**（I 组 3 例）：dict/str/int 三形态 400 + 既有章节不被清空。

### FIX-J（P2）· `save-as-outline` 改名保留正文章节产生幽灵子标题（R137 BUG-2b 未收口孪生）

**根因**：本路径按「归一化标题/索引路径」匹配旧章节并写入**新** title（含占位标题自动改写），落库后 `_renormalize_all_section_contents` 不带 `rename_map` ⇒ 批量重规范化只拿得到新标题，正文首行旧标题块被当普通子标题编号（`1.1 旧标题`），后续真子标题整体顺移。R137 修了 `update_section` 与 `_save_outline_to_db` 两个入口，upload 侧是第三条同因路径（R144 教训①「同族缺陷修一处漏一处」再命中）；台账数据现成（`matched["title"]`）。

**修法**：`collect_rows` 收集 `renamed_titles[sid] = matched["title"]`（仅当新旧标题不同），`_renormalize_all_section_contents(db, scheme_id, rename_map=renamed_titles)`。

**护栏**（J 组 2 例）：AI 桩模拟改写 → 无幽灵子标题、真子标题编到 1.1；台账+传参静态锚。

### FIX-K（P3）· `delete_scheme` 级联清单落后于 `projects._SCHEME_SCOPED_TABLES`

**根因**：内联清单漏 `consistency_scan_cache`（projects.py 注释自证「曾长期漏删」，删项目链路修过、本独立写路径未回灌——同族修复不回灌家族）与 `placeholder_baselines`（自带 CASCADE 但测试连接/历史库未开 `PRAGMA foreign_keys=ON`，级联不生效）；磁盘只清 `.docx`（历史 PDF 产物残留）。

**修法**：清单单一事实源（`from app.routers.projects import _SCHEME_SCOPED_TABLES`）+ 磁盘清理 docx/pdf 双扩展名（与 projects 同口径）。

**护栏**（K 组 2 例）：静态锚（禁内联字面量清单复活）+ 行为级（删方案后两表无残留、磁盘 docx/pdf 产物已清）。

### FIX-L（P3 · 前端）· `buildTree` 漏拷贝后端已下发、类型已声明的三个字段

**根因**：`_build_tree`（sections.py:110-115）下发 `generation_standard`/`last_generation_standard`/`word_status`，TreeNode 类型已声明，但 buildTree 映射漏拷贝 ⇒ 页面刷新后「章节级生成标准」选择器显示错值（实际 fuzzy 显示成「沿用方案级」）、字数状态归空，直到下一次 SSE 事件才被补丁写回。「类型里声明字段 ≠ 会装配」（R139 FIX-2 同族，前端形态）。

**修法**：buildTree 补三行字段映射（`|| ""` 归一）。

**护栏**（L 组 1 例，跨语言 parity）：后端下发列、前端类型声明、前端 buildTree 装配三面逐字段锁定（读 TSX 源码的 pytest parity，与 `test_import_outline_deep_fix` 同型）。

## 九、判据教训归档

1. **「注释与代码矛盾」是最高优先级缺陷信号** —— FIX-B 的 `break` 与其正上方「含本窗各单元已完成的章节」注释直接矛盾；FIX-G 的 D-8a 注释声称「含 0 号段一律非法」而判据只拒字面 `"0"`。凡读到「这里已收口」的注释，用探针验证一遍再信。
2. **「同族修复必须回扫所有平行入口」第三次命中** —— R137 修了 update_section + save-outline 改名，upload save-as-outline 是第三条同因路径（FIX-J）；projects 修了删项目级联，delete_scheme 是第二条同因路径（FIX-K）；content_agent 用了 `<task_id>_baseline`，outline_agent 是唯一偏离者（FIX-E）。修族不修点。
3. **A/B 锚要断「定义处调用形态」而非只断使用点** —— M10 首轮 MISSED：护栏断言了 `_collect_ai` 的三处使用，变异把**定义**换成裸 collect 后全部使用点字面不变（R144 教训②「锚被自己的注释误伤」的孪生形态：这次是被「使用点」误伤）。定义与使用都要锚。
4. **源码锚负向断言会被自己的说明注释误伤（R144 教训②再验证）** —— `assert '/ "baseline"' not in src` 被 FIX-E 注释里记载的旧形态命中；负向锚必须断完整赋值语句。同轮还两次踩中：`_SCHEME_SCOPED_TABLES:` 冒号锚被 for 循环命中、`interface TreeNode` 锚被 `export type TreeNode` 实际形态 miss。
5. **基线必须跑在改动前，且以「当时快照」归因** —— 簇回归两次出现失败：① demote 样式断言（并行会话中途同时改生产代码与测试文件，pytest 收集旧测试、执行新代码，错位红）；② 前端正则 parity（并行会话改后端字母分支未同步前端）。二者复跑/文件核对后均归因并行在途工作，与本轮改动集合无交集（双向佐证：违反项文件不在本轮 diff）。
6. **「类型声明 ≠ 会装配」在前端的形态是「映射漏拷贝」** —— TS 对「少拷贝一个可选字段」不报错（R139 FIX-2 后端 hook 形态的前端孪生），护栏必须三面锁：后端下发、类型声明、映射装配。
7. **E2E 打桩必须落在被测函数的实际读取点** —— `EXPORTS_DIR` 是 delete_scheme 内函数级 `from app.config import EXPORTS_DIR`，打 `schemes.EXPORTS_DIR` 模块属性是无效桩（E4c/d 假失败）。函数级导入每次调用都从源模块取值，桩必须打在源模块。
8. **工具链转义三层衰减**（bash heredoc → JSON 工具参数 → Python 字符串字面量）：本轮三次踩中 `\\n`/`\\d`/`\\(` 被逐层折叠成真实控制字符/错误正则（FIX-C 函数体损坏、parity 测试正则断行、SyntaxWarning）。多行锚点补丁一律改走 **Write 脚本文件 + 执行**，不走 heredoc；写完必须 `py_compile` + 行为断言双验。
9. **ruff 全仓 I001 类告警先比对 HEAD** —— `sections.py:2:1 I001` 在 HEAD 同位置同代码存在，属预存；只对本轮净增告警负责，不顺手「修」它（会产生越界 diff）。
