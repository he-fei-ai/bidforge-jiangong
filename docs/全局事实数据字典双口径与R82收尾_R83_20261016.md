## 1. R80 §6-1 数据字典双口径（实装）

### 1.1 设计事实

`content_data_contract.build_global_data_dictionary` 的**键即压形后的 `value_text`**（无对象维度时）。因此「要求≤90 天」与「本方案 85 天」本就是两个独立键，天然不互斥——§6-1 的真实价值不是「去重冲突」，而是**给 requirement 条目标注口径**，防止 AI 把招标/规范要求值误当本方案采用值引用。

### 1.2 改动（`backend/app/services/content_data_contract.py`）

- 新增 `_row_value_kind(row)`：局部白名单归一（仅 `''`/`fact`/`requirement` 合法，其余归一 `''`），**零跨模块依赖**（避免契约层 ↔ 提取层循环依赖）。6 元组取法为 R80 注入契约第 5 项，3/4/5 元组（历史行）无此列 → `''`（读侧按 fact，行为零变化）。
- `iter_consistency_values`：每个 hit 产出携带 `value_kind`。
- `build_global_data_dictionary`：
  - requirement 命中**独立建键**（值位留空，绝不并入其它同主题异值键）；
  - 同键（同值）的要求源收进 `requirements` 桶，**绝不**计入 `conflicting`；
  - fact/fact（含 `''`）同键不同值仍走原冲突判定（行为零变化）。
- `render_data_dictionary_block`：requirement-only 条目值位回退展示「要求口径」注记（「招标/规范要求口径，须满足；非本方案采用值」），且**不**渲染「另有候选取值」；采用值 + 要求口径同主题共存时单列「另含招标/规范要求口径」约束行。

### 1.3 护栏

`tests/test_data_dict_value_kind_r83_20261016.py` **7 例/6 组**（requirement-only 标注 / requirement+fact 独立键 / 同值进 requirements / iter 携 value_kind / dict 行 + 脏值归一 / 渲染回退）。`test_content_data_contract_r52` **56 例零回归**。
