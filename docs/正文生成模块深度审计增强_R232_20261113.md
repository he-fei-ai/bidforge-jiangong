## 四、修复项清单（5 项，全部主会话亲验定罪 + 探针证据）

### FIX-0 · P2 · 并行 R231 回归代收（`sse_checkpoint.py:113`）

- **缺陷**：partial checkpoint 终态守卫写点 `if cur.rowcount == 0:` 绕过 R13 `safe_rowcount` 单一出口（cursor None 时 AttributeError 顶替「放弃写」语义）。
- **修法**：导入 `safe_rowcount` 并改走 `safe_rowcount(cur, what="partial checkpoint 终态守卫写入")`；None 兜 0 进「放弃」分支，fail-closed 方向与 R231 原意图一致。
- **证据**：隔离复跑护栏红（offenders 列出 ：113）→ 修后 TestRowcountIsCentralized 2 passed。
- **既有护栏**：R13 静态护栏即回归锚，零新增。

### FIX-1 · P2 · `scan_documents` 图/表混桶假「图号虚跳」（`omp_agent_roles.py`）

- **缺陷**：`_FIGURE_RE = [图表]\s*(\d+)\s*[-—]\s*(\d+)` 不捕获前导字，「图 3-1」与「表 3-1」被混进**同一个章号桶** ⇒ 同章同号的图+表（工程方案常态：图 3-1 布置图 + 表 3-1 参数表并存）必判「图号虚跳 图 3-1→3-1」假发现 ⇒ `export_contract.checks.figure_ref=False` → `ready` 被误判 False + AUDIT_REPORT.md 假发现误导人工复核。**探针实证**：`{"sec1": "如图 3-1 所示\n\n见表 3-1\n\n如图 3-2"}` → 产出假发现。
- **修法**：`_FIGURE_RE` 加前导字捕获组 `([图表])`，桶键改 `(kind, chap)` 两元组——图/表两套独立序号互不挤占；detail 同步携带 kind（`表号虚跳 表 2-1→2-4`）。真跳变检测不变（同 kind 同章 1→3 仍报）。

### FIX-2 · P2 · `scan_documents` 编号跨父桶假「编号跳变」（同文件）

- **缺陷**：编号桶只按**深度**归集（`levels[depth].append(parts[-1])`），跨父节点的合法多章编号（`### 1.1 → ### 1.2 → #### 2.1`）被同桶比对末段 ⇒ 判「L2 编号跳变 2→1」假发现（探针实证）。多章编号合法是常态 ⇒ numbering 检查在最常见形态下恒误报。
- **修法**：桶键改 `(深度, 父链 tuple(parts[:-1]))`——**同一父链内**才做末段递增判定；L1 父链为空元组（同卷 `# 1 → # 2 → # 4` 仍判跳变）；detail 格式逐字保留。
- **既有护栏兼容**：`test_scan_documents_detects_numbering_figure_fence_and_format` 的真跳变样本（同父 1.1→1.3、同章图 1-1→1-3）修复后仍全检出（114p 回归实证）。

### FIX-3 · P2 · `OmpContentAgent` 草稿身份丢失叶子原始 id（`omp_content_agent.py`）

- **缺陷**：`sid = safe_task_id(leaf.get("id"))` 把**文件安全名**同时当回包身份——非 ASCII 叶子 id（中文标题型 id 经 body.leaves 直传时）被替换成下划线（探针：`基础工程-1 → ____-1`），导致三重断裂：① `ContentDraft.section_id` 携带安全名 ⇒ 下游按 id 落库应用必 404「章节不存在」；② `documents` 键 = 安全名；③ `run_full_chain` 的 `missing_sections` 用**叶子原始 id** 比对（`expected_ids`）⇒ 已生成的非 ASCII 章被恒报 missing ⇒ status 恒 degraded。
- **修法**：`raw_sid` 与 `sid`（安全名）分离——产物文件/工作区/instruction 内文件名仍用安全名（防路径穿越不变），`meta[sid]["raw_id"]` 回存原始 id，`ContentDraft.section_id` 用 `raw_id or r.task_id`（ASCII id 下两值相同，逐字节兼容）。

### FIX-4 · P3 · `OmpAuditAgent._verify` 索引键错配（`omp_audit_agent.py`）

- **缺陷**：`docs` 以原始 section id 为键，而 `_verify` 用 `safe_task_id(spec.task_id)` 查 `docs.get(safe)` ⇒ 非 ASCII id 时恒取空文档 + 回包 section_id（指令要求用原始 id）不在 `{safe: ""}` 索引中 ⇒ verify 恒失败 → fix 轮白烧 2 轮后任务恒 paused（修复正确的回包也被判死）。**探针实证**：旧键错配下 `verify_audit_fixes` 报「section_id 不在章节索引中」。
- **修法**：`raw_by_safe = {safe_task_id(k): k for k in docs}` 反查映射，verify 索引与回包契约对齐（ASCII id 下行为逐字节不变）。

## 九、教训归档

1. **「新接缝首审」窗口期纪律**：并行会话深夜落地的未跟踪文件（omp 阶段 3 四代理 + 编排器 + 租约）不因「已有 58 条并行护栏」而免审——并行护栏锁的是**主路径**（happy path / 阻断契约 / 租约 / 回收），本round 4 缺陷全部藏在**判据细节**（桶键维度 / id 双口径）里，正是护栏覆盖密度最低的面。
2. **「安全名」与「业务身份」必须双轨**：`safe_task_id` 的文件名白名单职责被顺手复用为回包身份是本轮 2 个缺陷的共同根因——凡「id 进文件系统」的转换层，原始 id 必须随行携带（meta 映射），消费方按业务身份回连。
3. **确定性扫描器的桶键维度必须与「序号语义的归属维度」一致**：编号序号的语义归属是「同父链内递增」、图表序号是「同 kind 同章内递增」——按深度/章号单维归桶就把跨组序列误拼进同一比对面（R225「统计口径与判定口径必须同源」的扫描器变体）。
4. **并行轮回归的代收判据**：基线红先 `ls -l --time-style` 对时间线（02:49 落盘 vs 基线 03:52）+ 隔离复跑稳定红 ⇒ 定罪并行轮漏网（其过滤器不含 facts 簇）⇒ 按「护栏意图保留、代码归位」修复而非重锚护栏（R13 判据无豁免理由）。
5. **`| tail` 吞退出码第 2 次现场复现**（R216 教训①）：`PYTEST_EXIT=$?` 捕获的是 tail 的 0——基线判定必须读 summary 行。
6. **测试夹具要与被测判据的分组语义一致**：护栏夹具两叶同父触发预算均分路径，混淆被锁语义——写夹具前先过一遍被测函数的分组/分配逻辑（R224 教训①「先跑底层行为探针」的夹具版）。
