## 0. 一段话讲完本轮在做什么

R61 的自动拆图是「每组叶子数 ≤ 8」贪心分组 → 递归渲染子图 → **无条件**竖向拼接成单张 PNG。
它隐含一个假设：**画布越窄，纸上字越大**。这个假设在 16cm 单上限的世界里成立，
但 DOCX 插图同时受**栏宽 16cm**与**单图高 22cm**两个上限、取更紧者等比缩小 ——
竖向拼接正是**拿高度换宽度**，份数一多，高上限反超宽度上限，整张拼接图（含**每一张**子图）
被**再缩一次**，纸面字号不升反降。本轮用真实渲染逐份数量出这条曲线，把「拆几张」
从**分组步长说了算**改成**纸面毫米说了算**，并在落图前用真实 PNG 尺寸复核一次；
顺带修掉复测时撞出的两条告警口径缺陷（过期毫米数 + 同一张图 2 条 warning）。

## 1. 机理：收益曲线先升后降（决定方案的那一条推导）

R60 已核对过的闭式（真实 PNG + 真实 `backend/app/routers/export.py:1829 _fit_image_cm`，非推演）：

```
自然cm       = px × scale × 2.54 / DPI
fit          = min(1, 16 / 自然宽cm, 22 / 自然高cm)
纸面字号(mm)  = 字号px × scale × 2.54 / DPI × fit × 10
```

- **宽度受限时** `fit = 16 ÷ 自然宽` ⇒ `scale` 与 `DPI` 分子分母同现、全部约掉 ⇒
  `纸面字号 = 160 × 字号px ÷ 画布宽(设计px)`。R61 只看到了这一项，于是「变窄 = 变好」。
- **高度受限时该约简不成立**：`fit` 由 22cm 决定，与画布宽无关，只跟**整张拼接图的总高**有关；
  此时把子图拆得更窄**完全不换回任何收益**，反而因总高增加而整体变小。
  ⇒ 这正是 R61 缺的那一半，也是本轮把判语写进**公共层**（而不是再写进架构图）的原因。

实测（8 组超预算树形 × 每个份数，探针 `artifacts/r62_leftover/_r62_curve_probe.py`，
口径 = monkeypatch 抓真正落墨字号 + 读真实 PNG + 走真实 `_fit_image_cm`，交付值取**最差那张子图**）：

| 树形（枝×叶） | 不拆 | R61 自然份数 | R62 选定份数 | R62 交付 | 变化 | 缩放绑定 |
|---|---|---|---|---|---|---|
| 4枝×7叶=28 | 1.43 | g=4 → **1.37（变差）** | 2 | 2.41 | +68% | 宽 |
| 4枝×10叶=40 | 1.01 | g=4 → 1.64 | 2 | 2.00 | +97% | 宽 |
| 6枝×6叶=36 | 1.12 | g=6 → **0.91（变差）** | 3 | 2.44 | +119% | 宽 |
| 8枝×6叶=48 | 0.84 | g=8 → **0.68（变差）** | 4 | 1.92 | +128% | **高**（插入 12.55×22.0cm） |
| 2枝×15叶=30 | 1.35 | g=2 → 2.46（恰最优） | 2 | 2.46 | +83% | 宽 |
| 12枝×4叶=48 | 0.83 | g=6 → 0.91（仅 +9%） | 3 | 2.45 | +194% | 宽 |
| 3枝×20叶=60 | 0.68 | g=3 → 2.01（恰最优） | 3 | 2.01 | +195% | 宽 |
| 5枝×8叶=40 | 1.01 | g=5 → 1.09（仅 +8%） | 2 | 1.67 | +65% | 宽 |

三条必须一起读的结论：

1. **R61 的自然份数只有 2/8 落在曲线顶点**（2枝×15叶、3枝×20叶）；
2. **4 组拆完比不拆还小**（4×7、6×6、8×6，以及 12×4 只 +9%、5×8 只 +8%）——
   这些组同时把插入宽度压到 3.25~7.52cm，**右半页空白凭空浪费**；
3. ⇒ 份数必须由**交付毫米**决定；叶子预算（`ARCH_SPLIT_MAX_LEAVES=8`）降级为
   **份数搜索的上界** + 每份的**规模预算硬约束**（`ARCH_MAX_LEAVES=24`），R61 的两条 env 契约原样保留。

## 2. 决策与取舍

| 决策 | 取舍理由 |
|---|---|
| 目标函数取**最差那张子图**的毫米，不是平均 | 平均会把「一张糊了」洗成达标（A/B M3 直接验证：取平均时护栏立刻红） |
| 只在**严格更好**时才拆（`mm > single_mm + 1e-9`） | 「拆图绝不变差」是本轮唯一硬不变量；相等即回落单图，省一次拼接与高度反噬 |
| 每份硬约束用 `ARCH_MAX_LEAVES`（24），**不用** R61 的步长 8 | 4枝×10叶 在步长 8 下每个单分支都是 10>8，硬约束会**把所有候选一起否掉** ⇒ 拆无可拆、纸面停在 1.01mm；步长只当份数上界（`hi`）保留 |
| 落图前用**真实 PNG 尺寸**再复核一次（第④步安全网） | 探针与落图理论上同源，但归一化/字体度量都可能让二者偏离；不变量必须由真实交付尺寸成立，不能靠预估自证 |
| 连续切分而非交错分配 | 拆出来是给人读的，同一子系统必须留在同一张子图里 |
| 告警**推迟到交付确认之后**（第⑤步） | 见 §3.4：拆完仍报拆分前的毫米数是过期值，且叫用户去做程序刚做过的事 |
| **不做**递归拆分支（R61 遗留①） | 见 §8 未落地：收益要与「份数搜索」重新对账，且 `_allow_split=False` 目前是有意的防环设计 |
| **不做**「预算内但低于下限」也自动拆 | 会直接反转既有护栏 `test_under_budget_chart_byte_identical_across_switch`（开关关闭态必须逐字回退） |

## 3. 落地清单（全部附落盘后实测行号）

### 3.1 公共纸面层（`backend/app/services/ai/mermaid_common.py:380-459`，本轮新增）

判语放在**所有 PIL 渲染器的公共模块**，因为「加高换变窄」这类改造将来还会发生在

- `PAPER_SCALE_DEFAULT / PAPER_DPI_DEFAULT / PAPER_COLUMN_WIDTH_CM / PAPER_MAX_HEIGHT_CM`（`:395-398`）
  —— 与 `export.py` 的权威值同值，由护栏 B 组 `test_constants_match_common_defaults` /
  `test_export_caps_are_the_truth` 双向钉住（**常量改了没同步 → 立刻红**）。
- `paper_font_mm(font_px, canvas_w, canvas_h=0, title_h=0, ...)`（`:401`）—— 宽/高双上限都参与；
  `canvas_h<=0` 表示「不设高限」，`<=0` 的脏输入返回 `0.0` 而**绝不抛**。
- `stitch_geometry(sizes, gap)`（`:424`）—— 竖向拼接的整图几何（宽=最大、高=求和+间隙）。

- `delivered_worst_mm(fonts_px, sizes, gap, **kw)`（`:447`）—— 本轮的**唯一判据**：
  整张拼接图共享同一个 `fit`，取**最差子图**。

`mermaid_architecture.paper_font_mm`（`:544`）改为**委派**本层同名函数，不留两套口径
（A/B M8：不委派 → 护栏立刻红）。

### 3.2 份数由纸面毫米决定（`mermaid_architecture.py`）

- `plan_architecture_split(root, *, max_leaves, max_parts) -> (groups, plan_mm, single_mm)`（`:340`）
  —— **纯函数、不绘制、绝不抛**（`:355` 的 `isinstance` 守卫：拆图是增强，不能反过来打挂渲染；
  A/B M9 验证摘掉守卫会红）。搜索域 `parts ∈ [2, hi]`，`hi = min(贪心组数, max_parts, 分支数)`（`:364`），
  每组过 `ARCH_MAX_LEAVES` 硬约束（`:377`），目标 = `delivered_worst_mm` 最大（`:382`），
  全域都不如单图 ⇒ 返回空组 = **拆无可拆**（`:386`）。
- `_group_branches_balanced(branches, parts)`（`:311`）—— 前缀和取最近切点，
  **`hi_i = n - (parts - k)` 保证后面的组 each 至少剩一个分支**：首版没写这项，
  份数在搜索域里**凭空消失**（A/B M7 定向复现，护栏 `test_balanced_partition_never_empty_even_skewed` 钉住）。
- `_group_branches_by_budget`（`:293`）逐字保留 R61 口径，只作份数上界来源。

### 3.3 落图前真实复核（`:391 review_delivered_mm` + 第④步 `:464`）

`review_delivered_mm` 是「复核」这一**动作**的唯一出口，内部就是 `delivered_worst_mm(..., _SPLIT_GAP_DESIGN_PX)`。
为什么要有这层薄壳：若护栏直接 patch 共享符号 `delivered_worst_mm`，变异会在第①步（份数决策）
就把候选全否决，**根本走不到第④步**，「安全网失效」这类缺陷任何测试都不会红 ——
A/B 首版 M6 实测正是 GREEN。拆出独立出口后，摘掉安全网（M6）与出口形同虚设（M11）才**分别**可测。

### 3.4 告警口径改到「你真的拿到什么」（本轮最大行为修复）

拆图编排 `_render_architecture_split`（`:401`）现为五步：① 份数决策 `:420` → ② 只记决策日志 `:430`
→ ③ 渲染子图 `:441` → ④ 真实复核 `:464` → ⑤ **告警** `:492`。

- **缺陷 A（P2）**：第②步旧实现按**整树**口径打唯一一条告警，于是拆成功后仍打印
  「纸面字号仅 1.01mm … 建议拆分为约 2 张子图」—— 数字是**过期值**（真实交付 1.98mm），
  并且**叫用户去做程序刚刚做过的事**。现改为第⑤步用「最差那张子图的几何 + 第④步真实交付毫米」出文案。
- **缺陷 B（P2）**：否决路径（第④步 `delivered <= single_mm` 回落单图）时，第②步**已经打过**，
  单图渲染路径再打一次 ⇒ 同一张图 **2 条一模一样的 warning**，打破 R60「同一张图只告警 1 次」
  （实测日志行号 439 + 916 同帧出现）。
- `compose_readability_warning(..., delivered_parts: int = 0)`（`:765`）新增形参：
  `delivered_parts >= 2` 时在预算半句后追加「（本轮已自动拆分为 N 张子图）」；
  **默认 0 时整条文案与旧实现逐字一致** ⇒ 单图路径零改动。
  必须守住的跨轮字面契约仍然在位：`架构图超出规模预算` / `建议拆分`
  （`test_arch_size_budget_20261010.py::TestBudgetRenderIntegration` 锁的是这两个字面量）。

### 6.1 本轮最大的护栏教训：monkeypatch 掉一个符号，就永远看不见它的实现

v2 的 M11 把 `review_delivered_mm` 的**函数体**换成「直接返回规划值 / `float("inf")`」，
护栏**全绿** —— 因为 D 组的安全网用例本身就 `monkeypatch.setattr(ma, "review_delivered_mm", ...)`，
它替换掉的正是被变异的那个符号。这与 R57「逻辑埋在 SSE 闭包里，A/B 变异它没有任何测试会红」
是**同一族**盲区。修法不是再补一条端到端用例，而是补**值级等式**：

```python
assert got == pytest.approx(mc.delivered_worst_mm(fonts, sizes, GAP), rel=1e-9)   # 出口 == 共享判据
assert 0 < got < _MIN_TARGET                                                      # fixture 自身可信
assert got < mc.delivered_worst_mm(fonts, sizes, 0)                                # 拼接间距**真的**被传进去
assert ma.review_delivered_mm([], []) == mc.delivered_worst_mm([], [], GAP) == 0.0 # 空输入精确 0
```

v3 中 M11 与 M12（间距写 0 ⇒ 高度算少 ⇒ 毫米被高估）**双双红**在同一条用例上。
**判据：每被 monkeypatch 一次，就要为该符号自身补一条不 monkeypatch 的等式。**

### 6.2 如实披露的一处未覆盖（M16）

第⑤步用 `min(range(...), key=part_fonts[i])` 挑「最差那张子图」的**几何**来组文案；
把它换成 `max` 后**没有任何护栏变红** —— 因为告警里的**毫米数来自共享交付值 `delivered`**，
与被挑的那一张无关，只有「画布 xxxpx 宽、可竖排叶子 xx 个」这几段**描述性文字**会变。
本轮**刻意不为此立护栏**（为一个描述性字段加断言，将来任何文案调整都会变成假红），
在此登记以免后人重复排查。
