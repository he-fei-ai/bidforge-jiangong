## 2. 源码改动（`numbering.py` 3 处 + `content_blocks.py` 1 处）

### 2.1 D-1 · 深嵌套被静默截断 + 环引用无守卫

`renumber_outline_nodes` 旧实现只有 `_MAX_TREE_DEPTH = 20` 一道防线，它同时承担
「防环」和「防失控」。实测 120 级合法链会被静默截断，超限子树**没有 `id`**，
调用方 `KeyError`（目录生成 500，且日志里没有任何定位线索）。

修法（职责分离）：

- **防环**：新增 `_path`（当前递归路径上的 `id(node)` 集合），进入子树前登记、
  退出后 `discard` —— 回溯式守卫，**DAG 共享子树不受影响**；环在第二次相遇处
  终止、跳过该子树、落 WARNING、**不占号**。
- **防失控**：`_MAX_TREE_DEPTH` 20 → 200，只作「异常输入失控」的最后兜底。

⚠️ 关键取舍：不采用「全局 visited 集合」——那会把合法的 DAG 共享子树误判成环。

### 2.2 D-8a · 存储编号判据两份实现，松过滤把垃圾编号抢救成合法值（新增）

`get_stored_section_id` 用 canonical 的 `_DOT_PATH_RE.fullmatch`
（注释明写「合法编号只能是点分路径；UUID 主键等一律视为无效」），而
`stored_id_to_display` / `stored_id_to_prefix` 各自用
`str(...).split(".") + isdigit` **松过滤**：

```
float 3.5    → "3.5" → ["3","5"] → 前缀 "5" / 展示 "5"
"abc1.2"     → parts ["abc1","2"] → "2"
```

于是 `renumber_section_body_subheadings("## 总体安排", 3.5, 2)` 会**静默改写落库
正文**为 `## 5.1 总体安排` —— 非法章节号污染正文编号，且导出/前端口径随之错位。

修法：新增 `_stored_id_parts(stored_id)` 作为**全模块唯一判据**（仅接受 `str` /
`int`，整体 `_DOT_PATH_RE.fullmatch`，含 `0` 号段视为非法），两个派生函数改为
委托。合法形态零回归：`"3.2"→"2"`、`"1"→"1"`、`int 3→"3"`、`"3.2.4"→"2.4"`。

> 本轮唯一一处「由正确用例捕获的真实源码缺陷」—— D-8a 用例本身没有缺陷。

### 2.3 D-8c · 行首 BOM 让首行标题解析成普通段落

`U+FEFF` **不属于空白字符**，`str.strip()` 不剥；它黏在 `#` 前会让首行标题被
解析成段落 → 导出少渲染一级标题、正文子标题编号整体**错位一格**。

修法（两处同口径）：

- `content_blocks.py` 唯一解析入口：行首剥 BOM 后再判空/判形态
  （**仅剥行首，不触碰行内数据**；BOM 是零宽标记，绝不是内容）；
- `numbering.py` 重写判定：`_body = line.lstrip().lstrip("\ufeff").lstrip()`，
  与解析侧同口径，否则 BOM 行会误走纯文本分支被重写。
