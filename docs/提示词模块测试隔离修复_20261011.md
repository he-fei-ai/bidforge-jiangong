## 2. 本轮加固项

### 2.1 前端治理开关 UI 测试覆盖（4 例，新增）

**问题**：`aiConfigGovernance.test.tsx` 此前未 mock `systemApi`，治理面板的 `loadGovernance()` 抛错被 `catch {}` 静默吞掉 → 测试「跑过了」但治理 Card **零覆盖**。

**修复**：
1. `h` hoisted mock 补 `getGovernance` / `updateGovernance` 两个 `vi.fn()`
2. `vi.mock("../api")` 补 `systemApi: { getGovernance, updateGovernance, ... }`
3. `beforeEach` 补治理默认 mock 返回（关闭态 0/False）
4. 新增 `describe("提示词治理开关")` 4 例测试

**测试用例**：
- `页面加载时 GET 拉取治理开关当前值` — 验证挂载时调用 `getGovernance`
- `注入防护 Switch 开启时调用 updateGovernance({prompt_injection_defense:true})` — 验证 Switch onChange 正确触发 PUT
- `上下文预算 InputNumber 改值后失焦调用 updateGovernance({prompt_context_budget:N})` — 验证 InputNumber onBlur 正确触发 PUT
- `治理面板加载失败不阻断主配置页（fail-soft）` — 验证 GET 请求失败时主配置页仍正常渲染

### 2.2 前后端 GovernanceSettings 字段 parity 护栏（4 例，新增）

**问题**：前端 `GovernanceSettings` TypeScript 接口与后端 `GovernanceSettings` Pydantic 模型无自动一致性检查，字段漂移不会被发现。

**修复**：新建 `tests/test_governance_field_parity_20261011.py`（4 例）：
- `test_backend_model_has_expected_fields` — AST 提取后端 Pydantic 类字段，断言 = `{prompt_context_budget, prompt_injection_defense}`
- `test_frontend_interface_has_expected_fields` — 正则提取前端 TS 接口字段，断言 = 同集合
- `test_frontend_and_backend_fields_match` — 双向相等断言（前端字段集 == 后端字段集）
- `test_get_and_put_return_same_fields` — 验证 GET 返回体字段集包含期望集合（API 契约对称）
