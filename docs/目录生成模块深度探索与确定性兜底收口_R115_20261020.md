## 四、修复项清单（6 项）

### FIX-1 · 占位标题「零 AI 确定性兜底」（核心）

**症状**：AI 不可用时，`专项6`／`总体实施策划（2）` 原样落库。
**根因**：三层出口全部 fail-soft 原样保留（见 §2.2 结论链）。
**修法**：`_try_outline_title_fix` 的**所有**返回出口统一过 `_finalize()`；AI 未生效时改用**纯确定性规则**再改一轮。

`app/services/outline_title_fix.py`：

```python
def deterministic_title_fallback(
        outline: list, hits: list[dict], *, stage: str = "") -> list | None:
    """零 AI 兜底：去「（N）」后缀基名 → description 首分句 → description 截断。
    仍走 `_apply_title_updates` 同一套六条保守红线，绝不改坏结构。"""
```

候选生成链（**有序**，逐级放宽）：

1. `strip_trailing_counter_suffix(title)` 的基名 —— `总体实施策划（2）` → `总体实施策划`
2. 节点 `description` 的首分句 —— `施工总体部署、进度计划与资源配置。` → `施工总体部署、进度计划与资源配置`
3. `description` 截断（`_FALLBACK_TITLE_MAX_LEN`）

**与红线的关系（关键设计）**：兜底**不绕过**任何一条保守红线 —— 基名若仍泛化（`^总体实施策划` 本就在 `GENERIC_TITLE_PATTERNS` 内）照旧被拒；与同级重名照旧被拒；带「（N）」后缀照旧被拒。因此兜底的最坏结果是「等于没做」，**不可能更糟**（除 FIX-5 修的例外）。

### FIX-2 · `_skip_ai` 快路径（性能 + 不白打）

**症状**：AI 已实证不可用（超时/401），后续每次改写仍从头再打一轮，白烧 120s。
**修法**：`_try_outline_title_fix(..., _skip_ai=True)` 直接进兜底，**零 AI 调用**。

`app/routers/sse_handlers.py`：

- `L2993` `_patch_state["timed_out"] = True`
- `L2998` `_patch_state["errored"] = True`
- `L3220` `_skip_ai=bool(_patch_state.get("timed_out") or _patch_state.get("errored"))`
- `L3363` `_skip_ai=bool(_review_skip_reason)`

### FIX-5 · 候选质量门槛（**由既有护栏反向发现的真实缺陷**）

**发现过程（务必保留）**：FIX-1 首版兜底**零门槛**，`-k outline` 立刻打红 **10 例既有护栏** ——
`test_outline_window_step_bug`（8 参数化）+ `test_outline_stepwise_window`（1）+ `test_outline_generic_titles_20261010`（1）。

失败形态：桩里 `description="desc1"`（**0 个中文**）、`"占位一级"`/`"占位二级"` 被当成合格候选，
于是 `第1章` 被改成 `desc1`、`专项6` 被改成 `占位一级` —— **比原占位名更糟**。

**这不是「测试桩太假」**：`description` 在生产里确实是模型写的自由文本，`N/A` / `见图3` / `待补充` / `占位` 都是真实可能值。

**修法**（`outline_title_fix.py`，产出侧就拒掉，不进红线也不进 AI）：

```python
_FALLBACK_MIN_CJK = 4
_FALLBACK_MIN_CJK_RATIO = 0.6
_CJK_CHAR_RE = re.compile(r"[\u4e00-\u9fff]")

#: 精确黑名单（整串去空白、小写后**等于**才拒）。含「略」「无」这类单字，故只能
#: 整串比对 —— 子串匹配会把「策略」「无缝钢管」「无支护放坡」这些真实标题拒掉。
_DESC_JUNK_EXACT = frozenset({
    "略", "无", "暂无", "无内容", "未填", "未填写", "同上", "同上文", "见上",
    "n/a", "na", "tbd", "todo", "待补充", "待定", "待确认",
})

#: 子串黑名单（**含**即拒）。只收元话语/占位标记，不收任何施工术语。
_DESC_JUNK_SUBSTR = ("占位", "待补充", "待完善", "详见", "同上", "见上文")

def _is_usable_title(s) -> bool:
    t = str(s or "").strip()
    if not t:
        return False
    probe = "".join(t.split()).lower()      # 模型常把「N / A」「占位 一级」拆开写
    if not probe or probe in _DESC_JUNK_EXACT:
        return False
    if any(m in probe for m in _DESC_JUNK_SUBSTR):
        return False
    cjk = len(_CJK_CHAR_RE.findall(t))
    if cjk < _FALLBACK_MIN_CJK:
        return False
    return cjk / len(probe) >= _FALLBACK_MIN_CJK_RATIO
```

接线点（4 处）：`_desc_title_candidates` 的整段 / 分句 / 截断三个产出点 + `_fallback_title_candidates` 出口统一过滤。

**判据刻意留在生成侧**（不进 `outline_quality`）：那边是**判定**已有标题是否泛化，这边是**生成**候选；
同一函数会把「无缝钢管」「无支护放坡」「基坑支护施工策略」误判掉 —— 已由 H 组参数化锁死。

### FIX-6 · 前端消费面（跨模块闭环）

**症状**：后端已如实标注 `review_skipped`，前端**从不读** ⇒ 用户看到的仍是「📘 审核依据：AI 审核链路」。

## 十、运维与判据教训

### 10.1 运维

- **前端需重建**（本轮有前端改动，与 R114 不同）。

  - `占位标题重写失败（…第 1/3 轮）…，转确定性兜底`（WARNING）
  - `确定性兜底改写 N/M 条`（INFO，若已接线）
  - `目录审核超时（60s），跳过审核直接完成`（WARNING）→ 前端应显示 ⚠ 首行

### 10.2 monkeypatch 表面

`otf.collect_json_response` / `otf._try_outline_title_fix` / `otf.autofix_generic_titles_on_save` / `settings.outline_deterministic_title_fallback` / `settings.outline_autofix_generic_on_save`

### 10.3 判据教训归档

1. **新护栏必须被既有护栏反向检验**：FIX-1 首版零门槛被 10 例既有用例打红 —— 这不是「桩太假」，而是**真实缺陷的早期信号**。先问「生产里这个值可能是垃圾吗」，再问「桩该不该改」。
2. **等价变异要诚实**：A/B 出现 `NOT-CAUGHT` 时，先判「变异是否等价」再判「护栏是否有洞」。把等价变异当成护栏缺陷去改代码，会引入真正的冗余。
3. **全量 pytest 的假故障必须先复现再定性**：本轮 76 failed 重跑后只剩 1 个真实失败；`9163+76+3 = 9242` 的对账是定性依据。**不要**在未复现前改代码。
4. **编辑工具会静默改行尾**：非 ASCII 路径 + Windows 下，SearchReplace 可能把 LF 文件整体写成 CRLF。改完前端文件必须跑字节体检（本仓有 `test_frontend_first_run_r57` 兜底）。
5. **`npx` 可能解析到别的同名二进制**：`tsc` 全量 TS6053 + 路径乱码是本机已知症状，改用 `node node_modules/typescript/lib/tsc.js`。
6. **临时目录会累积成护栏红灯**：`.tmp_r113_*` 480MB 里的 `.bak-*` 让 `test_no_bak_files_in_repo` 变红。跑全量前先清 `.tmp_*`。
