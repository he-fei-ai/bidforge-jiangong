### 2.3 关键设计纪律（AGENTS.md §4.14 记录，已落地）

1. **终态拼装点唯一性**：`_sse_content_payloads.py` 的三处函数（`build_content_checkpoint` / `build_stopped_payload` / `build_error_payload`）是所有终端路径的唯一出口。R194 FIX-1 已修复 `_progress_now()` 提前绑定的陷阱。
2. **非前缀路径零覆盖**：`/confirm` / `/rollback` / `/autofix/confirm` 走 `_resolve_finding(payload=...)` 惰性重算，不得触发全量 `_readiness_overview_compute`（R223 P1-B）。
3. **五处 fail-soft 守卫**：checkpoint 写入 / review 留痕 / 标准校验 / 图表登记 / 一致性修复 —— 任一失败不得阻断整批正文落库。
4. **`_stat`/`_prog`/`done_ids`/`_failed_reasons` 四者口径必须逐字对齐**——否则终态横幅与实际库状态对不上。

## 4. 本轮修复项

### 4.1 FIX-1 · AST 窗口过短导致假红（`test_seven_module_fixes_20260927.py`）

**根因**：R224（F15）把 `_mark_pending_once` 内嵌进 `retry_db_op` 闭包，从 `_prior: dict = {}` 标记点到 `_write_review_record` 调用点跨越超过 2600 字符。旧测试窗口 `src[i:i+2600]` 截取不到后半段，`re.search(r'_old,\s*"pending"', window)` 恒为 False → 定向失败。

**修法**：扩大窗口至 4000 字符，并补注释说明扩窗原因（防后人按"精简"名义缩减回去）。

**验证**：还原修改 → 定向失败；恢复 → 214 passed。

### 4.2 FIX-2 · 进程守护型 bare except 应豁免（`omp_rpc.py`）

**根因**：`OmpRpcClient._kill()` 的 `stdin.close()` / `proc.kill()+wait()` / `stop()` 的 `shutil.rmtree` 都是**进程生命周期守护**，捕获的是 `"process already gone"` 类预期异常。全仓扫 `except Exception` 的棘轮本意是抓「业务逻辑被静默吞」，不应误伤这类守卫。

**修法**：三处各加 `# noqa: BLE001 - <一句说明>`，让静态扫仓护栏可识别豁免理由。

**验证**：还原 → 3 例定向失败；恢复 → 47 passed。

## 5. 待跟进项（本轮探查发现，不落地）

### 5.1 L-1 · `completed_count` 命名歧义（P3 卫生）

`sse_handlers.py` 里有 `nonlocal completed_count`，但实际语义是"本轮已成功章节累计计数"——与 R194/FIX-5b 的 `_prog["words"]`/`_stat["over"]` 命名风格不一致。建议改名为 `_realized_sections` 或 `_success_count`，避免与 "completed 事件数量" 混淆。

**不做理由**：当前变量名虽略歧义但不影响正确性；改名牵涉 A/B 反向验证 + 15 处引用点 + 既有测试断言；属风格类改动而非缺陷。

### 5.2 L-2 · `_crossdup_snapshot` 作用域注释过于长

`_crossdup_snapshot` 的 nonlocal 注释写了 ~60 行解释根因（R224 F1 同族），阅读成本偏高。可考虑抽成 `_ensure_crossdup_snapshot(db, scheme_id)` 薄包装，让 gen_one 本体干净。

**不做理由**：当前实现已是"一次性 inline"模式，抽包装会新增一层函数调用链；且该快照只在首次调用时加载，后续直接读内存，性能无差异。

### 5.3 L-3 · 前端 `useContentGeneration.ts` 消费字段未全覆盖

`StandardReport` 类型缺少 `stats.placeholder_count` 等少数字段（后端会回传但前端忽略）。前端 `GenStats` 接口也未声明 `word_audit` 键。不影响运行（可选字段），但类型安全稍弱。

**不做理由**：TypeScript 接口是可选字段语义（`?`），未声明不会编译报错；且前端只消费自身需要的字段。改为严格对齐需要全仓 grep 所有消费点，成本高收益低。
