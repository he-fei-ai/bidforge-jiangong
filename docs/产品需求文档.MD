## 一、产品概述

### 1.1 产品定位

工程项目专项方案智能编制平台，面向施工方、咨询方、企业技术中心的 AI 辅助文档生成工具。以「**项目 — 方案 — 章节**」为核心结构，在一个工程项目下自由新建多个专项方案（深基坑、高支模、脚手架、塔吊安拆、临时用电、应急预案……），完成：

- 项目资料导入与解析（多格式 + OCR + 云端兜底）
- 项目资料结构化提取（18 项维度）
- 全局事实变量提取与人工裁决
- 方案目录生成（AI / 目录库 / 方案清单标准目录 / 上传识别 / 混合）
- 正文逐章生成（图表与正文一体产出）
- 全文一致性扫描、仲裁与定向修复
- 六维就绪度评分 + 程序化预检
- 规范符合性检查 + 专家论证预检（危大工程）
- DOCX / PDF 导出

平台**不是替代工程师**，而是把重复性、结构化、长文本编写工作自动化，让人专注于技术判断、参数确认、审核与落地。

### 1.2 目标用户

| 用户类型 | 典型角色 | 核心诉求 |
| -------- | -------- | -------- |
| 施工方 | 技术负责人、方案工程师、项目总工 | 快速编制危大工程专项方案、施工方案 |
| 咨询方 | 方案咨询顾问、编制机构 | 批量生成标准化方案，提高交付效率 |
| 企业 | 企业技术中心、安全质量部 | 沉淀企业目录库、知识库、标准模板 |
| 审核方 | 内部审核、专家论证准备人员 | 检查完整性、一致性、合规性 |

### 1.3 核心价值

| 价值维度 | 说明 |
| -------- | ---- |
| 效率提升 | 自动生成目录与正文，节省 70%+ 编写时间 |
| 质量保障 | 全局事实变量、一致性 Agent 修复、六维就绪度评分、规范符合性检查、专家论证预检 |
| 目录复用 | 专项方案目录库（12 个一级分类）+ 141 个内置标准目录模板 |
| 灵活编制 | 项目下自由新建多方案，互不干扰 |
| 图表丰富 | 7 类图表（流程图/甘特/组织架构/劳动力/对比/总平面/时间轴），正文一体生成、内置渲染 |
| 多格式解析 | DOCX、PDF（文本层 / 扫描件 OCR / MinerU 云端）、MD、TXT、XLSX、XLS、CSV、图片 |
| 稳定生成 | 弱模型也能稳定输出复杂 JSON（校验 → 定向修复 → 有界重试 → 分步生成） |
| 交付可控 | 六维评分 + 阻断项 + 放行结论，直接回答「这份方案能不能交付」 |
| 成本可控 | 提示词分层缓存、连接池复用、对冲请求、并发收敛、AI 调用审计日志 |
| 任务可靠 | Task Registry 持久化、断点恢复、SSE 实时进度、暂停/恢复/停止 |

### 1.4 术语定义

| 术语 | 说明 |
| ---- | ---- |
| 项目 | 一个工程项目，可包含多个专项方案 |
| 方案 | 项目下的一个专项方案，如深基坑专项方案、高支模专项方案 |
| 章节 | 方案下的目录节点。目录树只保留三个等级：一级「第一章」、二级「1」、三级「1.1」 |
| 目录库 | 企业/平台沉淀的专项方案目录模板库；另有内置标准目录模板库（141 个） |
| 目录识别 | 从上传文件中提取标题层级并生成树形目录 |
| 导入目录整理 | 把上传识别的「原样镜像」目录重整为软件标准结构（补编写要点、对齐危大法定章节） |
| 全局事实变量 | 方案中需保持一致的事实：工期、基坑深度、塔吊型号、混凝土等级、人员姓名等 |
| 提取项目 | 把项目资料按 18 个固定维度提取为 Markdown/JSON 结构（业务层结构化提取） |
| 预编排 / 图表同步生成 | 图表不单独编排，由撰写正文的同一个 AI 在行文时内嵌代码块一步完成 |
| 就绪度评分 | 六维加权评分（0-100）+ 阻断项 + 放行/整改结论 |
| 程序化预检 | 确定性规则引擎，离线秒级，覆盖完整性/标准时效性/安全/一致性/可追溯性/可交付性 |
| 弱模型稳定 JSON | 通过校验、定向修复、有界重试、分步生成，让普通模型稳定输出结构化数据 |
| 危大工程 | 危险性较大的分部分项工程，专项方案需按规定编制并论证 |

## 三、功能需求

### 3.1 项目管理模块

#### 3.1.1 项目列表（`/`）
- 展示所有项目，支持搜索、筛选、排序。
- 字段：项目名称、描述、工程类型、创建时间、更新时间、状态、方案数量。
- 操作：新建、编辑、删除、进入项目、归档。

#### 3.1.2 项目创建
| 字段 | 说明 |
| ---- | ---- |
| 项目名称 | 必填 |
| 项目描述 | 选填 |
| 工程类型 | 房建、市政、公路、铁路、水利、电力、地铁、桥梁、隧道、管廊、机电安装等 |
| 项目地点 | 选填 |
| 建设单位 | 选填 |
| 施工单位 | 选填 |
| 项目周期 | 选填 |

创建后自动初始化项目空间，默认无方案。

#### 3.1.3 项目详情（`/project/:id`）
- 项目基本信息、方案列表、最近任务、进入方案工作台。
- 项目级资料与事实在项目维度共享，方案可继承。

#### 3.1.4 项目删除
- 删除前二次确认；级联删除项目下所有方案、章节、附件、目录引用、导出缓存、任务记录。

---

### 3.2 方案管理模块

#### 3.2.1 方案列表
在项目详情页展示该项目下所有专项方案。字段：方案名称、方案类型、专业、状态、章节数、总字数/目标字数、目录来源、创建时间、更新时间。
操作：新建、编辑、复制、归档、删除、进入工作台、导出。

#### 3.2.2 新建方案
用户可在项目下自由新建多个方案，不限制数量。

| 字段 | 说明 |
| ---- | ---- |
| 方案名称 | 必填；可从**方案清单**（12 分类、141 个标准目录）一键选用 |
| 方案类型 | 深基坑、高支模、脚手架、塔吊、施工电梯、临时用电、消防、安全文明、绿色施工、质量创优、进度计划、应急预案、施工组织设计、钢结构吊装、降水、土方开挖、模板工程、混凝土工程、有限空间等 |
| 专业 | 土建、机电、钢结构、安全、绿色施工等 |
| 编制依据 | 可引用项目资料、规范、企业标准 |
| 目标字数 | 方案总目标字数 |
| 目录来源 | AI 生成 / 目录库调用 / 方案清单标准目录 / 上传目录识别 / 混合生成 |
| 目录库模板 | 可选择多个目录库模板（最多 3 个参与参考注入） |
| 知识库范围 | 项目级 / 企业级 / 指定知识库 |
| AI 配置 | 使用全局 AI 或方案级指定模型 |
| 图表偏好 | 是否启用 Mermaid、AI 生图、表格数量倾向 |
| 导出样式 | 字体、字号、行距、页边距、封面、目录、页眉、页脚、页码 |
| 编制要求 / 评审要点 | 自由文本；注入目录生成（一级必须逐条覆盖）与审核（缺失判不通过并自动补齐建议） |

#### 3.2.3 方案状态（与章节/任务状态解耦）
```text
草稿 → 目录生成中 → 目录已确认 → 正文生成中 → 审核中 → 已完成 → 已归档
```
- 方案状态**不再由任务进度直接推导**。历史上「任务在跑 = 方案状态被改写」导致刷新页面时状态回跳；现二者各自独立维护，方案状态只在明确的业务动作（确认目录、生成完成、审核通过、归档）时推进。

#### 3.2.4 方案版本与快照
- 支持保存方案快照（`scheme_snapshots`）。
- 一致性修复前自动为涉及章节保存快照，支持一键回滚（只影响快照涉及的章节）。
- 目录库侧支持新版本、历史版本、回滚。

#### 3.2.5 方案复制
- 复制方案结构、目录、全局事实、导出配置；可选择是否复制正文、图表、知识引用。

### 3.3 专项方案目录库模块

#### 3.3.1 功能目标
将企业常用专项方案目录沉淀为目录库，在新建方案或生成目录时直接调用；同时内置 **141 个标准目录模板**（`outline_templates.py`），覆盖 12 个一级分类，开箱即用。

#### 3.3.2 目录库分类
- **一级分类（12）**：基坑与土方、模板与支撑、脚手架、起重吊装、临时设施、安全文明、质量与创优、防水与渗漏、装配式与结构、装饰装修、机电与智能化、应急与专项
- **工程类型**：房建、市政、公路、铁路、水利、电力、地铁、桥梁、隧道、管廊、机电安装
- **专业**：土建、机电、钢结构、安全、绿色施工、质量、测量、试验

#### 3.3.3 目录库字段
| 字段 | 说明 |
| ---- | ---- |
| 目录库 ID | 唯一标识 |
| 名称 | 如「深基坑专项方案标准目录」 |
| 方案类型 / 工程类型 / 专业 | 分类维度 |
| 适用条件 | 基坑深度、支护形式、工程规模等 |
| 编制依据 | 规范、标准、企业制度 |
| 目录 JSON | 树形目录结构（含 description 编写要点） |
| 标签 | 多标签（分类 + 方案名 + 模板 + 危大分级） |
| 版本 | v1.0、v2.0（`outline_library_versions`） |
| 来源 | 手动创建、上传识别、AI 生成保存、历史方案提取、内置模板 |
| 审核状态 | 待审核、已通过、已停用 |
| 引用次数 | 被方案调用次数 |
| 创建人 / 更新时间 | 元数据 |

#### 3.3.4 目录库操作
- 新增目录（手动创建树形目录）
- 上传入库（DOCX/PDF/MD/Excel/图片，识别后入库）
- **从方案导入**（`from-scheme`）：把已有方案的目录树沉淀为目录库
- 编辑目录（增删改章节、调整层级、排序）
- 版本管理（新版本、历史版本、回滚）
- 审核（提交审核、批量审核，通过后方可被公共调用）
- 停用/启用、删除、复制
- 检索（按名称、类型、工程类型、专业、标签、适用条件）
- 导出（txt / markdown，由 `outline_reference.py` 渲染）
- 调用（`/apply`、`/apply-and-save`）

#### 3.3.5 目录库调用方式
| 模式 | 说明 |
| ---- | ---- |
| 目录库优先 | 以目录库为骨架，AI 只补全描述和子节点 |
| 目录库参考 | 将目录库渲染为紧凑参考文本注入 prompt，AI 生成新目录 |
| 多库合并 | 选择多个目录库（最多 3 个），合并去重 |

### 3.4 目录生成与上传识别模块

#### 3.4.1 目录生成来源
1. AI 自动生成
2. 专项方案目录库调用
3. **方案清单标准目录**（`/api/v1/scheme-catalog`，141 个内置模板）
4. 手动上传目录并识别提取
5. 多种方式混合生成

#### 3.4.2 AI 目录生成
**短方案 + 强模型**：一次性生成完整三级目录 JSON。
**长方案 + 普通模型**：先生成一级目录 → 逐章生成二三级 → 程序拼接、统一编号、校验。

**上下文注入（实现要点）**：
- 优先消费「提取项目」的**结构化成果**作为项目摘要（原始摘录降级为附录）——修复了早期「结构化提取无人消费」的断链。
- 已解析资料通过 `load_parsed_texts`（非空条件下推 SQL + 固定排序）取用——修复了「LIMIT 5 取到未解析文件导致资料完全不可见」的缺陷。
- 注入**项目关键事实**（开挖深度、搭设高度、地质条件、周边环境等，3000 字上限）与**知识库素材**，使目录紧扣本项目真实参数。
- 注入**编制要求/评审要点**，一级目录须逐条覆盖。

**稳定 JSON 工作流**：
```text
生成目录 → JSON 解析 → Schema 校验 → 业务校验 → 定向 JSON 修复 → 多轮重试
→ 分步生成 → 目录审核（L1→L2→L3）→ 建议回灌 → 二次生成 → 程序统一编号 → 返回结果
```

#### 3.4.3 上传目录识别提取
**入口**：方案工作台「目录生成」→ 上传目录；目录库 → 上传入库。

**支持格式**：
| 格式 | 处理方式 |
| ---- | -------- |
| DOCX | python-docx / docx2python 解析标题样式、编号、大纲级别 |
| PDF | PyMuPDF（`fitz`）快速通道 → pdfplumber / pypdf 回退；扫描件走 OCR 或 MinerU 云端 |
| Markdown | 按 `#` 层级解析 |
| TXT | 按编号规则解析 |
| XLSX / XLS / CSV | openpyxl / xlrd / csv 按列识别层级 |
| 图片 | OCR（tesseract / RapidOCR / 视觉大模型三通道） |

**识别规则**：标题样式（Heading 1/2/3、加粗、字号、大纲级别）→ 编号规则（1、1.1、一、（一）、第一章）→ 缩进层级 → 目录域 → 表格中的目录结构。

**输出结构**：
```json
{
  "outline": [
    {
      "id": "1",
      "title": "工程概况",
      "level": 1,
      "source_text": "第一章 工程概况",
      "source_page": 1,
      "confidence": 0.98,
      "children": [
        { "id": "1.1", "title": "工程简介", "level": 2, "confidence": 0.95, "children": [] }
      ]
    }
  ]
}
```

**导入目录整理（`outline_reorganize.py`）**：
上传识别的结果是文档结构的「原样镜像」，存在三个问题：无 description 编写要点、可能偏离危大工程法定章节、命名与粒度不一致。整理服务将其重整为软件生成标准结构（补编写要点、对齐法定内容、统一命名粒度），并统一裁剪为三级（更深节点标题并入父节点 description，避免内容线索丢失）。

**人工校正**：树形预览、拖拽调整层级、合并/拆分/重命名、批量改层级、删空节点、补充缺失节点；保存为方案目录或入库。

**校验**：层级连续、编号唯一、无循环引用、深度限制（>3 级裁剪）、空节点提示、置信度 < 0.7 高亮。

#### 3.4.4 目录审核
审核要点：是否覆盖方案必要章节、是否符合危大工程专项方案编制要求（工程概况/编制依据/施工计划/施工工艺技术/安全保证措施/人员分工/验收要求/应急处置措施/计算书及相关图纸/监测方案）、一级目录是否合理、是否存在重复错位遗漏、是否与目录库标准结构偏差过大。

```json
{
  "passed": false,
  "suggestions": ["补充应急处置章节", "增加计算书及相关图纸", "一级目录需更贴合专项方案类型"]
}
```
审核不通过时，建议回灌到生成 Prompt 重新生成。
> 语义约定：`passed` 缺失时——**有 `suggestions` 按不通过处理；无建议视为通过**（避免无依据空跑修复轮）。

#### 3.4.5 目录编辑
- 树形编辑器；默认三级，支持拖拽排序、批量操作
- 新增子章节 / 同级章节、重命名、上移下移、删除（含子节点）
- 支持锁定一级目录、程序统一重排编号（`reorder`）
- 编辑后不破坏原有 JSON 结构

### 3.7 正文生成模块

#### 3.7.1 图表同步生成（替代原「预编排」）
> **实现已变更**：不再单独跑编排阶段。正文提示词要求撰写正文的同一个 AI 在行文合适位置**直接内嵌代码块**，配图判定、图表代码、插入位置一步完成，格式与正文一致。

- 代码块形态：` ```mermaid `（Mermaid 语法）或 ` ```chart-json `（结构化图表数据）
- 落库时由 `_chart_pipeline.py` 提取 → 校验 → 修复 → 登记到 `chart_predictions`
- 导出时才由渲染引擎按内联代码块渲染为图片
- 同一章节最终只执行一种配图类型：`ai` / `mermaid` / `none`

#### 3.7.2 正文生成参数
| 参数 | 取值 | 说明 |
| ---- | ---- | ---- |
| `mode` | `all` / `missing` / `section` / `continue` | 生成范围与续写模式 |
| `section_id` | 章节 ID | 指定章节及子树 |
| `concurrency` | `slow` / `balanced` / `fast` 或整数 | 并发档位（受全局上限 5 约束） |
| `word_budget_override` | 整数 | 覆盖字数预算 |
| `force_rewrite` | bool | 强制覆盖已生成章节 |
| `auto_shrink_over` | bool（**默认关**） | 超 130% 自动压缩（每章额外 AI 调用，属费用决策项） |
| `auto_consistency_repair` | bool（**默认开**） | 生成后自动跑一致性 Agent 修复（结果待用户确认） |
| `consistency_severity` | `high`/`medium`/`low` | 自动修复处理的最低严重级 |

- 字数控制：按 `word_budget` 生成，不足自动续写（有上限），超出标记 `over`
- 标题编号由程序统一管理（`heading_v1` / `heading_v2`），不依赖模型编号

#### 3.7.3 上下文传递
项目概述（优先结构化提取成果）、方案类型、上级章节链、同级章节、当前章节标题与描述、**全局事实变量**、知识库素材、编制要求、用户额外要求。

#### 3.7.4 全局事实变量
**事实类型**：项目人员角色与职责；工期、运维期、交货时间；技术路线、设备型号、统一配置；施工做法、执行安排；工程规模、基坑深度、支护形式；混凝土等级、荷载参数、计算参数。

**提取来源**：项目资料、设计文件、规范标准、合同/项目要求、知识库、用户手动编辑。

**提取管线（`facts_extractor.py`）**：
1. 分段提取：超长资料自动切分，分段并发调用 LLM（支持增量：只处理新增/变更段落）
2. 合并去重：归一化 key 聚类，按来源优先级选取（归一化字典为**单一事实源**，Prompt 与程序共用）
3. 矛盾检测：同 key 多值标记冲突，支持人工裁决
4. **交叉校验**（`facts_cross_validators.py`，零 LLM 依赖）：
   - `XV-MAT-DESIGN` 材料规格 ↔ 设计参数（等级序列比对，范围值兼容）
   - `XV-MACH-SCHED` 机械进退场时间 ↔ 工期（时序约束链 C1~C5）
   - `XV-FLOW-SEQ` 流程序列 ↔ 流程序列（LCS 相似度）
5. 模拟值处理：强制标记 + **安全关键项禁止模拟**；无值处理策略三选一
   - 智能补全（标记模拟值）/ 不杜撰（剔除模拟值）/ 留待填写（写【待填写】）
6. 缓存失效：事实变更后自动清空导出缓存

**使用方式**：方案级全局事实；项目级可继承到方案；正文生成强制注入；**未确认的模拟值可在正文生成前强制拦截**（模拟值闸门）。

#### 3.7.5 正文清洗与质量（`content_polish.py`）
落库前清洗与告警：
- 清除口语化 / AI 腔残留（「说白了」「咱们」「搞定」「需要注意的是」等）
- 清除 AI 身份披露与客套套话（「作为人工智能…」「以上是本章内容」）
- 过期标准引用扫描（命中已废止编号即告警，见 §3.12.2 规范时效库）

#### 3.7.6 提示词缓存优化
1. `system` 只放稳定规则
2. 大且稳定的上下文前置：项目资料、规范、目录树、上级章节链
3. 任务差异放最后：当前章节、当前任务
4. 同一份数据格式保持稳定
5. 不把随机信息、时间戳放入共享上下文

#### 3.7.7 弱模型稳定输出
所有 JSON 输出统一走：
```text
请求模型 → 优先 JSON 模式 → 不支持则降级普通请求 → 提取 JSON
→ Pydantic 校验 → 业务校验 → 失败进入定向修复（传入具体错误）
→ 有界重试 → 大 JSON 切换分步生成 → 程序统一编号 → 返回结果
```

- `chart_payload.py` 是图表载荷的**唯一构造器 + 唯一解析器**（双写：`chart_predictions.data_json` 与 `sections.<type>_json`，两条写入路径必须产出同一形状）

| 封面页 | 开关；封面信息：工程名称、编制单位、方案编号、版本 |
| 目录页 | 开关；目录收录层级 |
| 字体字号 | 正文字体（宋体/微软雅黑等）、字号、行距 |

#### 3.10.2 导出格式
- **DOCX**（主）：`/export/docx`
- **PDF**：先生成 DOCX 再转换（需本机 Microsoft Word 或 LibreOffice）
- **格式预设**（`export_presets`）：保存/应用/设默认/删除多套样式配置

#### 3.10.3 公式与乱码修复（`docx_math.py`）
导出前统一处理三类问题：
1. LaTeX 公式残留（`$...$` / `$$...$$` / `\(...\)` / `\[...\]`）→ 转 Word 原生公式 **OMML**，不再以反斜杠源码出现
2. 常见乱码符号（U+FFFD、控制字符、GBK「锟斤拷」、Latin-1 mojibake、西里尔误植）→ 清洗
3. 导出内容结构校验

#### 3.10.4 导出缓存
- 基于内容 MD5 指纹；缓存键 `{scheme_id}_{config_hash}_{content_fingerprint}`
- 命中则复用最近导出结果；结果文件保留策略（最多 5 份）
- 缓存在 `data/_exports/`；图表 PNG 在 `data/_exports/charts/`
- 全局事实变更会主动清空导出缓存

#### 3.10.5 导出预检（`/export/check`）
空章节、孤立节点、控制字符、图表未生成、计算书缺失；输出 JSON 问题列表。


可靠性增强（2026-09-17）：
| 机制 | 参数 | 说明 |
| ---- | ---- | ---- |
| 对冲请求 | `ai_hedge_delay_seconds = 20` | 主候选 20s 无响应则并行启动下一候选，先成功者胜并取消其余在途调用（消除长尾，实测 p90 181s） |

### 3.12 质量管理模块

#### 3.12.1 六维就绪度评分（`audit_scoring.py`）
统一回答「这份方案能不能交付」。

| 维度 | 权重 | 关注点 |
| ---- | ---- | ------ |
| 内容完整性 completeness | 25 | 法定章节齐备、无空章节、无「有标题无实质」 |
| 规范符合性 compliance | 20 | 现行标准引用、废止标准零命中 |
| 安全措施有效性 safety | 20 | 安全技术措施、组织保障、特种作业 |
| 全文一致性 consistency | 15 | 全局事实一致、无自相矛盾 |
| 可追溯性 traceability | 10 | 参数有出处、引用可溯源 |
| 可交付性 deliverability | 10 | 图表可渲染、计算书齐备、导出无阻塞 |

输出：六维得分、加权总分、**阻断项**、放行/整改结论。检查项 ID 前缀：`CMP`（完整性）/ `STD`（标准）/ `SAF`（安全）/ `CON`（一致性）/ `TRC`（可追溯性）/ `DEL`（可交付性）。
审核规则由 `audit_rules.py` **单一事实源**维护（此前分散在前端清单、后端常量、提示词三处，已合并）。

#### 3.12.2 规范符合性检查 + 规范时效库
- `standards_registry.py` 维护**现行有效**标准清单（按方案类型注入提示词）+ **已废止/被替代**清单（提示词禁止项 + 生成后扫描告警）
- 三级流程：清单管理（通用 + 项目定制）→ 逐条扫描 → AI 深度分析（命中项上下文判定 → 风险等级）

#### 3.12.3 程序化预检（`preflight_engine.py`）
- **确定性规则、纯本地计算、秒级返回、可离线、可回归测试**（同一份正文永远得到同一份结论）
- 六组检查：完整性 / 标准时效性 / 安全 / 一致性（含 Jaccard 相似度查重）/ 可追溯性 / 可交付性
- 与 AI 语义判定互补：程序化管硬伤，AI 管语义（措施是否有针对性、参数取值依据）

#### 3.12.4 全文一致性 Agent 修复闭环
```text
扫描（consistency_scanner：程序预扫线索 + AI 分片提取跨章节冲突）
→ 仲裁（conflict_arbiter：优先用全局事实程序化命中，其余 AI 批量仲裁；定级高/中/低）
→ 定向修复（repair_agent：按章节分组，最小必要修改）
→ 二次校验（repair_validator：冲突消除 / 无新冲突 / 结构完整 / 字数合理 / 事实一致）
→ 保存快照（repair_record）+ 写入正文待确认
→ 用户逐条接受 / 拒绝（拒绝 = 该章整体恢复快照原文）
→ 一键回滚
```
- 扫描只读，不修改正文；修复失败标 `failed` 且**不写库**（保证「修复失败不留痕」）
- 无法确定权威值的冲突标记 `skipped`，不强行修复

#### 3.12.5 专家论证预检（危大工程）
检查 10 项论证必要项：工程概况、编制依据、施工计划、施工工艺技术、安全保证措施、人员分工、验收要求、应急处置措施、计算书及相关图纸、监测方案。
输出齐备项 / 缺失项 / 补充建议 / 论证就绪度评分。

#### 3.12.6 审核工作流（`review.py`）
```text
pending → reviewing → approved / rejected
```
- 章节级 `review_status` 落地（此前是死字段），支持批量提交、按章节记录意见
- 方案级汇总（`/summary`）、检查清单（`/checklist`）、审核记录（`/records`）

### 3.14 安全与凭据模块

#### 3.14.1 API 鉴权（`ApiAuthMiddleware`）
- `API_AUTH_TOKEN` 为空 → 完全放行（本地单机默认）
- 非空 → 除豁免路径（`/api/v1/health`、`/docs`、`/redoc`、`/openapi.json`）外，所有请求必须携带 `X-API-Key: <token>` 或 `Authorization: Bearer <token>`，否则 401
- 常数时间比较（`secrets.compare_digest`，bytes 形态，规避非 ASCII 输入导致的 TypeError/500）
- 预检 `OPTIONS` 直接放行（由外层 CORS 处理）
- **中间件顺序：CORS 必须最外层**（实际执行 CORS → RequestLog → ApiAuth → 路由），写反则跨域调用整体 401

#### 3.14.2 前端凭据页（`/settings/security`）
- 写入 `localStorage.api_token`（键名与 `api/index.ts` 的 `getApiToken()` **逐字符一致**）
- 取值优先级：`VITE_API_TOKEN`（构建期）优先于 `localStorage`；构建期写死时页面显式告警
- 启动时输出鉴权状态日志，避免「以为开了鉴权其实没开」

#### 3.14.3 其他安全要求
- API Key AES-256 加密存储（`crypto.py`）
- SQL 参数化防注入
- 文件上传类型/大小限制 + 文件头校验 + 压缩比/解压量闸门
- 前端 Markdown 渲染走 DOMPurify 消毒

### 3.15 任务、缓存与稳定性模块

#### 3.15.1 Task Registry
- 任务状态持久化到 SQLite（`task_registry`），支持多客户端订阅、断线重连
- 暂停/恢复/停止：`pause_event` / `stop_event` / `cancel_tasks` 统一取消并发子任务
- 进程重启后断点恢复；**启动恢复**：`progress ≥ 0.95` 的遗留任务判定已完成，其余标记失败（避免僵尸任务永久停在 running）
- 「提取项目」中断遗留的解析项一并清理

#### 3.15.2 SSE 超时
- `SSE_TOTAL_TIMEOUT_DEFAULT = 1800s`
- 动态公式基于并发数与章节数分摊；硬上限 `14400s`
- 单请求超时 `900s`

#### 3.15.3 自适应并发
- `AdaptiveConcurrencyController`：`FAST_THRESHOLD = 8s`、`SLOW_THRESHOLD = 30s`、`WINDOW_SIZE = 20`
- 连续 429 ≥ 2 次触发限流降速保护
- 全局硬上限 5

#### 3.15.4 熔断保护
连续失败 ≥ 2 次触发，冷却 5 秒，自动探测恢复。

```text
上传文件 → 文件解析（file_parser，含 OCR / MinerU 兜底）
→ 提取项目（18 项结构化维度，并发）
→ 全局事实提取（分段 → 去重 → 交叉校验 → 人工裁决）
→ 目录生成（优先消费结构化成果 + 项目关键事实 + 知识库 + 编制要求）
```

### 7.3 上传目录识别
```text
上传文件 → 解析格式 → 提取标题层级 → 生成树形 JSON（含 confidence）
→ 导入目录整理（补编写要点 / 对齐危大法定章节 / 统一粒度）
→ 人工校正 → 层级校验 → 保存为方案目录或入库
```

### 7.4 正文与图表同步生成
```text
逐叶子节点生成正文（AI 在行文位置内嵌 ```mermaid / ```chart-json）
→ _chart_pipeline 提取 → 校验/修复 → 登记 chart_predictions
→ 落库清洗（content_polish）→ 字数检查（续写 / 压缩）
→ 导出时由 PIL v2 渲染为图片嵌入
```

### 7.5 一致性修复闭环
```text
扫描（程序预扫 + AI 分片）→ 仲裁（全局事实优先 + AI 批量）→ 定级
→ 定向修复（最小必要修改）→ 二次校验 → 保存快照 → 用户确认/拒绝 → 一键回滚
```

### 7.6 弱模型稳定 JSON
```text
模型生成 → JSON 解析 → Schema 校验 → 业务校验
→ 定向修复 → 有界重试 → 分步生成 → 程序编号 → 审核 → 返回
```
