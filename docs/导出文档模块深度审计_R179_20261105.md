## 0. 结论摘要

1. **报告的归因（“PDF/Word/HTML/Markdown 多次转换”）只是表象。** 逐段追查后，痕迹的真实写入者有三类：① 上传解析把 PDF 分页标记/页脚/HTML 表格压平文本写进内容模型；② 生成侧直接输出 LaTeX、HTML 实体、Markdown 管道符与手工编号；③ 渲染旁路（封面、事实附录、题注、表格单元格）绕过内容解析器，把残留直接写进成稿。
2. **既有清理确实存在，但“没生效”的原因不是没写，而是接错了位置**：`content_sanitize` 只挂在解析入口，渲染旁路不经过它；`_docx_final_lint` 旧实现只遍历 `doc.paragraphs`（不含表格单元格与页眉页脚），且**命中后只记日志、原样出稿**。
3. 本轮在**三个位置**收口：渲染层统一文本出口（`_add_runs_with_inline_format`）、渲染前结构重排（`_normalize_render_blocks`）、落盘前出口闸门（`_docx_final_lint` 两轮规范化 + 第三遍只读残留计数 → `X-Export-Degraded: content-residue` + 降级不写缓存）。
4. **不做“检测到就放过”**：无法自动消除的残留计入 `lint_residual_total`，走既有可见性机制（`X-Export-Degraded` + `X-Fix-Stats` 明细 + `X-Cache-Status: degraded`），且**不写导出缓存**，避免“残缺态被固化”。
5. 基线 **819 passed / 86.71s**（41 文件）→ 本轮后 **864 passed / 89.39s**（42 文件，新增 45 例），`ruff check` 三处改动文件全绿。
6. 明确**不能机器判定**的 5 项（「一」形破折号、列表语义跳级、目录页码域惰性、缺失流程图、无分隔符的单元格粘连）已列入遗留清单，未做假修复。

## 3. 现状分析：16 类缺陷逐条三问

> 每条的三个答案固定为：**① 谁写进内容** / **② 现有清理为什么没生效** / **③ 修在哪一段**。
> 报告的“多次转换”说法只在第 5、7、8 类部分成立（HTML→MD 二次转换确实会造成双重实体），其余均为本系统链路内的写入或漏检。

### 3.1 `===== Page N =====` 与「第X页共Y页」页脚残留
- ① 上传解析（PDF 文本抽取）把分页标记与页脚当正文行写进 `sections.content`；生成侧复制旧文时也会带入。
- ② `content_sanitize._RE_PAGE_MARK_LINE` / `_RE_FOOTER_PAGE_LINE`（见 `content_sanitize.py:49-50`）只匹配**整行**，且只作用在 `_parse_content_blocks`；封面/事实附录/题注/表格单元格不经解析器 → 漏；`_docx_final_lint` 旧版只扫 `doc.paragraphs`，表格内与页眉页脚全盲。
- ③ 入口（已有，保留）+ **出口闸门扩展**：`_docx_final_lint` 的 `_RE_PAGE_RESIDUE` 现在对 run 级任意位置（含全角空格）删除，配合 `_iter_doc_paragraphs` 覆盖表格单元格与页眉页脚。

### 3.2 目录页码与正文不一致
- ① 目录是 Word TOC **域**，页码由打开时计算；旧产物目录域未更新，人工目录与正文混排。
- ② 本系统已插入 TOC 域（`_add_toc_field` export.py:1481）并在 `settings.xml` 声明 `<w:updateFields w:val="true"/>`（`_set_update_fields` export.py:2112），Word 打开即刷新；但**域是惰性的**——WPS/第三方阅读器不保证刷新，且无法在服务器端预计算真实页码。
- ③ 渲染层保持域 + `updateFields`；**不**做“渲染死页码”（会引入新的不一致）。“目录层级与正文标题不匹配”的真实成因是标题重复/编号混用，由 §3.3、§3.15 处理。→ 遗留项（需打开后 F9/更新域）。

### 3.3 标题层级混乱与 `##/###` 残留
- ① 生成侧输出 Markdown 井号；多版本合并后同级标题样式不统一；手工编号与程序编号叠加。
- ② 解析层本应把 `#` 转 `heading` 块，但**遗留成段落的 `##`** 只由旧 lint 的 `_RE_MD_HASH`（行首、run 级、仅删一次）处理，且只扫正文顶层；跨章错号（“4.3 出现在第 3 章”）无任何校验。
- ③ 渲染层：标题统一 `doc.add_paragraph(style="Heading N")`（export.py:3128、3390），**不会把 `#` 原样输出**；出口闸门兜住段落化残留（`lint_md_residue` / `lint_residual_md`）。跨章错号属“语义编号”，列入遗留（程序按所在章重编，不猜测作者意图）。

### 3.4 列表 `a、a、` 重复与跳级
- ① 复制粘贴保留源前缀；生成侧把源前缀又写一遍。
- ② `content_blocks.strip_subitem_ordinal_prefix` **只剥一次**（`count=1`）→ 第一个前缀剥掉后第二个仍留着；且该函数属【正文生成】边界，本轮不动。
- ③ **渲染前结构收口**：`_normalize_render_blocks` 的 ⓪ 分支**循环剥离**字母序前缀（export.py:2777-2786），渲染层本就会重新分配编号 → 输出只剩一套。跳级（“1./2./1.”）由既有分层有序计数器（export.py:3195 起的 `ordered_stack`）重排为连续编号；语义层面的“层级错判”不可机器判定 → 遗留。

### 3.5 `<table>` / `colspan` 残留与单元格粘连
- ① 上传解析把 HTML 表格（含 `colspan`）压成连续文本；`content_blocks` 只能把**结构完整**的 `<table>` 转 GFM，合并单元格信息在解析时已丢失。
- ② `_export_issue_scan` 的 `html_tag` 规则只是**体检**（error 级提示），不阻断、不改写；旧 lint 只删标签不重建表格，且不扫表格单元格。
- ③ 渲染前：连续纯管道行/「表题|表头|…」段落 → **原生表格**（`_make_table_block`，export.py:2740）；出口闸门删除残余标签并计数。**无分隔符的“一整行数据”不可逆**（缺列边界）→ 遗留，靠 `X-Export-Degraded` 让用户看见。

### 3.6 表格跨页断裂 / 表头不重复
- ① 旧产物表格未设 `w:tblHeader`；PDF 转换把跨页表拆成两个块。
- ② 本系统**已实现**：`_add_table_from_markup` 的 `_mark_header_row_repeat`（`w:tblHeader`，_export_docx_parts.py:715-716）；表题 `keep_with_next=True`（:529）。旧产物不是当前渲染器产出（或早于该修复）。
- ③ 无需新改；回归测试锁定 `tblHeader` 存在（E2E 断言）。

### 3.7 LaTeX `\(...\)` 与 `\mathrm/\leq/\Omega/\Phi`
- ① 生成侧直接吐 LaTeX 源码；上传解析把 `\(...\)` 原样带进正文。
- ② `docx_math.iter_formulas` 会把 `\(...\)`/`$...$` 转 OMML，但**转换失败时回退为原文**（`_add_omml_formula` 的兜底），且非公式跨度的零散命令（`\(\leq\)`）在纯文本段里没有任何清理。
- ③ 渲染层：`_latex_to_plain`（_export_docx_parts.py:230）把 `\mathrm{m}^2`→`m²`、`^{\circ}C`→`℃`、`\%`→`%`、`\leq`→`≤`、`\Omega`→`Ω`、`\Phi`→`Φ`、`\frac`/`\sqrt`/上标等确定形态转普通符号；公式跨度内**原样保留**交给 OMML（`_normalize_delivery_text(residual=False)`）。出口闸门用 `residual=True` 剥离分隔符再还原，仍命中未知命令 → `lint_residual_latex` 计数并降级（**不静默**）。

### 3.8 HTML 实体双重转义 `&amp;gt;`
- ① “HTML→Markdown→docx”链路每多一层就多一个 `amp;`（`&gt;`→`&amp;gt;`→`&amp;amp;gt;`）。
- ② `docx_math.clean_text` 只解**两轮**实体；旧 lint 无实体规则 → 三重形态必残留。
- ③ 渲染层：`_normalize_plain_segment` 逐层解码**最多 3 轮**（`_export_docx_parts.py:250 起`）；闸门 `_RE_ENTITY = &(?:amp;)*(?:gt|lt|amp|nbsp);` 兜住任意 `amp;` 前缀层数，解不掉的计入 `lint_residual_entity`。

### 3.9 Markdown 管道符表格残留
- ① 生成侧输出 GFM 表格，但**首字符不是 `|`**（前面粘了表题）→ 解析层不认表格，整行当段落。
- ② 解析层只认 `|` 开头或标准表块；`content_sanitize` 只拆「表X-Y 表名|…」一种前缀形态；其余（如带空格的表题、跨行表题）漏。
- ③ 渲染前：`_normalize_render_blocks` ③④ 两个分支把纯管道行合并为 `table` 块、把「表题前缀 | 表头 | …」并入后随表格或单独成表（export.py:2810-2863）；闸门对残余管道文本计 `lint_residual_pipe`。

### 3.10 表号/图号重复（表4-1 出现三次）与图注格式
- ① 源文手工编号（复制未改）；同一“章号”被多个一级章节复用。
- ② 本系统**已按章编号**：`table_num = f"{chapter_num}-{计数器}"`（export.py:3210-3214），`_strip_leading_table_number`（:540）剥离源文自带编号；闸门此前无重复检测。
- ③ 渲染层保持按章唯一；闸门新增 `lint_duplicate_table_no`：只统计**居中且以“表”开头**的表题段（避免「见表 4-1」正文引用误判，export.py:1984-1995）。图注由 `_insert_image_with_caption` 统一生成、失败走 `_write_chart_placeholder_line` 且**不占图号**。

### 3.11 标点/破折号/单位空格/标准编号
- ① OCR 与多来源复制：`—`→`一`/`-`；`GB50303- 2015` 空格不一；`30 mA` / `0.5m` 混用；中英括号混用。
- ② 此前无任何统一规则（只有错词表）。
- ③ 渲染层 `_normalize_plain_segment` 顺序固定的确定性规则：标准号 → `GB 50303-2015`（`_RE_STD_NO`）、中文语境半角括号 → 全角（`_RE_PAREN_CJK_CONTENT` / `_RE_PAREN_AFTER_CJK` / `_RE_PAREN_STD`）、**两个中文之间**的 `-`/`–` → `—`（`_RE_CJK_DASH`，`GB 50303-2015` 与 `1-2` 不动）、数字与单位去空格（`_RE_UNIT_GAP`，只收多字符/无歧义单位）、比较符与波浪号两侧去空格。**「一」形破折号不自动替换**（无法与“统一/一致”区分）→ 遗留。

### 3.12 错别字与未翻译词（峻工/devices/fabrication/ventilation/spots/矩矩/0.5MQ/1.5% 0）
- ① OCR 误识 + 模型中英混排。
- ② `content_sanitize._TYPO_RULES` 覆盖 峻工、矩矩、MQ、`% 0`、`°C`（content_sanitize.py:64-77），但**不做英文词替换**（原设计担心误伤术语）；且只作用于解析入口。
- ③ 渲染层新增高置信规则：`_RE_MQ`（数字后 `MQ`→`MΩ`）、`_RE_PERMILLE`（`1.5% 0`→`1.5‰`）、`力矩矩/峻工`、`_RE_EN_TERMS` **仅替换紧邻中文的独立英文词**（devices/fabrication/ventilation/spots/materials/equipment），URL/代码/品牌不误伤。

### 3.13 标准编号格式不统一
- ① 手工复制标准清单，空格/连字符/大小写不一。
- ② 无规则。
- ③ `_RE_STD_NO` 统一为「前缀 编号-年份」（`GB/T` 斜杠去空格并大写），斜杠/全角连字符一律规范；配合括号全角化。

### 3.14 标题与正文粘连
- ① 生成侧把标题与正文写进同一行；解析层按真实换行切行 → 整行成为 `list_item`/`paragraph`。
- ② 解析层无“重复前缀”检测；旧 lint 无此规则。
- ③ 渲染前：`_RE_ADHERED_TITLE`（重复 2~14 字前缀）把 `1）国家法律国家法律是…` 拆为 `list_item` + `paragraph`；标题含句号且其后 ≥8 字 → 句号前降为标题、其后降为正文（export.py:2787-2805）。

### 3.15 正文与标题重复
- ① 多版本合并、复制大纲未删重复。
- ② 既有 `_strip_duplicate_leading_title` 只剥**开头连续**重复。
- ③ `write_section` 新增“任意位置与章节标题同文本的内容子标题一律剔除”（export.py:3143-3155）；重复**正文段落**语义级合并仍属人工（遗留）。

### 3.16 总页数与完整性
- ① 旧产物页脚是**字面文本**“第X页共259页”，且正文被截断。
- ② 本系统页脚用 `PAGE` / `NUMPAGES` **域**（`_add_page_field` export.py:1472、`_add_numpages_field` :1477），不存在字面总页数；截断由生成侧 max_tokens/围栏未闭合导致，`audit_content` 的 `unclosed_fence` 与 `auto_fix_unclosed_fences` 已覆盖（见 `_export_issue_scan.py`）。
- ③ 无需新改；残留的字面页码由闸门 `_RE_PAGE_RESIDUE` 删除并计数。

## 10. 遗留问题与后续建议

1. **人工打开核对**：本机无 WPS/Office 自动化，交付前需人工打开一份真实成稿确认域刷新与版式（Word：打开即刷；WPS：必要时 F9）。
2. **「一」形破折号**（“施工工艺一给水”）：与“统一/一致/一般”无法机器区分，**故意不替换**。建议在提示词侧约束（属【正文生成】），或在编辑器加“疑似破折号”高亮提示。
3. **列表跳级/错层**（“1. 工艺流程 / 2. 操作要点 / 1. 质量控制”）：程序会重排为连续编号，但是否应为独立层级需语义判断 → 人工。
4. **无分隔符的整行单元格粘连**与 **HTML `colspan` 合并**：解析期信息已丢失，不可逆；现以可见降级提示，建议上游上传解析侧保留结构化表格（后续工作项）。
5. **`_export_issue_scan.py` 审计规则**：本轮因并发写盘未改（page_residue / double_entity 两条规则取消）。出口闸门已覆盖同等判定；建议该文件属主后续补规则并同步 `audit_rules_fingerprint`（新增字段必须纳入指纹，否则旧旁车误命中）。
6. **静态交叉引用**（“见图 4-1”）：目前是纯文本，图号重排后不联动。建议后续用书签 + `REF` 域改造。
7. **重复正文段落**：同义段落合并属语义级，建议在审核环节提示（`audit_content` 可扩展相似度规则）。
8. **生成侧约束**：提示词宜显式禁止输出 LaTeX/HTML/`#`/手工编号，从源头减少清洗负担（归【正文生成】会话）。
