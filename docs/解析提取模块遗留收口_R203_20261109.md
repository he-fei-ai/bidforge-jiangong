## 七、教训归档

1. **「教训只在同类一侧落实」会复发**：R191 的「置位必须在全部早退之后」写进了
   parse 侧注释与护栏，upload 侧同构缺陷原样存活两轮——防重入/置位类纪律必须
   两侧（所有同类入口）同时锁，源码锚要对每个入口断言。
2. **Edit 工具大文件多段编辑可能发生跨区错位匹配**（FactsTab 事故）：`oldString`
   在文件中不存在时可能匹配到拼接形态；jsx 结构编辑后必须立即 tsc + git diff
   复核，`/>\s*<Button` 类跨界锚点用完整组件块而非属性片段。
3. **编辑过程可能静默改变整文件行尾**（file_parser.py 5181 行行尾漂移）：字节
   体检护栏常驻参数化是唯一可靠防线——「体检脚本跑一次」不如「体检断言进测试」。
4. **新增规则先查重**：关键词表/规则表类单一事实源，插入新条目前必须全文检索
   同名规则（本轮「招标文件」重复被既有契约护栏抓获——「端点输出与单一事实源
   逐字一致」型护栏的价值再次实证）。
5. **样例断言要先跑一遍被测函数**（「投标报价文件」预期报价清单、实际按既有
   规则正确归招标文件）——护栏样例必须以实证行为为准而非直觉。
6. **antd 组件级 jsdom 测试三件套**：`// @vitest-environment jsdom` 头声明 +
   `window.matchMedia` 桩（R201 教训复现一次）+ 断言「接口体内不含键」时注释
   里的字样不算（用 `key?:` 带类型标注形态断言）。
7. **静态锁须覆盖使用点**（M11 教训第 4 次实证）：FE-3 初版只锁 `uploadNote`
   定义，A/B 设计阶段推演发现摘除两个使用点仍静态通过——补
   `msg.error(notice.text + uploadNote)` 出口断言后才具备可裁决性。
