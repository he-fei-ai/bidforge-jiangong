## R123 · ①-① 解析失败重试/断点恢复

### 现状与缺口（代码依据）
- `app/routers/global_facts_docs.py:1099-1204` `parse_document`：解析在 `async with _doc_parse_guard(doc_id)` 内串行执行。
- 失败路径：`ParseError` → `_mark_parse_failed` + 抛 400（L1128-1134）；其它异常 → 同（L1135-1139）；文本过短 → 同（L1140-1147）。**无任何重试**。
- 硬依赖：`_persist_parse_result`（L1176）失败即抛 503；四层落盘 `_ingest_parsed_doc`（L1181）失败仅告警不阻断。
- 解析是**单函数一次性**完成（read_bytes → parse_file_content_ex → 落库），无阶段拆分、无断点；大文件中断须整份重来。

### 架构设计
1. **分级重试**（仅对"瞬时/可恢复"失败重试，避免对"结构性失败"空转）：
   - 重试适用：`MinerU` 超时/限频、`OCR` 引擎瞬时不可用、`_persist_parse_result` 抛 503（DB 瞬时故障）。
   - 不重试：`ParseError`/`HTTPException 400`（文件结构/格式/加密/空白——结构性，重试无意义）。
   - 策略：指数退避 `backoff = min(base*2**n, cap)`，`max_retries=2`（可配置 `parse_retry_max`），每次重试前重查 `_doc_parse_guard` 防并发。
2. **阶段化断点**（大文件可续跑）：
   - 新增轻量表 `doc_parse_checkpoints(doc_id, stage, status, error, updated_at)`，阶段：`extract`(解析文本) → `persist`(落库) → `layers`(四层) → `stale`(标陈旧)。
   - 每段成功即写 checkpoint；入口先查 checkpoint，已完成阶段跳过，从首个未完成阶段续跑。
   - 全成功清 checkpoint；失败保留最后失败阶段供前端展示"断点位置 + 可续跑"。
3. **接口/路由**：`parse_document` 内部行为变更（新增重试/断点），**对外签名不变**；`/documents/{id}/reparse` 与首次解析同入口，自动获得续跑能力。可选新增 `GET /documents/{id}/parse-checkpoint` 供前端展示断点（加法式端点）。

### 数据模型（DDL，零迁移：新表 + 补列）
```sql
CREATE TABLE IF NOT EXISTS doc_parse_checkpoints (
    doc_id TEXT PRIMARY KEY,
    stage TEXT DEFAULT 'extract',     -- extract|persist|layers|stale
    status TEXT DEFAULT 'pending',     -- pending|done|failed
    error TEXT DEFAULT '',
    retries INTEGER DEFAULT 0,
    updated_at TEXT DEFAULT (datetime('now','localtime'))
);
```
- 迁移：`db.py::_migrate` 幂等 `CREATE TABLE IF NOT EXISTS`（不进 SCHEMA_SQL，遵循 R80 教训）。
- 配置项新增（默认行为不变、向后兼容）：
  - `parse_retry_max: int = 2`
  - `parse_retry_base_ms: int = 300`
  - `parse_retry_cap_ms: int = 3000`

### 回滚策略
- 每阶段写 checkpoint 在独立事务；失败回滚仅该阶段，不影响已落 `parsed_markdown`（既有 `_persist_parse_result` 仍为真依赖）。
- 重试耗尽仍失败 → 走既有 `_mark_parse_failed` 流程，语义与现状一致（零行为变化）。
- 新表为纯辅助，删除即退回"无断点"旧行为，无数据风险。

### 专项回归测试策略（`tests/test_parse_retry_checkpoint.py`）
- `test_retry_transient_db_503_then_success`：mock `_persist_parse_result` 首次 503、二次成功 → 断言最终 ok 且只落库一次（断点去重）。
- `test_no_retry_on_structural_parse_error`：mock `parse_file_content_ex` 抛 `ParseError` → 断言**不重试**、直接 400。
- `test_checkpoint_resume_skips_done_stage`：预置 checkpoint(stage=persist,done) → 续跑跳过 extract、只跑 persist 起 → 断言 extract 未再调用。
- `test_checkpoint_records_failed_stage`：persist 持续失败 → 断言 checkpoint.stage=persist,status=failed,error 非空。
- `test_concurrent_parse_single_guard`：并发 2 请求同 doc → 断言仅 1 次实际解析（守卫不退化）。

## R124 · ①-③ 分块级 OCR 补漏

### 现状与缺口（代码依据）
- `app/services/file_parser.py:1242-1268` OCR 触发：`avg_chars = len(text)/n_pages`；仅当 `avg_chars < threshold OR text_missing` 才 `_pdf_ocr_fallback(content, diag=diag)`（文档级，整 PDF 重渲染 OCR）。
- 后果：**一份 300 页文档若 290 页有文字、10 页中间是扫描图**，`avg_chars` 偏高 → OCR 不触发 → 这 10 页**静默丢失且无告警**（Bug 13）。
- 根因：解析产出是**整篇拼接文本**，无逐页文字量视图；OCR 只能文档级兜底。

### 架构设计
1. **page-aware 解析包装**：`_parse_pdf_fallback` / MuPDF 路径改为返回 `(text, n_pages, page_texts: list[str])`；`page_texts[i]` 为第 i 页纯文本。旧调用点（仅消费 `text,n_pages`）按前两元组兼容，新增第三元为可选（向后兼容）。
2. **逐页扫描判定**：对每页算 `page_chars = len(page_texts[i].strip())`；`is_image_page = page_chars < ocr_min_chars_per_page`（复用 config `ocr_min_chars_per_page=30`）。
3. **按页 OCR 拼接**（替代/补充文档级兜底）：
   - 仅对 `is_image_page` 集合渲染并 OCR（`_pdf_ocr_fallback` 增加 `pages: list[int]` 参数，仅渲指定页，避免整 PDF 重渲染开销）。
   - OCR 文本按页码回填 `page_texts[i]`；最终 `text = "\n".join(page_texts)`。
   - 文档级触发仍保留（整篇无文字时全量 OCR），逐页补漏作为补充通道。
4. **可观测性**：若某页 OCR 仍不可用且为 image-only → `diag.warnings` 记录"第 X/Y/Z 页为纯图片且 OCR 不可用，内容可能缺失"（加法式告警，填补"静默丢失"）。

### 接口/路由变更
- `_parse_pdf_fallback` 返回签名扩展为 3 元组（第三元可选，旧消费点不受影响）。
- `_pdf_ocr_fallback(content, diag, pages=None)` 新增 `pages` 参数（默认 None=全量，兼容现状）。
- 下游 `parse_file_content_ex` 透传 `page_texts` 至 `diag`，供 `parse_document` 落库告警（复用既有 `parser_warnings` 机制）。

### 数据模型
- 无新表/新列（逐页信息仅存于内存 `diag`，必要时随 `parser_warnings` 落 `parse_truncated` 同类字段）。
- 如须前端展示缺失页，可加法式字段 `diag["missing_pages"]: list[int]`（不影响既有契约）。

### 回滚策略
- 逐页 OCR 失败不影响该页原文本（保留空/原值），不阻断整篇解析；与现状"OCR 失败保留已提取文字"语义一致。
- 改动集中在 `file_parser.py` 解析路径；`pages` 参数默认 None 保证旧行为零变化。
- 专项测试全绿方可合入；失败即整文件回退（git revert），不影响 R123/R125。

### 专项回归测试策略（`tests/test_page_level_ocr.py`）
- `test_page_aware_returns_page_texts`：mock PDF 3 页（有/空/有）→ 断言返回 `page_texts` 长度 3 且空页为空串。
- `test_middle_image_page_triggers_per_page_ocr`：构造 5 页其中第 3 页 image-only → 断言 `_pdf_ocr_fallback` 以 `pages=[2]` 被调用、拼接后文本含 OCR 结果。
- `test_doc_level_ocr_still_fires_when_all_image`：全 image → 断言文档级（pages=None）触发。
- `test_ocr_unavailable_image_page_warns`：mock OCR 抛错 → 断言 `diag.warnings` 含"第 3 页纯图片且 OCR 不可用"。
- `test_legacy_callers_ignore_third_tuple`：旧调用点仅 unpack 前两元 → 断言不报错（向后兼容）。

## R125 · ③ 事实库版本化

### 现状与缺口（代码依据）
- `app/schema_sql.py:288-339` `global_facts` 表：**无 version 列**，仅 `updated_at`；每次 `persist_extraction` 走 `DELETE+INSERT`（全量替换），无版本/快照概念。
- 后果：重抽事实无法整体回滚；跨阶段"抽取 v1 vs v2"不可比；误删/误改无恢复点。

### 架构设计
1. **版本列**（零迁移：补列 + 默认值，由 `db.py::_migrate` 幂等 `ALTER TABLE ADD COLUMN`）：
   - `global_facts.version INTEGER DEFAULT 1`
   - `global_facts.version_label TEXT DEFAULT ''`（如 "v20261021-初抽" / "手工修正"）
2. **快照表**（新增，幂等 CREATE）：`global_facts_snapshots(snapshot_id, project_id, scheme_id, version, label, created_at, fact_ids_json)`；快照时把当前 `global_facts`（该 project/scheme）全量行序列化入 `fact_ids_json`（或复制行到 `global_facts_history`）。
3. **提取版本闭环**：`facts_extractor.persist_extraction` 在 `DELETE+INSERT` 前，若 `enable_fact_versioning`（默认 False，向后兼容）则先建快照 + 新 `version = max(version)+1`；旧行为（不建快照、version 恒 1）不变。
4. **回滚接口**（加法式端点）：`POST /api/v1/global-facts/{project_id}/rollback`，body `{snapshot_id}` → 将快照行写回 `global_facts`（同一事务，旧行先归档到 history）。默认关闭，需 `enable_fact_versioning=true` 才生效。

### 数据模型（DDL）
```sql
-- 补列（db.py::_migrate 中 ALTER TABLE，零迁移惯例）
ALTER TABLE global_facts ADD COLUMN version INTEGER DEFAULT 1;
ALTER TABLE global_facts ADD COLUMN version_label TEXT DEFAULT '';

-- 新表（幂等 CREATE TABLE IF NOT EXISTS）
CREATE TABLE IF NOT EXISTS global_facts_snapshots (
    snapshot_id TEXT PRIMARY KEY,
    project_id TEXT DEFAULT '',
    scheme_id TEXT DEFAULT '',
    version INTEGER DEFAULT 1,
    label TEXT DEFAULT '',
    created_at TEXT DEFAULT (datetime('now','localtime')),
    fact_rows_json TEXT DEFAULT ''   -- 快照时全量行 JSON
);
CREATE TABLE IF NOT EXISTS global_facts_history (
    id TEXT PRIMARY KEY,
    global_fact_id TEXT DEFAULT '',
    version INTEGER DEFAULT 1,
    op TEXT DEFAULT 'archive',       -- archive|restore
    fact_rows_json TEXT DEFAULT '',
    created_at TEXT DEFAULT (datetime('now','localtime'))
);
CREATE INDEX IF NOT EXISTS idx_gf_snap_proj ON global_facts_snapshots(project_id);
```

### 接口/路由变更（加法式，默认关闭）
- `facts_extractor.persist_extraction(..., versioning: bool = False)`：默认 False → 现状行为；True → 建快照 + 递增 version。
- 新增端点 `POST /global-facts/{project_id}/rollback`、`GET /global-facts/{project_id}/snapshots`（列出可回滚点）。
- 配置项新增（默认关闭，向后兼容）：
  - `enable_fact_versioning: bool = False`

### 回滚策略
- 版本化默认关闭：既有抽取/注入/一致性校验**零行为变化**（version 列恒默认 1，读路径忽略）。
- 开启后：每次重抽先快照（独立事务），回滚为该快照的反向写；history 表保留审计。
- 任何版本化路径异常 → 整事务回滚 + 告警，退回"不建快照"行为，不污染主链路。
- DDL 均 `IF NOT EXISTS` + `ALTER ADD COLUMN DEFAULT`，旧库自动兼容（遵循 R80 索引教训：索引在 `_migrate` 补列后创建）。

### 专项回归测试策略（`tests/test_facts_versioning.py`）
- `test_versioning_off_is_noop`：默认 `enable_fact_versioning=False` → 重抽后无快照行、version 恒 1（确保零行为变化）。
- `test_extraction_creates_snapshot_and_increments_version`：开启 → 首次 version=1 有快照；二次抽取 version=2、新快照。
- `test_rollback_restores_previous_version`：抽取 v2 后回滚到 v1 快照 → 断言 global_facts 内容等于 v1、history 留痕。
- `test_rollback_is_atomic_on_failure`：回滚中途注入异常 → 断言 global_facts 未被破坏（事务回滚）。
- `test_migration_adds_version_columns`：空库 init → 断言 `version`/`version_label` 列存在且历史行默认 1。
