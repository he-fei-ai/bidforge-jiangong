# R125 事实库版本化 · 验收报告（2026-10-21）

> 承接 `docs/三项大改造详细方案与排期_R122c_20261021.md`（R125 节）。本文档为 R125 交付与验收记录。
> 方法：加法式、零迁移、零新增配置项（默认关闭）、向后兼容。所有改动有代码依据，测试支撑。

## 一、改动清单（文件 / 函数 / 作用）

### `app/config.py`
- 新增 `enable_fact_versioning: bool = False`（默认关闭，向后兼容）。开启后每次重抽先快照 + 递增 version。

### `app/db.py`（`_migrate`）
- 幂等补列：`ALTER TABLE global_facts ADD COLUMN version INTEGER DEFAULT 1` 与 `version_label TEXT DEFAULT ''`（SQLite 无 IF NOT EXISTS，包 try/except 忽略已存在）。
- 幂等建表：`global_facts_snapshots(snapshot_id PK, project_id, scheme_id, version, label, created_at, fact_rows_json)` 与 `global_facts_history(id PK, global_fact_id, version, op, fact_rows_json, created_at)`，并建 `idx_gf_snap_proj` 索引。
- 纯加法，删除即退回旧行为，无数据风险。

### `app/services/facts_extractor.py`
- 新增常量 `GLOBAL_FACTS_INSERT_COLS_V` / `GLOBAL_FACTS_INSERT_SQL_V`（在既有 27 列后追加 `version`/`version_label`）。
- `persist_extraction(..., versioning: bool = False)`：
  - 默认 `False` → 走原 27 列 INSERT（`GLOBAL_FACTS_INSERT_SQL`），version 列由 DEFAULT 1 填充，**零行为变化**。
  - `versioning=True` 时：重抽前先快照当前作用域事实（`existing`）到 `global_facts_snapshots`、计算新版本号 `max(version)+1`；新插入行带 `version`/`version_label`。
  - **降级策略**：任何版本化路径异常 → `logger.warning` + 退回不建快照、`version` 恒 1，不污染主链路；快照与主链路同事务（主链路失败回滚时快照一并回滚，无孤儿快照）。
- 新增服务层函数：
  - `rollback_facts_to_snapshot(db, snapshot_id, project_id)`：将指定快照写回 `global_facts`（同一事务；先归档当前作用域到 `global_facts_history`），异常整事务回滚 + 上抛；快照不存在/项目不匹配抛 `ValueError`。
  - `list_fact_snapshots(db, project_id)`：列出项目可回滚快照（按时间倒序）。

### `app/routers/sse_handlers.py`
- `persist_extraction(..., versioning=settings.enable_fact_versioning)`：仅在配置开启时触发版本化快照。

### `app/routers/global_facts.py`
- 导入 `rollback_facts_to_snapshot` / `list_fact_snapshots`。
- 新增端点（默认关闭，需 `enable_fact_versioning=true` 才生效，否则 409）：
  - `POST /api/v1/global-facts/{project_id}/rollback`（body `{"snapshot_id": ...}`）。
  - `GET /api/v1/global-facts/{project_id}/snapshots`。

## 二、设计对照（与 R122c 方案一致点）
- ✅ 版本列零迁移补列 + 默认可向后兼容（version 恒 1，读路径忽略），既有抽取/注入/一致性校验零行为变化。
- ✅ 快照在 `DELETE+INSERT` 前捕获「重抽前一状态」；回滚 = 该快照反向写回，history 审计留痕。
- ✅ 任何版本化异常降级 + 整事务回滚，不污染主链路（与 R123 的「解析失败不阻断」同族兜底哲学）。
- ✅ 端点默认 409 关闭，零新增对外行为（不改已有路由契约）。

## 三、测试（专项回归）

  7. `test_endpoints_enabled_roundtrip` —— 开启：建快照→列出→回滚端到端可用。

## 五、范围与边界
- **未做**（方案已声明，保持最小风险）：
  - 未改读路径注入口径（version 列对注入/导出完全透明，旧逻辑零感知）。
  - 回滚范围按 `(project_id, scheme_id)` 作用域整体替换（与 persist 作用域一致），不做单条事实级回滚 UI（属后续增强）。
  - 快照行以 `SELECT *` 全字段存储，回滚时按原列写回，兼容后续补列（列不存在时该快照将失败，属预期——旧快照与当前 schema 不匹配不应静默回滚）。
- **默认关闭**：生产环境不显式开启 `enable_fact_versioning=true` 时，行为与升级前逐字节一致。
