## 2. 修复的 BUG（均有测试/探针依据）

### FIX-1 · `get_trace_tree` 缺 `orphan_spans`（前端已消费）
**改动**：`services/observability.py::get_trace_tree` 追加 `"orphan_spans": detect_orphan_spans(items)`。
**依据**：前端 `LogViewerPage.tsx:136-138` 已读取 `traceView.orphan_spans` 渲染「断链 span」提示，旧后端从不返回 ⇒ 断链提示静默失效。护栏：`test_trace_tree_returns_orphan_spans`（断言 `s_orphan ∈ orphan_spans`）；E2E E3.4。

### FIX-2 · `redact_sensitive` 对字典敏感键下的值不脱敏（**真实安全缺陷**）
**改动**：`utils/observability.py` 新增 `_SENSITIVE_KEY_RE`（pwd/passwd/password/pass/secret/token/api_key/apikey/access_token/refresh_token/authorization/bearer/private_key/client_secret/fernet_key），字典遍历时若键名命中则**整值掩码为 `****`**。
**依据**：旧实现对 dict 只递归值，而「值字符串本身」不带 `key=` 前缀 ⇒ `{"token": "eyJ..."}` / `{"pwd": "s3cret!"}` 明文入日志（用户需求「API Key、密码、token、密钥不入日志」直接违背）。护栏：`test_redact_recursive_dict` / `test_log_event_redacts_secret`。

### FIX-3 · `Span.__exit__` 不恢复根 span 上下文（嵌套失真）
**改动**：`utils/observability.py` `set_context` 新增 `_force` 参数（允许显式置空）；`Span.__enter__` 记录 `_prev_parent`；`Span.__exit__` 用 `_force=True` 恢复 `span_id=parent`、`parent_span_id=_prev_parent`。
**依据**：旧 `set_context` 对空值跳过（`v not in (None,"")`），根 span（parent=""）退出时 `set_context(span_id="", ...)` **什么都不写** ⇒ `span_id` 残留本 span id，后续嵌套上下文失真。护栏：`test_span_records_event` / `test_span_nested_parent`。

### FIX-4 · 前端 `logsApi.cleanup` 方法不匹配
**改动**：`frontend/src/api/index.ts` `cleanup: (keepDays) => api.post("/logs/cleanup", null, { params })`（原为 `api.delete`，后端是 POST ⇒ 前端点击清理恒 404）。
**依据**：后端 `routers/observability.py` `@router.post("/cleanup")`。E2E E5 以真实 POST 验证。

### FIX-5 · cleanup 端点不清结构化日志文件
**改动**：`routers/observability.py::cleanup` 追加调用 `cleanup_expired_logs`（按 ERROR 90/INFO 30/DEBUG 7 的保守最小天数清理磁盘 `structured/*.jsonl`），响应追加 `removed_files` 键（纯加法，既有调用方零影响）。
**依据**：用户需求「日志文件无限增长无轮转无清理」。E2E E5.2。

## 3. 接线：任务生命周期 → `system_logs`（需求二/七）

**改动**：`services/ai/task_registry.py` 新增 `_log_task_event(task_id, event, *, level, status, message, detail)`（fail-soft），在以下节点落 `system_logs`：

| 节点 | 事件 | 字段 |
|---|---|---|
| `register_task`（注册成功） | `task.created` | status=running, task_type/scheme_id/project_id |
| `set_task_status`（控制迁移） | `task.paused` / `task.resumed` / `task.stopping` | from_status/to_status/reason/operator |
| `finish_task`（终态落库成功） | `task.completed` / `task.failed` / `task.stopped` / `task.degraded` | terminal=true, task_type/scheme_id |

**事件字典**（`task.*`）：`task.created` → `task.running` → `task.paused` ⇄ `task.resumed` → `task.stopping` → `task.completed` / `task.failed` / `task.stopped` / `task.degraded`。覆盖用户需求生命周期全集（created/queued/started/running/paused/resumed/stopping/stopped/completed/failed）。

**安全设计**：`_log_task_event` 全部 `try/except` fail-soft；只写 `system_logs`，不动 `task_registry` 主表 / 内存态 / SSE 广播；任何失败仅 WARNING。**零行为变化**（可观测性失败绝不阻断任务）。

**验证**：护栏 `test_task_lifecycle_writes_system_logs`（register→created、finish→completed）、`test_task_control_writes_status_events`（pause→paused 含 from/to/operator）；E2E E2/E6。

## 4. 接线：HTTP 请求根 span → `system_logs`（需求二）

**改动**：`middleware.py` 在 `RequestLogMiddleware` 请求收尾处，对业务 API（`/api/v1/*` 且非 `/logs`、非 `/health`）fire-and-forget 写 `http.request` 根 span（`services/observability.record_http_request`）。响应头仍回写 `X-Trace-Id`。
- **非阻塞**：`asyncio.create_task`（用户需求「日志写入不得阻塞主流程」）。
- **测试守卫**：新增 `_should_skip_obs_db_write()`（pytest/TestClient 上下文跳过，与 `main.py::_should_skip_file_log` 同口径，避免测试流量污染生产 `system_logs`；逃生开关 `ALLOW_SYSTEM_LOG_IN_TESTCLIENT=1`）。
- **调用树根**：`http.request` 的 `trace_id` 与后续业务 span 同源（contextvars 透传），`get_trace_tree` 按 trace_id 即可还原「请求 → 任务 → 子调用」全链路。

**验证**：护栏 `test_record_http_request_root_span`、`test_middleware_skip_guard_in_test_context`；E2E E1（响应头 X-Trace-Id + `system_logs` 写入 `http.request` 且 `request_id=trace_id`）。

**R142-B 追加 · 未处理异常统一落入 system_logs**：`RequestLogMiddleware.__call__` 的 `except Exception` 路径在 `logger.exception` 之后，对业务 API（`/api/v1/*` 且非 `/logs`）fire-and-forget 写 `event="error"`、`error_code="GEN_500"`、`error_layer="api"`、`retryable=False`、`trace_id=trace_id`、`detail={"exc_type","exc","traceback"}`（traceback 截 2000 字）。仍 `raise`（响应行为零变化）。**⚠️ 实现陷阱**：延迟任务引用 `except` 块异常变量 `_exc` 会抛 `UnboundLocalError`（CPython 在 except 块结束时清除异常变量）——须先把 `_exc_type/_exc_str/_tb_str` 捕获为纯值再传入任务（探针 `_probe_err_r142.py` 实证：直接引用 `_exc` 时任务 fail-soft、无行写入；改纯值捕获后 `GEN_500` + trace_id 正常落库）。护栏 `test_middleware_error_writes_error_span`。

### 4.5 异步批量缓冲器 `SystemLogBuffer`（R142-B · 需求四）

**改动**：`services/observability.py` 新增：
- `bulk_log_events(db, events)`：**单次 executemany + 单次 commit** 批量写 `system_logs`（减少 IO）；`_normalize_event` 与 `log_event` 同口径（contextvars 回填 + 脱敏 + DEBUG 采样），但只归一不落库。
- `SystemLogBuffer`：异步非阻塞队列 + 后台 `_flush_loop` 攒批（`batch_size=50` 或 `flush_interval=1.0s` 到期）→ `bulk_log_events`；队满丢弃最旧并计数（限速防拖垮主流程）；失败降级内存缓冲并 WARNING（fail-soft）。
- 模块级单例 `system_log_buffer`：`main.py` lifespan 启动（init_db 后）/ 停止（close_db 前，把剩余内存事件落盘）。

**验证**：护栏 `test_system_log_buffer_enqueue_flush` / `test_system_log_buffer_drops_on_full` / `test_bulk_log_events_batch_and_redact` / `test_bulk_log_events_empty`。

## 5. AI 调用记录（需求二/七）

**结论（R142-B 更新）**：AI 调用明细由既有 `ai_audit_logs` 表**批量承载**（`provider_factory._log_audit` → `_flush_audit_rows_once`，攒批 50 条落库，字段齐全：`provider_name / model / prompt_tokens / completion_tokens / cached_tokens / duration / success / error / scene / config_id / base_url`）。**同时**（R142-B）AI 调用事件以**非阻塞**方式写入 `system_logs`（`event="ai.call"`），供「按 trace_id 还原调用树」看到 AI 调用节点 —— **两条路径并行、各自独立**：
- **`ai_audit_logs`**：用量统计 / 审计主数据（`/ai/stats`、`/ai/audit-logs`），不变。
- **`system_logs`**：全链路追踪节点（`ai.call`，含 trace_id/task_id/project_id/scheme_id/duration_ms/status/模型/令牌数/错误），经 `SystemLogBuffer` 异步批量写入（见 §4.5）。

**架构理由**：
- 不改 `_log_audit` 缓冲元组宽度（13 列 + legacy 降级切片 `r[:11]`/`r[:10]` 高度敏感）—— 只在其**之后**追加一条 `system_log_buffer.enqueue(...)`（纯加法，零触碰既有元组）。
- `system_logs` 侧写入走 `SystemLogBuffer`（队列 + 攒批 + 单次 executemany + 单次 commit），**不阻塞 AI 调用主流程**（`enqueue` 为非阻塞 `put_nowait`）。
- `ai.call` 事件**显式**携带 `trace_id/task_id/project_id/scheme_id`（flush 时 contextvars 已不在原请求上下文，故入队时快照）。
- fail-soft：缓冲写失败仅 WARNING，绝不中断 AI 调用。

**验证**：护栏 `test_ai_call_event_wired_to_buffer`（`_log_audit` → `system_logs` 出现 `ai.call`，`status="ok"`、`message` 含 provider/model）；回归 `test_audit_overflow`/`test_ai_config_*` **133 passed**（审计路径零回归）。

**已知遗留**：`ai_audit_logs` 无 `task_id` 列，与 `system_logs` 按 `scene`/时间关联（列存在但未填，列为后续项）。

| AI 调用 | 明细（model/tokens/duration/success/error/scene） | ✅ 双通道：`ai_audit_logs` 批量（用量主数据）+ `system_logs` 的 `ai.call`（R142-B 接线，异步缓冲） |
| 解析/提取/目录/正文/图表/审核/导出 | 业务节点 | ⚠️ 日志文本已存在（`logger.info`），结构化事件经 `_obs_extra` 进文件；**DB `system_logs` 事件化**为后续项（需在各路由/服务调用点逐点接入 `log_event`） |
| 工具调用 / DB 写入 / 文件生成 / 缓存命中失效 / 重试降级 | span 事件 | ⚠️ `Span` 基础设施已就绪（`span(name, kind)`），业务点接入为后续项 |

**留痕**：完整的事件化接入（10 模块 × 每类节点）超出本轮「接线关键节点 + 全量验证」的范围，按「只修有代码依据的项」原则**不铺开改造**，避免一次性改动面过大导致回归不可控；基础设施（`Span`/`log_event`/`make_error_code`/`log_error`/`SystemLogBuffer`）已全部就绪，后续按模块逐个接入即可。**AI 调用（最高频且已有审计）已接入**；工具/DB/文件等 span 事件按需逐个接入。
