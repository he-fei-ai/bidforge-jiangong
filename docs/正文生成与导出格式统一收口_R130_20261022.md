## 二、六类标准统一方案（标准对照表 + 唯一事实源）

契约常量集中在 **`backend/app/services/content_format_contract.py`**（R130 新建），
提示词 / 正文自检 / 导出渲染三方一律 import，禁止复制字面量。

### 2.1 标准对照表

| 类别 | 标准（用户要求） | 契约常量/判据 | 生成侧落点 | 导出侧落点 |
|---|---|---|---|---|
| **文字** | 标题黑体、正文宋体/仿宋、西文 Times New Roman；标题不倾斜；禁止内联格式，用命名样式 | `FONT_HEADING_EAST_ASIA="黑体"`、`FONT_BODY_EAST_ASIA="宋体"`、`FONT_LATIN="Times New Roman"`；`_HEADING_BAD_RE`、`_HEADING_INLINE_RE` | 提示词（既有）+ 自检 text 类 | `_DEFAULT_HEADING_STYLES` 改黑体；Normal/Heading `w:ascii/hAnsi=TNR`；`_set_run_font` 中文名只进 eastAsia；`italic=False`（既有） |
| **符号** | 中文全角/英文半角；标准 Markdown 列表；禁控制字符/西里尔/GBK 乱码 | `_MANUAL_LIST_RE`/`_MD_LIST_RE`；`_CONTROL_CHARS_RE`/`_CYRILLIC_RE`/`_MOJIBAKE_TOKENS` | 自检 symbol 类（advisory/error） | 导出前体检并入（§6.2） |

| **图表** | ```mermaid 类型白名单；标题 `图{章号}-{序号} {图名}`；渲染失败跳过不占号；≥150dpi；配色稳重 | `MERMAID_SOURCE_TYPES=("flowchart","graph","sequenceDiagram","gantt","timeline")`、`CHART_FENCE_LANGS`、`FIG_TITLE_RE`、`MIN_IMAGE_DPI=150` | 自检 chart 类；`_chart_pipeline` 白名单（既有） | 图名提取优先级（v11/v16 既有）；dpi 告警（§4.3）；基础设施回退（§4.2） |

### 2.2 六类标准的检查分类（`CONTRACT_CATEGORIES`）

```python
CONTRACT_CATEGORIES = ("text", "symbol", "formula", "chart", "table", "number", "numbering")
```

severity 三档：`error`（不修必然出错）/ `warning`（大概率降级）/ `advisory`（风格建议）。
每类每章最多上报 5 条（`_MAX_ISSUES_PER_CATEGORY`，报告体积控制）。

## 三、结合 DOCX 修正正文（七项 + 第一层自检）

| # | 修正项 | 正文输出格式 | 导出映射 | R130 状态 |
|---|---|---|---|---|
| 1 | 标题层级 | `#`~`######`（`#` 后必须空格） | Heading 1-9 + outlineLvl（L7-L9 显式） | 自检拦截 `#缺空格`（error）与标题内联格式（warning） |
| 2 | 列表 | 标准 Markdown `-`/`1.`，禁手工「1、」「（一）」 | numbering.xml（`w:numPr`） | 自检 advisory 上报手工序号 |
| 3 | 表格 | GFM：表头行+分隔行+数据列数一致 | tblHeader/cantSplit/gridSpan/vMerge | 自检 error（缺分隔行/列数错位），见 §7 BUG-1 |
| 4 | 图表源码 | ```mermaid / ```chart-json 围栏 | 类型白名单校验→渲染→图号 | 自检：未闭合 error、类型白名单 warning、JSON 非对象 error |
| 5 | 图片 | 行内嵌入（`![alt](url)`/ai_image 围栏） | `_insert_image_with_caption` 单一实现 | dpi≥150 告警（§4.3） |
| 6 | 公式 | `$行内$` / `$$块级$$` LaTeX | OMML→PNG→跳过三级降级 | 自检：`$` 奇数不成对 error |
| 7 | 格式自检 | 正文生成后跑 `check_format_contract` | 写入 `report["format_contract"]` | **第一层校验已接线**（§6.1） |

**设计红线遵守**：自检**只上报不阻断不改正文**（对齐 `content_standard` 既有纪律），
fail-soft —— 自检器任何异常降级为空报告，绝不影响正文落库。

## 四、图表商业级增强

### 4.1 生成机制（四阶段）

编排（`_chart_pipeline` 定类型/数据/位置/优先级）→ 生成源码或载荷
（```mermaid / ```chart-json）→ 校验（类型白名单 + JSON 校验器 + 契约自检）→
按需渲染（HTTP Service → PIL v2）失败降级跳过不占号。
图号 `图{章号}-{序号} {图名}`，图名提取优先级 **载荷 title > Mermaid title >
引导语 > 类型通用名**（`export.py:2224` 附近，v11/v16 已实现，本轮沿用）。

### 4.2 【TOP1 根因修复】基础设施回退分流（`mermaid_renderer.py`）

旧逻辑：HTTP 失败 + `allow_pil=False` → 一律 `return None`。
新逻辑：新增 `_http_infra_fail` / `_http_content_fail` 双标志：

| 失败原因 | 判据 | allow_pil=False 行为 |
|---|---|---|
| 服务不可用/连接失败/超时/5xx/空响应 | `_http_infra_fail=True`（含 `MermaidRenderError status_code=0`「无可用后端」、普通网络异常） | **回退 PIL v2 出图**（`基础设施回退` WARNING） |
| 代码语法错（HTTP 4xx） | `_http_content_fail=True` | 维持不降级 `return None`（写占位提示，不掩盖语法错） |
| 未尝试 HTTP（`skip_http=True`） | 双标志均 False | 维持不降级 `return None`（尊重调用方显式跳过） |

不改 `allow_pil` 开关语义（配置默认值与兼容性保持），只新增「基础设施不可用」
这一逃生通道 —— 降级出图优于整篇缺图，且 PIL v2 本身即 2.5x 超采样 + 300 DPI
商业级渲染器。

### 4.3 质量要求 · 分辨率≥150dpi

`export.py::_insert_image_with_caption`（DOCX 位图插入**唯一实现**）在确定入稿
尺寸后反算有效 dpi：`有效dpi = 像素 / (入稿cm / 2.54)`，低于 `MIN_IMAGE_DPI=150`
打 WARNING（fail-soft 只告警不阻断）。标题图例坐标轴完整、配色稳重、中文无乱码、
尺寸适配页面由 PIL v2 各渲染器（既有）与 16cm/22cm 双上限（既有）保证。

## 六、三端格式统一（格式契约 + 三层校验）

### 6.1 格式契约模块（唯一事实源）

**`backend/app/services/content_format_contract.py`**（R130 新建，纯函数、零 DB、
零 AI、零 IO，异常降级为空报告）：

```python
# 数据结构
check_format_contract(content, *, section_id="", section_title="") -> dict
# 返回：
# {"checked": bool, "passed": bool,                 # passed = 无 error
#  "error_count": int, "warning_count": int, "advisory_count": int,
#  "issues": [{"category": "text|symbol|formula|chart|table|number|numbering",
#              "severity": "error|warning|advisory",
#              "message": str, "line": 1基行号, "excerpt": str≤80}],
#  "counts": {category: int}, "section_id": str, "section_title": str}

format_contract_summary(report) -> str   # 一行日志文案（无问题空串）
```

**三方契约映射（三端格式契约说明）**：

| 契约维度 | 正文生成端 | 图表端 | DOCX 导出端 |
|---|---|---|---|
| 标题语法 ↔ 图表代码块 ↔ Heading 映射 | `#`~`######` + 空格 | 围栏独立成行、lang 白名单 | Heading 1-9 + outlineLvl |
| 列表语法 ↔ 数据格式 ↔ numbering.xml | `-`/`1.` 标准语法 | — | `w:numPr(w:ilvl/w:numId)` |
| 表格语法 ↔ 数据结构 ↔ DOCX table | GFM 表头+分隔行+等列数 | — | tblHeader/cantSplit/gridSpan/vMerge |
| 公式语法 ↔ 渲染 ↔ OMML | `$`/`$$` 成对 | — | OMML→PNG→跳过 |
| 图片引用 ↔ 渲染输出 ↔ DOCX 嵌入 | ai_image/`![]()` | 渲染 PNG ≥150dpi | `_insert_image_with_caption` |

### 6.2 三层校验

| 层 | 时机 | 落点 | 行为 |
|---|---|---|---|
| **第一层 正文生成后自检** | 正文收尾、落库前 | `sse_handlers.py`（`paragraph_structure_report` 块之后）：写 `report["format_contract"]`，error 打 WARNING、其余 INFO | 加法式新键，不改 error/warning 计数、不进修复链路、不动正文；fail-soft |
| **第二层 导出前校验** | 导出体检 | `export.py::audit_content`：契约问题并入体检清单（`format_contract_{cat}` 键，error→error/warning→warn/advisory→info）；与既有 `unclosed_fence` 同一事实**去重不二次计数** | 只体检不篡改（含护栏测试） |

    键均为**新增键**，不改既有字段与计数口径（`issues` 问题计数不受影响）；
  - 自检 fail-soft：任何异常只 WARNING，不阻断落库/导出。
- 第二层体检清单新增项会出现在既有 `content_audit`（独立字段，不进 `issues`），
  排序沿用 `error → warn → info`（`order` 表本就支持 info 档）。
