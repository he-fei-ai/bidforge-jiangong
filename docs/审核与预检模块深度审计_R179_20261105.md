## 4. 修复项清单（改了什么 / 为什么 / 如何验证 / 结果）

### R179-1（P0）冲突跨轮状态与主题错配
- **文件/函数**：`backend/app/services/consistency_scanner.py` → 新增 `_conflict_identity()`（L848），改写 `persist_conflicts()`（L881–922）。
- **改了什么**：以「冲突类型 + 主题 + 排序后的章节/取值集合」作为身份签名；upsert 前批量读取同 id 旧行，仅当**同方案且身份一致**时继承旧 `status`，否则重置 `pending`；DO UPDATE 同步刷新 `topic/conflict_type`。
- **为什么**：冲突 id 是按顺序重编的 `C001/C002…`，旧实现只按 id 继承状态，会让本轮另一处新问题直接挂上一轮的「已确认/已跳过」。
- **验证**：`backend/tests/test_review_preflight_r179_20261105.py::TestConflictUpsertIdentity`（3 例）与 `TestConflictIdentityHelper`（2 例）。
- **结果**：5/5 通过；`test_cross_module_chain` 的 upsert 契约断言仍通过（SQL 前缀保持 `scheme_id=excluded.scheme_id`）。

### R179-2（P0/P1）恢复结果三态记账
- **文件/函数**：`backend/app/routers/consistency_repair.py` → `confirm()`（L326–386、L413、L434、L448–454）。
- **改了什么**：
  1. 新增 `restored_sections`（真正写回快照成功的章节）与 `restore_skipped_sections`（快照缺失、仅回写冲突状态的章节）；
  2. `restored_sections` 返回值改为「实际恢复」集合，新增加法字段 `restore_skipped_sections`；
  3. `rescan_required` 改为 `bool(restored_sections)`；
  4. 审核状态重置只作用于**实际恢复**的章节。
- **为什么**：旧实现把请求拒绝的章节全部当已恢复，快照丢失时正文没动却提示已恢复，且凭空重置审核状态。
- **验证**：同文件 `TestConfirmRestoreAccounting`（3 例，覆盖快照缺失/正常恢复/仅接受不恢复）。
- **结果**：3/3 通过；`test_consistency_repair_wiring.py` 原有 `restored_sections == [SEC]` 断言（快照存在场景）不回归。

### R179-3（P1）前端确认结果以后端为准
- **文件/函数**：`frontend/src/pages/schemeWorkbench/useReviewAudit.tsx` → 新增 `ConsistencyConfirmResult`（L14–25），重写 `handleCrConfirm`（L517–541）。
- **改了什么**：成功文案按后端 `accepted/rejected` 回显计数；快照缺失时追加 warning「N 章因修复快照缺失未回滚正文…」；仅在真的有正文回滚时提示「恢复原文」，`rescan_required` 单独提示；任何受理决策后递增 `reviewTick` 触发总检重算。
- **为什么**：旧文案使用请求条数（E13），且忽略 `restored_sections/rescan_required`（E4 前端半环）。
- **验证**：`frontend/src/tests/crRepairCancelR168.test.tsx` 新增 E 组 3 例（E1 快照缺失不得称恢复、E2 真恢复需失效审核、E3 部分受理按后端计数）。
- **结果**：3/3 通过，全文件 47/47（连带 `ReadinessDashboard.test.tsx`）。

### R179-4（P1）审核动作触发总检重算
- **文件/函数**：`frontend/src/pages/schemeWorkbench/tabs/ReviewTab.tsx` → `ReviewWorkflowPanel.onChanged`（L934–939）。
- **改了什么**：`load()` 之外同时 `setReviewTick(v => v + 1)`。
- **为什么**：旧实现只刷新章节清单，`ReadinessDashboard` 的 `refreshKey=reviewTick` 不变，总检停留在旧结论（E8）。
- **验证**：tsc 通过；`ReadinessDashboard` 既有 `refreshKey` 单测不回归。

### R179-5（P1）问题行章节展示与定位跳转
- **文件/函数**：`frontend/src/components/review/ReadinessDashboard.tsx` → 新增可选 `onLocateSection`（L101–104）、findings「章节」列（L759–786）；`ReviewTab.tsx` 接线 `onLocateSection={handlePlaceholderJump}`（L169）。
- **改了什么**：章节列优先显示 `section_title`；有 `section_id` 且有回调时渲染为链接，点击跳到正文生成并选中章节；无 `section_id` 显示「跨章节」，不提供无效跳转。
- **为什么**：后端早已返回 `section_id/section_title`，前端只展示说明文字，用户无法从总检直接定位（E12）。
- **验证**：`ReadinessDashboard.test.tsx` 新增 2 例：可点击定位传入 `sec-3`；跨章节不提供跳转入口。
- **结果**：2/2 通过。
