### 1.2 AGPL §13 的含义

AGPL §13 的触发条件是**通过网络向用户提供服务**，不是「分发安装包」。即使只把我们自己的服务部署在服务器上、让客户通过浏览器使用，只要该服务包含 AGPL 程序的代码或衍生表达，就负有向这些远程用户提供**完整对应源码（Corresponding Source）**的义务。对以方案文档生成为核心卖点的商业交付而言，这等于要求公开整套实现，不可接受。

### 1.3 「only」的含义

`AGPL-3.0-only` 表示权利人**没有**授予「或任何后续版本」的选项：不能主张按 AGPL-3.0-or-later 或未来版本条款行事，也不能靠「升级到 or later」来适配更宽松的未来条款。组合作品必须**恰好**以 AGPL-3.0 授权，并保留原作者归属与许可声明（§7(b)）。

## 二、可保留的抽象机制（最多 3 条，均为方法论，不含实施方案）

1. **参数等级作为单一事实源，贯穿多类下游文书。** 对方在技术需求书里用 ★/△ 标记参数等级，并让评审办法的废标条款、合同草案的验收条款复用同一套等级语义。可解决本软件的具体问题：一致性扫描与评分项覆盖目前主要靠自由文本相似度比对，缺少稳定的「同一参数多处落点」判据锚点，容易出现漏配或误配。
2. **模型推断值必须显式打标，并与原文抽取值区分。** 对方在结构化结果里给补全值加「(推断)」后缀。可解决本软件的具体问题：事实/结构化抽取环节中，模型补全值与原文事实混同后，下游注入与审核无法区分来源强度（与本仓 `is_simulated` 语义呼应，但强调「注入时对读者可见」）。
3. **审查产物与修订动作分离：模型只出检查结论，确定性修正交给代码。** 对方把一致性检查从「全文重写」收窄为「关键实体摘要比对 + 代码层确定性修正」。可解决本软件的具体问题：长文一致性检查的输入成本高，且让模型重写全文会引入新的不一致；把判定与执行拆开后，修订可审计、可回滚。

以上三条均只描述「要解决什么问题」，不涉及对方代码结构、字段命名或提示词措辞。
