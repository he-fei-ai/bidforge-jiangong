## 2. 修复项详情

### 2.1 `scale` 事实类型归位（P2）

**缺陷**：`CATEGORY_TITLES` / `_CATEGORY_ORDER` / `CATEGORY_TO_CHAPTER` 早已注册 `scale`（工程规模与地质参数），但 `_FACT_TYPE_TO_CATEGORY` 无 `fact_type="scale"` 映射。弱模型输出 `fact_type="scale"` 时：

1. `_parse_fact_dict` 的 `category = _FACT_TYPE_TO_CATEGORY.get(fact_type, "other")` 静默归到 `other`；
2. `CATEGORY_TO_FACT_TYPE` 反查不到 `scale` 类别；
3. 前端手工录入/编辑下拉可创建 `category=scale`，但提取链无法回推，造成「提取结果丢失分类」。

**修复**（均加法式、零签名变更）：

| 文件 | 位置 | 变更 |
| --- | --- | --- |
| `backend/app/services/facts_extractor.py` | `_FACT_TYPE_TO_CATEGORY` | 新增 `"scale": "scale"`（注释 `R245`） |
| `backend/app/services/facts_classification.py` | `FACT_TYPE_TO_CHAPTER` | 新增 `"scale": "overview"`（九大章节=第一章工程概况） |
| `backend/app/services/ai/prompts/analysis.py` | `facts_json_fix_system` Schema 枚举 | `fact_type` 枚举补 `scale`（置于 `design_param` 后） |

**设计说明（主提取提示词刻意不含 `scale`）**：`facts_extract_system` 主提取提示词枚举表保持 21 类精选列表，**不**加入 `scale`。依据：①既有 `equipment` 先例——该类型在 `_FACT_TYPE_TO_CATEGORY` 有映射但不在主提取枚举，代码注释明确「保留给手工录入选项使用」；②`scale`（工程规模与地质参数）语义与 `basic`（规模）及 `tech_param`（地质参数）重叠，加入会诱导 AI 把事实分流到 `scale`，破坏既有 `basic`/`tech_param` 提取口径。故 `scale` 设计为**手工录入 / 自然语言调整 / 弱模型边角输出**的稳健归位类别，而非主提取枚举。

**防御价值（`facts_json_fix_system` 补 `scale`）**：主提取枚举不引导模型产出 `scale`，但弱模型仍可能输出；若修复 Schema 缺 `scale`，弱修复模型可能按「枚举校验」把 `fact_type="scale"` 改名成 `other`，抵消映射归位。补入后修复路径保留 `scale` 语义。
