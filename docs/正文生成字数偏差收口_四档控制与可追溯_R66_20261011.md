# 正文生成字数偏差收口 · 四档控制 + 300 字下限 + 容差带可追溯（R66 · 2026-10-11）

> 任务来源：用户指令「正文生成文字数量与实际要求的偏差较大 —— 定位根因、修复字数控制机制，确保三级目录字数符合目标要求（含 300 字左右要求与四档控制 800/1200/2000/2500），偏差可控可追溯，无回归」。

## 1. 偏差现象量化（生产库取证）

取证脚本 `artifacts/_r66_db_quantify.py`（只读连接 `backend/data/scheme_assistant.db`，实际字数用**生产同口径** `text_word_count`），输出 `artifacts/_r66_db_quantify.txt`。

**样本**：当前库 43 条 section（10 个 L1 父 + 33 个叶子正文章节），全部 `word_budget = 1500`（旧默认值），方案类型均为「施工组织设计」。

| 指标 | 值 |
|---|---|
| 叶子且有正文 | 33 |
| 目标字数分布 | 全部 1500（四档从未生效） |
| 平均实际/目标比率 | **136.90%** |
| 中位比率 | **140.73%** |
| 落在 ±10% 容差带（0.9X~1.1X） | 3 / 33 = **9.1%** |
| 超上界 | 28 = **84.8%**（其中 >1.3X 有 19 = **57.6%**） |
| 低于下界 | 2 = 6.1%（最低 84.27%） |
| 实际 <300 字 | 0 |
| 极端样例 | 「劳务作业人员管理」2821/1500 = **188%**；「法律法规及规范性文件」2777/1500 = 185% |

**偏差分类判定**：属**系统性偏高**（31/33 超或近上界、无断崖式缺失、非随机对称分布）；章节间累积偏差与必含要素完整率正相关（安全/应急类章节要素最多、超纲最狠，达 160%~188%）。按方案类型 / 章节 / 模型的分桶因当前库仅 1 方案 1 模型（默认路由）而退化为总体统计，口径已写入取证脚本，后续多方案库可直接复用。

## 2. 根因清单（按优先级）

| # | 层 | 根因 | 证据 |
|---|---|---|---|
| P0-1 | 控制机制 | **四档控制（800/1200/2000/2500）根本不存在**：全链路只有单一默认 1500，目录创建 / SSE 请求体 / 前端均无档位概念 | 库内 33 叶子 budget 全 1500；改造前代码 grep 无 tier 常量 |

| P0-3 | 提示词/校验 | **容差带只在提示词里口头承诺（0.9X~1.1X），生成后无任何按带校验**；容差散写为魔法数 | 旧 `_word_budget_hint` 硬编码 0.9/1.1/1.3 |
| P1-4 | 生成机制 | **超标自动压缩 `auto_shrink_over` 默认关** ⇒ 84.8% 超标无人纠正 | 旧默认 `False`；前端 `useState(false)` |

| P1-6 | 可追溯 | **每节目标/实际/偏差无处记录**，审核预检读不到字数达标情况，也无对应规则 | sections 有列但无日志/审计/规则接线 |

## 3. 修复落地（file:symbol）

### 3.1 单一事实源常量与纯函数 — `backend/app/services/content_utils.py`
- `WORD_BUDGET_TIERS = {"brief":800,"standard":1200,"detailed":2000,"ultra":2500}`（:46）、`WORD_BUDGET_DEFAULT_TIER="standard"`（:47）、`LEAF_MIN_WORD_BUDGET=300`（:50）
- `DEFAULT_WORD_BUDGET 1500→1200`（:36，= standard 档）
- `resolve_word_budget_tier(raw)`（:53）：档名/数值双容忍，bool 与非法值→None，不做区间吸附
- `word_deviation_of(wc, wb, *, tolerance=0.1)`（:83）：返回 `{deviation, ratio, within_band}`
- `word_audit_summary(rows, *, tolerance=0.1)`（:109）：聚合 `{total, in_band, under_band, over, under, below_leaf_floor, mean_ratio, median_ratio, max_ratio, items}`；脏行（非数值 budget/count）逐行 try/except 跳过不炸
- 容差**唯一来源** `settings.word_budget_tolerance`（`app/config.py`，默认 0.1，非法回落 0.1）

### 3.2 生成链路 — `backend/app/routers/sse_handlers.py` + `content_runtime.py`
- 请求体解析 `word_budget_tier`（:4252）；`auto_shrink_over` 缺省改为「给了 tier 或 override 即默认开」（:4276-4278）
- 档位分支（:4578-4591）：每叶子 `max(档值, 300)` 落库 `UPDATE sections.word_budget`（executemany，失败仅 warn）；旧 `word_budget_override` 分配路径同加 300 floor（:4685-4687）
- 提示词 `_word_budget_hint`（:596-624）：容差带文案由 `settings.word_budget_tolerance` 实时计算，默认 0.1 时与旧硬编码**逐字节一致**（护栏参数化锁 7 个 budget 值）
- **校验与重生成**：生成后逐节结构化日志 `字数校验|节=…|目标=…|实际=…|偏差=…|偏差率=…|判定=…`（:5951-5970）；`section_done` 事件附 `word_deviation/word_ratio/word_within_band`（:6251-6262）
- 续写：`should_continue_round(..., min_floor_chars)` 触发线 = `max(budget×0.8, floor)`；调用点 floor 做钳制 `min(LEAF_MIN_WORD_BUDGET, word_budget)`（:5843-5853），杜绝「预算<300 时触发线反超 1.1X 上限」的死循环；`build_continuation_messages(..., total_cap_factor=1.0+tol)`（:5890）把续写总上限钉到容差带上沿
- 可追溯：checkpoint 载荷与 completed_payload 增 `word_audit` 兄弟键（:4447-4465 / :6888-6891），`_CHECKPOINT_KINDS["content_generation"]` 与 `checkpoint_schema.CHECKPOINT_FIELD_TYPES["content_result"]` 白名单同步，`tools/generate_checkpoint_schema.py` 再生成前端 TS（幂等复核 hash 一致）

### 3.3 审核预检 — `preflight_engine.py` + `audit_rules.py` + `compliance.py` + `review_autofix.py`
- `compliance.py:869` 预检取数 SELECT 补 `word_budget` 列
- **新规则 DLV-16「三级目录字数偏差可控」**（medium / 程序模式）：逐叶子判 ±tol 带 + 300 下限；**33 个偏差章节聚合为恰好 1 条 finding**（满足「审核问题数量不因字数控制而增加」），evidence 上限 10 条，未设预算的节**完全静默**（向后兼容既有 ~25 个测试上下文）
- `audit_rules.py`：DLV-16 注册 + `_PROGRAM_EMITTED_RULE_IDS` + `RULE_VERSION 1.9.0→1.10.0`；`review_autofix.py` 给 DLV-16 配「人工处理」能力卡（扩写/缩写不是改写问题，指引回正文生成页重选档位）

### 3.4 前端 — `ContentGenerationTab.tsx` / `SchemeWorkbenchPage.tsx` / `useContentGeneration.ts` / `workflowDerived.ts`
- 字数选择器 6 项：使用目录默认值 / 简短800 / 标准1200 / 详细2000 / 超长2500 / 自定义；**tier 与 custom 互斥**（选档位发 `word_budget_tier`，选自定义发 `word_budget_override`，二者不共存）
- 三态 Tag：custom→「按二级章节总字数控制」、tier→「按叶子章节档位字数控制」、default→无
- `autoShrinkOver` 默认 `useState(false)→useState(true)`；6 处 1500 兜底 → 1200；`workflowDerived.canShrinkSection` 兜底同改（1200×1.3=1560.0000000000002 与 JS 双精度逐位一致，压缩阈值前后端同判）
- 刻意不改：`WORD_BUDGET_MIN=50` —— 用户显式预算优先于 300 咨询性下限（已设护栏说明该决策）

| 300 字要求未生效 | 已修：分配 floor + 续写触发线 + 提示词 + DLV-16 下限判定 |

| 提示词被截断字数丢失 / 上下文过载挤占 | 核查未复现：字数要求位于任务差异段（末段），上下文组装无截断该段的代码路径 |

| 内容不足/过多导致偏差 | 过多方向已由 shrink 默认开治理；不足方向由续写 floor 治理 |
| 空话套话字数虚高 | 既有 `content_standard.py` 空话检测在位，不虚高计入判定（未重复造口径） |
| 前后一致性校验删减必要内容 | 核查：一致性修复仅局部改写、不整节删除；DLV-16 读取的是生成后终稿 |
| 输出 token 上限限制字数生成 | `max_tokens_for_budget` 在位；默认模型上限 ≥2500 字档不构成约束 |

## 8. 遗留问题与后续建议

1. **存量 1500 行**：不迁移（避免动历史字节契约）；用户重选档位重新生成即被覆盖，DLV-16 在此之前按 1500 如实判定。
2. **模型层遵循度分桶**：待库内出现多模型生成记录后，把 `ai_audit_logs` 模型字段并入 §1 取证脚本即可分桶，无需新代码。
3. **`WORD_BUDGET_MIN=50` < 300**：刻意保留（显式预算赢过咨询下限），若产品侧希望全面钉死 300，改一处常量即可，护栏 D 组已锁定钳制语义。
4. **真实生成复测**：修复后的偏差率需用真实 LLM 跑一轮全量生成后按 §1 脚本复测（mean ratio 预期从 136.9% 收敛到 ≤110%±带宽）；本轮以护栏 + 契约冒烟替代。
5. 同机并行作业期间禁全量单跑 `pytest tests`（SQLite 争用假失败），沿 R65 口径分簇验证。
