## 二、本轮实际落地修复（2 项，均加法式、已测试）

### FIX-1（R122 已交付）· 全局事实 AI 调整超长事实库截断无告警

- 验证：新增 2 例测试；全局事实相关 4 套件 **167 passed / 1 skipped / 0 failed**。

### FIX-2（本轮）· reparse 重解析缺机器可读的要素重提取信号
- **根因**：`doc_pipeline.reparse_document` 复用 `parse_document`，后者在 force / 首次解析时会把项目既有全局事实标 `stale`（`global_facts_docs.py:1195-1204` 已带 `stale_facts`+`note` 文案），但响应**无布尔字段**，前端难以程序化识别"要素需重新提取"，用户易误以为要素已随重解析自动更新。
- **修复**（加法式、零行为变更）：`doc_pipeline.py:reparse_document` 在 `result["stale_facts"]` 存在时加 `result["facts_need_reextract"] = True`。
  - **不自动触发 AI 提取**：那会引入不可控的额外调用与回写风险，违背零回归；仅给信号，由前端提示用户手动触发"AI 提取事实"（与既有 `note` 文案一致）。
  - 旧前端忽略新字段不报错；增量模式跳过时不带该字段。
- **新增配置项**：无（纯响应字段，向后兼容）。
- **验证**：`tests/test_doc_pipeline.py` 新增 `test_reparse_signals_facts_need_reextract_when_stale`（force→`facts_need_reextract=True`；incremental 跳过→不带该字段）；doc_pipeline 全套 **27 passed / 0 failed**（`ruff`/`read_lints` 0 问题）。
