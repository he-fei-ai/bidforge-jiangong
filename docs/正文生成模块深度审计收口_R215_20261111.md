## 十一、教训归档

1. **「注释里的契约」最容易被自己的兜底出卖**——`_segment_blocked` docstring 写着「无法判定不删正文」，实现却 `return bool(offending)`；`rollback_snapshot` 的 resync_fn 契约注释直接写 `-> None`，把「调用方不消费」写成了契约。**写契约注释前先跑一遍行为实证**。
2. **「设计已写、接线缺失」是「注释承诺 ≠ 功能存在」的温和变体**——R204 的预算 helper 带着点名本调用点的 docstring 躺了一年；B1 的 paused_ms 设计在 docstring 里完整存在却从未接线。**新 helper 落地时必须同轮 grep 全部既有点名的调用点**。
3. **消费方丢返回值是「同族漏改」的新形态**——resync 契约「修正后正文由调用方落库」在 5 处正确、3 处漏改，且其中一处的漏改被写进了契约注释。修复时不能只修被报障的那一处，必须 grep 全部消费方。
4. **改判据字面量的修复必须同步重锚源码锁**——本轮 4 处既有护栏红全部因为「锁实现（字面量）而非锁意图」；重锚时一律补「旧形态不得回流」反向断言（强度不减）。
5. **heredoc/python 写回会整文件改行尾**——第二次实证（R203 教训③同族）；编辑既有 CRLF 文件必须用 Edit 工具或写后逐字节校验行尾。
6. **行为实证两次当场抓获自己的修复缺陷**（C2 丢闭合行 / F821 task_id 作用域）——「修复后必须跑被测函数」，静态过 ≠ 行为对。
7. **并发会话污染回归的识别锚再次生效**——失败测试的目标代码带他人轮次标记（`✅ R216`）+ 隔离复跑转绿 = 判定为他人在跑测期间改文件，不采信该轮全量数据（AGENTS 教训⑤⑥第三次实证）。
