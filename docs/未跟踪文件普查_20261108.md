# 未跟踪文件静态普查（2026-11-08）

2026-11-07 对 `backend/tests/**/*.py` 做过一次「测试是否依赖未入库文件」的静态普查，结论当时只留在会话记录里。本文把那次普查的方法、分类、逐条明细与现状复核落盘，便于后续审计与复跑。

唯一判据是 **git 是否跟踪该路径**（`git ls-tree -r` / `git ls-files`）；「本机能跑过」不算证据——本机存在的文件（如 `esbuild.exe`）同样可能从未入库。

## 1. 方法

### 1.1 枚举

- 取 `git ls-tree -r --name-only <sha>`，筛出 `backend/tests/` 下的 `*.py`。**读 git 树而不是遍历工作区**，避免未跟踪的测试文件混入分母。
- 逐文件用 `git show <sha>:<path>` 取源码，`ast.parse` 后扫两类节点：
  - `ast.Constant` 字符串，且形如路径：含 `/`、无空白、无 `%` / `{}`、不含 `://`、不以 `/` `\` `~` 开头、长度 ≤ 260；
  - 组合表达式：`Path / "a" / "b"`（`ast.BinOp` + `ast.Div`）与 `os.path.join(...)`（`join` / `Path` 的参数按源码顺序取字符串段拼接），并允许从任一顶层目录段起算。
- 例：`REPO / "frontend" / "node_modules" / "@esbuild" / "win32-x64" / "esbuild.exe"` 折叠为 `frontend/node_modules/@esbuild/win32-x64/esbuild.exe`。

### 1.2 去重与折叠

- 锚定规则：首段是仓库顶层目录（`backend`、`frontend`、`docs`、`scripts`、`artifacts`、`chart-gap-filler`、`tools`、`logs`、`_diag`、`_diagnostics`、`平台智能体设计`、`reference_research`）→ 原样作为仓库相对路径；首段是 backend 内相对目录（`app`、`tests`、`data`、`logs`、`alembic`、`scripts`）→ 补 `backend/` 前缀；其余丢弃。
- 同一路径的多次引用折叠为一条；未跟踪的目录前缀只保留最长的叶子路径（`frontend/node_modules` 的 4 级前缀收敛为 `…/@esbuild/win32-x64/esbuild.exe`）。

### 1.3 判据

- 唯一依据：路径是否出现在 `git -c core.quotepath=false ls-tree -r --name-only <sha>` 的已跟踪集合里。
- 必须关闭 `quotepath`：否则中文文件名被八进制转义，`docs/全局事实模块审计_R175_20261103.md` 一类**已入库**文档会被误判成未跟踪（本次普查中真实发生过）。
- 此外，目录前缀若其下存在已跟踪子路径，不判为未跟踪。

## 3. 逐条明细

### 3.1 必红型（1 条）

**位置**：`backend/tests/test_outline_closeout_r87_20261016.py`

**依赖**：`frontend/node_modules/@esbuild/win32-x64/esbuild.exe`（`node_modules` 不入库）。

**原始形态**：`_fe_transpiled()`（由 `_fe_num()` 调用，唯一消费用例是 `test_frontend_and_backend_agree_on_garbage`）在 helper 内现取路径并硬断言：

```python
esbuild = REPO / "frontend" / "node_modules" / "@esbuild" / "win32-x64" / "esbuild.exe"
assert esbuild.exists(), "esbuild 本体不存在（需先 npm i）；不得退化为正则剥离 TS 类型"
```

在未执行 `npm i` 的机器上，该断言直接判红。

**处理方式**（提交 `6b62044`）：

1. 路径提为模块常量 `ESBUILD`（当前 [第 59 行](file:///j:/编程/专项方案工具箱/backend/tests/test_outline_closeout_r87_20261016.py#L59)；修复前该字面量在 helper 内第 93 行）；
2. **断言留在 `_fe_transpiled()` 里**（当前 [第 96 行](file:///j:/编程/专项方案工具箱/backend/tests/test_outline_closeout_r87_20261016.py#L96)）；
3. 给消费用例加**条件**跳过：`@pytest.mark.skipif(not ESBUILD.exists(), reason=…)`（当前 [第 279-285 行](file:///j:/编程/专项方案工具箱/backend/tests/test_outline_closeout_r87_20261016.py#L279-L285)），reason 写明「缺少 …（需先在 frontend 执行 npm i）」与「跨语言 parity 用例未执行——不得退化为正则剥离 TS 类型」。

**为什么这样改，而不是直接跳过整条**：

- 不用无条件 `skip`：装了依赖的机器/CI 仍要真跑跨语言 parity；无条件跳过等于永久放弃这条护栏，且报告里看不出来。
- `skipif` 只挡入口。若有人删掉或绕过 `skipif`（例如改为直接调 helper、或条件写错），helper 里的断言仍是硬失败，失败信息明确指向「缺 esbuild、不得退化为正则剥离」，而不是一个难定位的 `FileNotFoundError` / `ValueError`。**断言留在 helper = 能力的最后一道防线**，防止「缺依赖 → 悄悄退化为正则剥离 TS 类型」。
- 该用例同时承载后端侧 fail-closed 断言 `assert all(x == [] for x in be)`（当前 [第 295 行](file:///j:/编程/专项方案工具箱/backend/tests/test_outline_closeout_r87_20261016.py#L295)）。因此选择「条件跳过」而非删除或永久跳过：依赖在场时两层都跑，缺依赖时只让 parity 层缺席且显式可见。

### 3.2 静默跳过型（2 条用例 / 1 个路径）

**位置**：`backend/tests/test_global_facts_closeout_r75b_20261013.py`

**依赖**：`artifacts/r75b_g8/inventory_g8.py`。核实结果：`git log --all -- artifacts/r75b_g8/inventory_g8.py` 无任何提交，`git ls-files` 查无此路径，`Test-Path` 为 `False`——**从未入库，本机也不存在**。

**原始形态**：两条用例各自在函数体内条件跳过：

```python
if not os.path.exists(INVENTORY_PATH):
    pytest.skip("G8 盘点脚本未随仓携带（artifacts 归档缺失）")
```

由于文件在任何机器上都不存在，这两条用例在**任何机器上永远不跑**：零覆盖，但报告里只是「2 skipped」，与「已覆盖」无法区分——看起来有这个护栏，实际形同不存在。

**处理方式**（提交 `6b62044`）：新增模块级显式标记 `_G8_SCRIPT_MISSING = pytest.mark.skip(reason=…)`（当前 [第 53-60 行](file:///j:/编程/专项方案工具箱/backend/tests/test_global_facts_closeout_r75b_20261013.py#L53-L60)），两条用例改挂装饰器（当前 [第 190 行](file:///j:/编程/专项方案工具箱/backend/tests/test_global_facts_closeout_r75b_20261013.py#L190)、[第 201 行](file:///j:/编程/专项方案工具箱/backend/tests/test_global_facts_closeout_r75b_20261013.py#L201)）。reason 写明：缺少什么文件、该脚本从未入库且本机也不存在、「归档入库并删除本 skip 前，本护栏不执行」。

**删除 skip 的条件**：把该脚本随仓储归档入库（`git ls-files artifacts/r75b_g8/inventory_g8.py` 有输出）后，删除 `_G8_SCRIPT_MISSING` 与两处装饰器。

**为什么不保留条件式 skip**：条件式 skip 的判定发生在运行时，结果面上与「文件存在且用例通过」不可区分；显式 `mark.skip` 让「未跑」变成声明式、可枚举、可审计，不会再被当成有效覆盖。

## 5. 诚实边界

- **只覆盖字面量路径**：静态枚举只覆盖「路径以字面量形式出现在测试源码里」的情况。运行时拼接（配置/环境变量、函数返回值、f-string 动态段、glob 结果再拼接等）扫不到；本报告**不能**证明其余路径都不依赖未跟踪文件。
- **折叠规则有已知偏差**：锚定只看首段，没做基址变量的常量传播。本次产生两类偏差：(a) 把以 `_FE` 为基址的 frontend 相对路径错补成 `backend/` 前缀（3 条，已人工剔除）；(b) 把 `tmp_path` 夹具内的同名相对路径当成仓库路径（2 条，按安全型记账）。人工裁决名单见 §1.4 与 §3.3，未做二次自动校验。
- **`_diag/` 未核对**：该目录因 NTFS ACL 拒绝访问（`Get-ChildItem _diag -Force` 报「访问被拒绝」），内容始终未核对。本报告不声称已检查该目录内是否存在测试引用目标，也不对其中文件名做任何推断。
- **本地存在不算证据**：判据只有 git 树。`esbuild.exe` 本机存在，仍按未跟踪记账；反之亦不因「本机跑得通」而排除。
- **未跑测试**：本次复核未运行全量 pytest，所有数字均来自静态枚举与 git 命令（`git ls-tree -r`、`git ls-files`、`git log`、`git show`、`git diff`）。
