## 3. 本轮处置明细（原来 → 现在 → 验证）

### 3.1 N-01（高 · 修复）全局事实「同名异值双注入」闸门

**位置**：`backend/app/routers/global_facts.py:640-690`（新增闸门）、`:2351`（`resolve_fact`）、`:2621`（`resolve_conflict`）

**原来怎样**：确认事实只校验自身状态（模拟值未确认、冲突未裁决等），不检查**同作用域是否已存在另一条同名可注入事实**。生产可复现路径：资料 A 写「工期 180 天」、资料 B 写「工期 200 天」，两条都被人工确认后 `injectable=1`；正文注入时两份值同时进入提示词，模型随机取一个 → 成稿自相矛盾，且界面无任何异常（静默失真）。

**现在怎样**：
- 新增纯函数 `_norm_fact_text`（去全部空白含全角空格 + 小写）与异步闸门 `_assert_no_conflicting_injectable_duplicate(db, fact_id, row, *, name, value)`。
- 只在「同作用域 + 同名 + 不同值 + 同样是可注入行」时抛 **409**，`detail` 为结构化对象：`code=duplicate_injectable_fact`、`message`（含事实名与可执行动作「删除或合并重复项后再确认」）、`duplicate_fact_ids`（最多 20 条）。
- 作用域不存在（`_load_fact_rows` 抛 404）时记 INFO 并放行（该作用域不可能产生双值注入）；其它读取异常 **fail-closed → 503**，绝不「读不到就当没冲突」。
- 接入点：`resolve_fact`（确认）与 `resolve_conflict`（冲突裁决为非模拟值时）。
- 闸门**不写库**：拦截发生在任何 UPDATE 之前。

**如何验证**：`tests/test_degrade_hardening_r179_20261105.py` 中 7 条用例 —— 同名不同值 → 409 且库内 `is_simulated` 未变；同名同值 → 放行；全角空格同名 → 409；不同名 → 放行；未确认 peer（`is_simulated=1`）→ 不拦；`resolve_conflict` → 409 且 `has_conflict` 仍为 1；`_norm_fact_text` 归一断言。

### 3.2 N-02（中 · 显式化）单章保存的围栏补齐结果回传

**位置**：`backend/app/routers/sections.py:761/790/947-948`

**原来怎样**：`update_section` 保存正文时会调用 `auto_fix_unclosed_fences`（补 `missing_fence_open/close`、统计 `swallowed_prose`），但结果只进日志；接口恒回 `{"ok": true, "word_count": N}`。用户以为「原样保存成功」，实际后端已改写正文（自动补围栏），甚至吞掉若干行正文——只能靠肉眼翻原文发现。

**现在怎样**：仅在本次请求真的提交了 `content` 时，响应**加法式**新增：
- `fence_fixed`：本次自动补齐的围栏数（`open + close` 合计）；
- `fence_swallowed_lines`：被自动围栏「吞进代码块」的行数（>0 表示有正文被改动，需要回看）。

只改标题等字段时不挂这两个键（旧客户端零影响）。

**如何验证**：同一测试文件中 3 条 —— 正文含未闭合围栏 → `fence_fixed>=1` 且 `fence_swallowed_lines==0`；只改 `title` → 响应**不含**围栏字段（确认不是恒挂键）。

### 3.3 N-03（中 · 显式化）场景路由列表回传目标配置 `enabled`

**位置**：`backend/app/routers/ai_config/scene_routes.py:87/106`

**原来怎样**：`GET /ai/config/scene-routes` 的每条路由只回 `scene/config_id/config_name`；若目标配置处于 disabled，运行时 `_apply_scene_route` 会跳过并回落主配置，但列表页仍显示「已绑定该配置」——承诺落空。

**现在怎样**：SQL 增加 `CASE WHEN c.id IS NULL THEN 0 ELSE c.enabled END AS config_enabled`，条目**加法式**回传 `"enabled": bool(...)`；`config_id` 为空（跟随主配置）时为 `False`。旧字段一个不删。

**如何验证**：2 条 —— 目标配置 `enabled=0` → 列表 `enabled is False`；`enabled=1` → `True`。

### 3.4 N-04（中 · 加固）悬空图表引导语判据与导出侧同源

**位置**：`backend/app/routers/_chart_pipeline.py:526`（判据改为 `content_blocks._is_orphan_lead_in_text`）

**原来怎样**：正文链路 `_drop_dangling_lead_in` 只用 `ORPHAN_LEAD_IN_RE`（「如下图所示/见下图」等固定语序）；导出侧 `content_blocks._pop_orphan_lead_in` 用 `_is_orphan_lead_in_text`（`LEAD_IN_HINT_RE ∪ _RE_LEADIN_BROAD`，覆盖「流程图如下/示意图如下」）。同一句「施工工艺流程**流程图如下**：」在正文链路删不掉（留下无图的悬空引用），导出侧却会删——两侧口径不一致，用户在不同产物里看到不同结果。

**现在怎样**：`_drop_dangling_lead_in` 直接复用 `_is_orphan_lead_in_text`（**不复制第二套正则**），长度/非段落过滤与导出侧一致；保留既有「删除后补空行」行为。

**如何验证**：3 条 —— 「施工工艺流程流程图如下：」词序变体 → 删除且保留一个空行；长段落含关键字 → 不删（避免误删正文）；「要求如下：」→ 不删（非图表引导语）。

### 3.5 N-05（低 · 显式化）`/charts/list` 占位标题

**位置**：`backend/app/routers/charts.py:33/36/294`

**原来怎样**：`chart_predictions.purpose` 落库值可能为 `正文同步生成`（占位），清单页直接把它当标题展示，用户看到同名的「正文同步生成」条目无法区分章节与图型。

**现在怎样**：新增 `_PLACEHOLDER_CHART_PURPOSES` 白名单与 `_display_chart_title(purpose, chart_type, section_title)`：占位值 → 回退「章节标题 · 图表类型中文名」（无章节标题时仅类型名）。**只改展示**，不改库、不改导出图题、不改排序。

**如何验证**：`gantt` + 占位 purpose → 「甘特图」；有章节标题 → 「第三章 · 甘特图」；非占位 purpose → 原样返回。

### 3.6 N-06（中 · 显式化）配置导出时场景路由缺段

**位置**：`backend/app/routers/ai_config/config.py:560/563/611/624`

**原来怎样**：`_export_scene_routes` 查询失败时只 `return []`（无日志、无标记），导出 JSON 悄悄缺少整个 `scene_routes` 段。用户拿旧机导入后「场景路由全没了」，且不知道是查询失败还是本来为空。

**现在怎样**：`_export_scene_routes(db, status)` 在 except 中记 WARNING 并写 `{"ok": False, "code": "scene_routes_query_failed"}`；`export_config` 响应**加法式**新增 `"scene_routes_ok": bool`。成功路径恒为 `True`，与旧行为一致。

**如何验证**：2 条 —— 正常库导出 → `scene_routes_ok is True`；`DROP TABLE ai_scene_routes` 后导出 → `False`（且导出本身仍成功）。

### 3.7 N-07（低 · 显式化）图片格式探测失败的日志级别

**位置**：`backend/app/routers/_export_docx_parts.py:1273`

**原来怎样**：`_image_format_supported` 读取图片头异常时按「不支持」处理 → 对应图表/配图被跳过，但只打 `debug`；默认日志级别下零痕迹，用户只看到「图没了」。

**现在怎样**：升级为 `WARNING` 并带 `exc_info=True`（保留同一 fail-soft 行为：仍按不支持处理，不阻断导出）。

**如何验证**：代码锚点断言（异常分支为 `logger.warning` 且文本含「按不支持处理」）；行为不变由既有导出域测试覆盖。
