## ② 探查结果（对应指令第 1–2 步）

### ②.1 编号命名空间四层结构（`backend/app/services/numbering.py`，996 行，全量读过）

| 命名空间 | 权威 | 关键函数 |
|---|---|---|
| 存储态 | `sections.outline_json.id` 点分路径 | `_stored_id_parts`（fail-closed，公开别名 `stored_id_parts` :422） |
| 结构 | `parent_id + sort_order` 树 | `renumber_section_outline_ids`（编号由**位置**派生，写回 `outline_json.id` + `level = depth`） |
| 展示态 | L1=第X章（中文数字），L2+=存储编号去首段 | `heading_templates.outline_number_parts`（:125 消费 `stored_id_parts`）+ 前端 `storedIdParts`（`frontend/src/utils/outlineNumbering.ts`） |
| 正文子标题 | Markdown 内 `N.N` 行 | `renumber_section_body_subheadings`（:460–591，前端预览=落库=导出三处同源） |

**子承父系 / 等级正传机制**：编号不在子节点上各自维护，而是重排时由树的 DFS 位置统一派生 —— `renumber_section_outline_ids` 按 `(sort_order, id)` 全序遍历，`level` 由 `new_id.count(".")+1` 刷新，因此"子编号继承父系、等级随深度正传"是**结构必然**，任何只改 title 不动结构的操作不破坏编号（R85 ①实证锁）。

**DB 子章节 vs 正文 Markdown 子标题编号冲突**：两者是**第三命名空间隔离**设计 —— 正文子标题重排按展示域前缀（存储 `3.2` → 展示 `2` → 子标题 `2.1`），与 `stored_id_parts` 同一判据；校验器 :801–829、修复链 :832–918、回滚 :927–947 均在同一文件。**判定：已闭合，无缺口**（R86 L2 / R87 FIX-1 双侧护栏在位并在 §③ 基线中存活）。

### ②.2 save-outline 重排链（`backend/app/routers/sections.py` + `backend/app/services/outline_utils.py`）

```
save-outline 路由 (sections.py:1457/1458/1491, lock_roots 参数)
  → _save_outline_to_db (sections.py:1067)

```

**活体探针**（脏 id 树 `abc1.2 / 0.3 / 1.2.x / 1..2 / 第一章` 经 normalize_outline）：

```
输入:  abc1.2 / 0.3 / 1.2.x / 1..2 / 第一章
输出:  1 / 1.1 / 1.1.1 / 1.2 / 2      （两个入口点重排结果逐字一致）
```

**判定：脏客户端 id 经 save-outline 重排为合法点分路径 —— 已闭合，非缺口。**

### ②.4 AI 调用与提示词 —— 本轮唯一真实缺口（R148 修复，详见 §④）

R38-P1-c 立约：所有 `collect_json_response` 家族调用必须显式传 `repair_key`，目录族必须用 `OUTLINE_REPAIR_KEY`（否则非目录任务拿到"把目录 JSON 修好"的方向完全错误的修复提示词）。既有护栏 `tests/test_json_repair_key_parity_20261006.py` 的扫描器只认 `ast.Name` 形态函数引用，对以下三类**结构失明**：

1. **属性形态**：`_sse_outline_review.py` 中 6 处 `_sh.collect_json_response(...)`（R101 拆分文件后新增形态）；
2. **统一通道**：4 处 R57/R58 时代合法的 `collect_json_response_with_chat(...)`（自带注入，repair_key 由通道内部处理）；
3. **关键字注入**：`outline_title_fix.py:371` `_collect=_sh.collect_json_response` 传 `repair_key=OUTLINE_REPAIR_KEY`（:375）——"委派 A" 形态，静态锁锁不到委派本体（R98 教训同族）。
