
## 二、失效点清单与根因分类

| 编号 | 现象 | 根因 | 优先级 |
|---|---|---|---|
| RC-1 | 目录生成刚发起的 30s 内点「停止」完全无效 | `event_stream` 先 `await _assemble_context()`（读文档/摘要/规范，可能发 AI 调用）再 yield `connecting`；期间前端 `activeTaskIdRef.current` 仍是**上一代已终结 id**，停止打到死 id，后端回 `{"ok":false,"message":"任务不存在或已结束"}` | **P0（活体实测，直接成因）** |
| RC-2 | 任务已死但状态永远 running，停止/替换都救不回，只能重启进程 | `finish_task` 协程从未进入执行（全程无「任务终止」INFO，该 INFO 仅在 DB 落终态成功时打印）→ `_tasks` 内存态永久 running；`GET /sse/task/{id}` 内存优先；`reap_orphan_tasks` 明文「本进程内存态存在的任务一律不动」→ 三道僵尸自愈全部绕过 | **P0（活体实测）** |
| L-1 | 目录 / 事实两 Tab 无停止入口 | 进度卡为纯展示组件，控制区未接线（后端 pause/resume/stop 早已生效） | P1 |
| L-2 | 「取消导出」是假停止 | 前端只 abort fetch；后端 `to_thread` 线程不可取消，成本段（图表渲染 / AI 配图 / 章节写入）继续烧 | P1 |
| L-3 | 停止按钮可连点、`data.ok=false` 静默、指令 accepted 即乐观提示"已停止" | 无同步锁、无失败回执、无「停止中」态 | P2 |
| L-4 | 审核与预检（最长 1-3 分钟）运行中无法取消 | 前端未接 AbortController | P2 |
| L-5 | 上传解析无停止入口 | 低频秒级 await REST，abort 即断 | P3（登记不改） |

### FIX-6 · P0 · 内存僵尸自愈第四道防线（`sse_utils.py` + `task_registry.py` + `sse_handlers.py`）
- `with_heartbeat(..., on_end=None)`：在 finally **最前**同步调用 `on_end()`（同步代码不受协程取消风暴影响，是「SSE 流确实结束」的唯一权威时刻）。

- `_stream_end_guard(holder)`（`sse_handlers.py` L3591）+ 目录链 `StreamingResponse(with_heartbeat(..., on_end=_stream_end_guard(_stream_holder)))`。

## 六、遗留问题与设计取舍（登记不隐瞒）

1. **正文链同类窗口未改**：正文 `event_stream` 的 connecting 仍在主 try 内偏晚位置（约 L5009 区段）。本轮只把目录链接入 FIX-6/7，正文链暴露面由 `on_end` 宽限回收兜住，同类"发起瞬间停止打空"的窗口未彻底消除 —— 下一轮承接。
2. **bid_analysis 故意不接 `on_end`**：它是后台跑批语义（SSE 断开 ≠ 任务该停），流结束即回收会误杀正在跑批的任务；停止仍走 `request_control` 协作式检查点。
3. **审核/预检/上传解析不注册 task**：await REST 断连即在服务端下一 await 边界取消，注册任务反而引入新的僵尸面；上传解析为 P3 低频秒级，无停止入口。
4. **宽限回收的降级边界**：极端情况下 DB 锁重试失败会把 `failed` 记成 `stopped`（语义与"断线收尾"一致），已保留 WARNING 便于甄别。

6. **进程内僵尸需重启才清**：修复只保证此后不再产生新僵尸；存量内存态（如 E2E 期间遗留）须重启后端清除。
7. **并行会话覆写风险（本轮实测复现，两类污染）**：收口期间 `backend/app/{routers/sse_handlers.py, routers/export.py, services/ai/task_registry.py, services/ai/provider_factory.py, db.py, models.py, main.py, routers/_chart_pipeline.py}` 被会话外进程持续改写（mtime 每十几秒前进、字节数持续增长，且 `settle_global_conn` 等外来改动进入）。后果一：FIX-7 的 connecting yield 一度被外来缓冲区覆盖丢失 —— 由 `artifacts/r106/restore_b_m25.py` 复现式补回，并新增可反复运行的接线体检 `artifacts/r106/audit_wiring.py`（18 项判据 + holder<yield<assemble 顺序锁）。后果二：宽簇回归出现"随写窗漂移"的失败（44 例源码锁假红 + 3 例 `provider_factory` 审计 INSERT 绑定 13≠11 的复现失败，本轮零接触该文件）。这是 R105「并行会话未完整落盘」教训的第二次实证：**跨会话共仓时，任何"已验证"结论都需按接线体检复核，且回归数字必须标注采样时点。**
