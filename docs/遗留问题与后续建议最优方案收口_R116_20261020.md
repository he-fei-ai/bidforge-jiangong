## 二、落地项清单

### A-1（L1）· 两开关 4 组合矩阵

两个开关的**语义分层**此前只在单开关维度被锁，组合态无覆盖：

| 开关 | 位置 | 作用 |
|---|---|---|
| `outline_check_generic_titles` | `sse_handlers._detect_generic_titles` | 管「**检不检**」 |
| `outline_deterministic_title_fallback` | `outline_title_fix.deterministic_title_fallback` | 管「检出后**要不要零 AI 兜底**」 |

四组合的**正确期望**（已参数化锁死）：

| 检出 | 兜底 | 期望 |
|---|---|---|
| ✅ | ✅ | 改写落地：`专项6` → `灌注桩成孔与钢筋笼吊装` |
| ✅ | ❌ | `_try_outline_title_fix` 返回 `None`，**原树一字未动**且**零 AI 调用** |
| ❌ | ✅ | `hits` 为空 ⇒ 兜底不启动（**总闸优先，兜底永不自行重跑检测**） |
| ❌ | ❌ | 全关：检出空 + 不兜底，落库原样 |

**为什么第 3 行必须单独锁**：`deterministic_title_fallback` 的入参是 `hits`，若它内部自行重跑一次 `detect_generic_titles` 就能绕过总闸——这是「关掉总闸但仍被改写」的唯一可能路径。A 组 `test_signature_has_no_hits_bypass` 以 AST 断言该函数体内**不得出现**任何 `detect_generic_titles*` 调用。

**为什么补 `test_direct_call_respects_fallback_switch`**：见 §八.2「等价变异」——这条用例不是锦上添花，而是让 A/B 的 M7 从 `NOT-CAUGHT` 转为 `CAUGHT` 的必要条件。

### A-2（L3 + 建议 1）· 上游已实证不可用 ⇒ 跳过审核

**病灶（跨阶段信号被切断）**：R115 FIX-2 给补齐链路加了 `_state` 归因出参（`timed_out` / `errored`），但那个字典**定义在补齐分支内部（12 空格）**，而**审核调用在函数体顶层（4 空格）**——拿不到信号。于是补齐超时 120s 之后，审核照旧发起并再等 60s。

**修法两处**：

```python
# ① 函数级定义（插在 `if not outline: return ...` 之后）
_patch_state: dict = {}

# ② 审核入口闸门（紧跟 _notify("review")）
_upstream_dead = bool(_patch_state.get("timed_out") or _patch_state.get("errored"))
if _upstream_dead and getattr(
        settings, "outline_skip_review_when_upstream_dead", True):
    logger.warning(
        "上游已实证 AI 链路本轮不可用（补齐 timed_out=%s / errored=%s），"
        "跳过审核（省 %ds 等待）（scheme=%s）", ...)
    _review_skip_reason = "upstream_dead"
    review_obj = {"passed": True, "suggestions": ["上游 AI 链路不可用，已跳过审核"]}
else:
    try: ... 原审核调用逐字不变 ...
```

补齐分支改为**复用**函数级字典（注释明写「此处不再重新定义——重新定义会切断跨阶段信号」）。

**新配置项** `backend/app/config.py:652`：

```python
outline_skip_review_when_upstream_dead: bool = True
```

- `True`（默认，bug 修复性质）：命中信号直接跳过，省下整个审核超时预算；
- `False`：**逐字回到本项引入前**——无论上游状态如何都发起审核调用；
- **不调** `outline_review_timeout`（保持 60）与 `outline_fix_timeout`（保持 120）。

**前端消费**（`SchemeWorkbenchPage.tsx:1925`）：`reasonMap` 增加

```ts
upstream_dead: "本章目录补齐已失败（同一 AI 链路不可用）",
```

文案刻意点明「同一链路已失败」，否则用户会以为审核被无端省略；且**不甩英文 token**（护栏断言渲染文本不含 `upstream_dead`）。

### A-3（建议 2）· 兜底成功侧计数（防回流锁）

R115 已落地的成功侧日志：

```

```

本轮**不改代码**，补四层锁：

### A-4（建议 3）· `description` 内容契约四处齐改

`backend/app/services/ai/prompts/outline.py` 四处（L29 / L61 / L91 / L292）：

| key | 位置 | 场景 |
|---|---|---|
| `outline_short_system` | L29 | 短方案一次直出 |
| `outline_level1_system` | L61 | 长方案一级 |

统一契约：

> `description` 必须是**具体施工内容短语**（8~20 字，如"灌注桩成孔与钢筋笼吊装""支护桩顶冠梁施工"），不得写"本章依据…""详见…""同上""待补充""N/A""占位"等元话语或占位标记

## 三、刻意不落地项及理由

### 3.1 不做「开跑前主动探活」（建议 1）

| 维度 | 主动探活 | 被动探活（本轮采纳） |
|---|---|---|
| 额外请求 | 每次生成 +1 次轻量调用 | **0** |
| 额外延迟 | 固定叠加（全挂时也先付一次超时） | **0** |
| 信号可信度 | 单次探活成功**不能证明**后续大调用成功 | 补齐**已经**跑完整条链路并失败 |
| 反例 | agnes 401：探活可能命中另一个健康 provider，判定「可用」后大调用仍全挂 | 无（失败即失败） |

补齐（`scene=outline_fix`）与审核（`scene=outline_review`）共用同一批 provider，**补齐刚以超时/异常收场即已实证本轮链路不可用**——这是比探活更强的证据，且免费。

### 3.2 不调大 `outline_review_timeout`（L3 原始表述）

把 60 调大，在 AI 全挂时**只会让用户多等更久**才拿到同样的「跳过审核」结果；在 AI 正常时 60s 已足够（审核输入是骨架 JSON，不是正文）。真正的病灶是「已经知道挂了还再等一次」，不是「等得不够久」。

### 3.3 不做「多级语义候选」（L2）

**不做的红线判据**：`_apply_title_updates` 的六条保守红线只能判「是否泛化 / 是否同级重名 / 是否含换行 / 剥编号后是否为空 / 是否过长 / 是否带（N）后缀」——**判不了「语义是否比原占位名更差」**。继续往后挑"语义更贴切"的分句、或借父节点/兄弟节点/项目事实造词，会把「零 AI、零失败面、**绝不改坏**」的兜底，变成「可能改出一个更离谱的标题」。产不出候选时原样保留、交给人工核对与落库闸门，是刻意选择的**更小危害**。

**决策留痕**（`outline_title_fix.py:419` 起，`_desc_title_candidates` docstring）：写明「生产上确实存在首分句是空话的形态」「不做更激进派生的三条理由」「护栏指引 `TestCL2DeliberateNonLanding`」。C 组 `test_decision_documented_in_code` 断言 docstring 同时含「多级」与「刻意」，防止留痕被后人删掉。

**同时固化的三条边界护栏**（防「不落地」被误解为「没人管」）：

1. `test_candidates_only_from_own_node`：AST 常量集合 ⊆ `{"title", "description", ""}`——候选**只读自身字段**，不得读父/兄弟/项目事实；
2. `test_candidate_budget_bounded`：`_FALLBACK_DESC_CANDIDATES == 3` 且实际候选数 ≤ 1 + 3（title 基名 1 条 + description 3 条），防止「悄悄扩大预算」变成事实上的多级派生；
3. `test_derivation_chain_is_zero_ai`：`_desc_title_candidates` / `_fallback_title_candidates` / `deterministic_title_fallback` 三函数体内**禁出现** `collect_json_response` / `chat_with_fallback` / `render`——零 AI 是兜底成立的前提。

## 四、既有护栏冲突处置

`backend/tests/test_outline_call_optimization.py::TestProgrammaticPrecheck::test_patch_failure_falls_back_to_full_review` 断言「补齐失败 → 回退完整审核（`len(calls) == 2`）」，与 A-2 直接冲突（实际 1 次）。

**定性**：该用例 docstring 自称「（旧行为）」⇒ 属**行为契约变更**，不是测试桩故障。

**处置原则**：改契约必须**保留检测力**。若简单删掉 `== 2`，就再也抓不住「有人把 A-2 写成无条件早退」——那才是真正的「审核被静默删除」事故。因此改写为**双分支锁**：

```python
# ① 默认（闸门开）：上游已实证不可用 ⇒ 1 次调用 + 如实标注
assert len(calls) == 1, "上游已实证不可用：不得再发起审核调用"
assert review["passed"] is True
assert review["review_skipped"] is True
assert review["review_skip_reason"] == "upstream_dead"
assert "review_mode" not in review

# ② 关闸门：逐字回到旧行为
calls.clear()
monkeypatch.setattr(sh.settings, "outline_skip_review_when_upstream_dead", False, ...)
... assert len(calls) == 2
assert "review_skipped" not in review
```

分支 ② 是**回归锚**：它证明「关掉开关 ⇒ 逐字回到引入前」，同时让「无条件早退」的变异无法通过。文件 **33 passed**。

## 八、判据教训（本轮新增归档）

### 8.1 `Path.write_text` 在 Windows 会把 `\n` 翻成 CRLF

A/B 脚本首版用 `path.write_text(text)` 做还原，导致两个**纯 LF** 文件被写成 CRLF：

| 文件 | 原字节 | 被污染后 |
|---|---|---|
| `prompts/outline.py` | 28521 | 28862 |
| `SchemeWorkbenchPage.tsx` | 606647 | 619306 |

`SchemeWorkbenchPage.tsx` 被仓内既有护栏 `test_no_lone_cr_no_bom_no_replacement_char` 强锁（断言 `b.count(b"\r") == 0`）。**立即以字节级 `replace(b"\r\n", b"\n")` 精确复原**（回到 28521 / 606647）。

**归档结论**：A/B 脚本**必须字节级读写**（`read_bytes` / `write_bytes`），不得用文本模式；还原后**必须做 sha 自校**，本轮的 `restore_sha` 就是为此而设，也正是它抓出了污染。

### 8.2 等价变异（equivalent mutant）要诚实处理，不能靠换锚点蒙过去

M7（摘掉 `deterministic_title_fallback` 内的开关门控）首轮 `NOT-CAUGHT`。原因：`_try_outline_title_fix._finalize` 在转兜底**之前**已有一道同款提前返回 ⇒ 从 `_try_outline_title_fix` 入口观察，摘掉内部门控**行为完全不变**——这是真正的等价变异，不是判据不够强。

**正确处置不是改判据，而是补一条走真实形态的用例**：`sections` / `upload_outline` 两条落库链路**直接调用** `deterministic_title_fallback`（不经过 `_finalize`）。新增 `test_direct_call_respects_fallback_switch` 后 M7 转为 CAUGHT。

**归档结论**：遇到 `NOT-CAUGHT` 先问「是不是等价变异」，若是，找**另一条真实调用路径**建判据；不要为了变绿去放宽断言。

### 8.3 静态文本锁的替换体不得含原关键字

M8 把「兜底落地」替换为「兜底完成」——若替换成「兜底落地（旧）」则 `count==1` 仍成立，护栏假绿。**归档结论**：字面量锁的变异必须真正抹掉关键字。

### 8.4 CRLF 文件的跨行锚点必须适配行尾

M6 首改 `hits=0`（锚点没匹配到）：`sse_handlers.py` 是**纯 CRLF**，脚本里的多行锚点写的是 LF。修法：

```python
def _adapt(text: str, eol: bytes) -> bytes:
    """把脚本里的 ``\n`` 锚点适配到目标文件的实际行尾（CRLF/LF）。"""
    b = text.encode("utf-8").replace(b"\r\n", b"\n")
    return b.replace(b"\n", b"\r\n") if eol == b"\r\n" else b
```

**归档结论**：本仓同时存在纯 LF（`prompts/outline.py`、`SchemeWorkbenchPage.tsx`）与纯 CRLF（`sse_handlers.py`、`outline_title_fix.py`）文件，跨行锚点**一律**经 `_adapt` 适配，否则表现为「变异没生效」的假失败。

### 8.5 「确认已落地」必须落在护栏**行为**，不是护栏**文字**

A-3 若只断言「日志字符串在文件里出现 1 次」，那么把它改成硬编码 `0 条` 仍然通过。因此 B 组补了 caplog **行为取证**：真跑一次兜底，断言日志里是真实数字。同族教训见 R114 「A 组 AST 锁只能证明代码里写了 kwargs，故补 E 组真 DB 端到端」。
