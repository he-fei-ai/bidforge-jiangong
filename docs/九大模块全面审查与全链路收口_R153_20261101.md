## 三、修复项清单（本轮实际改动）

### FIX-1 · `create_from_scheme` 四级树静默丢弃（R149 遗留 L-11 升级为现行缺陷）
- **文件**：`backend/app/routers/outline_library.py`
- **根因**：`build()` 硬编码 `level < 3`——R151 四级标准（L4 为最小叶子）后，方案沉淀到目录库会**静默丢弃全部 L4 章节**；孤儿行（parent 已删）同样无声消失。旧字面同时兼做 parent_id 环防护。
- **修法**：下降深度改由 `OUTLINE_MAX_LEVEL`（单一事实源 `outline_rules.py`）驱动，保持**有界下降**（递归至多到 L4 层，环防护语义保留）；入库仍经 `_normalize_outline`（深度钳位 + 编号重排），与其他入库路径同口径。响应新增**加法式键 `dropped_sections`**（孤儿 + 超深脏行计数回传，不再静默）。
- **顺带**：`_normalize_outline`/`_count_nodes` docstring 中「三级」陈旧字样修正（注释与代码矛盾，R149 教训①家族）。

### FIX-2 · seed 预置目录 outline_json 无节点 id（R149 遗留 L-10）
- **文件**：`backend/app/seed_data.py`
- **根因**：`_build_record` 直接 `json.dumps`，节点无 id——前端 React key 取 `outline_json.id` 恒 undefined；seed 是全库**唯一**不经 normalize 的入库路径（手动 create/update/new_version 早已 normalize）。
- **修法**：新增 `_seed_outline_json()`——统一过 `normalize_outline_json`（补 id/level 与点分编号）；normalize 失败（default）时**回落原始序列化**（预置内容绝不因规范化异常丢失，最坏维持旧行为）。`SEED_VERSION v3.0→v3.1` 触发存量预置库刷新（与 `_EXPORTER_VERSION` 同纪律）；既有版本锚测试同步重锚（`test_outline_library_full_update_20261001.py`）。

**行为变化（2 处，均为修复目标内）**：① 四级方案沉淀目录库不再丢 L4，孤儿/超深行计数回传；② 存量预置目录在下次启动 seed 时刷新为带点分编号版本。**零迁移零 DDL 零新增配置项**；前端零改动（`dropped_sections` 为加法式键）。

## 八、判据教训归档

1. **E2E AI 打桩必须覆盖「成稿后管线」的旁路模块属性**——AI 调用面按「import 到哪个模块属性」盘点，而非按「业务入口」盘点（R144 教训②的 E2E 形态放大版）。
2. **A/B 多行锚点必须按文件实际行尾归一后匹配、按原风格写回**（R137 教训⑨再验证）——M1 首轮锚点双 bug（缺前引号 + CRLF）。
3. **E2E 崩溃路径也要 os._exit 收口**——脚本自身异常时 observability 写线程挂住进程，timeout 误报 124 掩盖真实 FAIL 位置。
4. **断言加法式新键/嵌套键前先查契约位置**——`mermaid_service` 在 `/check` 响应的 `content_audit` 子键（:1675），顶层断言必失败。
