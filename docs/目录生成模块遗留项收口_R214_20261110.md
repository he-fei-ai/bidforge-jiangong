## 5. 登记项（各带可执行方案与触发判据，非「以后再说」）

### 5-1 L-1 第二分叉：`_prompt_number` vs 落库 `outline_json.id`

- **现状**：生成期 `_preferred_section_number` 优先真实树重算值 `_prompt_number`（R182 修「陈旧存储编号进提示词」），落库 `numbering.py:914-929` 只读 DB 快照；`index` 预取路径（`:905`）另有 `info["number"]`。目录重排/结构漂移且尚未被 `repair_scheme_numbering_consistency` 自愈时，两侧前缀可能不同。
- **方案**：给 `normalize_section_content_subheadings` 增加 `number_override: str = ""`，在 `:927` 与 `_normalize_from_meta`/`index` 两条分支同时生效；`sse_handlers.py:3940` 调用点传入本次逐章的 `_sec_stored`（真实树编号）。配套护栏：构造「DB 快照 `1` / 真实树 `2`」的漂移样本，断言落库前缀与导出前缀同为 `2`。
- **不本轮落地的原因**：属**正文生成模块**契约（5 个调用点 + 预取索引），且 R182 的 `renumber_section_outline_ids` 已在写路径把漂移自愈；在目录模块遗留轮做跨模块大改，回归面与收益不成比例。
- **触发判据**：出现「用户可见的正文子标题前缀与导出成稿不一致」的实测案例（非手工改库构造），或审核预检产出 `stale_cross_reference` 且归因到该分叉时，立即立项。

### 5-2 熔断标记的多实例部署

- **方案**：把 `_QUOTA_BLOCKED_TASKS` 迁到与 `task_registry` 同层的共享状态（Redis / DB 任务行 `checkpoint_json` 的一个键），或把熔断标记随 `retry_state` 参数链显式传递；届时同步重锚本轮「进程内内存态」护栏。
- **触发判据**：部署形态从单进程 uvicorn 变为多 worker / 多实例，且 `task_registry` 已先改为共享存储（否则熔断不是首个失效点）。

### 5-3 全仓行尾 renormalize（运维动作）

- **命令**（**必须限定 `frontend/src`**，`.gitattributes` 把 `*.bat/cmd/ps1` 设为 `-text`，后端 9 个 `.py` 被 R199 护栏锁 CRLF，全仓 `--renormalize .` 会越界）：
  ```
  git add --renormalize -- frontend/src
  git diff --cached --ignore-space-at-eol --stat   # 应为空：证明只有行尾变化
  git commit -m "chore(eol): renormalize frontend/src (ops only)"
  ```
- **触发判据**：其余 84 个非目录模块 CRLF 文件被任一模块轮触碰，或 `git diff` 因行尾假膨胀影响审阅时执行；本轮已把目录模块 35 个收敛，避免与功能提交混提。

## 10. 教训归档

1. **「待产品裁决」不等于「不能修」**：R210 把提示词编号口径挂起两年轮次，本轮用三个既有纯函数做单点换算就消除了交叉引用悬空 —— 关键是先把「存储态 / 展示态 / 真实树」三条链画清，再判断是否需要改模板语义。
2. **护栏锁实现会在产品文案演进时假红**：本轮两处重锚（R188 restore 函数名、3 个折叠 description 整句）都是同一病根；锁意图（内容不丢、旧后缀剥离、统一出口）才能强度不减地活下去。
3. **`inspect.getsource` 在文件被改写后会切错函数**：R210 教训再次应验；护栏改用「源码全文 + 调用点 `context`」切片，既避开旧 pyc 行号错位，也不受 R190 写锁薄壳拆分影响。
4. **行尾归一必须按模块名筛 + 精确清单**：目录级 glob 会把 bidAnalysis 等其它模块、以及外部编辑器反复写回的文件纳入，制造无法收敛的红；按模块名筛后的清单才是可承诺的棘轮。
5. **并发负载下的超时是环境性假红**：先隔离复跑确认真因，再决定是放宽文件级超时还是优化 import；改全局 config 会拖慢其余 92 个文件的失败反馈，属过度修复。
