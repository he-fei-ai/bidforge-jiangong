### 2.3 数据链与存储

```
上传 → 格式白名单 + 文件头签名 + 体积/数量/累计配额三重预检
     → 落盘（流式分块，非全量入内存）
     → 档案入库 project_documents（doc_category 自动分类）
     → 四层原文层（指纹 MD5/SHA256 + meta + 索引）
解析 → parse_file_content_ex（14 格式分派 + 诊断 diag）
     → 落库 parsed_markdown（≤ MAX_PARSED_CHARS=400000）
     → parse_status / parse_truncated / parse_warnings 持久化
     → 四层解析层（Markdown + pages/tables/images + 分块 + 语义索引）
     → 失效下游：全局事实 stale + 导出缓存失效
提取 → 全局事实 AI 提取 → 标前分析 18 项 → 正文生成 → 导出
```

## 八、遗留问题与后续建议

1. **P2-1 完整性报告恒 1.0**（最高价值遗留）——建议单独立项：先把 `n_pages` 从 `_parse_pdf` 透出到 `diag`，再让 `parse_coverage` 用两个独立来源。
2. **P2-2 提取层项目级/文档级语义**——需产品确认后修正 `sync_extract_layer`。
3. **P2-6 无扩展名文件的前后端口径分裂**——建议以后端为准（文件头嗅探已是后端既定能力），前端放宽并补测试。
4. **配置快照语义**——`upload_max_bytes` 等 4 项在 import 期求值，改 `.env` 需重启；建议后续统一为「每次调用现读」或明确写入运维文档。
5. **能力探测口径**（P2-9）——`main.py` 的 `docx`/`fitz` 探测与真实解析依赖不一致，建议随诊断模块一并梳理。
6. **本轮教训归档**：
   - **pytest 串行纪律**：并发跑多个 pytest 会争抢同一 SQLite 库 ⇒ 表现为「单跑 6s、并发跑挂死」的假故障。R108 已记录同族事故，本轮二次实证 —— **回归必须串行**。
   - **守卫放置层级**：`atomic_write_bytes` 是**通用原语**，把「管理层路径约束」下沉到该层会误伤正常用法（本轮首版即如此，被 `test_fingerprints_and_atomic_io` 抓出）。正确层级是**路径构造层**（`doc_dir`/`index_path`）。
   - **判据写法**：AST 锁 `to_thread` 必须查「Await 的 .value.func.attr」与「实参含被调名」；`ast.walk(call)` 只能看**子节点**，看不到父节点的 Await。
   - **字节体检须覆盖前端**：本轮自己引入过一个 U+FFFD（编辑时误伤中文注释），被仓内既有护栏 `test_global_facts_frontend_parity_r89_20261017` 当场抓住 —— 仓内护栏是有效防线，改完必须跑。
   - **PowerShell 5.1 的 `.ps1` 编码陷阱（本轮新踩）**：`write` 工具落盘的脚本是 **UTF-8 无 BOM**，而 Windows PowerShell 5.1 对无 BOM 的 `.ps1` 按 **ANSI（GBK）** 解码 ⇒ 脚本里的中文字符串被解成乱码并**吃掉后面的 ASCII 引号** ⇒ 报「Missing closing '}'」且**根本不执行**（静默失败，最易误判成「脚本跑完了但没输出」）。修法：① 辅助 `.ps1` 一律**纯 ASCII**（日志文案只是给自己看）；或 ② 落盘后加 UTF-8 BOM。**追加纪律**：长跑脚本上线前必须先做一次**语法预检**（`[System.Management.Automation.Language.Parser]::ParseFile`），不要直接 `powershell -File` 盲跑 —— 语法崩掉会白等一个小时的锁。
   - **8GB 机器上的「进程活着但 CPU 不动」**（本轮新踩）：并行会话的 pytest + 其 spawn 的 `tsc`/`vitest`(7 worker) + IDE 一起抢内存（本机 7.84GB 只剩 1.79GB 可用）⇒ `tsc` 进程 6.5 分钟只累计 10s CPU、pytest 主进程 CPU **10 分钟零增长**。这是**资源饥饿**，不是代码死锁。识别判据：**进程存在但 CPU 计数长期不变 + 内存逼近耗尽**。处置：停掉自己新增的并发重活给主跑让路，再把验证拆成**串行队列**（后端全量 → R55 前端真跑 → tsc → eslint → vitest），不要让 node 与 pytest 同时开跑。
