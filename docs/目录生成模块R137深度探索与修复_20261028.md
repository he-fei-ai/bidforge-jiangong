## 四、修复项清单

### FIX-1（P1）· BUG-1：E3 降级字母前缀非幂等

**根因**：`_STRIP_NUMBER_RE`（`numbering.py:63`）只有 `第X章 / （三） / 1） / 点分编号` 等分支，**没有 `[a-z]、`**。而 `_compute_subheading` 在降级模式（`has_db_children=True`）下把 L7 输出成 `a、标题`。下一轮规范化读到的 `a、标题` 无法剥离 ⇒ 再叠一层 `b、`。结构变更入口（create/delete/reorder/save-outline）都会触发 `_renormalize_all_section_contents`，所以**每次拖拽/改结构都会让正文标题变长一段**，且不可逆。

**修改**：`backend/app/services/content_blocks.py`

```python
# 行 1288（新增）
_LETTER_PREFIX_RE = re.compile(r"^\s*[a-z]{1,2}\s*、\s*")

# 行 1291（新增）
def _strip_body_letter_prefix(text: str) -> str:
    """剥掉正文子标题之前由本模块降级模式产出的「字母、」前缀（有界 8 轮）。
    剥空则保留原文（避免把纯字母标题清成空串）。"""
    s = str(text or "")
    if not s:
        return s
    for _ in range(8):
        new = _LETTER_PREFIX_RE.sub("", s, count=1).strip()
        if not new or new == s:
            return new or s
        s = new
    return s
```

`_compute_subheading`（行 1310）内，`md_lv` 归一之后、`counts` 之前：

```python
# ✅ R137：先剥掉「上一轮本函数自己产出的字母前缀」再参与编号
pure = _strip_body_letter_prefix(pure)
```

**为什么放在 `_compute_subheading` 而不是 `_STRIP_NUMBER_RE`**：
- 该正则在 `numbering.py`，被三档剥离（标题链路）共用；加 `[a-z]、` 分支会误伤**真实以字母开头的业务标题**（如英文缩写章节）。
- `_compute_subheading` 是**正文子标题**的唯一算法本体（numbering 落库 / export 预检 / export 写稿三处同源），把剥离限定在「正文子标题」作用域内，语义精确、零外溢。

**探针复验**（`artifacts/r137/_probe1_demote_idempotency.txt`）：

| 轮次 | 修复前 | 修复后 |
|---|---|---|
| demote pass1 | 产出 `a、` | 产出 `a、` |
| demote pass2 | `b、a、`（changes=3） | `changes=0` |
| demote pass3 | `c、b、a、` | `changes=0` |
| demote pass4 | `d、c、b、a、` | `changes=0` |
| 切回非降级 | `2.1.1 a、关键节点`（残留） | `2.1.1 关键节点`（干净） |

### FIX-2（P2）· BUG-2：`update_section` 改名产生幽灵子标题

**根因**：`_strip_duplicate_leading_title(blocks, *titles)` 只从**计数**里排除「与本节标题重复」的前导块（保留正文，不占编号格子）。R89 已把触发条件从 `"content" in fields` 扩到 `content 或 title`，但**传进去的仍是新标题**：改名后正文首行是旧标题，归一化比对不匹配 ⇒ 该块被当普通子标题，拿到 `1.1`，其后的真子标题全部 +1 顺移。

**修改**：`backend/app/services/numbering.py`

1. `renumber_section_body_subheadings(..., rename_from: str = "")`（行 460）新增形参。
2. 在 `lines = content.split("\n")` **之前**，先按**旧标题**识别前导重复块，并按 `src_line` 把该行改写为新标题（保留 `#` 数量与缩进；纯文本行升级为 `#`×`level` 形态保证幂等）：

```python
_rename_changes: list[dict] = []
if rename_from and str(rename_from).strip():
    _old_bare = strip_outline_numbering(str(rename_from).strip())
    _new_bare = strip_outline_numbering(str(section_title or "").strip())
    if _old_bare and _new_bare and _old_bare != _new_bare:
        _blocks0 = _parse_content_blocks(content)
        _kept0 = _strip_duplicate_leading_title(_blocks0, _old_bare)   # ← 按旧标题排除
        _lead = _blocks0[:len(_blocks0) - len(_kept0)]
        if _lead:
            _lines0 = content.split("\n")
            for _b in _lead:
                _src0 = _b.get("src_line")
                if not isinstance(_src0, int) or not (0 <= _src0 < len(_lines0)):
                    continue
                _line0 = _lines0[_src0]
                _indent0 = _line0[:len(_line0) - len(_line0.lstrip())]
                _m0 = re.match(r"^(#{1,6})\s+", _line0.lstrip().lstrip("\ufeff").lstrip())
                _new_line0 = (
                    f"{_indent0}{_m0.group(1)} {_new_bare}" if _m0 else
                    f"{_indent0}{'#' * min(int(_b.get('level') or 2), 6)} {_new_bare}")
                if _new_line0 == _line0:
                    continue
                _lines0[_src0] = _new_line0
                _rename_changes.append(
                    {"line": _src0 + 1, "old": str(_b.get("text") or ""), "new": _new_bare})
            if _rename_changes:
                content = "\n".join(_lines0)
```

3. 返回值改为 `return content, _rename_changes` / `return "\n".join(lines), _rename_changes + changes`。

> **关键细节**：若不把改名动作计入 `changes`，`_normalize_from_meta` 的 `bool(changes)` 为 `False` ⇒ `sections.py` 判定「无变更」**不写库**，改名后的正文改写被丢弃。这是本轮踩到的坑，已在护栏 B 组加反向锁。

## 九、判据教训归档

1. **「幂等」断言必须覆盖所有模式分支** —— 既有 `test_outline_body_subheading_sync.py:137-151` 的幂等锁**只跑非降级模式**，而 `_STRIP_NUMBER_RE` 缺的恰好是降级模式独有的 `[a-z]、` 分支。写幂等锁时要把「开关的每一个取值」都当独立命名空间各锁一遍。
2. **「同一份数据被两处逻辑分别解释」是幽灵条目的通病** —— 正文首行既是「内容」也是「标题回声」，`_strip_duplicate_leading_title` 只按**当前**标题比对，一旦标题变了，回声就变成正文。修法不是加正则，而是**把「变更前值」显式传下去**（`rename_from`），让判断有两侧信息。
3. **批量入口与单章入口必须共用同一语义** —— 本轮 FIX-2 修完单章（`update_section`）后，批量入口（`_save_outline_to_db`）仍带同一缺陷（BUG-2b）。凡是「单个能成、批量失败」类缺陷，修完单章必须立刻回扫所有批量调用点。
4. **改写了要同时保证被写库** —— `changes` 不仅是日志，更是 `bool(changes)` 写库判据。只改内容不进 `changes` = 静默丢弃；护栏必须验「落库后读回」而非只验函数返回值。
5. **墙钟不可作性能判据** —— 同一份代码三次全量 58.37s / 87.63s / 130.36s，passed 恒为 1394。性能回归判定要用**直调微基准**（本轮 1.62 µs / 3.50 µs per call）。
6. **A/B 变异判定不能用「输出里有没有出现 selector」** —— selector 字符串本身会出现在 pytest 输出中，恒真。正确判据：`returncode != 0 and ("failed" in out.lower())`。
7. **PowerShell 把子进程 stderr 当异常** —— 脚本 stderr 有既有告警时管道 ExitCode=1，判定必须以脚本自身摘要行（`E2E_EXIT=0`）为准。
