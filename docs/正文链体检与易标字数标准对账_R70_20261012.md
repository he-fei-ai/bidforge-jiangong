## 2 · F1 详解：口径噪声被当成模型缺陷

### 2.1 当前口径是什么（唯一事实源，先确认它确实唯一）

`backend/app/services/content_utils.py:254-288` `text_word_count`：

```python
content = content.replace("\r\n", "\n").replace("\r", "\n")
return len(strip_fenced_code_blocks(content))
```

**剔除图表代码块后的字符数**。除此之外什么都没剔 —— 标点、Markdown 结构符（`|`、`-`、`#`、`*`、列表符号）、URL 字符、空白、换行全部计入。

**唯一性取证**（后端）：`word_count` 相关 18 处调用全部 import 同一函数；真实库 33 章 **落库 `word_count` ≠ `text_word_count` 的行数 = 0/33**。⇒ **后端单口径成立，这一项是绿的。**

### 2.2 三档口径实测（同一批 33 章语料，逐字重算）

| 口径 | 定义 | 全库总量 | mean ratio（总量/总预算） | in_band(±10%) | over | >1.3× 触发压缩 |
|---|---|---|---|---|---|---|
| **当前**（len 剔围栏） | 后端实配 | 67,767 | **136.9%**（中位 140.7%） | 3/33 (9.1%) | 19 (57.6%) | **19/33 (57.6%)** |
| **可读字数** | CJK 字符 + 西文按词，剔标点/结构/围栏/图片/URL | 52,717 | **106.5%**（中位 107.5%） | 10/33 (30.3%) | 4 (12.1%) | **4/33 (12.1%)** |
| **Word 式** | 中文按字、含中文标点、西文按词 | 58,164 | 117.5%（中位 117.7%） | 9/33 (27.3%) | 12 (36.4%) | 12/33 (36.4%) |

**口径差分解**（当前 → 可读，总缺口 15,050 字）：
- 标点字符 **8,744**，占当前口径 **12.9%**，占缺口 **58%**
- 其余来自空白折叠 / 西文按词合并 / Markdown 结构符 / 换行不计
- 逐章偏差：(可读−当前)/当前 中位 **−21.2%**、均值 −22.0%、区间 [−31.2%, −12.2%]

**当前口径均值 136.9% 与 R66 归档基线（`artifacts/_r66_db_quantify.txt`：mean 136.90% / median 140.73% / in_band 9.1% / over 84.8%）逐字吻合** ⇒ 探针口径与生产一致，不是探针自己造出来的数。

### 2.3 后果一：自动压缩的默认值建立在噪声上

`sse_handlers.py:4266-4274` 的注释**明写**了这条因果链：

```
#   · 传了 word_budget_tier 或 word_budget_override → **默认开**——
#     用户明确设定了全局字数标准，系统性超写（实测均值 136.9%）却
#     从不纠偏正是本轮要修的缺陷；
_shrink_default = word_budget_tier is not None or word_budget_override is not None
```

判定线 `WORD_OVER_RATIO = 1.3`，与 `_should_auto_shrink`（`:623`）同口径。

⇒ 换到可读字数口径，**触发压缩的章节从 19/33 掉到 4/33**。也就是说：**当前每批生成里约 15 章（79%）的压缩调用是在纠一个并不存在的超写**，每章最多 `SHRINK_MAX_ROUNDS = 3` 轮额外 LLM 调用（`content_shrink.py`），直接换算成费用与时延；而压缩本身有内容损坏风险（本仓红线是"宁可超字数不可损坏正文"）。

### 2.4 后果二：虚高口径反向掩盖"正文偏短"

| 判定 | 当前口径 | 可读口径 |
|---|---|---|
| `word_status` 翻转 | — | **19/33**（over→normal 15、normal→under 4） |
| 容差带（±10%）within_band 翻转 | 3/33 达标 | 10/33 达标（**13/33 翻转**） |
| `under`（`WORD_UNDER_RATIO=0.8`，续写门槛） | 0 章 | 4 章 |
| 低于 `LEAF_MIN_WORD_BUDGET=300` 地板 | 0 | 0（地板翻转 0/33，此项不受口径影响） |

⇒ 4 章在真实口径下偏短、应当续写，但当前口径把它们判成 `normal`，**续写门槛提前满足 → 漏判**。这与"虚高只影响成本"的直觉相反：**同一口径噪声同时放大两类相反的错误**（该压的不该压、该补的没补）。

### 2.5 换算系数（若只切口径、不动预算，等价于把目标全部下调）

`当前/可读 = 1.285` ⇒ 预算 1500 在可读口径下等价约 **1167 字**；四档 tier `(800, 1200, 2000, 2500)` 等价 `(622, 933, 1556, 1945)`。

⚠️ **这条系数不是"应该改成的新配置"**，只是量化"切口径而不调预算"的隐含影响，供选型时判断"口径与预算必须一起动、还是只动一个"。

### 2.6 语料代表性局限（必读，禁止据此直接调参）

本轮全部结论基于**本机运行库的一份方案**，样本形态：

- **33 章 / 1 个方案 / 预算全部 = 1500**（无任何 tier 分布、无 override 样本）
- 含围栏 6 章、含表格 21 章、**含图片语法 0 章、含 URL 0 章**
- 正文换行形态：**33/33 全 LF**（无 CRLF 样本）

⇒ 直接后果：**图片/URL 对缺口的贡献本轮实测为 0，不代表生产中为 0**；标点占比 12.9% 强依赖「施工方案正文表格密集」这一形态，换成图表/链接多的语料，缺口构成会变形。**1.285 这个系数不可外推为常数**，它只能说明「当前口径显著高于可读口径」这个方向性结论。任何调预算/tier 的动作前，必须用多方案、多 tier 语料复测。
> **→ Round 7 已复测（§12）**：盘库证实「多方案 / 多 tier」在本机结构性不可得（4 份库全是同一方案），改以 165 独立跨章章池复测 —— 总量级系数稳定（median 1.267，与 1.285 仅差 1.4%），但**逐章非常数**（CV 9.5%、极差 1.12~1.93）且**形态依赖**（表格/列表密集章 1.30+ vs 散文 1.20）。

## 6 · 方法论教训（本轮最重要的一条）

E 项缺口在场性**首轮探针给出的结论是错的**：正则计数显示 R4/R6/R7/R12"已在场"，与手工对账表直接冲突。逐条拉上下文复核后证实 **4 条全是误报**（见 §5 表内"零命中"行的取证）。

⇒ **可复用判据：在场性核查绝不能只数正则命中，必须逐条拉出命中行的上下文并排除同名异义。** 本仓同族教训已记录多次（AGENTS §5「D1 编排 100% 空转」、§5.14「AST 常量 vs 源码全文」），本轮再加一条：**正则命中 ≠ 在位；正则零命中也不能直接 = 缺口**（需确认不是换名实现）。

次轮教训：**并列口径的差异评估必须按输入逐个验证**（§3 的 ⚠️ 段）——`data.word_count || content.length` 看上去"任何口径都会分叉"，实测 8 个场景只有 1 个真分叉。

## 7 · 建议（不在本轮执行，等第二个确认门）

按"最小动作优先、可逆优先、不动既有默认"排序：

1. **先重估 R66 的自动压缩默认值**（最高性价比，纯配置/默认值动作）。当前默认开的依据（`sse_handlers.py:4268` 注释里那句「实测均值 136.9%」）已被 F1 证伪约 30 pt。**建议改回默认关 + 显式开启**，或保留默认开但把判定线从 `1.3×` 提到口径无关的位置。⚠️ 该动作直接影响每批生成的费用与时延，属行为变更，需要单独一轮 + A/B 护栏。（Round 7 补充证据：standard 1200 档模拟下字符口径触发的压缩有 **43% 属无谓纠偏**，见 §12.4。）

1. **文件工具的返回报文在本工作区不可信，实测三种形态同时出现**：

   去重靠一次性字节级补丁 `_r70_dedup_patch.py`（起点锚计数==2、终点锚==1、删除范围

标点+空白占剔围栏字符比：median **14.1%**（区间 7.9%~26.4%）。

- 方向与 §2.6 的预警一致：**表格/列表密度是抬高系数的主因**（`|`、列表符、单元格
  间空白计字符不计可读），纯散文/低结构章向 1.20 收敛；含围栏章系数反而更低
  （围栏已被两口径共同剔除，剩正文结构密度低）。
- 图片/URL 形态维度本轮探针仍**未覆盖**（只分围栏/表格/列表），§2.6 那条缺口未闭合，
  与「缺第二个方案」一并列为真复测的待补面。
- ⇒ 若未来真切口径，折算系数应**按正文形态取值**（施工组织类密集表格章 ≈ 1.30，
  散文章 ≈ 1.20），而非全库一个常数。

### 12.4 C · 四档 tier 敏感性（人为套用，语料无自然分布）

同一批 165 章分别套用 `WORD_BUDGET_TIERS` 四档，两口径各自跑 `word_status_for` /
±10% in_band / `>1.3×` 压缩触发线：

| tier | status 翻转 | in_band 翻转 | 压缩触发（字符/可读） | 其中无谓压缩 | 漏触发 |
|---|---|---|---|---|---|
| brief 800 | 4 (2%) | 1 (1%) | 165 / 161 | 4 | **0** |
| standard 1200 | **61 (37%)** | 37 (22%) | 139 / 79 | **60 (43%)** | **0** |
| detailed 2000 | **66 (40%)** | **71 (43%)** | 7 / 0 | 7 | **0** |
| ultra 2500 | 65 (39%) | 40 (24%) | 0 / 0 | 0 | **0** |

四点读数：
1. **漏触发恒为 0**（`readable ≤ text` 恒成立）⇒ 若切可读口径，**不会新增任何「该压没压」**；
   风险全部单侧 —— 与 §2.4「虚高掩盖偏短」方向一致，反向坐实。
2. **无谓压缩占比在 standard 档高达 43%**（60/139）：字符口径触发压缩的章里近一半
   在可读口径下根本不超 1.3× —— 每章最多 3 轮额外 LLM 调用（`SHRINK_MAX_ROUNDS`）
   纠的是口径噪声。这是 F1 「默认值依赖噪声」结论在扩样 5 倍后的**定量复现**（首轮
   19/33→4/33 相当于此表的 standard 行）。
3. in_band 翻转率在 1200~2000 档达 22%~43% ⇒ 「只切口径不调预算」会把大量 normal
   章改判 under（多余续写），§11.1 「口径与预算必须同轮」断言获得跨章样本支撑。
4. 语料真实预算 1500（介于 standard/detailed 之间）未单列 —— 两轮样本（33 章首轮 /
   165 章本轮）在 1500 档的结论已互相印证（mean 136.9% vs 137%量级）。
