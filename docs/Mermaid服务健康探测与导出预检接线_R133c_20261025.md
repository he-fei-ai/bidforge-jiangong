## 一、背景与目标

R130 已修「渲染失败」根因分流（infra 故障回退 PIL v2，不再全量缺图），
但本机 Mermaid HTTP Service 未部署，所有 Mermaid 源码图走 PIL v2
（版式弱于原生）。`mermaid_service.py` 早已具备 `/health` 探测能力
（Docker 2s / Railway 2s / mmdc 5s，60s TTL 缓存），但**探测结果从未
暴露到导出预检** —— 用户在导出页看不到「本次出图走原生 / 回退」的
确定性结论，只能事后翻日志。

本轮按 R131 计划落地两件事：

1. **导出预检携带 Mermaid 服务健康结论**（`content_audit` 顶层新增
   `mermaid_service` 键，响应头 `X-Content-Audit` 同步透出）；
2. **提供 Docker Compose 部署模板**（与 `mermaid_service.py` 现有
   URL 配置对齐），使部署方有据可依。

## 三、护栏（13 例 / 3 组）

`backend/tests/test_mermaid_health_r133_20261024.py`：

- **A 组 · audit_content 返回结构一致性（4 例）**：不传 `mermaid_status`
  返回仅含 `total/items`（与改造前逐字一致）；传入时顶层新增键且
  `total/items` 不动；`available=False` fail-soft 形态；多后端 backends 完整。
- **B 组 · mermaid_service 键字段（1 例）**：不污染 total/items 语义，
  键只含 `available`/`backends`。
- **C 组 · 源码锚点 + 功能实证（8 例）**：`audit_content` 签名含
  `mermaid_status`（AST）；`_probe_mermaid_status` 必须含
  `asyncio.wait_for(timeout=2)` 硬封顶 + `except Exception` fail-soft
  （AST 段锁）；**功能实证**——真实调用 helper 得到正确结构、摘除
  客户端（抛 RuntimeError 的假客户端）后降级为 `{"available": False,
  "backends": []}` 绝不抛；`collect_export_issues` 接线锚点 +
  **裸调用（不带 mermaid_status）不得回流**反向锁；响应头三分支行为
  （items 空 + mermaid 仍发精简头 / 有 items 发全量逐字 / 空 audit 不发头）。

## 五、配置默认行为说明

- **零新增配置项**：探测完全复用既有 `MERMAID_SERVICE_URL` /
  `MERMAID_RAILWAY_URL`（`main.py::capabilities` 读取，docker/railway
  URL 为空时即时返回 False，不发任何网络请求）；mmdc 探测走既有
  subprocess 检测。
- **未部署 Mermaid 服务时**（默认环境）：`mermaid_service.available=false`、
  `backends=[]`，导出行为与 R130 现状逐字一致（PIL v2 渲染），仅多一个
  确定性回传 —— 满足「服务不可用：预检显式提示回退状态」验收。
- **部署后**：按 `docker-compose.yml` 启动并设
  `MERMAID_SERVICE_URL=http://localhost:8080/render`，重启后端，
  `available=true` + `backends=["docker", ...]`，Mermaid 图走原生渲染 ——
  满足「服务可用：Mermaid 出图为原生版式」验收。
- **`allow_pil_fallback` 默认 False 契约不回归**（护栏
  `test_allow_pil_fallback_default_false_contract` 锁死 export.py 内
  不得硬编码 True；R100/R104 回归零失败佐证）。

## 六、风险与约束遵守

- 探测 2s 硬超时（`asyncio.wait_for`）+ fail-soft，绝不阻塞导出主流程 ✓
- 部署模板不把内部 URL 提交进代码默认值（走环境变量，compose 内
  仅容器互联地址）✓
- 探测失败按 advisory 档（logger.warning，不打 ERROR，无新增告警噪音）✓
- 既有响应头两种形态逐字不回归（护栏锁定）✓

## 七、遗留与后续

   真实提供 `/render` + `/health` 端点的服务镜像，或按注释自建
   Dockerfile。模板已把端点契约（POST /render body、GET /health）写清。
